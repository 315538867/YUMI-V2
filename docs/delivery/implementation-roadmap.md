# YUMI V2 实施路线图

## 1. 路线图原则

实施按可独立验收的业务闭环推进。每个阶段都必须包含 Flyway 迁移、领域测试、MySQL 集成测试、API 契约和可操作界面，不先铺设没有业务入口的通用平台。

技术基线：Java 21、Spring Boot 3.5.x、Spring Modulith、Spring Data JPA、Flyway、Maven、MySQL 8.x、JUnit 5、Testcontainers、React、TypeScript 和 Electron。

## 2. 全局门禁

每个阶段至少通过：

- `mvn test` 全量测试；
- Spring Modulith 模块依赖验证；
- Testcontainers MySQL 空库执行全部 Flyway 迁移；
- 新旧结构升级迁移测试；
- 金额 `BigDecimal` 精度和 JSON 字符串契约测试；
- 数据库约束、事务回滚、乐观锁和关键行锁测试；
- React 类型检查、单元测试和相关页面浏览器验证；
- 业务事实不可修改、更正路径和审计字段测试。

## 3. 阶段一：工程与基础设施

交付：Maven 工程、Spring Boot 应用、Spring Modulith 边界、React 共享前端、Electron 薄壳、MySQL 连接、Flyway、管理员认证、审计上下文、编号能力、文件适配层和统一错误响应。

验收：空库启动成功；Flyway 建立历史；Hibernate `validate` 通过；浏览器和 Electron 能登录并调用同一受保护 API；模块边界测试阻止跨模块访问内部包。

不做：复杂角色、员工账号、微服务、消息队列和 Kubernetes。

## 4. 阶段二：基础资料

交付：商品、客户、员工、工种、启停状态、成本参数、星级人工费、图片和基础资料变更记录。

验收：商品成本使用 `BigDecimal` 计算并保留 4 位小数；历史变更可追溯；停用资料不能进入新业务但历史可查询。

前置：阶段一。

## 5. 阶段三：订单核心

交付：订单草稿、订单明细、金额计算、确认校验、客户与商品快照、当前有效需求、订单变更、取消和履约事实基础结构。

验收：确认操作原子完成；确认后当前资料变化不影响快照；订单变更不能将有效数量降到累计有效发货以下；金额公式和待退款基础计算正确。

前置：阶段二。

## 6. 阶段四：库存

交付：库存批次、期初库存、库存流水、盘点调整、订单库存领用、取消领用和来源追溯。

验收：库存只能通过流水改变；领用在同一事务中扣减库存并登记订单履约接入；并发领用不会产生负库存；取消使用反向流水且已消费领用不能取消。

前置：阶段三。

## 7. 阶段五：生产

交付：正常计划、等待上游、逐工序一次性核验、返工、报废重做、未完成提醒、超额任务、其他排班和计划调整留痕。

验收：制作、捏毛装袋和缝边剪袋共享同一订单数量；核验满足完成等式；返工与重做使用独立来源余额；报废不自动减少客户需求；并发核验不能重复消费来源。

前置：阶段三；库存接入场景依赖阶段四。

## 8. 阶段六：订单发货

发货是 `orders` 模块内部组件，不建立独立顶级模块。

交付：发货草稿、确认、物流修改、作废、已关闭订单等量更正、来源快照、打印和 PDF。

验收：发货不超过可发货和当前有效需求；库存领用后发货不再次扣库存；作废恢复可发货但不自动恢复库存；已关闭订单的更正必须原批次失效和等量替代原子完成。

前置：阶段四和阶段五提供可发货来源。

## 9. 阶段七：收退款与关闭

收退款和关闭属于 `orders` 模块内部组件。

交付：收款、退款、实收净额、待退款、结清判定和订单关闭。

验收：收退款事实不可修改；退款关联订单变更或售后；待退款未处理不能关闭；只有有效需求全部发货或明确取消且款项结清时才能关闭；并发关闭必须在事务内重验条件。

前置：阶段六。

## 10. 阶段八：发货后售后

售后属于 `orders` 模块内部组件，使用独立台账且不重开原订单；已确认发货批次中的有效已发商品即可受理，订单剩余需求可以并行履约。

交付：售后单、有效发货来源校验、退回核验、售后返工、售后报废、库存补发、生产补发、补发发货和售后退款。

验收：只有已确认且有效的发货批次明细可作为来源；客户退回数量等于返工与报废之和；退回不自动入库；库存或生产合格只增加可补发；补发发货确认后才增加已补发；补发和售后退款不改变原订单订购数量、累计发货、未交付需求、有效应收或主状态；部分发货售后与剩余履约可并行。

前置：库存、生产、发货和退款能力。

## 11. 阶段九：报表与上线

交付：订单履约、库存台账、生产台账、发货、收退款和售后查询导出；Actuator 健康检查；日志与告警；备份恢复脚本和发布流程。

验收：事实可以重建当前投影；业务导出不包含物流字段；打印和 PDF 可展示当前有效物流；完成 MySQL 与文件一致恢复演练；按部署架构完成发布冒烟验证。

前置：阶段一至八。

## 12. 首期范围外

- 工资计算、结算、调整和发放；
- 完整财务模块、总账和会计凭证；
- 员工登录和复杂角色权限；
- 离线录入、同步队列和冲突合并；
- 在线支付；
- 原材料库存；
- 售后补差价；
- 自动库存批次合并；
- 复杂报表平台；
- 微服务、消息队列、Kubernetes 和多节点高可用。

未来财务模块读取订单模块的收退款事实，不反向接管订单生命周期。工资模块在业务规则单独确认后再进入新的设计和实施周期。
