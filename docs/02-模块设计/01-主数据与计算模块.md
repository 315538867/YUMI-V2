## 2. 权威边界

### 2.1 `master-data` 拥有

- 商品当前资料和核心制作规格；
- 商品标准工序预算、材料预算和预计分摊；
- 商品可复用定制预算方案及其当前预算快照；
- 客户当前资料和默认收货资料；
- 员工当前资料、就业事实和工种资格；
- 生产小组当前定义、当前成员关系、不可变小组成员快照和按人数配置的全局协作效率标准；
- 系统固定静态数据类别及其用户可维护条目；
- 商品录入默认值当前配置；默认值只用于新建商品时预填，提交后由商品版本保存最终采用值；
- 材料定义和材料标准单位；
- 向其他模块提供冻结快照所需的不可变主数据视图。

### 2.2 `master-data` 不拥有

- 订单商品、交付约定、成交价格和订单预计成本快照；
- 制品物理阶段、质量、处置、生产来源和数量余额；
- 排班任务、执行主体分配、工作量评估快照和核验事实；
- 正式工资、经营成本和真实现金；
- 售后义务、售后交付和售后金额决定；
- 文件对象本身、登录账号、角色或会话。

### 2.3 `calculation` 拥有

- 纯数值公式；
- 金额、比例和中间值精度；
- 舍入策略；
- 代码化公式规则版本；
- 公式输入输出值类型；
- 公式目录和自动化测试标识；
- 面向其他模块发布的纯计算接口及其输入输出契约。

### 2.4 `calculation` 不拥有

- 数据库表、Repository 或迁移；
- HTTP Controller、认证、权限或会话；
- 当前时间、随机数、外部服务或文件；
- 商品、订单、生产、工资或成本快照；
- 动态公式编辑、数据库表达式或脚本执行；
- 对业务模块的反向依赖。

## 3. 已确认的不变量

```text
商品、客户、员工和静态数据的当前定义由 master-data 持有；商品录入默认值只负责预填，不是保存后持续引用的核算参数
主数据修改不追溯刷新已确认订单和其他历史快照
定制预算方案只是预算与录单模板，不是订单事实
客户自供改变成本承担方，不删除材料需求
商品标准预算和定制预算必须按工序、人工、材料和分摊拆分
calculation 是唯一公式实现，业务模块只能调用公开纯计算接口，并保存输入快照、结果和规则版本
任何模块不得依赖 calculation 内部实现类、复制公式或用 SQL 重新实现公式
公式代码与自动化测试是规则权威来源
不建设动态公式编辑器和数据库公式引擎
不恢复固定生产路线、公共库存或跨订单制品领用
缝边剪袋是可选加工能力，不是所有商品的固定必经路线
```

## 4. 标识、精度与时间

所有独立记录使用正数 `BIGINT` 内部主键。进入公开契约或跨模块来源链的业务对象使用全局唯一、不可变的 `VARCHAR(64)` 稳定业务标识。

人工业务编号与稳定业务标识分离：

```text
商品编码：系统自动生成，格式为 P + 5 位递增序号（例如 P00001）；只保证唯一，允许空号且不补用
客户编号：C + 5 位以上递增序号
员工编号：E + 5 位以上递增序号
```

编号创建后不可修改，记录停用、离职或归档后不得复用。

公共数据类型：

```text
金额、成本、单价：DECIMAL(19,4)
比例、效率、损耗率：DECIMAL(12,8)
标准分钟：INT
数量：INT 或 BIGINT，按公共基线选择
重量和材料用量：DECIMAL(19,4)，单位由 unit_code 明确
系统时间：DATETIME(6)，按 UTC 保存
业务日期：DATE
版本：BIGINT，初始值 0，每次成功业务修改后递增
```

Java 金额、比例、重量和材料用量统一使用 `BigDecimal`。正式 HTTP 契约以十进制字符串传输这些值。

## 6. 商品与预算表

商品不是只有一张基础资料表。它在业务上是一个完整聚合，固定结构为：

```text
商品
├─ 核心制作规格
│  ├─ 单件标准重量
│  ├─ 制作星级及单件标准制作分钟
│  ├─ 模具数量
│  └─ 单模每日标准批次数
├─ 制作工序预算（必选）
│  ├─ 制作人工
│  ├─ 胶水
│  ├─ 色浆
│  └─ 其他制作物料
├─ 捏毛装袋工序预算（可选）
│  ├─ 装袋人工
│  ├─ 袋子
│  ├─ 填充物
│  └─ 其他装袋物料
├─ 缝边剪袋工序预算（可选）
│  ├─ 缝边剪袋人工
│  ├─ 缝线
│  └─ 其他缝边剪袋物料
├─ 商品级预计分摊
│  ├─ 模具摊销
│  ├─ 日常杂费
│  └─ 房租水电
├─ 交付级预算项目
│  ├─ 装箱
│  ├─ 外层运输包装
│  └─ 标准运费估算
└─ 多个定制预算方案
   ├─ 交付终点
   ├─ 各工序预算模板
   ├─ 各物料默认供应方
   ├─ 默认成交价格
   └─ 预算结果：预计成本、预计利润和预计利润率
```

其中，商品创建时自动生成内置标准方案；内置标准方案不是供用户选择的“默认方案”，不能被单独编辑，其内容随商品基本字段、工序字段和额外字段的正式修改同步更新。定制预算方案是预算与录单模板，不是订单事实；预计利润是根据方案成交价格和工作室承担预计成本计算出的预算结果，不是人工维护的独立账务事实。创建订单时可以选择某个方案作为初始模板，也可以按本次交易调整，订单确认后由 `orders` 冻结自己的交付约定和预计成本快照。

商品模块不提供服务端草稿。`CreateProductCommand` 必须一次提交完整的商品基本字段、制作工序字段、可选工序字段和额外字段；创建成功时商品、从属工序数据、内置标准方案及其计算结果原子生成，任一步失败均不得留下不完整商品。商品编辑和定制方案创建、编辑同样直接提交完整正式命令；计算预览只读且不持久化。`ACTIVE`、`INACTIVE` 只表示正式商品或方案是否可用于新业务，不是草稿与发布状态。

本章后续表结构是上述业务聚合的物理拆分：`products` 保存商品身份和核心制作规格，工序模板与物料预算表保存标准预算，预计分摊表分别保存商品级预计分摊和交付级预算项目，定制方案及其工序、材料条款表保存多个可复用方案，预算快照表保存按公式计算出的不可变结果。不得因为物理拆表而把它们理解成互不相关的独立业务对象。

### 6.1 `products`

| 字段 | 类型 | 空值 | 规则与含义 |
|---|---|---|---|
| `id` | BIGINT | 否 | 内部主键，正数 |
| `business_id` | VARCHAR(64) | 否 | 稳定商品标识，全局唯一 |
| `product_no` | VARCHAR(32) | 否 | 系统自动生成，格式为 `P` + 5 位递增数字；只保证唯一，允许空号且不补用；创建后不可修改且不得复用 |
| `name` | VARCHAR(120) | 否 | 去除前后空格，不允许空白；允许重复，以商品编号作为唯一识别依据 |
| `description` | VARCHAR(1000) | 是 | 可选商品说明，用于记录商品特征和制作注意事项；不参与排班、产能或成本计算 |
| `standard_weight_grams` | DECIMAL(19,4) | 否 | 必填的单件标准重量，统一按克保存且必须大于 0；用于材料用量、标准成本和预算快照计算 |
| `source_making_star_entry_id` | BIGINT | 否 | 创建或编辑时所选制作星级的来源标识，仅用于追溯选择来源；商品保存后不再依赖该条目的当前值进行计算 |
| `making_star_name` | VARCHAR(120) | 否 | 选择制作星级时带出并写入商品版本的星级名称 |
| `making_standard_minutes` | INT | 否 | 选择制作星级时带出并写入商品版本的单件标准制作分钟，保存后作为商品事实使用且不随静态数据变化 |
| `standard_sale_price` | DECIMAL(19,4) | 否 | 商品标准售价，非负；用于自动生成标准方案版本 |
| `glue_loss_rate` | DECIMAL(12,8) | 否 | 商品实际采用的胶水损耗率，非负；新建时由商品录入默认值预填，提交后写入商品版本 |
| `glue_unit_price` | DECIMAL(19,4) | 否 | 商品实际采用的胶水单价，非负；新建时由商品录入默认值预填，提交后写入商品版本 |
| `color_paste_unit_price` | DECIMAL(19,4) | 否 | 商品实际采用的色浆单价，非负；新建时由商品录入默认值预填，提交后写入商品版本 |
| `making_commission` | DECIMAL(19,4) | 否 | 单件制作提成，非负；作为计算模块的输入 |
| `making_other_material_cost` | DECIMAL(19,4) | 否 | 单件制作工序其他材料费用，非负，不拆成动态材料明细 |
| `mould_count` | INT | 否 | 商品可用模具数量，必须大于 0；与单模每日标准批次数共同决定该商品单日最大产能 |
| `daily_batch_count` | INT | 否 | 每个模具单日可完成的最大标准批次数，必须大于 0；与模具数量共同决定该商品单日最大产能 |
| `status` | VARCHAR(32) | 否 | `ACTIVE`、`INACTIVE` |
| `version` | BIGINT | 否 | 乐观版本 |
| `created_at` | DATETIME(6) | 否 | 创建时间 |
| `created_by` | VARCHAR(64) | 否 | 操作者标识 |
| `updated_at` | DATETIME(6) | 否 | 最后修改时间 |
| `updated_by` | VARCHAR(64) | 否 | 最后修改人 |

约束与索引：

- `UNIQUE(business_id)`；
- `UNIQUE(product_no)`；
- `CHECK(standard_weight_grams > 0)`；
- `CHECK(making_standard_minutes > 0)`；
- `CHECK(standard_sale_price >= 0)`；
- `CHECK(glue_loss_rate >= 0)`；
- `CHECK(glue_unit_price >= 0)`；
- `CHECK(color_paste_unit_price >= 0)`；
- `CHECK(making_commission >= 0)`；
- `CHECK(making_other_material_cost >= 0)`；
- `CHECK(mould_count > 0)`；
- `CHECK(daily_batch_count > 0)`；
- `CHECK(version >= 0)`；
- `INDEX(status, name, id)`；
- `source_making_star_entry_id` 在创建或编辑时必须解析为 `STAR_LEVEL` 类别中的有效条目；解析得到的名称和标准分钟在同一商品命令中写入商品版本，后续计算不得回读静态条目的当前值。

商品单日最大物理产能固定为：

```text
商品单日最大产能 = 模具数量 × 单模每日标准批次数
```

该上限必须参与后续工作量和排班可行性评估，不能只按有效工时与制作标准分钟判断。它是工作室范围内按业务日期和商品汇总的总上限；同一天该商品分配给所有个人与小组的有效任务计划数量合计都不得超过该上限。具体计入哪些任务状态、由哪个公开接口完成计算以及并发锁定方式，在计算模块和排班模块确认。

商品名称允许重复。商品创建后不提供物理删除，只允许启用或停用；停用只阻止新订单选择和新方案创建，不影响已有订单、历史快照和历史查询，商品编号不得复用。

### 6.2 `product_file_associations`

| 字段 | 类型 | 空值 | 规则与含义 |
|---|---|---|---|
| `id` | BIGINT | 否 | 内部主键 |
| `association_id` | VARCHAR(64) | 否 | 稳定关联标识 |
| `product_id` | BIGINT | 否 | 模块内商品外键 |
| `formal_file_id` | VARCHAR(64) | 否 | platform 正式文件标识，逻辑跨模块引用 |
| `purpose_code` | VARCHAR(32) | 否 | `MAIN_IMAGE`、`GALLERY_IMAGE` |
| `display_order` | INT | 否 | 主图固定为 0，画廊图从 1 开始 |
| `created_at` | DATETIME(6) | 否 | 正式关联时间 |

- `UNIQUE(product_id, formal_file_id, purpose_code)`；

- `UNIQUE(line_id)`；
- `UNIQUE(所属快照, line_no)`；

- 金额除利润外均不得为负；
- 快照创建后不可更新或删除；
- 输入摘要相同且来源版本、公式版本相同的重复重算可以复用已有结果，但不能覆盖；
- 订单确认时引用 `master-data` 提供的预算快照，并形成 `orders` 自己业务语义下的订单冻结快照；订单快照必须保留上游 `SnapshotRef`，不能把本表快照载荷复制成第二个主数据快照。

- 修改 `STAR_LEVEL` 名称或标准分钟时不批量更新商品；只有用户在商品编辑命令中明确重新选择或重新应用该星级，才把当前名称和标准分钟写入新的商品版本，并生成对应的 `PRODUCT` 与 `PRODUCT_MAKING_STANDARD` 快照；
- 快照头及明细创建后禁止 UPDATE/DELETE；来源当前记录停用或继续修改不得覆盖历史快照；
- 创建或变更当前主数据、追加对应事实、生成必要快照、递增版本、幂等成功记录和审计必须处于同一事务，任一步失败整体回滚；
- 查询端口只能读取已经物化的快照，不得在 GET/query 调用中补写“缺失快照”；迁移旧数据时必须先通过专用迁移命令补齐版本 `1`；
- `PRODUCT_STANDARD_BUDGET` 和 `PRODUCT_CUSTOMIZATION_BUDGET` 是可对外解析的计算结果快照类型，但不得替代 `PRODUCT`、`PRODUCT_CUSTOMIZATION_PROFILE` 等业务定义快照；预算快照必须保留其计算所采用的定义快照指针。商品计算输入已经固化在商品版本中，不存在录入默认值快照指针。

## 11. `calculation` 公式契约

### 11.1 纯函数要求

每个公式必须满足：

- 相同输入和相同规则版本始终得到相同输出；
- 不读取数据库、系统时间、当前用户或环境变量；
- 不写日志作为业务结果，不产生审计或业务事实；
- 输入输出为不可变类型；
- 不接受缺少单位和业务语义的裸 `Map`；
- 不在公式内部读取商品录入默认值或其他当前配置；所有计算值必须由调用方作为输入显式传入；
- 不以异常堆栈表达预期业务拒绝，使用结构化公式错误。

### 11.2 规则与舍入版本

每个可冻结结果固定携带：

```text
formulaCode
formulaRuleVersion
roundingVersion
```

首期版本标识固定为：

```text
formulaRuleVersion = COSTING_V1
roundingVersion    = MONEY_HALF_UP_SCALE_4_V1
```

版本是代码化解释标识，不是数据库公式记录。公式语义变化时新增版本实现和回归用例；历史规则在仍需重算或核对时必须可调用，不能在同一版本下静默改变结果。

### 11.3 公开纯计算接口边界

`calculation` 只通过公开纯计算接口提供能力。合法调用链为：

```text
调用模块应用层
→ calculation 公开纯计算接口
→ calculation 内部公式实现
```

约束：

- 调用方只能依赖公开输入、输出、错误和规则版本类型；
- 公式实现类、舍入工具、内部值对象和测试夹具均不得跨模块引用；
- 调用方不得复制公式、在 Repository/SQL 中重算公式，或通过当前数据库字段拼装另一个“等价算法”；
- 公式接口不读取主数据；需要主数据、业务标准和公式共同完成的业务判断，由拥有这些标准的模块公开查询接口并在内部调用 `calculation`；
- 返回值是计算结果，不是跨模块写入授权。正式命令仍需在自己的事务和版本条件下完成写入。

### 11.4 中间精度与最终舍入

- 输入按数据库公共精度校验；
- 中间乘除计算使用不低于 16 位小数的明确计算上下文；
- 不能在每一步无条件先舍入到 4 位后再继续计算；
- 对外冻结的金额统一四位小数；
- 比例冻结为八位小数；
- 数量产能使用 `floor` 时必须在公式定义中明确；
- 除零返回结构化错误或“不可计算”结果，不返回 0、无穷或 NaN；
- 汇总结果必须由未过早舍入的明细计算，并同时返回已舍入明细供核对。

## 12. 公式目录

### 12.1 材料公式

#### `GLUE_USAGE_V1`

```text
胶水用量 = 商品标准重量 × (1 + 损耗率)
```

输入：商品标准重量、损耗率。输出单位：克。损耗率必须非负。

#### `GLUE_COST_V1`

```text
胶水成本 = 胶水用量 × 胶水单价
```

#### `PIGMENT_COST_V1`

```text
色浆成本 = 胶水用量 × 色浆单价
```

胶水用量已经包含损耗，色浆成本不得再次乘损耗率。

#### `GENERIC_MATERIAL_COST_V1`

```text
材料成本 = 标准用量 × (1 + 适用损耗率) × 预算单价
```

只有明确采用该通用口径的材料使用本公式。胶水和色浆继续使用专用公式，避免重复损耗。

### 12.2 制作人工

#### `MAKING_STANDARD_DAILY_QUANTITY_V1`

```text
工作日标准数量
= floor(工作日小时数 × 60 ÷ 制作标准分钟)
```

#### `MAKING_EFFECTIVE_DAILY_QUANTITY_V1`

```text
制作有效产量
= floor(工作日小时数 × 60 × 制作有效工时率 ÷ 制作标准分钟)
```

制作有效产量必须大于 0，否则拒绝计算单件制作人工。

#### `TEAM_AVAILABLE_STANDARD_MINUTES_V1`

```text
小组可用标准分钟
= 工作日小时数 × 60 × 制作有效工时率 × 小组人数 × 协作效率因子
```

该公式用于制作排班工作量评估，不用于计算成员工资或拆分个人产量。个人执行主体仍使用：

```text
个人可用标准分钟
= 工作日小时数 × 60 × 制作有效工时率
```

计划标准分钟统一为：

```text
计划标准分钟
= Σ(商品制作标准分钟 × 计划数量)
```

#### `MAKING_UNIT_LABOR_COST_V1`

```text
制作单件人工成本
= (时薪 × 工作日小时数) ÷ 制作有效产量
```

制作有效工时率只作用于制作。

### 12.3 包装和缝边剪袋人工

#### `PACKAGING_UNIT_LABOR_COST_V1`

```text
包装单件人工成本
= 包装标准分钟 × (时薪 ÷ 60)
+ 适用包装提成
```

适用提成由商品或方案保存的明确值决定；公式本身不读取任何默认值。

#### `SEAM_CUTTING_UNIT_LABOR_COST_V1`

```text
缝边剪袋单件人工成本
= 缝边标准分钟 × (时薪 ÷ 60)
```

不乘制作有效工时率。

### 12.4 汇总、售价和利润

#### `UNIT_TOTAL_COST_V1`

```text
单件总成本
= 材料成本合计
+ 人工成本合计
+ 其他预计分摊合计
```

人工成本合计已经包含制作、包装、缝边剪袋和适用交付人工，不得再次把人工分项与人工总额重复相加。

#### `REFERENCE_UNIT_PRICE_V1`

```text
参考售价 = 单件总成本 ÷ (1 - 目标利润率)
```

目标利润率必须大于等于 0 且小于 1。

#### `EXPECTED_PROFIT_V1`

```text
预计利润 = 预计收入 - 工作室承担预计成本
```

#### `EXPECTED_PROFIT_RATE_V1`

```text
预计利润率 = 预计利润 ÷ 预计收入
```

预计收入为 0 时返回 `NOT_CALCULABLE`，不得执行除零。客户自供材料标准价值不计入工作室承担预计成本，但计入标准完整资源成本。

### 15.4 工作量评估查询


计算语义固定如下：

- 每个输入行 `plannedQuantity > 0`；同一集合内重复商品先按 `productBusinessId` 求和，标准快照引用按稳定商品标识升序返回；
- `standardMinutes = Σ(candidatePlanLines.商品制作标准分钟 × plannedQuantity)`；它只表示本次候选计划，不表示全天总量；
- `plannedMinutesBefore = Σ(existingPlanLines.商品制作标准分钟 × plannedQuantity)`；`plannedMinutesAfter = plannedMinutesBefore + standardMinutes`；
- `availableMinutes` 按执行主体公式计算；`remainingMinutes = availableMinutes - plannedMinutesAfter`，查询结果允许为负，只有 `UNDER_STANDARD/WITHIN_STANDARD` 结果可被排班持久化，因此持久化列仍非负；
- `loadRate = plannedMinutesAfter ÷ availableMinutes`，按 `WORKLOAD_ROUNDING_V1` 保留 8 位小数；`availableMinutes <= 0` 时不做除法；
- `plannedMinutesAfter < availableMinutes` 为 `UNDER_STANDARD`，相等为 `WITHIN_STANDARD`，大于为 `OVER_STANDARD`；主体无效、资格不满足、有效工作时间标准缺失或商品标准缺失为 `UNAVAILABLE`，并返回稳定 `unavailableReasonCode`；
- 商品制作标准、有效工作时间标准或小组人数效率标准缺失时禁止由排班模块自行补默认值。对外业务入口把对应 unavailable reason 映射为本章登记的稳定错误码；
- 所有乘除中间值使用 `BigDecimal`，禁止 `double`；分钟乘法不提前舍入，最终分钟和负载率按 `WORKLOAD_ROUNDING_V1` 四舍五入（`HALF_UP`）到 8 位。

边界规则：

- `master-data` 拥有标准、资格和评估口径，`calculation` 拥有纯公式实现，`scheduling` 拥有计划事实；
- 工作量评估接口不保存排班、不读取排班 Repository、不返回主数据 Entity 或内部主键；
- `scheduling` 只保存自己拥有的评估结果快照和本次返回的上游 `SnapshotRef`，不复制小组成员、商品标准或效率标准快照载荷；
- 正常任务是否允许 `OVER_STANDARD` 由排班业务策略决定；首期继续整体拒绝，不自动超排；
- `EMPLOYEE` 的可用分钟为 `workdayHours × 60 × makingEffectiveHourRate`；
- `TEAM` 的可用分钟为 `workdayHours × 60 × makingEffectiveHourRate × memberCount × collaborationEfficiencyFactor(memberCount)`；
- `TEAM` 代表小组共同产出，不拆分内部步骤、不分摊成员个人贡献；工资均分等规则属于 `payroll`，协作效率因子不得用作工资分配比例。

## 16. 命令锁定与事务

### 16.1 模块内锁序

```text
商品 / 客户 / 员工 / 小组效率标准 / 商品录入默认值业务根
→ 从属预算、方案或资格记录
→ 事实来源
→ 当前投影
```

同类型记录按内部主键升序锁定。

### 16.2 典型命令

商品创建或修改：

```text
接收完整商品命令，不接受部分保存或草稿标记
→ 创建时分配商品标识；修改时锁定商品及全部受影响从属行
→ 重验 expectedVersion、静态条目、材料状态和字段范围
→ 写入商品基本字段、工序字段和额外字段
→ 自动生成或同步更新内置标准方案
→ 调用 calculation 计算内置标准方案预算
→ 更新商品内容版本及当前从属数据
→ 按快照规则生成或复用必要快照
→ 提交幂等、审计和文件关联
```

任一步失败时，商品、工序数据、内置标准方案、预算结果、快照、幂等和审计整体回滚。定制方案创建或修改也必须一次提交完整方案，不允许先保存不完整方案再补充工序或材料字段。

客户更新：

```text
锁定客户
→ 重验 expectedVersion
→ 查询重复候选但不以重复为硬拒绝
→ 追加客户变更事实和明细
→ 更新客户当前记录与版本
→ 同事务提交幂等和审计
```

员工离职：

```text
锁定员工
→ 重验在职状态与 expectedVersion
→ 追加离职事实
→ 更新就业状态投影
→ 不修改历史任务、核验和工资事实
```

商品录入默认值更新：

```text
锁定 product_entry_defaults 单行
→ 重验 lockVersion 和全部默认值范围
→ 更新当前预填值与技术乐观锁版本
→ 记录平台操作审计，不生成业务变更事实或快照
→ 不自动重算或覆盖既有商品、方案、预算和历史快照
```

小组配置变更或停用：

```text
workforce-coordination 开启正式命令事务
→ 调用 scheduling.WorkTeamPlanReferenceGuardPort
→ scheduling 插入或锁定小组引用守卫并重验不存在 ARRANGED 引用
→ 调用 master-data.WorkTeamMutationParticipantPort
→ master-data 锁定小组根、当前成员和版本
→ 重验 expectedVersion、成员在职状态、制作资格和目标状态
→ 追加小组配置变更事实并更新当前投影
→ 无条件形成新的 master-data 小组快照版本
→ 同一事务提交；任一步失败整体回滚
```

页面预检查得到的“无引用”结果不能代替正式命令中的守卫。守卫锁一直保持到主数据变更提交，确保并发创建 `TEAM` 任务只能发生在变更提交之后，并读取变更事务已经物化的新快照。依赖方向固定为 `workforce-coordination → scheduling / master-data` 和 `scheduling → master-data 查询`，禁止 `master-data → scheduling`。

## 17. 幂等和领域唯一性

外部正式命令按公共基线使用：

```text
command_owner
operation_type
operator_id
idempotency_key_hash
```

参与写入的领域唯一约束至少覆盖：

- 同一命令只创建一个商品、客户、员工或生产小组；
- 同一命令只追加一次就业、资格或小组成员变更事实；
- 同一商品录入默认值更新命令只成功应用一次，不产生业务快照或变更事实；
- 同一商品或方案快照版本只创建一次；
- 同一文件不重复关联到同一商品用途。

试算查询不写成功幂等记录。输入摘要仅用于预算快照复用和核对，不替代正式命令幂等。

## 20. 查询、分页与重复提示

- 商品、客户和员工长列表使用稳定游标分页；
- 静态数据类别及单类别条目属于有界管理列表，可以不分页或使用页码分页；
- 排序字段使用服务端白名单，不暴露数据库列名；
- 客户重复候选按规范化名称和规范化电话分别检索，展示客户编号、名称、联系人、电话和默认地址摘要；
- 模糊重复检索只用于提示，不参与唯一约束；
- 核心预算数据缺失必须显式失败，不能以 0 补齐；
- 商品详情可显示最新预算快照，但必须同时显示快照版本、来源版本和规则版本。

## 21. Flyway 和种子

`master-data` 迁移必须：

- 建立本文列出的表、外键、唯一约束、检查约束和锁定索引；
- 预置四个固定静态数据类别；
- 预置四个固定工种 code；
- 预置商品录入默认值单行配置；该配置不物化业务快照；
- 预置胶水和色浆等系统必需材料时使用稳定 code；
- 不预置用户尚未确认的星级、包装档位或缝边种类；
- 不建立 JPA 序列表、公共库存表、固定生产路线表、数据库公式表或通用事件表；
- 不使用触发器执行预算计算、客户重复判断或跨模块编排。

固定种子必须在启动验证中与代码常量逐项核对。种子显示名允许后续受控修改时，稳定 code 不变。

## 22. 验证门禁

### 22.1 结构与约束

- 所有稳定业务标识和人工编号唯一；
- 负金额、非法比例、非法标准分钟和空白名称被数据库或边界拒绝；
- 静态时间定义不能用于 WORK_TYPE；
- 工种定义只能使用四个系统 code；
- 客户名称和电话允许重复；
- 员工编号、客户编号、商品编号和小组编号不可复用；
- 小组成员配置事实只追加，当前投影与事实在同一事务更新；`schedule_team_reference_guards` 串行化配置变更与新任务引用，活动计划引用期间禁止修改，取消或核验后可修改；
- 商品、定制方案、制作标准、客户、员工执行主体、小组、协作效率标准和两类预算结果快照均由 master-data 管理，其他模块只保存强类型引用；商品录入默认值不属于快照类型；
- `PRODUCT_STANDARD_BUDGET`、`PRODUCT_CUSTOMIZATION_BUDGET` 快照及明细不可更新和删除，且能追溯到本次计算采用的商品和方案（如有）快照；商品计算输入由商品版本自身提供；
- 所有快照类型均能通过 `(ownerModule, snapshotType, snapshotBusinessId, snapshotVersion)` 精确解析，类型与物理表映射不可歧义；
- calculation 模块没有数据库迁移和 Repository；
- 业务模块只依赖 calculation 公开纯计算接口，不依赖内部公式实现。

### 22.2 真实 MySQL 事务与并发

- 并发更新同一商品、客户、员工或商品录入默认值时只有一个 expectedVersion/lockVersion 成功；
- 商品当前记录、业务定义快照、制作标准快照、预算模板、预算快照、版本、幂等和审计按命令语义原子提交；
- 预算计算失败时不留下部分模板或快照；
- 客户当前记录、变更事实与新的 `CUSTOMER` 快照原子提交；
- 员工就业事实、当前就业投影与新的 `EMPLOYEE_ASSIGNMENT_SUBJECT` 快照原子提交；
- 工种授予和撤销不会产生两个有效投影，并与新的 `EMPLOYEE_ASSIGNMENT_SUBJECT` 快照原子提交；
- 定制方案头、工序或材料变更只形成一套完整同版本快照，不产生局部快照；
- 商品明确重新应用静态时间条目时，新的商品版本、`PRODUCT` 快照、`PRODUCT_MAKING_STANDARD` 快照和标准方案新版本原子提交；静态时间条目自身修改不批量锁定或刷新商品；
- 相同幂等键不产生第二套主数据、事实或快照；
- 锁定查询命中明确索引并按内部主键稳定排序。

### 22.3 公式测试

每个公式目录项必须登记自动化测试标识，并至少覆盖：

- 正常值；
- 精度边界；
- 0 值允许与禁止场景；
- 除零；
- 非法负数；
- 极大值溢出；
- 中间精度和最终舍入；
- 客户供料只改变承担成本、不删除标准价值；
- 胶水损耗只计算一次；
- 色浆不重复乘损耗率；
- 制作有效工时率只作用于制作；
- 包装与缝边剪袋不乘制作有效工时率；
- 收入为 0 时利润率不可计算；
- 历史规则版本在相同输入下保持原结果。

### 22.4 契约测试

- 命令输入不包含内部主键、调用方计算的总成本或目标预算投影；
- 快照查询不返回 Repository、行模型或文件存储键；
- 预算试算不产生业务写入；
- 正式保存不信任先前试算，必须重新计算；
- orders 引用主数据快照，并形成订单自己拥有的确认快照；主数据修改不回写历史；
- scheduling 通过 `EmployeeQualificationQuery` 或 `WorkAssignmentSubjectQuery` 校验员工/小组有效性和工种资格，不读取主数据表；
- scheduling 通过 `WorkloadAssessmentQuery` 获取标准工时评估，不复制公式、不读取标准工时表；
- 工作量评估返回标准、可用、计划前后、剩余、状态、输入指纹和完整规则版本；
- `TEAM` 评估只表达共同产出，按冻结成员数和全局协作效率因子计算，不返回成员个人贡献拆分；
- 小组配置变更通过 `workforce-coordination` 调用 `WorkTeamPlanReferenceGuardPort` 与 `WorkTeamMutationParticipantPort`，并与 `TEAM` 任务创建串行化；普通查询结果不能作为提交授权；
- 小组创建及每次成功变更都物化新快照，所有 Query 契约均为只读，不能在查询路径补建快照；
- payroll 通过 `WorkTeamSnapshotQuery` 解析历史成员并自行结算到人，master-data 和 scheduling 不生成工资分配；
- 固定类别和工种 code 没有通用增删接口；
- 公式接口不读取商品录入默认值、其他当前配置或系统时间；
- ArchUnit/Spring Modulith 门禁拒绝跨模块引用内部公式类、Repository、Entity 和基础设施实现。

## 23. 明确不采用

- 用商品当前值替代订单确认快照；
- 把所有成本压成一个可手改总成本；
- 用客户供料布尔值覆盖整道工序；
- 客户供料时删除材料需求或把用量改为 0；
- 把包装或缝边剪袋恢复为所有商品固定必经路线；
- 在商品中保存生产数量、公共库存或可发货数量；
- 为客户建立首期多地址簿、等级、标签和默认折扣；
- 用员工当前姓名覆盖历史任务和工资快照；
- 把管理员账号和员工身份合并；
- 让用户新增、删除静态数据类别或系统工种；
- 把包装提成放入包装档位定义；
- 用自由 key/value 配置替代字段明确的商品录入默认值；
- 在数据库保存公式表达式、脚本或动态规则；
- 在前端、订单、工资或成本模块复制同一套公式；
- 使用 FLOAT、DOUBLE、MySQL ENUM、EAV 或通用 JSON 保存核心预算；
- 用预算预计值代替正式工资、已归集经营成本或真实现金。

## 24. 与后续分册的衔接

`orders` 分册必须从本册取得商品、客户和预算快照引用，并根据订单确认行为形成 orders 自己拥有的、语义独立的确认快照；不得复制并冒充 master-data 快照。

`production` 与 `scheduling` 分册必须使用稳定商品标识和强类型快照引用，不直接读取本册表，也不得复制商品预算、小组成员或协作效率快照载荷。

`payroll` 分册可以调用 calculation 的工资相关纯公式，但正式工资规则、封账和补差由 payroll 拥有。

`cost-ledger` 只能把正式发生事实归集为经营成本，不能把本册预计预算直接认定为已发生成本。

`reporting` 可以组合本册当前主数据与其他模块公开查询，但其报表投影不得参与主数据命令校验。

## 25. 最终确认结论

```text
master-data 维护当前定义、标准和可复用预算模板
calculation 维护唯一的纯公式、精度和规则版本
商品拥有核心制作规格，但不拥有履约状态
预算按工序、人工、材料、承担方和分摊拆分
客户自供不删除材料需求，只改变工作室承担成本
定制方案是录单模板，订单确认后复制冻结
客户不启停、不删除，重复只提示
员工保留就业事实和工种资格历史
静态数据类别和工种 code 固定，时间条目可维护
商品录入默认值使用明确字段，只负责预填；最终采用值写入商品版本
公式不持久化、不动态编辑、不在多个模块重复实现
所有历史快照携带公式规则与舍入版本
```
