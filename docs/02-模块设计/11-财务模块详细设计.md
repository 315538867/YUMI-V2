# 财务模块详细设计

> 模块：`finance`　状态：已完成技术一致性审查，待 G0 多方签字冻结　版本：v1.0　日期：2026-09-29　实施阶段：G4/G8/G11

## 1. 职责与首期范围

`finance` 只拥有真实现金账户、收款、退款、赔付、工资支付、经营支出、现金更正和余额投影。订单应收、售后结算决定、工资应付和成本类别分别由业务模块拥有。

首期不建设采购模块和库存模块。采购、房租、水电及其他经营支出由财务通过具名命令录入真实现金事实，并在同一事务调用 `cost-ledger` 登记经营成本；这不表示系统具有采购订单、入库、库存余额或应付账款能力。

## 2. 不变量与状态

1. 现金事实必须引用财务账户、方向、币种、金额、对手方快照和业务来源。
2. 账户余额只能由有效现金事实重算，禁止直接改余额。
3. 同一外部支付流水在同一账户内唯一。
4. 退款和赔付不得超过调用方公开端口确认的可付金额。
5. 工资支付先由 `payroll` 锁定和登记支付关联，再写 finance 现金事实。
6. 经营支出必须选择受控 `expenseType`，并成功登记成本后一起提交。
7. 已对账事实只能追加更正，不能删除或覆盖。

账户状态：`ACTIVE -> FROZEN -> CLOSED`。现金事实类型：`CUSTOMER_RECEIPT`、`CUSTOMER_REFUND`、`AFTER_SALES_RECEIPT`、`AFTER_SALES_REFUND`、`COMPENSATION_PAYMENT`、`PAYROLL_PAYMENT`、`OPERATING_EXPENSE_PAYMENT`、`CASH_CORRECTION`。

## 3. 表设计

| 表 | 最终业务字段 | 关键约束与索引 |
|---|---|---|
| `finance_accounts` | `id, account_business_id, account_code, account_name, account_type, currency_code, status, opening_balance, opened_on, version, created_at, created_by` | `UK(account_business_id)`, `UK(account_code)`, `CHECK(opening_balance >= 0)` |
| `finance_cash_facts` | `id, fact_business_id, account_business_id, cash_type, direction, currency_code, amount, business_date, occurred_at, recorded_at, counterparty_type, counterparty_business_id, counterparty_name_snapshot, source_module, source_type, source_business_id, source_version, external_transaction_no, payment_method_code, description, operator_id, command_execution_id, corrects_fact_id, is_valid` | `UK(fact_business_id)`, `UK(account_business_id, external_transaction_no)`, `UK(source_module, source_type, source_business_id, source_version, cash_type)`, `IX(account_business_id, business_date)` |
| `finance_cash_allocations` | `id, allocation_business_id, cash_fact_business_id, target_module, target_type, target_business_id, allocated_amount, currency_code` | `UK(allocation_business_id)`, `UK(cash_fact_business_id, target_module, target_type, target_business_id)` |
| `finance_operating_expense_details` | `id, cash_fact_business_id, expense_type, bearer_type, bearer_business_id, tax_amount, net_amount, formal_file_id, cost_entry_business_id` | `UK(cash_fact_business_id)`, `UK(cost_entry_business_id)` |
| `finance_reconciliation_facts` | `id, fact_business_id, account_business_id, statement_date, statement_balance, system_balance, difference_amount, status, evidence_file_id, occurred_at, operator_id, command_execution_id, is_valid, active_unique_key` | `UK(fact_business_id)`, `UK(account_business_id, statement_date, active_unique_key)` |
| `finance_account_projections` | `account_business_id, currency_code, available_balance, last_fact_id, last_business_date, updated_at` | `PK(account_business_id)`, `IX(updated_at)` |
| `finance_source_projections` | `source_module, source_type, source_business_id, received_amount, paid_amount, refunded_amount, last_fact_id, updated_at` | `PK(source_module, source_type, source_business_id)` |

`finance_reconciliation_facts.active_unique_key = IF(is_valid, CONCAT(account_business_id, '|', statement_date), NULL)`，允许保留多次失效对账历史且同日最多一个有效结果。金额使用 `DECIMAL(19,4)`；`direction` 仅允许 `IN/OUT`；`amount > 0`。经营支出 `expense_type` 与成本类别映射由受控配置定义，提交时固化映射代码版本。

## 5. 正式命令

| 动作 | 命令所有者 | 参与模块 | 固定锁序 |
|---|---|---|---|
| 订单收款/退款 | orders | finance | order -> payment obligation -> finance account |
| 售后收款/退款/赔付 | after-sales | finance | after-sales -> settlement decision -> finance account |
| 实际工资支付 | finance | payroll | payroll result -> finance account |
| 采购/房租/水电等经营支出 | finance | cost-ledger | finance account -> cost source guard |
| 现金更正/对账 | finance | 无 | finance account -> original cash fact |

外部支付网关调用或回单生成属于提交后动作。数据库事务内只保存确定的业务与现金事实。

## 6. HTTP、权限与错误

端点：`POST /api/v1/finance/payroll-payments`、`POST /api/v1/finance/operating-expenses`、`POST /api/v1/finance/cash-facts/{id}/corrections`、`POST /api/v1/finance/accounts/{id}/reconciliations`、`GET /api/v1/finance/accounts`、`GET /api/v1/finance/cash-facts`。

权限：`finance.account.read`、`finance.cash.read`、`finance.cash.record`、`finance.payroll.pay`、`finance.expense.record`、`finance.cash.correct`、`finance.reconcile`、`finance.sensitive.read`。

错误码：`FINANCE_ACCOUNT_NOT_ACTIVE`、`FINANCE_CURRENCY_MISMATCH`、`FINANCE_EXTERNAL_TRANSACTION_DUPLICATED`、`FINANCE_SOURCE_DUPLICATED`、`FINANCE_AMOUNT_EXCEEDS_ELIGIBLE`、`FINANCE_PAYROLL_NOT_PAYABLE`、`FINANCE_EXPENSE_TYPE_INVALID`、`FINANCE_COST_REGISTRATION_FAILED`、`FINANCE_RECONCILIATION_CONFLICT`、`FINANCE_VERSION_CONFLICT`。

## 7. 迁移与验证

G4 内核使用 `V022`，G8 订单资金扩展使用 `V052`，G11 完整能力使用 `V081-V082`。G4 交付账户、客户收退款事实、来源防重和查询；G8 接入订单资金；G9 复用现金参与端口接入售后；G11 交付工资支付、经营支出、成本参与、更正和对账。

真实 MySQL 必测：同外部流水竞态、订单/售后资格变化、工资支付锁序、经营支出成本失败全回滚、余额并发、退款超额、现金更正、对账差异、投影重建、无采购和库存表、跨模块 SQL 为零。
