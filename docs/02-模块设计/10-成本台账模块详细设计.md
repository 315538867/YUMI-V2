# 成本台账模块详细设计

> 模块：`cost-ledger`　状态：已完成技术一致性审查，待 G0 多方签字冻结　版本：v1.0　日期：2026-09-29　实施阶段：G4/G11

## 1. 职责与不变量

`cost-ledger` 只记录已发生经营成本、成本更正、分摊和归集结果，不负责预算、报价、工资计算或现金支付。来源模块通过具名参与端口提交成本，调用方不能写成本表。

- 每一笔有效成本必须有唯一来源 `{sourceModule, sourceType, sourceBusinessId, sourceVersion}`；
- 原始成本与分摊结果分离，分摊不改变原始金额；
- 更正只追加，任何维度的有效成本合计必须可从事实重算；
- 金额、币种、承担方、成本类别、业务对象和发生日期不得缺失；
- `production`、`payroll`、`finance` 只提交自己的来源事实标识，不传任意 SQL 维度。

## 2. 分类

成本类别：`DIRECT_MATERIAL`、`DIRECT_LABOR`、`PRODUCTION_OVERHEAD`、`AFTER_SALES`、`FREIGHT`、`RENT`、`UTILITY`、`PURCHASE`、`ADMINISTRATIVE`、`OTHER_OPERATING`。

业务对象类型：`ORDER`、`ORDER_ITEM`、`PRODUCTION_DEMAND`、`SCHEDULE_TASK`、`AFTER_SALES_CASE`、`EMPLOYEE`、`PERIOD`、`UNALLOCATED`。

## 3. 表设计

| 表 | 最终业务字段 | 关键约束与索引 |
|---|---|---|
| `cost_source_guards` | `id, source_module, source_type, source_business_id, source_version, entry_business_id, created_at` | `UK(source_module, source_type, source_business_id, source_version)` |
| `cost_ledger_entries` | `id, entry_business_id, entry_no, source_module, source_type, source_business_id, source_version, cost_category, bearer_type, bearer_business_id, currency_code, amount, occurred_on, description, command_execution_id, created_at, created_by, version` | `UK(entry_business_id)`, `UK(entry_no)`, `IX(occurred_on, cost_category)`, `CHECK(amount >= 0)` |
| `cost_ledger_entry_dimensions` | `id, entry_business_id, dimension_owner_module, dimension_type, dimension_business_id, dimension_snapshot_owner_module NULL, dimension_snapshot_type NULL, dimension_snapshot_business_id NULL, dimension_snapshot_version NULL, allocation_weight` | `UK(entry_business_id, dimension_owner_module, dimension_type, dimension_business_id)`, `CHECK` 四个快照指针字段全空或全非空 |
| `cost_adjustment_facts` | `id, fact_business_id, entry_business_id, adjustment_type, currency_code, amount, reason_text, occurred_at, operator_id, command_execution_id, corrects_fact_id, is_valid` | `UK(fact_business_id)`, `IX(entry_business_id, occurred_at)` |
| `cost_allocation_runs` | `id, run_business_id, period_code, rule_code, rule_version, source_cutoff_at, source_fingerprint, status, started_at, finished_at, command_execution_id` | `UK(run_business_id)`, `UK(period_code, rule_code, rule_version, source_fingerprint)` |
| `cost_allocation_run_lines` | `id, line_business_id, run_business_id, source_entry_business_id, target_type, target_business_id, allocation_basis, allocation_ratio, allocated_amount` | `UK(line_business_id)`, `UK(run_business_id, source_entry_business_id, target_type, target_business_id)` |
| `cost_entry_projections` | `entry_business_id, effective_amount, allocated_amount, unallocated_amount, last_fact_id, updated_at` | `PK(entry_business_id)` |
| `cost_object_projections` | `object_type, object_business_id, currency_code, direct_material_amount, direct_labor_amount, overhead_amount, after_sales_amount, other_amount, total_amount, watermark, updated_at` | `PK(object_type, object_business_id, currency_code)` |

金额使用 `DECIMAL(19,4)`；分摊比例 `DECIMAL(12,8)`，同一来源的比例合计必须为 1，金额尾差按目标稳定业务标识升序分配最小单位。

## 4. 公开契约

```java
public interface CostLedgerParticipantPort {
    PreparedCostEntry prepare(PrepareCostEntry command);
    CostEntryRef commit(CommitCostEntry command);
}
public interface CostLedgerApplicationService {
    CostAdjustmentRef adjust(AdjustCostEntryCommand command);
    AllocationRunRef allocate(RunCostAllocationCommand command);
}
public interface CostLedgerQuery {
    CostObjectSummary getObjectCost(CostObjectRef objectRef);
    Page<CostEntryView> search(CostSearchCriteria criteria);
}
```

`prepare` 校验来源唯一性、类别、金额、维度和承担方并锁定 `cost_source_guards`；`commit` 只能提交准备范围，禁止扩大金额或维度。

## 5. 命令与事务

| 动作 | 所有者 | 参与模块 | 锁序 |
|---|---|---|---|
| 生产核验成本 | fulfillment-coordination | production、scheduling、cost-ledger | scheduling -> production -> cost source guard |
| 工资人工成本 | payroll | cost-ledger | payroll -> cost source guard |
| 经营费用现金与成本 | finance | cost-ledger | finance account -> cost source guard |
| 成本调整/分摊 | cost-ledger | 无 | allocation period guard -> entries |

G4 只需交付生产核验成本的来源防重、登记和查询；G11 扩展工资、经营费用、更正和分摊，不能在 G4 创建空占位命令冒充完整模块。

## 6. HTTP、权限和错误

端点：`GET /api/v1/cost-ledger/entries`、`GET /api/v1/cost-ledger/objects/{type}/{id}`、`POST /api/v1/cost-ledger/entries/{id}/adjustments`、`POST /api/v1/cost-ledger/allocation-runs`。

权限：`cost-ledger.read`、`cost-ledger.adjust`、`cost-ledger.allocate`、`cost-ledger.sensitive.read`。

错误码：`COST_SOURCE_DUPLICATED`、`COST_SOURCE_CHANGED`、`COST_AMOUNT_INVALID`、`COST_DIMENSION_INVALID`、`COST_PREPARED_SCOPE_CONFLICT`、`COST_ALLOCATION_RATIO_INVALID`、`COST_ALLOCATION_PERIOD_CLOSED`、`COST_VERSION_CONFLICT`。

## 7. 投影、迁移和验证

投影可从成本条目、有效更正和最后成功分摊运行重建。报表不得直接读取本模块表，只调用查询端口或使用 reporting 自有投影。

G4 内核使用 `V021`，G11 完整能力使用 `V080`。真实 MySQL 必测：来源唯一竞态、prepare/commit 范围扩大、参与命令失败全回滚、金额尾差、并发分摊、负金额拒绝、事实更正、对象投影重建、跨模块 SQL 为零。
