# V3 客户模块

> 模块代码：`customer`  
> 文档版本：V3.0  
> 编写日期：2026-10-29  
> 状态：V3 客户模块评审稿；评审通过前不进入页面实现

本文是 V3 客户模块的唯一需求与设计依据。客户模块只维护客户当前资料和客户快照；订单、收款、发货、售后和生产事实均不属于本模块。

## 摘要

- 客户档案是一张简单的主数据表：编号、名称、联系人、电话、备注和一组默认收货信息。
- 客户没有启用/停用状态，建档后长期可用，不硬删除。
- 客户名称和电话不要求唯一；保存前提示可能重复，由管理员确认是否继续。
- 客户模块自己保存客户快照；订单只保存客户快照引用和本次实际收货信息。
- 客户资料修改由平台审计记录，不建字段级变更历史表或历史页。
- 本模块没有业务计算，不依赖计算模块；只依赖平台编号、权限、审计和幂等。

## 1. 模块说明

客户模块管理可复用的客户身份、联系方式、默认收货信息和客户快照。

客户可以先于订单建立，被多个订单复用。订单确认时取得客户快照引用，并另行保存本次实际收货信息；之后修改客户资料不回写历史订单。

客户模块回答“这个客户是谁、默认怎么联系和收货、历史订单当时看到的是什么”；订单回答“这一单实际发给谁、发到哪里、成交了什么”。

## 2. 用户与使用场景

### 2.1 用户

| 用户 | 关心什么 | 在客户模块做什么 |
|---|---|---|
| 管理员 | 客户资料是否准确、是否重复 | 新建、编辑客户，维护默认收货信息 |
| 老板 | 客户数量和客户资料 | 查看客户列表和详情 |
| 订单 | 客户身份、联系方式和默认收货信息 | 通过客户快照引用取得客户资料；本次实际收货信息由订单自己保存 |
| 报表 | 客户维度汇总 | 通过客户公开查询或后续报表投影读取，不直接读客户表 |

### 2.2 现状与目标

管理员现在用 Excel 记录订单、商品、兼职每日产出和排班，客户信息通常夹在订单表里。

V3 把客户独立成一份可复用档案：

- 同一个客户不因多次下单重复录入；
- 客户默认收货信息只维护一组，订单可以本次修改；
- 客户资料修改不影响历史订单；
- 保存前提示可能重复的客户，但不自动合并。

## 3. 本期范围

### 3.1 本期提供

- 客户创建、编辑、查看；
- 客户编号自动生成；
- 客户名称、联系人、联系电话、客户备注；
- 一组默认收货信息：默认收货人、默认电话、默认地址、默认收货备注；
- 客户名称/电话重复提示；
- 客户快照创建、复用和按版本查询；
- 客户列表搜索和分页。

### 3.2 本期不提供

- 客户启用/停用状态；
- 客户硬删除；
- 客户合并；
- 多收货地址、地址簿、地址标签；
- 客户等级、客户类型、销售负责人、默认折扣、默认付款方式、默认结算周期、默认价格；
- 客户附件、营业执照、合同、客户图片；
- 客户订单数、应收、收款、退款等汇总投影；
- 客户字段级变更历史表和历史页；
- 客户服务端草稿；
- 客户业务计算；
- 通用“基础资料模块”。

## 4. 业务概念

| 术语 | 定义 |
|---|---|
| 客户 | 一个可复用的客户身份和联系资料，以客户编号区分 |
| 客户当前资料 | 客户现在的名称、联系人、电话、备注和默认收货信息 |
| 默认收货信息 | 客户档案上的一组默认收货人、电话、地址和备注；只用于新订单带入 |
| 本次收货信息 | 某一订单实际使用的收货人、电话、地址和备注；属于订单事实，不写回客户 |
| 客户快照 | 客户被订单引用时冻结的客户身份、联系方式和默认收货信息 |
| 内容版本 | 客户资料每次成功修改后递增的版本号 |

## 5. 字段定义

### 5.1 客户基本信息

| 字段 | 必填 | 类型/精度 | 规则 |
|---|---|---|---|
| 客户编号 | 系统生成 | `VARCHAR(32)` | 格式 `C-000001`；创建后不可修改、不可复用 |
| 客户名称 | 是 | `VARCHAR(80)` | 去首尾空格；不允许只输入空格、换行或控制字符；允许重名 |
| 联系人 | 是 | `VARCHAR(40)` | 去首尾空格；不允许换行或控制字符 |
| 联系电话 | 是 | `VARCHAR(30)` | 文本保存；允许数字、`+`、括号、空格、短横线；6 至 30 字符且至少 6 位数字；不要求唯一 |
| 客户备注 | 否 | `VARCHAR(500)` | 可空；用于客户习惯、结算说明或内部提醒；不参与订单计算 |

### 5.2 默认收货信息

| 字段 | 必填 | 类型/精度 | 规则 |
|---|---|---|---|
| 默认收货人 | 是 | `VARCHAR(40)` | 新建时默认带入联系人，可修改 |
| 默认电话 | 是 | `VARCHAR(30)` | 新建时默认带入联系电话，可修改；校验规则同联系电话 |
| 默认收货地址 | 是 | `VARCHAR(200)` | 新订单带入的默认地址，不代表每次交付都使用同一地址 |
| 默认收货备注 | 否 | `VARCHAR(300)` | 可空；只描述收货要求 |

每个客户只保存一组默认收货信息，不建地址簿。

### 5.3 系统字段

| 字段 | 说明 |
|---|---|
| `customer_business_id` | 稳定业务标识，不对外显示 |
| `content_version` | 客户正式内容变化时递增 |
| `row_version` | 并发编辑控制 |
| `created_at/created_by` | 创建时间和操作人 |
| `updated_at/updated_by` | 最近修改时间和操作人 |

### 5.4 客户快照字段

客户快照冻结：

- 客户编号、名称、联系人、电话、客户备注；
- 默认收货人、默认电话、默认地址、默认收货备注；
- 客户内容版本、内容指纹、创建时间。

客户快照不包含客户状态（客户没有状态），也不包含任何订单的本次收货信息。

## 6. 业务规则

### R1 客户编号

- 由平台编号能力生成，格式 `C-000001`；
- 创建后不可修改、不可复用；
- 客户不硬删除。

### R2 客户资料修改

- 客户资料一次提交完整内容，不保存服务端草稿；
- 修改携带 `rowVersion`，冲突返回 `CUSTOMER_VERSION_CONFLICT`；
- 内容实际变化时 `content_version` 递增，并由平台审计记录变更；
- 内容未变化时不递增版本，也不写审计变更记录；
- 客户资料修改不影响历史订单和历史快照。

### R3 客户名称和电话不要求唯一

- 客户名称允许重复；联系电话允许重复；
- 保存前查询同名或同电话的客户，向管理员展示候选客户；
- 名称按去首尾空格后的完整文本比较；电话按数字部分比较，忽略空格和分隔符；
- 管理员可以取消，也可以确认确属不同客户后继续保存；
- 系统不自动合并客户，不按名称自动匹配客户；
- 订单始终关联明确的客户编号。

### R4 默认收货信息只有一组

- 每个客户只保存一组默认收货人、默认电话、默认地址和默认收货备注；
- 新建订单时带入默认值；
- 订单可以修改本次收货信息，不写回客户档案；
- 修改客户默认收货信息不影响已确认订单。

### R5 客户没有业务状态

- 客户不设置启用/停用；
- 建档后可以继续用于新订单；
- 不提供客户删除；
- 客户资料错误通过编辑修正，订单历史仍按快照保留。

### R6 客户变更审计

- 客户创建和修改由平台审计记录；
- 审计记录操作人、时间、操作类型和变更摘要；
- 客户模块不建字段级变更事实表，也不提供客户变更历史页面；
- 快照创建、读取不写客户变更审计。

### R7 客户快照

- 客户模块拥有客户快照；
- 快照按客户内容版本唯一，同一版本复用；
- 快照创建在调用方事务内通过客户模块参与端口完成，失败时调用方事务回滚；
- 客户快照不可修改、不可删除；
- 其他模块只保存客户快照引用，不复制快照载荷；
- 订单的本次实际收货信息由订单自己保存，不放客户快照，也不回写客户档案。

### R8 历史与不回溯

- 客户当前资料修改只影响后续新订单；
- 已确认订单继续使用原客户快照引用；
- 客户模块不读取订单、收款、发货、售后表；
- 客户订单/收款汇总由订单/报表模块提供，不在本模块建投影。
## 7. 状态设计

客户没有业务状态，没有 `ACTIVE/INACTIVE`，也没有启停操作。

- 客户建档后长期可用；
- 客户不删除；
- 客户快照没有状态，不可修改；
- 客户资料变更由平台审计记录。

## 8. 数据模型与表设计

### 8.1 关系

```text
customer_customers
└─ 1:N customer_snapshots

客户快照不包含订单本次收货信息；订单保存自己的交付信息。
```

### 8.2 表清单

| 表 | 类别 | 用途 |
|---|---|---|
| `customer_customers` | 当前根 | 客户当前资料和默认收货信息 |
| `customer_snapshots` | 不可变快照 | 按客户内容版本冻结的客户资料 |

### 8.3 客户当前表

```sql
CREATE TABLE customer_customers (
    id BIGINT NOT NULL AUTO_INCREMENT,
    customer_business_id VARCHAR(64) NOT NULL,
    customer_no VARCHAR(32) NOT NULL,
    name VARCHAR(80) NOT NULL,
    contact_name VARCHAR(40) NOT NULL,
    phone VARCHAR(30) NOT NULL,
    customer_note VARCHAR(500) NULL,
    default_recipient VARCHAR(40) NOT NULL,
    default_phone VARCHAR(30) NOT NULL,
    default_address VARCHAR(200) NOT NULL,
    default_address_note VARCHAR(300) NULL,
    content_version BIGINT NOT NULL,
    row_version BIGINT NOT NULL,
    created_at DATETIME(6) NOT NULL,
    created_by VARCHAR(64) NOT NULL,
    updated_at DATETIME(6) NOT NULL,
    updated_by VARCHAR(64) NOT NULL,
    PRIMARY KEY (id),
    UNIQUE KEY uk_customer_business_id (customer_business_id),
    UNIQUE KEY uk_customer_no (customer_no),
    KEY ix_customer_name (name),
    KEY ix_customer_phone (phone),
    CONSTRAINT ck_customer_name CHECK (name <> ''),
    CONSTRAINT ck_customer_contact CHECK (contact_name <> ''),
    CONSTRAINT ck_customer_phone CHECK (phone <> ''),
    CONSTRAINT ck_customer_recipient CHECK (default_recipient <> ''),
    CONSTRAINT ck_customer_default_phone CHECK (default_phone <> ''),
    CONSTRAINT ck_customer_address CHECK (default_address <> '')
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_0900_ai_ci;
```

说明：

- 客户名称、电话不建唯一约束；
- 客户没有状态列；
- 客户不硬删除；
- 默认收货信息只有一组，字段直接放在客户根表。

### 8.4 客户快照

```sql
CREATE TABLE customer_snapshots (
    id BIGINT NOT NULL AUTO_INCREMENT,
    snapshot_business_id VARCHAR(64) NOT NULL,
    customer_business_id VARCHAR(64) NOT NULL,
    customer_content_version BIGINT NOT NULL,
    customer_no VARCHAR(32) NOT NULL,
    name VARCHAR(80) NOT NULL,
    contact_name VARCHAR(40) NOT NULL,
    phone VARCHAR(30) NOT NULL,
    customer_note VARCHAR(500) NULL,
    default_recipient VARCHAR(40) NOT NULL,
    default_phone VARCHAR(30) NOT NULL,
    default_address VARCHAR(200) NOT NULL,
    default_address_note VARCHAR(300) NULL,
    content_fingerprint CHAR(64) NOT NULL,
    created_at DATETIME(6) NOT NULL,
    created_by_command_execution_id VARCHAR(64) NULL,
    PRIMARY KEY (id),
    UNIQUE KEY uk_customer_snapshot_business_id (snapshot_business_id),
    UNIQUE KEY uk_customer_snapshot_version (
        customer_business_id, customer_content_version)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_0900_ai_ci;
```

说明：

- 快照不保存客户状态（客户没有状态）；
- 快照不保存订单本次收货信息；
- 同一客户、同一内容版本只创建一个快照；
- 快照只插入，不更新、不删除。

### 9.3 快照所有权

- 客户快照只保存在客户模块；
- 订单、售后、报表等模块只保存 `CustomerSnapshotRef`；
- 需要客户内容时调用 `CustomerSnapshotService.resolve`，按引用版本解析；
- resolve 结果只用于当前读取/展示，不持久化为快照副本；
- 订单本次收货信息由订单自己保存，不在客户快照中。

## 10. 事务与并发

### 10.1 创建客户

```text
校验字段
→ 生成客户编号
→ 写客户当前记录
→ 写平台审计和幂等
→ 一次提交
```

### 10.2 编辑客户

```text
按 rowVersion 锁定客户
→ 校验字段
→ 内容未变化：直接返回，不写版本和审计变更记录
→ 内容变化：更新客户当前记录，contentVersion 递增
→ 写平台审计
→ 一次提交
```

锁顺序固定为客户根；客户模块不涉及其他业务表。

### 10.3 客户快照

```text
按 customerId 读取当前客户
→ 按 customerContentVersion 查已有快照
→ 已存在则复用
→ 不存在则插入快照
→ 唯一键冲突时读取已创建快照返回
```

快照在订单确认等调用方事务内通过客户模块参与端口创建；创建失败时调用方事务回滚。

### 10.4 幂等

- 客户创建接入平台幂等；
- 更新使用 `rowVersion`，旧版本请求返回冲突；
- 快照唯一键作为并发兜底。

## 11. 历史与追溯

- 客户当前资料可以修改；
- 客户资料变更由平台审计记录，不建字段级变更历史表；
- 客户快照按内容版本冻结，历史订单继续按引用解析；
- 客户资料修改、默认收货信息修改不影响历史快照；
- 客户快照不包含订单本次收货信息，订单自己的交付事实独立保存；
- 客户不删除，因此历史引用不会失效。

## 12. 权限、审计与错误

### 12.1 权限

| 权限 | 能力 |
|---|---|
| `customer.read` | 查看客户列表、详情、默认收货信息；查询重复候选 |
| `customer.manage` | 新建、编辑客户 |
| `customer.snapshot.read` | 直接读取客户快照；订单/售后内部调用按调用方权限鉴权 |

- 客户页面直接读取快照需 `customer.snapshot.read`；
- 订单、售后等内部模块取得客户快照引用时按调用方业务权限鉴权；
- 客户模块不直接读其他模块表。

### 12.2 审计

必须审计：

- 客户创建、编辑；
- 客户快照创建、复用；
- 敏感客户资料读取（电话、地址、备注）按平台敏感数据访问审计记录。

客户模块不建字段级变更表，也不提供客户变更历史页；平台审计记录操作和访问，客户快照提供历史数据。

### 12.3 错误码

| 错误码 | 含义 |
|---|---|
| `CUSTOMER_NOT_FOUND` | 客户不存在 |
| `CUSTOMER_FIELD_INVALID` | 客户字段不合法 |
| `CUSTOMER_NO_CONFLICT` | 客户编号生成冲突 |
| `CUSTOMER_VERSION_CONFLICT` | 客户资料版本冲突 |
| `CUSTOMER_SNAPSHOT_CONFLICT` | 客户快照并发冲突且无法复用 |
| `CUSTOMER_SNAPSHOT_NOT_FOUND` | 客户快照不存在 |
| `CUSTOMER_SNAPSHOT_INVALID` | 客户快照类型、版本或指纹不匹配 |

前端提示：

- 字段错误在输入框内联显示；
- 客户不存在提示返回列表；
- 版本冲突提示刷新后重试，不覆盖服务端资料；
- 快照版本不存在或不匹配提示“数据已失效，请刷新后重试”；
- 不显示英文错误原文、内部 ID、指纹和版本号。

## 13. 页面与交互要求

### 13.1 页面清单

| 页面 | 建议路由 | 目的 |
|---|---|---|
| 客户列表 | `/customers` | 搜索、分页、查看、新建、编辑 |
| 客户详情 | `/customers/:id` | 只读查看客户资料和默认收货信息 |
| 新建客户 | `/customers/new` | 一次录入完整客户 |
| 编辑客户 | `/customers/:id/edit` | 修改客户资料和默认收货信息 |

客户没有状态页、停用操作或删除操作。

### 13.2 客户列表

- 页头使用紧凑页栏，不使用大标题；
- 列：客户编号、客户名称、联系人、联系电话、默认收货地址、更新时间；
- 搜索：名称、编号、联系人或电话；
- 操作：查看、编辑、新建客户；
- 不展示内部业务 ID、内容版本和指纹；
- 默认按客户编号升序，支持分页；
- 空状态提供“新建客户”。

### 13.3 客户详情

1. 页头：客户名称、客户编号、更新时间；
2. 基本信息：联系人、联系电话、客户备注；
3. 默认收货信息：收货人、电话、地址、备注；
4. 操作：编辑客户。

客户详情默认只读，编辑通过明确按钮进入；不显示客户状态或删除按钮。

### 13.4 新建/编辑客户

使用全页表单，不使用抽屉，不拆成多步向导。

分区：

```text
基本信息
→ 默认收货信息
→ 重复提示（如有）
→ 保存
```

交互要求：

- 客户编号新建时显示“保存后自动生成”；
- 客户名称、联系人、联系电话必填；
- 默认收货人、默认电话、默认地址必填；新建时默认收货人/电话预填联系人和电话，可修改；
- 默认收货备注可选；
- 离开未保存表单时确认；
- 更新时携带 `rowVersion`，冲突后提示刷新；
- 保存前调用重复查询；发现同名或同电话客户时显示候选列表：
  - 展示客户编号、名称、联系人、电话、默认地址；
  - 管理员可以取消或确认“仍然保存”；
  - 系统不自动合并；
- 保存成功后返回客户详情；
- 1600×900 下页头和主要操作首屏可见。

### 13.5 全局交互原则

- 不出现内部业务 ID、内容版本、指纹等术语；
- 无 `customer.manage` 不显示新建/编辑入口；
- 无 `customer.read` 不显示客户列表和详情；
- 列表、详情、编辑统一 loading、空态和错误态；
- 电话、地址等敏感资料按平台权限展示；
- 使用项目既有设计令牌和组件，不为客户模块单独造视觉；
- 控件按内容定宽，不横向拉满。

## 14. 验收标准

### 14.1 客户主数据

- [ ] 新建客户后客户编号自动生成且不可修改；
- [ ] 客户编号唯一，回滚可产生空号但不重复；
- [ ] 客户名称、联系人、电话、默认收货人、默认电话、默认地址必填；
- [ ] 客户名称和电话允许重复，重复时展示候选客户并可确认继续保存；
- [ ] 客户没有状态字段和启停操作；
- [ ] 客户不硬删除；
- [ ] 修改客户实际内容后内容版本递增；
- [ ] 内容未变化时不递增版本；
- [ ] 并发编辑使用 `row_version` 拒绝后提交者。

### 14.2 客户快照

- [ ] 同一客户内容版本只创建一个客户快照；
- [ ] 快照按客户内容版本复用，不重复创建；
- [ ] 快照不包含客户状态；
- [ ] 快照不包含订单本次收货信息；
- [ ] 客户修改后新订单取得新快照，历史订单继续解析旧快照；
- [ ] 客户快照只保存在客户模块，其他模块只保存 `CustomerSnapshotRef`；
- [ ] 其他模块通过版本化查询读取快照，不直接读快照表、不复制快照载荷；
- [ ] 快照创建失败时调用方事务回滚；
- [ ] 快照不能更新或删除。

### 14.3 数据与边界

- [ ] 客户模块不访问订单、收款、发货、售后、生产表；
- [ ] 客户模块不依赖计算模块，没有业务公式；
- [ ] 客户快照不包含订单交付覆盖值；
- [ ] 订单自己保存本次收货信息，不写回客户默认收货信息；
- [ ] 客户表和快照表字段对应；
- [ ] 页面按权限隐藏新建/编辑和敏感资料；
- [ ] 客户创建、编辑、快照创建有平台审计记录；
- [ ] 客户编号、字段长度和必填约束在数据库和应用层都生效。

## 15. 明确不采用

- 不采用客户启用/停用状态；
- 不采用客户硬删除；
- 不采用客户合并；
- 不采用多地址、地址簿、地址标签；
- 不采用客户等级、类型、销售负责人、折扣、账期、授信、会员体系；
- 不采用客户附件、图片、合同、营业执照；
- 不在客户模块汇总订单数、应收、收款、退款；
- 不采用客户服务端草稿；
- 不采用客户字段级变更事实表和历史页；
- 不采用通用“基础资料模块”；
- 客户模块不实现业务计算；
- 不把订单本次收货信息写回客户档案。

## 16. 与 V2 的主要差异

| V2 | V3 |
|---|---|
| 客户有 `ACTIVE / INACTIVE` 状态和停用/恢复操作 | 删除客户状态；客户建档后长期可用 |
| 客户字段只有名称、联系人、电话、默认地址 | 增加客户备注、默认收货人、默认电话、默认收货备注 |
| 客户快照接收订单收货覆盖值，并用覆盖指纹区分 | 客户快照只冻结客户资料；订单自己保存本次收货信息 |
| 快照唯一键包含覆盖指纹 | 快照按客户内容版本唯一 |
| 客户快照包含状态 | 快照不含状态（客户没有状态） |
| 客户模块包含订单/收款汇总 | 汇总不进入客户模块，留给订单/报表 |
| 客户变更事实表和历史页 | 删除；客户修改由平台审计记录，不提供字段级历史页 |

## 17. 外部依赖

客户模块只依赖平台能力，不依赖计算模块、全局模块或文件模块。

| 平台能力 | 对接要求 |
|---|---|
| 编号 | `nextNumber("CUSTOMER", "C-", 6)` 生成 `C-000001`；唯一、不可修改、不可复用 |
| 权限 | 提供认证上下文；客户使用 `customer.read/manage/snapshot.read` |
| 审计 | 平台记录敏感资料访问；客户模块记录创建、编辑、快照创建/复用 |
| 幂等 | 客户创建接入平台幂等；更新用 `rowVersion`；快照用唯一键兜底 |

平台对接验收：

- 客户编号唯一且不复用；
- 未授权请求被拒绝；
- 客户敏感资料读取有访问审计；
- 重复创建请求幂等；
- 客户模块不直接访问平台编号表、权限表或审计表。

## 18. 已确认口径

- 客户订单数、应收、收款、退款等汇总不在本模块；后续需要时由订单/报表模块提供。
- 不建客户字段级变更事实表，也不提供变更历史页；客户修改由平台审计记录。

本模块暂无待确认项。

## 19. 评审收口

- 客户无状态、无删除、无计算、无静态数据依赖，不建字段级变更历史表或历史页；
- 客户快照由客户模块保存，订单只存引用并自己保存本次收货信息；
- 客户名称/电话允许重复，保存前提示候选；
- 客户编号、快照版本、权限、审计和验收已对齐；
- 文档为 V3 客户模块评审稿，评审通过后再进入订单模块。
