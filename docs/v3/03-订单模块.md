# V3 订单模块

> 模块代码：`orders`  
> 文档版本：V3.0  
> 编写日期：2026-10-29  
> 状态：V3 订单模块评审稿；评审通过前不进入页面实现

本文是 V3 订单模块的唯一需求与设计依据。订单模块管理客户交易、订单明细、订单快照、发货和收退款登记；生产任务、生产进度、库存、工资和现金账户不属于本模块。

## 摘要

- 新订单一次创建并确认，不保存服务端草稿。
- 一个订单可以有多条商品明细；每条明细引用商品快照和方案快照，订单自己保存数量、成交单价、金额和备注。
- 订单自己保存订单快照；客户、商品、方案只保存快照引用。
- 订单收货信息归订单自己；客户档案只提供默认值。
- 订单支持多次分批发货和多次收款/退款。
- 订单状态只保留已确认、已完成、已取消；发货和收款进度用独立标签展示。
- 订单模块不做售后、已有订单接管、库存、生产任务、现金账户和物流平台同步。

## 1. 模块说明

订单模块回答：

- 哪个客户、什么时候下的单；
- 买了哪些商品、分别选了什么方案、多少件、成交价多少；
- 什么时候交付、发到哪里；
- 已经发了多少、收了多少、还差多少；
- 订单是否已经结束。

生产模块回答“怎么做、做到哪一步”，财务模块回答“现金在哪个账户”，订单模块只保存客户交易和履约事实。

## 2. 用户与使用场景

### 2.1 用户

| 用户 | 关心什么 | 在订单模块做什么 |
|---|---|---|
| 管理员 | 今天接了哪些单、哪些要交付、哪些没发货、哪些没收款 | 新建订单、修改订单、登记发货、登记收退款、取消订单 |
| 老板 | 订单金额、待交付、待收款、完成情况 | 查看订单列表、订单详情和履约进度 |
| 生产 | 这一单做什么商品、什么方案、多少件、什么时候要 | 通过订单快照引用取得生产依据，不直接修改订单 |
| 财务 | 订单应收、已收、退款 | 通过订单支付事实和订单快照核对，不在订单模块管理现金账户 |

### 2.2 现状与目标

管理员现在用 Excel 记录订单。V3 要让订单像一张可控的表：

- 新建时选客户、加商品、填数量和价格，确认后生效；
- 列表直接看到客户、金额、交付日期、发货和收款进度；
- 订单变化有记录，不静默覆盖；
- 已确认订单不受商品、客户后续修改影响。

## 3. 本期范围

### 3.1 本期提供

- 新建并确认订单；
- 订单多商品明细；
- 订单客户快照引用、商品快照引用、方案快照引用；
- 订单自己的收货信息和订单备注；
- 订单整单优惠、应收金额、已收/退款和余额；
- 订单快照和订单变更；
- 分批发货；
- 收款和退款登记；
- 订单完成和取消；
- 订单列表、详情、编辑和履约操作。

### 3.2 本期不提供

- 订单草稿；
- 售后案例、退回、返工、补发、赔付；
- 已有订单接管；
- 库存出库、库存余额；
- 生产任务、生产进度、排产；
- 现金账户、银行流水、支付渠道对接；
- 物流平台自动同步；
- 发货更正；
- 多收货地址、地址簿；
- 订单成本核算和工资；
- 通用折扣规则、客户等级价、促销。

## 4. 业务概念

| 术语 | 定义 |
|---|---|
| 订单 | 一个客户的一次交易和履约根，以订单编号区分 |
| 订单明细 | 订单中的一条商品交易，包含商品、方案、数量、单价、金额和备注 |
| 订单快照 | 订单确认或变更后冻结的订单条款版本，由订单模块保存 |
| 订单变更 | 已确认订单的条款变化，追加变更事实并生成新订单快照 |
| 本次收货信息 | 该订单实际使用的收货人、电话、地址和备注，属于订单，不属于客户 |
| 发货批次 | 一次实际发货，包含发货日期、物流信息和本次各明细数量 |
| 收款/退款 | 订单上的收款或退款登记，不代表现金账户余额 |
| 订单完成 | 当前有效明细全部发货，且净收款达到应收 |
| 订单取消 | 订单不再继续履约，保留历史记录 |

## 5. 字段定义

### 5.1 订单主表

| 字段 | 必填 | 类型 | 规则 |
|---|---|---|---|
| 订单编号 | 系统生成 | `VARCHAR(32)` | 格式 `SO-000001`；创建后不可修改、不可复用 |
| 客户 | 是 | 客户快照引用 | 新建时选择客户，保存客户快照 ID 和版本 |
| 下单日期 | 是 | `DATE` | 默认当前日期，可改为实际下单日期 |
| 期望交付日期 | 否 | `DATE` | 不得早于下单日期；只保存年月日 |
| 状态 | 是 | `CONFIRMED / COMPLETED / CANCELLED` | 新建即 `CONFIRMED` |
| 收货人 | 是 | `VARCHAR(40)` | 新建时从客户默认收货人带入，可修改 |
| 收货电话 | 是 | `VARCHAR(30)` | 新建时从客户默认电话带入，可修改 |
| 收货地址 | 是 | `VARCHAR(200)` | 新建时从客户默认地址带入，可修改 |
| 收货备注 | 否 | `VARCHAR(300)` | 本次收货要求 |
| 订单备注 | 否 | `VARCHAR(500)` | 整体说明、特殊要求 |
| 原始金额 | 计算返回 | `DECIMAL(19,4)` | 明细金额合计，由计算模块返回 |
| 优惠金额 | 是 | `DECIMAL(19,4)` | 大于等于 0，不大于原始金额 |
| 应收金额 | 计算返回 | `DECIMAL(19,4)` | 原始金额减优惠金额，由计算模块返回 |
| 已收金额 | 计算返回 | `DECIMAL(19,4)` | 有效收款合计 |
| 已退款金额 | 计算返回 | `DECIMAL(19,4)` | 有效退款合计 |
| 净收款金额 | 计算返回 | `DECIMAL(19,4)` | 已收减退款，由计算模块返回 |
| 完成时间 | 否 | `DATETIME(6)` | 订单完成时写入 |
| 取消原因 | 否 | `VARCHAR(500)` | 取消时必填 |

### 5.2 订单明细

| 字段 | 必填 | 类型 | 规则 |
|---|---|---|---|
| 明细编号 | 系统生成 | `VARCHAR(64)` | 订单内稳定标识 |
| 商品 | 是 | 商品快照引用 | 保存商品快照 ID 和版本 |
| 方案 | 是 | 方案快照引用 | 保存方案快照 ID 和版本 |
| 目标工序 | 系统 | `MAKING / BAGGING / SEAM_CUTTING` | 取方案快照的目标工序 |
| 订购数量 | 是 | `INT` | 大于 0 |
| 已发数量 | 系统 | `INT` | 大于等于 0，不大于订购数量 |
| 成交单价 | 是 | `DECIMAL(19,4)` | 默认带出所选方案快照的售价，不读商品标准方案售价；可修改；大于等于 0 |
| 明细金额 | 计算返回 | `DECIMAL(19,4)` | 由计算模块返回 |
| 明细备注 | 否 | `VARCHAR(300)` | 仅针对该商品的要求 |
| 生产需求引用 | 系统 | `VARCHAR(64)` | 确认后由生产模块返回，订单只保存引用 |
| 明细状态 | 是 | `ACTIVE / REMOVED` | 移除不删除行，保留历史 |

### 5.3 订单收货信息

订单收货信息和客户默认收货信息分开：

- 新建订单时从客户快照带入默认收货人、电话、地址、备注；
- 管理员可以在订单中修改本次收货信息；
- 订单确认后修改收货信息，只影响后续发货，不修改客户档案；
- 旧发货批次继续使用发货时的订单快照。

### 5.4 发货与收退款

| 字段 | 说明 |
|---|---|
| 发货编号 | 系统生成 `SH-000001` |
| 发货日期 | 只保存日期 |
| 物流公司、物流单号、发货备注 | 可选文本 |
| 发货明细 | 订单明细 + 本次数量 |
| 收款/退款类型 | `RECEIPT / REFUND` |
| 金额 | 大于 0 |
| 收款日期 | 只保存日期 |
| 收款方式 | 可选文本，如现金、微信、银行 |
| 收退款备注 | 可选 |

## 6. 业务规则

### R1 新订单一次确认

- 新建订单一次提交完整内容，创建成功即为 `CONFIRMED`；
- 不保存订单草稿；
- 创建时必须至少有一条有效明细；
- 创建时取得客户快照引用、每个明细的商品快照和方案快照引用；
- 创建时生成订单快照 v1；
- 创建时调用生产模块为每条明细建立生产需求，并保存引用；
- 生产需求创建失败时，订单创建整体回滚。

### R2 客户与商品引用

- 订单只保存客户快照引用，不复制客户资料；
- 订单明细只保存商品/方案快照引用，不复制商品定义；
- 订单明细的默认售价只取所选方案快照的售价，不取商品标准方案售价；
- 客户资料、商品或方案后续修改不影响已确认订单；
- 新订单只能选择启用商品；商品停用或快照取得失败时订单创建失败；
- 客户没有启停状态，客户不存在时订单创建失败。

### R3 订单快照

- 订单模块拥有订单快照；
- 确认时生成内容版本 1 的订单快照；
- 每次订单条款变更递增内容版本并生成新订单快照；
- 发货、收款、退款、状态变化不递增订单内容版本，不生成新订单快照；
- 订单快照包含订单编号、客户快照引用、收货信息、明细引用、数量、单价、金额、优惠、应收、备注和日期；
- 订单快照只包含当时 `ACTIVE` 的明细；`REMOVED` 明细保留在当前表，不进入后续快照；
- 订单快照不包含订单状态、已发数量、收退款和物流信息；
- 其他模块只保存 `OrderSnapshotRef`，不复制订单快照载荷。

### R4 订单变更

已确认订单允许的变更：

- 价格、优惠、订单备注、期望交付日期；
- 收货人、收货电话、收货地址、收货备注；
- 未发货数量的增减；
- 添加新明细；
- 移除未发货且未开始生产的明细。

限制：

- 已完成、已取消订单不能变更；
- 数量不能低于已发数量；
- 已有生产事实的数量变更由生产模块校验，生产模块拒绝时整笔变更失败；
- 不允许在原明细上直接更换商品或方案；需要换商品/方案时移除旧明细并新增明细；
- 已发货明细不能移除；
- 每次变更必须填写原因；
- 变更成功后内容版本递增、生成新快照、追加订单变更事实；
- 变更只影响后续发货和后续履约，不追溯修改历史快照。

### R5 发货

- 一个订单可以多次分批发货；
- 每次发货选择订单明细并填写本次数量；
- 本次可发数量上限由计算模块按订购数量和已发数量返回；订单只校验请求数量不超过返回上限；
- 生产可交付数量由生产模块单独校验并消费来源；生产不足时整笔发货失败；
- 发货使用当前订单快照中的收货信息；
- 发货成功后由计算模块返回新的已发数量、未发数量和履约进度，订单保存结果；
- 发货记录不可编辑、不可删除；
- 发货错误不在本期直接更正，留给后续发货更正/售后模块；
- 是否可完成由计算模块返回，订单只应用完成状态。

### R6 收款与退款

- 订单可以多次登记收款；
- 订单可以登记退款；
- 收款金额和退款金额必须大于 0；
- 可退款上限由计算模块返回，订单只校验请求不超过上限；
- 收退款记录不可编辑、不可删除；
- 收退款不管理现金账户，只登记订单上的收退款事实；
- 已收、已退、净收、余额和是否可完成由计算模块返回，订单保存结果；
- 订单完成后退款走后续售后模块，不在本模块新增退款。

### R7 完成与取消

订单完成：

- 计算模块根据有效明细、发货事实和收退款事实返回“是否可完成”；
- 订单只把状态置为 `COMPLETED` 并保存完成时间；
- 订单不自行比较已发数量和净收款。

订单取消：

- 计算模块返回是否可取消及阻塞原因；
- 订单只校验状态、原因权限，并调用生产模块取消生产需求；
- 订单不自行比较发货数量和净收款。

取消后状态为 `CANCELLED`，已完成和已取消都是终态，不能重新打开。

### R8 状态与进度

订单主状态只有：

- `CONFIRMED` 已确认；
- `COMPLETED` 已完成；
- `CANCELLED` 已取消。

发货进度、收款进度、生产进度不作为主状态，用独立标签展示：

- 待发货 / 部分发货 / 已发完；
- 待收款 / 部分收款 / 已收清；
- 生产进度由生产模块提供，订单只展示引用结果。

### R9 历史与不回溯

- 客户、商品、方案后续变化不影响已确认订单；
- 订单变更只影响后续版本；
- 发货批次使用发货时的订单快照；
- 收退款事实保留原记录；
- 订单不硬删除。

### R10 订单模块不读取其他模块的表

- 订单不直接读客户、商品、生产、财务、工资表；
- 客户/商品/方案通过快照引用和版本化查询读取；
- 生产需求和可发货数量通过生产模块公开接口校验；
- 收退款是订单业务事实，现金账户属于财务模块。

## 7. 状态设计

### 7.1 订单状态

| 当前 | 事件 | 下一状态 | 条件 |
|---|---|---|---|
| — | 创建并确认 | `CONFIRMED` | 输入完整、快照和生产需求创建成功 |
| `CONFIRMED` | 全部发货且净收款达到应收 | `COMPLETED` | 完成条件成立 |
| `CONFIRMED` | 取消 | `CANCELLED` | 无发货、无净收款、生产允许取消 |
| `COMPLETED` | — | 终态 | 不可重开 |
| `CANCELLED` | — | 终态 | 不可重开 |

### 7.2 发货与收款进度

- 发货进度 = 已发数量与有效订购数量的比较结果，由计算模块返回；
- 收款进度 = 净收款与应收的比较结果，由计算模块返回；
- 进度不改变订单主状态，只有完成条件成立才进入 `COMPLETED`。

## 8. 数据模型与表设计

### 8.1 关系

```text
orders_orders
├─ 1:N orders_order_items
├─ 1:N orders_order_snapshots
├─ 1:N orders_order_changes
├─ 1:N orders_shipments
│   └─ 1:N orders_shipment_items
└─ 1:N orders_payments

订单快照引用客户快照、商品快照和方案快照。
```

### 8.2 表清单

| 表 | 类别 | 用途 |
|---|---|---|
| `orders_orders` | 当前根 | 订单条款、状态、金额和履约投影 |
| `orders_order_items` | 当前明细 | 商品、方案引用、数量、价格和已发数量 |
| `orders_order_snapshots` | 不可变快照 | 订单条款版本 |
| `orders_order_changes` | 事实 | 订单变更原因和版本链 |
| `orders_shipments` | 事实头 | 发货批次 |
| `orders_shipment_items` | 事实明细 | 发货批次中的明细数量 |
| `orders_payments` | 事实 | 收款和退款登记 |

### 8.3 订单当前表

```sql
CREATE TABLE orders_orders (
    id BIGINT NOT NULL AUTO_INCREMENT,
    order_business_id VARCHAR(64) NOT NULL,
    order_no VARCHAR(32) NOT NULL,
    customer_business_id VARCHAR(64) NOT NULL,
    customer_snapshot_business_id VARCHAR(64) NOT NULL,
    customer_snapshot_version BIGINT NOT NULL,
    order_date DATE NOT NULL,
    expected_delivery_date DATE NULL,
    status VARCHAR(16) NOT NULL,
    delivery_recipient VARCHAR(40) NOT NULL,
    delivery_phone VARCHAR(30) NOT NULL,
    delivery_address VARCHAR(200) NOT NULL,
    delivery_note VARCHAR(300) NULL,
    order_note VARCHAR(500) NULL,
    original_amount DECIMAL(19,4) NOT NULL,
    discount_amount DECIMAL(19,4) NOT NULL,
    receivable_amount DECIMAL(19,4) NOT NULL,
    paid_amount DECIMAL(19,4) NOT NULL,
    refunded_amount DECIMAL(19,4) NOT NULL,
    net_paid_amount DECIMAL(19,4) NOT NULL,
    completed_at DATETIME(6) NULL,
    cancel_reason VARCHAR(500) NULL,
    content_version BIGINT NOT NULL,
    row_version BIGINT NOT NULL,
    created_at DATETIME(6) NOT NULL,
    created_by VARCHAR(64) NOT NULL,
    updated_at DATETIME(6) NOT NULL,
    updated_by VARCHAR(64) NOT NULL,
    PRIMARY KEY (id),
    UNIQUE KEY uk_order_business_id (order_business_id),
    UNIQUE KEY uk_order_no (order_no),
    KEY ix_order_status_date (status, order_date),
    KEY ix_order_customer (customer_business_id),
    CONSTRAINT ck_order_status CHECK (status IN ('CONFIRMED', 'COMPLETED', 'CANCELLED')),
    CONSTRAINT ck_order_discount CHECK (discount_amount >= 0 AND discount_amount <= original_amount),
    CONSTRAINT ck_order_receivable CHECK (receivable_amount >= 0),
    CONSTRAINT ck_order_paid CHECK (paid_amount >= 0),
    CONSTRAINT ck_order_refunded CHECK (refunded_amount >= 0),
```

## 10. 计算依赖

订单模块不计算金额、数量上限、余额、进度或完成/取消判断。需要计算模块提供：

| 方法 | 输入 | 输出 |
|---|---|---|
| `calculateOrderTotals` | 明细数量、单价、优惠金额 | 明细金额、原始金额、应收金额、优惠是否合法 |
| `calculateOrderChangeLimits` | 当前明细、已发数量、请求变更 | 每条明细的可增减范围、变更后金额 |
| `calculateOrderShipmentLimits` | 当前明细、已发数量 | 每条明细的可发数量上限 |
| `calculateOrderPaymentSummary` | 收退款记录 | 已收、已退、净收款、余额、可退款上限 |
| `calculateOrderFulfillment` | 有效明细、发货事实、收退款事实 | 每条明细已发/未发数量、发货进度、收款进度、是否可完成 |
| `calculateOrderCancellationEligibility` | 订单、发货、收退款 | 是否可取消及阻塞原因 |

要求：

- 计算模块拥有金额、数量范围、余额、进度、优惠校验、完成/取消判断和舍入；
- 订单模块只组装输入、调用方法、保存返回结果和应用状态，不自行计算或比较派生值；
- 生产可交付数量由生产模块校验，不进入计算模块的订单上限计算，订单也不自行相减；
- 计算失败时订单保存、变更、发货、收退款或取消整体回滚；
- 订单列表和详情金额、余额、进度全部来自计算模块结果或已保存投影；
- 字段必填、状态、权限、存在性校验仍由订单模块执行，不属于业务计算。

## 11. 事务与并发

### 11.1 创建订单

```text
校验客户和商品
→ 取得客户快照引用
→ 为每条明细取得商品/方案快照引用
→ 调用计算模块计算金额
→ 生成订单编号
→ 写订单、明细
→ 生产模块建立生产需求，保存需求引用
→ 生成订单快照 v1
→ 写审计和幂等
→ 一次提交
```

任一步失败整体回滚，不留下订单、快照或生产需求。

### 11.2 变更订单

```text
锁定订单和明细
→ 校验状态、contentVersion、rowVersion
→ 分类变更
→ 调用计算模块取得变更数量范围和变更后金额
→ 数量/明细变化：调用生产模块调整需求
→ 更新订单条款
→ 内容版本递增
→ 生成新订单快照
→ 写订单变更事实
→ 写审计
→ 一次提交
```

生产调整失败时订单变更整体回滚。

### 11.3 发货

```text
锁定订单和明细
→ 调用计算模块取得可发数量上限
→ 校验请求数量不超过上限
→ 生产模块校验可交付并消费来源
→ 写发货批次和明细
→ 调用计算模块取得新的已发数量、进度和是否可完成
→ 保存已发数量/进度；满足完成则写完成时间、状态 COMPLETED
→ 写审计和幂等
→ 一次提交
```

### 11.4 收退款

```text
锁定订单
→ 调用计算模块取得可退款上限
→ 校验请求金额不超过上限
→ 写收退款事实
→ 调用计算模块取得新的已收/已退/净收/余额和是否可完成
→ 保存结果；满足完成则写完成时间、状态 COMPLETED
→ 写审计和幂等
→ 一次提交
```

### 11.5 取消

```text
锁定订单
→ 调用计算模块取得取消资格和阻塞原因
→ 不可取消则返回原因
→ 生产模块取消对应需求，失败整体回滚
→ 写状态 CANCELLED、取消原因
→ 写审计
→ 一次提交
```

### 11.6 并发

- 订单和明细使用 `row_version` 拒绝并发覆盖；
- 订单快照唯一键防止重复版本；
- 发货/收退款/取消使用订单行锁；
- 订单内容版本冲突返回 `ORDER_VERSION_CONFLICT`。

## 12. 历史与追溯

- 订单当前条款可改，改后生成新订单快照；
- 历史订单快照不可修改；
- 发货和收退款是不可变事实；
- 订单变更事实保留原因、版本前后和操作人；
- 客户、商品、方案后续修改不影响订单快照；
- 订单不删除，取消保留历史。

## 13. 权限、审计与错误

### 13.1 权限

| 权限 | 能力 |
|---|---|
| `order.read` | 查看订单列表、详情、快照和履约进度 |
| `order.create` | 新建并确认订单 |
| `order.change` | 变更已确认订单 |
| `order.ship` | 登记发货 |
| `order.payment` | 登记收款和退款 |
| `order.cancel` | 取消订单 |
| `order.snapshot.read` | 直接读取订单快照；生产/财务内部调用按调用方权限鉴权 |

- 客户、商品资料读取通过对应模块快照服务，不直接读客户/商品表；
- 订单金额、收退款、客户联系方式属于敏感数据，读取按平台敏感数据访问审计记录；
- 生产、财务内部调用订单快照按调用方业务权限鉴权。

### 13.2 审计

必须审计：

- 订单创建、变更、取消；
- 发货、收款、退款；
- 订单快照创建、复用；
- 敏感数据读取由平台记录。

### 13.3 错误码

| 错误码 | 含义 |
|---|---|
| `ORDER_NOT_FOUND` | 订单不存在 |
| `ORDER_FIELD_INVALID` | 订单字段不合法 |
| `ORDER_CALCULATION_FAILED` | 金额、数量范围、余额或履约计算失败 |
| `ORDER_CUSTOMER_INVALID` | 客户不存在或客户快照不可用 |
| `ORDER_PRODUCT_INVALID` | 商品不存在、已停用或商品快照不可用 |
| `ORDER_ITEM_INVALID` | 订单明细不合法 |
| `ORDER_DISCOUNT_INVALID` | 优惠金额不合法 |
| `ORDER_VERSION_CONFLICT` | 订单内容版本或行版本冲突 |
| `ORDER_CHANGE_NOT_ALLOWED` | 当前状态不允许变更 |
| `ORDER_CHANGE_EXCEEDS_REMAINING` | 变更数量超过可调整数量 |
| `ORDER_CHANGE_PRODUCTION_REJECTED` | 生产模块拒绝订单变更 |
| `ORDER_HAS_SHIPMENT` | 已有发货，不能按当前操作处理 |
| `ORDER_PAYMENT_INVALID` | 收退款金额或类型不合法 |
| `ORDER_REFUND_EXCEEDS_PAID` | 退款超过净收款 |
| `ORDER_SHIPMENT_INVALID` | 发货字段或数量不合法 |
| `ORDER_SHIPMENT_QUANTITY_EXCEEDED` | 发货数量超过未发数量 |
| `ORDER_PRODUCTION_INSUFFICIENT` | 生产模块可交付数量不足 |
| `ORDER_SNAPSHOT_CONFLICT` | 订单快照并发冲突且无法复用 |
| `ORDER_SNAPSHOT_NOT_FOUND` | 订单快照不存在 |
| `ORDER_SNAPSHOT_INVALID` | 订单快照类型、版本或指纹不匹配 |
| `ORDER_NO_CONFLICT` | 订单编号生成冲突 |

前端提示：

- 字段错误内联显示；
- 订单不存在提示返回列表；
- 版本冲突提示刷新后重试；
- 发货/生产数量不足提示具体明细和可发数量；
- 权限不足统一提示，不暴露资源是否存在。

只读信息不使用禁用输入框伪装；操作通过明确按钮进入。

### 14.4 新建订单

使用全页表单，不使用抽屉，不拆成多步向导。

分区：

```text
客户与收货
→ 商品明细
→ 金额与优惠
→ 确认订单
```

交互要求：

- 选择客户后带入默认收货信息，允许修改；
- 商品只能选择启用商品；
- 选择商品后选择方案，带入方案快照售价作为成交单价，允许修改；
- 每条明细填写数量、单价、明细备注；
- 至少一条有效明细；
- 整单优惠不能大于原始金额；
- 金额和余额由服务端计算，前端不自行计算；
- 确认前显示订单摘要；
- 创建成功即已确认，不出现“保存草稿”；
- 离开未保存表单时确认；
- 1600×900 下页头、摘要和主要操作首屏可见。

### 14.5 变更订单

- 只允许已确认订单；
- 商业字段、收货信息、备注、期望日期可直接修改；
- 数量调整、添加/移除明细走变更命令；
- 已发数量不能减少；
- 不允许在原明细上更换商品/方案；
- 变更必须填写原因；
- 保存后显示新订单版本和变更记录；
- 版本冲突提示刷新。

### 14.6 发货与收退款

- 发货按明细显示可发数量，默认填入剩余数量，允许改小；
- 发货日期默认当前日期；
- 物流公司、单号、备注可选；
- 收款/退款金额大于 0，退款不能超过净收款；
- 收退款记录列表不可编辑、删除；
- 操作成功后刷新发货/收款进度和订单状态；
- 已完成订单不再显示发货/收款操作。

## 15. 验收标准

### 15.1 创建与快照

- [ ] 新订单一次提交后状态为 `CONFIRMED`，没有草稿；
- [ ] 订单编号自动生成且不可修改；
- [ ] 订单至少一条明细，数量大于 0；
- [ ] 创建时取得客户、商品、方案快照引用；
- [ ] 商品停用或快照不可用时订单创建失败；
- [ ] 创建时生成订单快照 v1；
- [ ] 创建时每条明细建立生产需求并保存引用；
- [ ] 生产需求创建失败时订单整体回滚。

### 15.2 订单变更

- [ ] 已确认订单可以修改价格、优惠、备注、期望日期和收货信息；
- [ ] 数量变更不能低于已发数量；
- [ ] 已发货明细不能移除；
- [ ] 不允许原明细直接更换商品/方案；
- [ ] 变更必须填写原因；
- [ ] 变更后内容版本递增并生成新订单快照；
- [ ] 变更只影响后续发货和履约，不修改历史快照；
- [ ] 已完成、已取消订单不能变更。

### 15.3 发货与收退款

- [ ] 支持多次分批发货；
- [ ] 发货数量不超过计算模块返回的订单可发上限；
- [ ] 发货前由生产模块校验可交付数量并消费来源；
- [ ] 发货记录不可编辑、删除；
- [ ] 收款和退款记录不可编辑、删除；
- [ ] 退款不超过计算模块返回的可退款上限；
- [ ] 已收、已退、净收、余额、可退款上限由计算模块返回；
- [ ] 完成资格由计算模块返回，订单只应用 `COMPLETED` 状态；
- [ ] 发货或收退款失败时整体回滚。

### 15.4 订单快照与历史

- [ ] 同一订单内容版本只创建一个订单快照；
- [ ] 订单快照不可修改、不可删除；
- [ ] 发货使用发货时的订单快照；
- [ ] 客户、商品、方案后续修改不影响订单快照；
- [ ] 其他模块只保存 `OrderSnapshotRef`，不复制订单快照载荷；
- [ ] 订单快照不包含状态、发货和收退款。

### 15.5 数据与边界

- [ ] 订单模块不访问客户、商品、生产、财务、工资表；
- [ ] 订单不保存商品定义、客户资料或方案定义的副本；
- [ ] 订单收货信息不写回客户默认收货信息；
- [ ] 订单、明细、快照、变更、发货、收退款表字段和读模型对应；
- [ ] 订单金额、数量、状态约束在数据库和应用层都生效；
- [ ] 订单模块不含金额、数量上限、余额、进度、完成/取消判断公式，只保存计算模块结果；
- [ ] 并发编辑使用 `row_version` 拒绝后提交者；
- [ ] 页面按权限隐藏新建、变更、发货、收款和取消操作；
- [ ] 敏感金额和客户联系方式读取有平台访问审计。

## 16. 明确不采用

- 不采用订单草稿；
- 不采用售后案例、退回、返工、补发、赔付；
- 不采用已有订单接管；
- 不采用库存出库和库存余额；
- 不采用订单内生产任务和排产；
- 不采用现金账户和支付渠道；
- 不采用物流平台自动同步；
- 不采用发货更正；
- 不采用多收货地址；
- 不采用客户等级价、促销和通用折扣规则；
- 不在订单模块实现金额、余额或履约判断公式；
- 不把客户、商品、方案资料复制进订单。

## 17. 与 V2 的主要差异

| V2 | V3 |
|---|---|
| 订单有草稿和复杂主状态 | 创建即确认，只保留已确认/已完成/已取消 |
| 使用交付约定组、约定版本、生产需求守卫 | 订单明细直接引用商品/方案快照，生产需求只保存引用 |
| 售后在订单模块内部 | 售后不在本模块，后续单独设计 |
| 发货更正、已有订单接管 | 本期不做 |
| 复杂订单变更和生产原子调账 | 保留价格/收货/备注/日期和未发货数量变更；生产调整失败整体回滚 |
| 客户快照接收订单收货覆盖 | 客户快照只冻结客户资料；订单自己保存收货信息 |
| 订单金额公式在订单文档 | 只列计算模块方法，不写公式 |

## 18. 已确认口径

- 订单编号格式采用 `SO-000001`，发货编号采用 `SH-000001`；与商品 `P-`、客户 `C-` 保持同一风格。
- 收退款由订单登记业务事实；现金账户、银行流水和支付渠道后续归财务模块。
- 本期不做发货更正；发货记录不可编辑、不可删除，错误留待后续更正/售后。
- 售后不在订单模块，后续独立模块设计。

本模块暂无待确认项。

## 19. 评审收口

- 订单创建即确认，不做草稿；
- 订单自己保存订单快照；客户、商品、方案只存引用；
- 收货信息归订单，客户只提供默认值；
- 支持多次分批发货和收退款，金额/履约由计算模块返回；
- 订单明细默认售价取所选方案快照的 `sale_price`，商品没有售价字段；
- 生产、财务、客户、商品通过公开端口协作；
- 售后、发货更正、已有订单接管不在本期；
- 文档为 V3 订单模块评审稿，评审通过后进入人员与排班模块。

## 20. 外部依赖对接要求

订单模块不直接读写依赖模块的表；依赖模块不反向依赖订单模块。

| 依赖 | 提供方 | 订单侧用途 | 失败语义 |
|---|---|---|---|
| 客户快照 | 客户模块 | 取得客户快照引用、解析客户资料、列表批量取客户名称 | `ORDER_CUSTOMER_INVALID` |
| 商品/方案快照 | 商品模块 | 取得商品和方案快照引用、解析商品/方案资料、校验商品启用 | `ORDER_PRODUCT_INVALID` |
| 生产需求与可发货数量 | 生产模块 | 创建/调整/取消生产需求，发货校验可交付数量 | `ORDER_CHANGE_PRODUCTION_REJECTED`、`ORDER_PRODUCTION_INSUFFICIENT` |
| 金额与履约计算 | 计算模块 | 明细金额、应收、收退款汇总、完成判断 | `ORDER_CALCULATION_FAILED` |
| 现金账户 | 财务模块 | 订单只登记收退款业务事实，不管理现金账户 | 由财务模块处理 |
| 平台能力 | 平台 | 订单/发货编号、权限、审计、幂等 | 平台错误 |

### 20.1 客户模块

订单调用：

```java
CustomerSnapshotService.acquireCurrentSnapshot(customerId);
CustomerSnapshotService.resolve(customerSnapshotRef);
```

要求：

- 订单只保存 `customer_snapshot_business_id + customer_snapshot_version`；
- 客户快照由客户模块保存，订单不复制客户资料；
- 订单列表需要的客户名称通过客户快照批量解析或客户模块查询取得；
- 客户不存在或快照不可用 → `ORDER_CUSTOMER_INVALID`；
- 订单收货信息由订单自己保存，不回写客户。

### 20.2 商品模块

订单调用：

```java
ProductSnapshotService.acquireCurrentSnapshotRefs(productId, schemeId);
ProductSnapshotService.resolveProductSnapshot(productSnapshotRef);
ProductSnapshotService.resolveSchemeSnapshot(schemeSnapshotRef);
```

要求：

- 每条明细只保存商品快照和方案快照引用；
- 商品必须为启用状态才能被新订单引用；
- 方案目标工序、售价和材料来源从方案快照读取；
- 商品停用、方案不存在或快照不可用 → `ORDER_PRODUCT_INVALID`；
- 订单不复制商品定义、方案定义或成本行。

### 20.3 生产模块

订单调用参与端口：

```text
createDemand(orderItemRef, productSnapshotRef, schemeSnapshotRef, quantity)
adjustDemand(demandRef, quantity)
cancelDemand(demandRef)
checkAvailableToShip(orderItemRef) → availableQuantity
consumeForShipment(shipmentRef, orderItemRef, quantity)
```

要求：

- 订单确认时每条明细建立生产需求并保存引用；
- 数量/明细变更时由生产模块校验并调整需求；
- 发货前校验可交付数量，发货时消费来源；
- 生产模块拒绝时订单创建/变更/发货整体回滚；
- 订单不保存生产任务、工序进度或质量事实。

### 20.4 计算模块

订单只调用方法，不写公式：

```java
OrderTotals calculateOrderTotals(OrderTotalsInput input);
OrderChangeLimits calculateOrderChangeLimits(ChangeLimitsInput input);
OrderShipmentLimits calculateOrderShipmentLimits(ShipmentLimitsInput input);
OrderPaymentSummary calculateOrderPaymentSummary(PaymentSummaryInput input);
OrderFulfillment calculateOrderFulfillment(FulfillmentInput input);
OrderCancellationEligibility calculateOrderCancellationEligibility(CancellationInput input);
```

- 计算模块拥有明细金额、原始金额、优惠校验、应收、已收、退款、净收、余额、数量上限、发货/收款进度、完成/取消判断和舍入；
- 订单只保存返回结果和应用状态；
- 计算失败时订单保存、变更、发货、收退款或取消整体回滚；
- 前端不自行计算订单金额、余额或进度。

### 20.5 财务模块

- 订单只登记收退款业务事实；
- 现金账户、银行流水、支付渠道属于财务模块；
- 财务模块后续通过订单查询或支付事实 feed 取得订单应收/已收，不直接读订单表；
- 订单完成以订单收退款事实为准，不以财务账户余额代替。

### 20.6 平台能力

| 能力 | 对接要求 |
|---|---|
| 编号 | 订单 `nextNumber("SALES_ORDER", "SO-", 6)`；发货 `nextNumber("SHIPMENT", "SH-", 6)`；唯一、不可复用 |
| 权限 | `order.read/create/change/ship/payment/cancel/snapshot.read` |
| 审计 | 订单、变更、发货、收退款、快照创建/复用由平台审计；敏感金额和客户联系方式访问由平台敏感访问审计 |
| 幂等 | 订单创建、发货、收款、退款接入平台幂等；快照唯一键兜底；更新用 `rowVersion` |
