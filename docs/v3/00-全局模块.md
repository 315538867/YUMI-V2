# V3 全局模块

> 模块代码：`global`  
> 文档版本：V3.0  
> 编写日期：2026-10-29  
> 状态：V3 全局模块评审稿；评审通过前不进入页面实现

本文是 V3 全局模块的唯一需求与设计依据。全局模块位于商品、客户、订单、员工和生产之前，只提供固定枚举、可维护静态数据和全局参数；不管理登录、权限、编号、文件、审计存储和业务计算。

## 摘要

- 全局模块是 V3 的第一个基础模块，其他模块只读调用，不直接读全局表。
- 岗位是全局固定枚举，只有 `MAKING / BAGGING / SEAM_CUTTING / OTHER` 四个代码；代码不能新增、删除、停用或修改，只能改显示名称。
- 可维护静态数据是岗位和三类工序星级；类型和属性由业务模块定义，全局模块只保存通用记录。
- 胶水和色浆作为多规格物料主数据管理：名称、规格、单价（元/克）、损耗率和启停状态。
- 全局参数先放五个：全局时薪、工作日小时数、制品有效工时率、目标利润率、每日可用工作分钟。
- 全局参数保留生效日期和历史版本；工资、成本按业务日期读取当时版本，不回溯。
- 静态数据修改写平台审计，不回溯已保存商品、员工、方案、订单和生产记录。
- 全局模块没有任何金额、成本、工资或产能公式，不调用计算中心。
- 全局模块和平台模块后端分开：平台管账号、权限、编号、审计和文件，全局模块管业务配置；页面入口可以合并到同一个“设置”菜单。

## 1. 模块说明

全局模块管理“所有业务模块共用、但又不属于某个业务模块的配置”。

它回答三类问题：

- 岗位有哪些：固定四个岗位代码和当前显示名称；
- 星级是什么：三类工序星级和标准分钟；
- 胶水和色浆有哪些规格：名称、规格、单价（元/克）和损耗率；
- 全局参数是多少：时薪、工作日小时数、有效工时率、目标利润率、每日可用工作分钟。

全局模块不回答业务问题：

- 不计算商品成本、利润和工资；
- 不决定员工能排什么班；
- 不保存订单、生产记录和工资；
- 不管理登录账号、角色权限和编号；
- 不存文件、不存审计日志、不存快照载荷。

商品、员工、生产、工资、计算等模块通过公开查询读取固定枚举、静态数据或参数版本，自己保存选择结果或快照引用。

## 2. 用户与使用场景

### 2.1 用户

| 用户 | 关心什么 | 在全局模块做什么 |
|---|---|---|
| 管理员 | 岗位名称、星级、胶水/色浆规格、时薪和工时参数 | 修改岗位显示名，维护星级、胶水/色浆和全局参数 |
| 老板 | 成本和工资使用的参数是否合理 | 查看当前参数和历史版本 |
| 商品 | 星级、标准分钟、胶水/色浆物料、全局时薪版本 | 只读查询，保存商品时冻结选择值 |
| 员工 | 四个固定岗位和当前显示名 | 只读查询，员工只保存岗位代码 |
| 生产 | 岗位枚举、每日可用工作分钟 | 只读查询，用于岗位校验和工作量提示 |
| 工资 | 时薪、工作日小时数、有效工时率、目标利润率的历史版本 | 只读查询，按员工和业务日期取参数版本 |
| 计算 | 全局时薪等参数版本 | 只读查询，按规则计算金额和成本 |

### 2.2 现状与目标

现在星级、时薪、工作日小时数等参数散落在 Excel 或口头约定里，商品、工资和生产各算各的。

V3 把跨模块共用的内容收进全局模块：

- 岗位不再由各模块自己定义，固定四个代码；
- 星级只维护一份；
- 胶水和色浆按物料规格统一维护；
- 全局参数有当前值和历史版本；
- 业务模块只读，不重复建配置表；
- 参数变化不回溯已经保存的数据。

## 3. 本期范围

### 3.1 本期提供

- 四个固定岗位枚举和显示名称维护；
- 三类工序星级的增加、改名、排序、启停和标准分钟维护；
- 胶水、色浆物料的新增、编辑、启停和规格维护；
- 五个全局参数当前值维护；
- 全局参数按生效日期保留历史版本；
- 静态数据、物料和参数的只读查询接口；
- 静态数据、物料和参数的权限、审计和幂等。

### 3.2 本期不提供

- 登录、员工账号和角色权限管理；
- 编号规则和编号生成；
- 文件、图片和附件存储；
- 审计日志存储和查询；
- 公司信息、门店信息和多组织；
- 任意新增静态数据类型的管理界面；
- 静态数据项物理删除；
- 全局参数未来生效或预约生效；
- 业务公式、金额、成本、工资和产能计算；
- 数据导入导出；
- 通用工作流和审批流。

## 4. 业务概念

| 术语 | 定义 |
|---|---|
| 固定枚举 | 代码写死、只能改显示名称的全局值；本模块只有岗位 |
| 静态数据 | 由全局模块保存、由业务模块解释的通用记录，使用 `typeCode / itemCode / name / status / attributes` |
| 类型代码 | 业务模块定义的静态数据类型，例如 `PRODUCT_MAKING_STAR` |
| 项代码 | 某个类型下的稳定代码，例如某个星级代码 |
| attributes | 静态数据项上的通用键值，具体含义由业务模块解释 |
| 物料主数据 | 胶水、色浆等可被商品选择的物料，包含规格、单价和损耗率 |
| 全局参数 | 跨模块共用的数值参数，例如全局时薪、工作日小时数 |
| 参数版本 | 某个参数在某个生效日期开始使用的值 |
| 当前值 | 当前业务日期生效的参数版本 |

## 5. 固定枚举与静态数据

### 5.1 岗位固定枚举

岗位是全局固定枚举，代码只有四个：

| 代码 | 默认显示名 | 用途 |
|---|---|---|
| `MAKING` | 制品（制作） | 制作工序岗位 |
| `BAGGING` | 捏毛（捏毛装袋） | 捏毛装袋工序岗位 |
| `SEAM_CUTTING` | 缝边（缝边剪袋） | 缝边剪袋工序岗位 |
| `OTHER` | 其他 | 打包、发货、清洁等非工序工作 |

规则：

- 岗位代码不能新增、删除、停用或修改；
- 全局模块只允许修改显示名称；
- 岗位没有独立状态，始终可用；
- 员工、生产计划、其他任务排班共用这套岗位代码；
- 岗位显示名称可改为“制品、捏毛、缝边、其他”等业务叫法，但代码不变；
- 历史快照保存当时的显示名称，之后改名不影响历史。

### 5.2 静态数据类型

本期只预置以下类型：

| typeCode | 所属模块 | 项模式 | 允许新增 | 允许停用 | 可编辑字段 | attributes |
|---|---|---|---|---|---|---|
| `POSITION` | `global` | 固定枚举 | 否 | 否 | 显示名 | 无 |
| `PRODUCT_MAKING_STAR` | `product` | 多项 | 是 | 是 | 名称、排序、状态、attributes | `standardMinutes` |
| `PRODUCT_BAGGING_STAR` | `product` | 多项 | 是 | 是 | 名称、排序、状态、attributes | `standardMinutes` |
| `PRODUCT_SEAM_CUTTING_STAR` | `product` | 多项 | 是 | 是 | 名称、排序、状态、attributes | `standardMinutes` |

说明：

- 类型目录由全局模块代码维护，不在页面任意新增类型；
- 业务模块定义 typeCode、attributes 键和校验规则；
- 全局模块只保存 attributes JSON，不解释 `standardMinutes`、`glueLossRate` 等业务含义；
- 以后新增静态数据类型需要修改类型目录和本文，不在页面开放任意类型；
- 岗位类型特殊：只有四个固定项，只允许改显示名。

### 5.3 静态数据项规则

- `typeCode + itemCode` 唯一；
- `itemCode` 创建后不可修改、不可复用；
- 静态数据项不物理删除；多项类型可以停用，固定枚举不能停用；
- 显示名称、排序、状态和 attributes 按类型规则编辑；
- 停用项不能再被新建业务引用，已有业务保留选择值和快照；
- 修改名称、状态或 attributes 不回溯已保存商品、方案、员工、订单、生产记录和快照；
- 静态数据修改写平台审计，不单独建版本表；
- 业务模块读取后自行校验 attributes，attributes 不合法时业务保存失败，由业务模块返回自己的错误码。

### 5.4 胶水与色浆物料

胶水和色浆是多规格物料主数据，不属于通用静态数据，也不做库存和采购批次。

| 字段 | 必填 | 类型/精度 | 规则 |
|---|---|---|---|
| 物料编号 | 系统 | `VARCHAR(32)` | 胶水 `GL-000001`、色浆 `CP-000001`；唯一、不可修改 |
| 物料类型 | 是 | `GLUE / COLOR_PASTE` | 胶水或色浆 |
| 物料名称 | 是 | `VARCHAR(100)` | 允许重名，以物料编号区分 |
| 规格 | 否 | `VARCHAR(200)` | 例如 5kg/桶、色号；只作说明 |
| 单价 | 是 | `DECIMAL(19,4)` 元/克 | 大于 0 |
| 损耗率 | 是 | `DECIMAL(12,8)` | 范围 `[0, 1)`；胶水和色浆分别维护 |
| 状态 | 是 | `ACTIVE / INACTIVE` | 停用后不能新建引用，已有商品保留 |
| 行版本 | 系统 | `BIGINT` | 并发控制 |

规则：

- 物料编号由平台编号能力生成，创建后不可修改、不可复用；
- 胶水和色浆共用一张物料表，用 `material_type` 区分；
- 名称允许重复，规格只作说明；
- 单价统一按元/克维护；
- 胶水和色浆都有损耗率；
- 物料不物理删除，只能停用；
- 停用物料不能被新建商品选择，已有商品保留原物料和冻结值；
- 修改单价、损耗率或名称不回溯已保存商品和快照；
- 物料修改写平台审计，不单独保留物料版本；
- 商品选择物料时复制当时名称、规格、单价和损耗率到商品或商品快照；
- 全局模块不计算商品成本，不判断物料是否适合某商品。

## 6. 全局参数

### 6.1 参数清单

| 参数代码 | 名称 | 类型 | 单位 | 规则 | 主要读取方 |
|---|---|---|---|---|---|
| `GLOBAL_HOURLY_RATE` | 全局时薪 | `DECIMAL(19,4)` | 元/小时 | 大于 0 | 计算、商品 |
| `WORKDAY_HOURS` | 工作日小时数 | `DECIMAL(5,2)` | 小时/天 | 大于 0 且不超过 24 | 计算、工资 |
| `PRODUCTIVE_WORK_RATE` | 制品有效工时率 | `DECIMAL(12,8)` | 比例 | 大于 0 且不超过 1 | 计算、工资 |
| `TARGET_PROFIT_RATE` | 目标利润率 | `DECIMAL(12,8)` | 比例 | 大于等于 0 且小于 1 | 计算、商品 |
| `DAILY_WORK_MINUTES` | 每日可用工作分钟 | `INT` | 分钟/天 | 大于 0 且不超过 1440 | 生产 |

说明：

- 五个参数都是全局唯一，不按员工、岗位或商品分开；
- `DAILY_WORK_MINUTES` 是生产排班的工作量提示参数，按实际可用时间维护；
- 每日可用工作分钟不强制等于 `工作日小时数 × 60 × 制品有效工时率`，避免兼职和停工场景被公式卡死；
- 参数名称、单位、类型和参数代码由全局模块固定，不允许页面新增参数；
- 参数值不参与业务公式实现，计算模块读取后按自己的公式版本计算。

### 6.2 参数版本

- 每个参数都有当前值和历史版本；
- 每次修改生成一个新版本，记录值、生效日期、修改原因、操作人和时间；
- 版本号在参数内递增；
- 生效日期不得晚于当天，不支持未来生效和预约生效；
- 新版本的生效日期不得早于当前最新版本生效日期；
- 当前值取最新版本；
- 历史版本只追加，不修改、不删除；
- 同一参数同一版本号唯一；
- 工资、成本等需要历史口径的模块按业务日期读取当时版本；
- 商品预算、工资结算等需要冻结参数时，保存 `GlobalParameterVersionRef`，不复制参数值；
- 参数修改不回溯已保存的预算、工资、成本和生产记录。

### 6.3 参数读取

- 页面显示当前值和生效日期；
- 支持查看历史版本；
- 业务模块只能通过公开查询读取，不直接读全局参数表；
- 按日期读取时取该日期或之前最近一个生效版本；
- 没有可用版本时返回 `GLOBAL_PARAMETER_NOT_FOUND`，业务模块不得自行使用默认值；
- 参数值未配置或非法时，依赖该参数的保存或计算失败，不能静默落默认值。

| 行版本 | 系统 | `BIGINT` | 并发控制 |

### 7.3 全局参数版本

| 字段 | 必填 | 类型/精度 | 规则 |
|---|---|---|---|
| 参数代码 | 是 | `VARCHAR(64)` | 固定参数代码 |
| 版本号 | 是 | `BIGINT` | 参数内递增 |
| 参数值 | 是 | `DECIMAL(19,8)` | 按参数规则校验 |

| 修改原因 | 是 | `VARCHAR(300)` | 说明为什么调整 |
| 创建时间/操作人 | 系统 | `DATETIME(6)` / `VARCHAR(64)` | 审计 |

## 8. 业务规则

### R1 模块边界

- 全局模块只提供固定枚举、静态数据和全局参数；
- 不提供登录、账号、角色、权限、编号、文件和审计存储；
- 业务模块只能通过公开接口读取，不直接读全局表；
- 全局模块不保存业务数据，不替业务模块做校验或计算；
- 全局模块不调用计算中心。

### R2 岗位固定枚举

- 岗位代码固定为 `MAKING / BAGGING / SEAM_CUTTING / OTHER`；
- 岗位代码不能新增、删除、停用或修改；
- 只允许修改显示名称；
- 显示名称不能为空，不能重复；
- 岗位没有状态，始终可用；
- 员工、生产计划和其他任务排班只保存岗位代码，显示名称按当前值读取；
- 员工快照、计划快照等冻结岗位名称后，之后改名不回溯。

### R3 静态数据项身份

- `typeCode + itemCode` 唯一；
- `itemCode` 创建后不可修改、不可复用；
- 不物理删除静态数据项；
- 多项类型可以停用，固定枚举和单项类型不能停用；
- 停用项不能被新建业务引用，已有业务保留原选择。

### R4 静态数据类型操作

- 类型目录由全局模块维护；
- 页面不提供任意新增类型；
- 岗位类型只允许改名；
- 星级类型允许多项新增、改名、排序、启停和 attributes 编辑；
- 类型操作不符合目录规则时返回 `GLOBAL_STATIC_ITEM_OPERATION_NOT_ALLOWED`。

### R5 静态数据 attributes

- attributes 必须是 JSON 对象；
- 全局模块只校验 JSON 结构，不解释业务键值；
- 星级类型由商品模块解释 `standardMinutes`；
- attributes 不合法时由业务模块拒绝保存，并返回业务模块自己的错误码；
- 全局模块不能因为业务 attributes 不合法而静默修正或补默认值。

### R6 静态数据不回溯

- 修改名称、排序、状态或 attributes 不触发已保存业务批量更新；
- 商品保存时冻结星级名称、标准分钟和录入值；
- 员工快照冻结岗位名称；
- 订单、方案、生产记录和工资继续使用原快照或原选择；
- 静态数据修改只写平台审计。

### R7 参数定义固定

- 五个参数代码、名称、值类型和单位由全局模块固定；
- 页面不允许新增、删除参数；
- 参数值必须符合本参数的类型和范围；
- 参数未配置或非法时，依赖模块不能使用默认值继续保存。

### R8 参数版本与生效

- 每次修改生成新版本；
- 版本号在参数内递增；
- 生效日期不得晚于当天；
- 新版本生效日期不得早于当前最新版本；
- 当前值取最新版本；
- 历史版本只追加，不修改、不删除；
- 参数不能删除；
- 同一参数同一版本号唯一。

### R9 参数历史读取

- 业务模块按业务日期读取参数版本；
- 取该日期或之前最近一个生效版本；
- 没有可用版本时返回 `GLOBAL_PARAMETER_NOT_FOUND`；
- 工资、成本等需要历史口径的模块保存 `GlobalParameterVersionRef`；
- 参数修改不回溯已保存预算、工资、成本和生产记录；
- 生产工作量提示读取当天生效的每日可用工作分钟，只影响后续计划。

### R10 审计

- 岗位改名写平台审计；
- 静态数据新增、修改、启停写平台审计；
- 参数修改写平台审计；
- 审计记录操作者、时间、类型、项代码、修改前后值、生效日期和原因；
- 全局模块不建独立审计表。

### R11 权限

- 查看静态数据、物料和参数需要 `global.read`；
- 维护静态数据需要 `global.static-data.manage`；
- 维护全局参数需要 `global.parameter.manage`；
- 业务模块内部调用按调用方权限鉴权；
- 全局模块不管理角色和权限，只声明权限代码。

## 9. 状态与版本

### 9.1 静态数据状态

| 当前状态 | 操作 | 目标状态 | 说明 |
|---|---|---|---|
| `ACTIVE` | 停用 | `INACTIVE` | 只有多项类型允许 |
| `INACTIVE` | 启用 | `ACTIVE` | 只有多项类型允许 |
| `ACTIVE` | 删除 | 不允许 | 不物理删除 |

岗位始终 `ACTIVE`，没有启停。

### 9.2 参数版本

- 参数没有“停用”；
- 当前值始终指向最新版本；
- 历史版本不可变；
- 参数不能删除；
- 生效日期按时间顺序递增。

## 12. 事务与并发

### 12.1 静态数据修改

```text
按 typeCode + itemCode 锁定静态数据项
→ 校验类型目录和可编辑字段
→ 校验 itemCode 不可修改
→ 更新名称/排序/状态/attributes
→ 递增 row_version
→ 写审计
→ 一次提交
```

### 12.2 静态数据停用

```text
按 typeCode + itemCode 锁定静态数据项
→ 校验类型允许多项停用
→ 校验当前状态
→ 改为 INACTIVE
→ 递增 row_version
→ 写审计
→ 一次提交
```

停用不影响已保存业务；新建业务读取启用项时自然排除。

### 12.3 物料维护

```text
按物料业务标识锁定物料
→ 校验物料类型、名称、规格、单价和损耗率
→ 生成物料编号（仅创建时）
→ 更新物料或状态
→ 递增 row_version
→ 写审计
→ 一次提交
```

- 物料编号由平台编号能力在创建事务内生成；
- 物料不能物理删除，只能停用；
- 修改物料不影响已保存商品和快照，商品保存时已经复制当时值；
- 物料修改和商品保存不在同一个事务内，商品读取物料后自行保存冻结值。

### 12.4 参数修改

```text
锁定当前参数行
→ 校验参数代码、值和生效日期
→ 读取当前最新版本
→ 生成新版本号和版本记录
→ 更新当前值、当前版本号和 row_version
→ 写审计
→ 一次提交
```

- 当前参数行和版本记录必须同事务提交；
- 版本号冲突返回 `GLOBAL_PARAMETER_VERSION_CONFLICT`；
- 参数修改失败时当前值和版本都不落库。

### 12.5 并发

- 静态数据项使用 `row_version` 拒绝并发覆盖；
- 参数当前行使用 `row_version` 拒绝并发覆盖；
- 参数版本按参数代码和版本号唯一；
- 同一参数并发修改只能一方成功；
- 死锁只允许重试整个幂等命令。

## 13. 历史与追溯

- 静态数据是当前记录，可修改名称、排序、状态和 attributes；
- 静态数据不建版本表，修改由平台审计记录；
- 全局参数当前值是投影，历史版本不可变；
- 参数版本按生效日期保留；
- 业务模块保存 `GlobalParameterVersionRef` 或选择值快照，不复制参数当前值；
- 修改参数或静态数据不回溯已保存商品、方案、员工、订单、生产记录、工资和成本；
- 岗位改名不影响员工快照中的岗位名称。

## 14. 权限、审计与错误

### 14.1 权限

| 权限 | 能力 |
|---|---|

- 全局参数修改；
- 记录修改前后值、生效日期、原因、操作者和时间。

| `GLOBAL_PARAMETER_VERSION_CONFLICT` | 参数版本并发冲突 |

前端提示：

- 字段错误内联显示；
- 岗位只显示名称输入，其他操作隐藏；
- 星级和物料停用后保留历史，不删除；
- 物料单价按元/克，胶水和色浆都必须填损耗率；
- 参数修改必须填原因和生效日期；
- 不显示内部 id、行版本和堆栈。

- [ ] 改名不影响员工快照中的历史名称。

### 16.2 静态数据

- [ ] 静态数据只有 `typeCode/itemCode/name/sortOrder/status/attributes` 通用字段；
- [ ] itemCode 创建后不可修改、不可复用；
- [ ] 岗位只能改名，不能新增、停用；
- [ ] 星级可以新增、改名、排序、启停和修改标准分钟；
- [ ] 停用星级不再出现在新建商品下拉；
- [ ] 修改静态数据不回溯已保存商品和方案；
- [ ] 业务模块只通过 `StaticDataQuery` 读取；
- [ ] 静态数据不物理删除。

### 16.3 胶水与色浆

- [ ] 物料按 `GLUE / COLOR_PASTE` 区分；
- [ ] 物料编号自动生成，唯一且不可修改；
- [ ] 物料名称允许重名，规格可空；
- [ ] 单价统一按元/克，且大于 0；
- [ ] 胶水和色浆都必须维护损耗率，范围 `[0, 1)`；
- [ ] 物料只能停用，不能删除；
- [ ] 停用物料不能被新建商品选择，已有商品保留；
- [ ] 修改物料不回溯已保存商品和快照；
- [ ] 商品通过 `GlobalMaterialQuery` 读取，不直接读物料表。

### 16.4 全局参数

- [ ] 只有五个固定参数，不能新增、删除和停用；
- [ ] 参数值类型和范围校验生效；
- [ ] 每次修改生成新版本和生效日期；
- [ ] 生效日期不得晚于当天，不得早于当前最新版本；
- [ ] 当前值取最新版本；
- [ ] 历史版本不可变、不删除；
- [ ] 按业务日期读取当时版本；
- [ ] 参数修改不回溯已保存预算、工资、成本和生产记录；
- [ ] 业务模块保存参数版本引用，不复制当前值；
- [ ] 没有可用参数时返回错误，不使用默认值。

### 16.5 数据与边界

- [ ] 全局模块不建角色、权限、编号、文件和审计表；
- [ ] 全局模块不调用计算中心，不计算金额、成本、工资和产能；
- [ ] 其他模块不直接读全局表；
- [ ] 岗位、静态数据、物料和参数写操作都有权限和审计；

## 18. 与 V2 的主要差异

## 19. 外部依赖

### 19.1 平台能力

- 权限：`global.read`、`global.static-data.manage`、`global.material.manage`、`global.parameter.manage`；
- 审计：静态数据、岗位、物料和参数修改；
- 幂等：所有写命令使用平台幂等键；
- 全局模块不管理账号、角色和权限本身。

### 19.2 商品模块

- 通过 `StaticDataQuery` 读取三类星级；
- 通过 `GlobalMaterialQuery` 读取胶水和色浆物料；
- 商品定义星级 attributes 键和校验规则；
- 商品保存时冻结星级名称、标准分钟和所选物料的名称、规格、单价、损耗率；
- 商品模块不读全局表、不维护静态数据和物料。

### 19.3 员工模块

- 通过 `StaticDataQuery` 读取四个岗位和显示名称；
- 员工只保存岗位代码；
- 员工快照冻结岗位名称；
- 员工模块不维护岗位。

### 19.4 生产模块

- 通过 `StaticDataQuery` 读取岗位枚举；
- 通过 `GlobalParameterQuery` 按日期读取 `DAILY_WORK_MINUTES`；
- 其他任务排班只选 `OTHER` 岗位员工；
- 生产模块不维护岗位和全局参数。

### 19.5 计算与工资

- 计算模块通过 `GlobalParameterQuery` 读取时薪、工作日小时数、有效工时率和目标利润率；
- 工资模块按业务日期读取参数版本；
- 计算和工资保存 `GlobalParameterVersionRef`；
- 全局模块不计算金额、成本、工资和产能。

### 19.6 报表

- 报表通过公开查询读取静态数据、物料和参数版本；
- 报表不直接读全局表；
- 全局模块不提供报表专用汇总表。

## 20. 已确认口径

1. 全局模块放在所有业务模块之前，文档编号为 `00`。
2. 全局模块只负责固定枚举、静态数据、物料主数据和全局参数；账号、角色、编号、文件和审计仍归平台。
3. 岗位是固定枚举 `MAKING / BAGGING / SEAM_CUTTING / OTHER`，代码不能改，只能改显示名称。
4. 静态数据本期只预置岗位和三类工序星级。
5. 静态数据使用通用 `typeCode/itemCode/name/sortOrder/status/attributes`，不建业务专用列。
6. 胶水、色浆按多规格物料管理，单价按元/克，胶水和色浆都有损耗率。
7. 商品选择物料，不能覆盖物料价格和损耗；商品保存时复制物料值，历史快照不受物料调价影响。
8. 全局参数为全局时薪、工作日小时数、制品有效工时率、目标利润率、每日可用工作分钟。
9. 全局参数保留生效日期和历史版本；工资、成本按业务日期读取，历史不回溯。
10. 每日可用工作分钟独立维护，不强制等于工作日小时数 × 有效工时率。
11. 静态数据、物料和参数修改不回溯已保存业务数据。
12. 其他模块只通过公开接口读取，不直接读全局表。
