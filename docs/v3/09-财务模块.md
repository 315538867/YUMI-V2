# V3 财务模块

> 模块代码：`finance`  
> 文档版本：V3.0  
> 编写日期：2026-10-30  
> 状态：V3 财务模块评审稿；评审通过前不进入页面实现

本文是 V3 财务模块的唯一需求与设计依据。财务模块只做日常支出登记、资金流水投影和老板看板；不做资金账户、银行对账、会计科目、凭证和总账。订单收退款、工资发放和订单成本分别由订单、工资与成本模块拥有，财务模块只读取和汇总。

## 摘要

- 财务模块是轻财务：日常支出 + 资金流水 + 老板看板。
- 日常支出由管理员登记，固定分类：房租水电、日常采购、运输、其他。
- 资金流水是订单收款、订单退款、工资发放和日常支出的统一投影；来源事实仍归各业务模块。
- 老板看板同时展示三套口径：商品毛利、经营利润和现金净额。
- 商品毛利 = 应收金额 − 商品成本（含标准人工）。
- 经营利润 = 应收金额 − 非人工商品成本 − 实发工资 − 日常支出；成本里的标准人工不重复扣。
- 现金净额 = 订单收款 − 订单退款 − 工资发放 − 日常支出。
- 资金流水是投影，可按日期范围重建；不保存账户余额，不做银行对账。
- 财务模块不修改订单、工资、成本和员工数据。
- 财务模块 2 张表：日常支出和资金流水投影。

## 1. 模块说明

财务模块回答“这个月花了多少、实际收付多少、商品毛利和经营利润多少”。

它不拥有订单收退款和工资发放：订单模块记录客户收款和退款，工资模块记录工资发放，财务模块只通过公开查询读取。日常支出是财务模块唯一的现金支出事实。

资金流水把三类外部来源和日常支出统一成一张只读列表，方便老板按日期看实际进出；它不是会计凭证，也不是资金账户余额。

老板看板把商品毛利、经营利润和现金净额分开：

- 商品毛利看商品本身赚不赚钱；
- 经营利润扣掉实际工资和日常支出，看经营整体赚不赚钱；
- 现金净额看实际收进来和付出去的钱。

## 2. 用户与使用场景

### 2.1 用户

| 用户 | 关心什么 | 在财务模块做什么 |
|---|---|---|
| 管理员 | 日常支出了多少、资金流水、老板看板 | 登记和作废日常支出，重建资金流水 |
| 老板 | 本月订单毛利、经营利润、现金净额 | 查看老板看板、趋势和商品排行 |
| 财务 | 实际收付和日常支出 | 登记支出，核对资金流水 |
| 订单/工资 | 各自收付款事实 | 不调用财务写接口，财务只读取它们 |
| 报表 | 财务汇总 | 通过财务或老板看板公开查询读取 |

### 2.2 现状与目标

管理员现在用 Excel 或口头记录日常支出，月底手工汇总订单收款、工资和支出。

V3 把财务拆成轻量的一层：

- 日常支出有固定分类和登记记录；
- 资金流水自动汇总订单收退款、工资发放和日常支出；
- 看板同时看毛利、经营利润和现金净额；
- 不再维护银行账户余额和会计凭证；
- 成本人工用标准成本、工资用实发，避免重复扣人工。

## 3. 本期范围

### 3.1 本期提供

- 日常支出创建和作废；
- 日常支出固定分类；
- 资金流水投影和按日期范围重建；
- 订单收款、退款、工资发放和日常支出的统一流水；
- 老板看板：商品毛利、经营利润、现金净额；
- 看板趋势和商品毛利排行；
- 财务权限、审计和幂等。

### 3.2 本期不提供

- 资金账户、银行账户和账户余额；
- 银行流水导入、对账和调节表；
- 会计科目、借贷凭证、总账和财务报表；
- 发票、税务申报和税务计算；
- 预算、费用审批流和报销单；
- 采购、库存和材料实际采购价；
- 订单应收、退款和售后的重新计算；
- 工资核定、调整和发放的重新计算；
- 资金流水直接编辑、删除；
- 多币种和汇率；
- 老板看板自定义指标和自助 BI。

## 4. 业务概念

| 术语 | 定义 |
|---|---|
| 日常支出 | 财务模块登记的房租水电、采购、运输等经营支出 |
| 支出分类 | 固定四类：`RENT_UTILITIES / DAILY_PURCHASE / TRANSPORT / OTHER` |
| 资金流水 | 订单收款、订单退款、工资发放和日常支出的统一只读投影 |
| 流水方向 | `IN` 收入或 `OUT` 支出 |
| 商品毛利 | 应收金额 − 商品成本（含标准人工） |
| 经营利润 | 应收金额 − 非人工商品成本 − 实发工资 − 日常支出 |
| 现金净额 | 订单收款 − 订单退款 − 工资发放 − 日常支出 |
| 非人工商品成本 | 材料成本 + 工序其他成本 + 额外单件成本，不含人工和提成 |
| 实发工资 | 工资模块已登记的有效工资发放金额 |

关系：

```text
订单收款/退款 ─┐
工资发放 ───────┼─ 资金流水投影（finance_cash_entries）
日常支出 ───────┘
日常支出 1 ── 1 资金流水来源（source_type = EXPENSE）
订单商品成本 ── 商品毛利
应收金额 + 非人工成本 + 实发工资 + 日常支出 ── 经营利润
```

## 5. 字段定义

### 5.1 日常支出

| 字段 | 必填 | 类型/精度 | 规则 |
|---|---|---|---|
| 支出业务标识 | 系统 | `VARCHAR(64)` | 稳定标识 |
| 支出日期 | 是 | `DATE` | 不得晚于当天 |
| 支出分类 | 是 | `VARCHAR(32)` | `RENT_UTILITIES / DAILY_PURCHASE / TRANSPORT / OTHER` |
| 支出金额 | 是 | `DECIMAL(19,2)` | 大于 0，人民币，2 位小数 |
| 支付方式 | 是 | `VARCHAR(16)` | `CASH / BANK / OTHER` |
| 收款方 | 否 | `VARCHAR(100)` | 商店、房东、物流等 |
| 备注 | 否 | `VARCHAR(300)` | 支出说明 |
| 状态 | 系统 | `ACTIVE / VOIDED` | 新建 `ACTIVE`；作废后不可恢复 |
| 作废原因 | 作废必填 | `VARCHAR(300)` | 作废时填写 |
| 作废时间/操作人 | 作废必填 | `DATETIME(6)` / `VARCHAR(64)` | 作废时记录 |
| 行版本 | 系统 | `BIGINT` | 并发控制 |
| 创建/更新时间与操作人 | 系统 | `DATETIME(6)` / `VARCHAR(64)` | 审计字段 |

支出不提供编辑，录错走作废重录；作废不删除记录。

### 5.2 资金流水投影

| 字段 | 必填 | 类型/精度 | 规则 |
|---|---|---|---|
| 流水业务标识 | 系统 | `VARCHAR(64)` | 稳定标识 |
| 来源类型 | 系统 | `VARCHAR(32)` | `ORDER_RECEIPT / ORDER_REFUND / WAGE_PAYMENT / EXPENSE` |
| 来源业务标识 | 系统 | `VARCHAR(64)` | 来源收付款或支出标识 |
| 业务日期 | 系统 | `DATE` | 收款、退款、发放或支出日期 |
| 方向 | 系统 | `VARCHAR(8)` | `IN / OUT` |
| 金额 | 系统 | `DECIMAL(19,2)` | 大于 0 |
| 来源状态 | 系统 | `ACTIVE / VOIDED` | 来源有效或已作废 |
| 来源指纹 | 系统 | `CHAR(64)` | 来源版本和金额指纹 |
| 重建时间 | 系统 | `DATETIME(6)` | 最近重建时间 |

同一来源类型和来源业务标识只有一条流水。流水只读，不提供页面编辑和删除；来源更正后重建。

## 6. 业务规则

### R1 日常支出

- 支出日期不得晚于当天；
- 分类只使用固定四类；
- 金额大于 0，精确到分；
- 支付方式只使用 `CASH / BANK / OTHER`；
- 收款方和备注可空；
- 支出创建后不提供编辑，录错作废重录；
- 作废必须填写原因，作废不删除记录；
- 作废支出不再进入资金流水有效汇总；
- 支出创建和作废写平台审计；
- 支出不修改订单、工资、成本和库存。

### R2 资金流水来源

资金流水只读取四类来源：

| 来源 | 方向 | 业务日期 | 金额 |
|---|---|---|---|
| 订单收款 | `IN` | 收款日期 | 收款金额 |
| 订单退款 | `OUT` | 退款日期 | 退款金额 |
| 工资发放 | `OUT` | 发放日期 | 发放金额 |
| 日常支出 | `OUT` | 支出日期 | 支出金额 |

规则：

- 来源事实由订单、工资和财务模块各自拥有；
- 重建读取有效和已作废两种来源：有效来源写 `ACTIVE` 流水，已作废来源保留流水并标记 `VOIDED`，两者都不改来源；有效汇总只统计 `ACTIVE`；
- 财务模块不修改来源金额、日期和状态；
- 流水金额与来源金额一致；
- 同一来源类型和来源标识只有一条流水；
- 资金流水不包含订单应收、工资应付和成本，只看实际收付。

### R3 资金流水重建

- 资金流水是投影，可按日期范围重建；
- 重建读取来源日期范围内的订单收款、退款、工资发放和日常支出，包含已作废来源（只作标记，不进有效汇总）；
- 重建先删除该日期范围的投影行，再按来源重新生成；来源事实不受影响；
- 重建保存来源指纹和重建时间；
- 重建失败整体回滚，原投影保留；
- 重建需要 `finance.cash.rebuild` 权限；
- 订单收退款或工资发放变化后，需要重建对应日期范围；
- 支出创建或作废可以同时更新该支出来源的流水，也可以由下一次重建覆盖；
- 资金流水不提供直接编辑和删除。

### R4 商品毛利

```text
商品毛利
= HALF_UP(应收金额（receivableRevenue）
          − 商品成本（studioBorneCost）, 2)

商品毛利率
= HALF_UP(商品毛利（grossProfit）
          ÷ 应收金额（receivableRevenue）, 8)
  应收金额 = 0 时返回空
```

- 商品成本包含材料、标准人工、标准提成、工序其他和额外单件成本；
- 只统计期间内订单的应收金额和订单商品成本；
- 取消订单、无效订单和不存在的订单不进入；
- 商品毛利可以按商品汇总，用于排行；
- 商品毛利使用应收口径，不使用实收。

### R5 经营利润

```text
非人工商品成本（nonLaborCost）
= 材料成本 + 工序其他成本 + 额外单件成本

经营利润（operatingProfit）
= HALF_UP(应收金额（receivableRevenue）
          − 非人工商品成本（nonLaborCost）
          − 实发工资（actualWagePaid）
          − 日常支出（operatingExpense）, 2)
```

- 经营利润不使用商品成本里的标准人工和标准提成，避免和实发工资重复扣；
- 实发工资取期间内有效工资发放金额；
- 日常支出取期间内有效支出，不含工资；
- 应收金额、成本、工资和支出按各自业务日期归入期间；
- 期间跨月时，工资按发放日期归入，不按工资期间强行匹配；
- 经营利润允许为负；
- 经营利润是管理口径，不是会计利润。

### R6 现金净额

```text
现金净额（cashNet）
= HALF_UP(订单收款（orderReceipts）
          − 订单退款（orderRefunds）
          − 工资发放（wagePayments）
          − 日常支出（operatingExpense）, 2)
```

- 只看实际收付，不看应收和成本；
- 订单收款和退款取订单模块有效收退款；
- 工资发放取工资模块有效发放；
- 日常支出取财务模块有效支出；
- 作废来源不计入；
- 看板现金净额直接取订单、工资和财务支出三方的有效来源事实汇总，不依赖资金流水投影，因此不受投影是否过旧影响；
- 资金流水页的汇总取自投影，与看板同一范围的现金净额应一致；不一致即判定投影过旧（见 R7）；
- 现金净额不是账户余额；
- 未收应收 = `max(0, 应收金额 − (订单收款 − 订单退款))`；
- 不计算期初、期末和银行对账差异。

### R7 看板

- 老板看板只读，不写业务数据；
- 默认期间为当月，支持日期范围，跨度不超过 366 天；
- 同时展示商品毛利、经营利润和现金净额；
- 趋势按日、周或月聚合；
- 商品排行按商品毛利降序，最多前 20；
- 看板汇总和趋势必须批量查询，不逐订单或逐商品回查；
- 资金流水最近重建时间在页面显示；
- 投影过旧的判定：所选范围内从未重建，或投影汇总的收入合计、支出合计与来源事实汇总的对应金额不一致；判定在看板查询时顺带完成，不另设时间阈值，过旧时只提示重建，不改看板数字；
- 看板不提供会计凭证、总账和税务报表。

### R8 与业务模块边界

- 订单模块拥有订单应收、收款和退款；
- 工资与成本模块拥有工资参考、核定、调整、发放和订单商品成本；
- 财务模块拥有日常支出和资金流水投影；
- 财务模块只通过公开查询读取订单、工资、成本和员工，不直接读表；
- 财务模块不修改订单、工资、成本和员工；
- 订单和工资模块不读财务支出表。

### R9 权限、审计与查询范围

- 支出查询和维护分别使用独立权限；
- 资金流水查询和重建分别使用独立权限；
- 看板只读权限；
- 支出创建、作废和流水重建写平台审计；
- 资金流水重建失败写失败审计；
- 看板查询不写审计；
- 看板日期跨度不超过 366 天，商品排行最多 20；
- 资金流水重建单次日期跨度不超过 366 天。

## 7. 状态设计

### 7.1 日常支出

| 当前状态 | 操作 | 目标状态 | 说明 |
|---|---|---|---|
| `ACTIVE` | 作废 | `VOIDED` | 写原因、时间和操作人 |
| `VOIDED` | 作废 | 不允许 | 已作废不能再次作废 |
| `VOIDED` | 重新登记 | 新建 `ACTIVE` | 同一笔支出重新创建 |

支出没有编辑状态、审批状态和删除状态。

### 7.2 资金流水

- 流水状态跟随来源：`ACTIVE / VOIDED`；
- 流水不单独提供状态操作；
- 来源作废后，重建保留对应流水并标记 `VOIDED`（来源状态由订单、工资、财务各自的状态提供）；
- 来源重新登记后，重建生成新的流水；
- 流水不硬删除，重建时按日期范围替换投影。

## 8. 数据模型与表设计

### 8.1 关系

```text
finance_expenses
└─ finance_cash_entries（source_type = EXPENSE）

订单收款/退款、工资发放 ── finance_cash_entries（投影）
```

财务模块只保存日常支出和资金流水投影；订单、工资和成本事实仍在各自模块。

### 8.2 表清单

| 表 | 类别 | 用途 |
|---|---|---|
| `finance_expenses` | 当前事实 | 日常支出 |
| `finance_cash_entries` | 投影 | 订单收款、退款、工资发放和日常支出统一流水 |

### 8.3 日常支出表

```sql

    updated_by VARCHAR(64) NOT NULL,

    CONSTRAINT ck_finance_expense_amount CHECK (amount > 0),
    CONSTRAINT ck_finance_expense_category CHECK (

    CONSTRAINT ck_finance_expense_status CHECK (
        status IN ('ACTIVE', 'VOIDED')
    ),
    CONSTRAINT ck_finance_expense_void CHECK (
        (
            status = 'ACTIVE'
            AND void_reason IS NULL
            AND voided_at IS NULL
            AND voided_by IS NULL
        )
        OR (
            status = 'VOIDED'
            AND void_reason IS NOT NULL
            AND void_reason <> ''
            AND voided_at IS NOT NULL
            AND voided_by IS NOT NULL
        )
    )
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_0900_ai_ci;
```

### 8.4 资金流水投影表

```sql
CREATE TABLE finance_cash_entries (
    id BIGINT NOT NULL AUTO_INCREMENT,
    entry_business_id VARCHAR(64) NOT NULL,
    source_type VARCHAR(32) NOT NULL,
    source_business_id VARCHAR(64) NOT NULL,
    business_date DATE NOT NULL,
    direction VARCHAR(8) NOT NULL,
    amount DECIMAL(19,2) NOT NULL,
    source_status VARCHAR(16) NOT NULL,
    source_fingerprint CHAR(64) NOT NULL,
    rebuilt_at DATETIME(6) NOT NULL,
    PRIMARY KEY (id),
    UNIQUE KEY uk_finance_cash_entry_business_id (entry_business_id),
    UNIQUE KEY uk_finance_cash_entry_source (
        source_type, source_business_id
    ),
    KEY ix_finance_cash_entry_date (business_date, source_status, direction),
    KEY ix_finance_cash_entry_type (source_type, business_date),
    CONSTRAINT ck_finance_cash_entry_type CHECK (
        source_type IN ('ORDER_RECEIPT', 'ORDER_REFUND', 'WAGE_PAYMENT', 'EXPENSE')
    ),
    CONSTRAINT ck_finance_cash_entry_direction CHECK (
        direction IN ('IN', 'OUT')
    ),
    CONSTRAINT ck_finance_cash_entry_amount CHECK (amount > 0),
    CONSTRAINT ck_finance_cash_entry_status CHECK (
        source_status IN ('ACTIVE', 'VOIDED')
    )
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_0900_ai_ci;
```

说明：

- 资金流水是投影，来源事实不在这里；
- 同一来源类型和来源标识只有一条流水；
- 重建按日期范围替换投影行，不修改来源；
- 订单收款/退款、工资发放和支出各自提供稳定来源标识；
- 流水不保存账户、余额和币种。

## 10. 事务与并发

### 10.1 日常支出

```text
校验日期、分类、金额和支付方式
→ 写支出事实（ACTIVE，row_version = 1）
→ 更新或等待重建该支出的资金流水
→ 写平台审计
→ 一次提交
```

- 支出作废锁定支出行，校验行版本，写原因和作废信息；
- 支出不提供编辑，录错作废重录；
- 同一支出并发作废只有一方成功。

### 10.2 资金流水重建

```text
校验日期范围和权限
→ 读取订单收退款、工资发放和日常支出（含作废状态）
→ 删除日期范围投影行
→ 重新写入流水和来源指纹
→ 写审计
→ 一次提交
```

- 重建失败整体回滚，原投影保留；
- 重建期间不修改来源事实；
- 并发重建由重建锁或幂等命令串行化；
- 单次重建日期跨度不超过 366 天。

### 10.3 看板查询

- 看板只读，不加业务锁；
- 订单、成本、工资和流水分别按日期范围批量读取；
- 看板不保证跨模块强一致；页面显示资金流水最近重建时间和投影是否过旧；
- 看板不触发重建，重建由管理员显式操作或运维任务执行。

## 11. 历史与追溯

- 日常支出只追加，不编辑、不删除；作废保留原因和操作人；
- 资金流水是投影，按日期范围重建；来源事实保留；
- 重建记录操作人、时间、日期范围和生成数量；
- 看板查询不保存结果；
- 财务模块不保存会计凭证和总账；
- 订单收退款和工资发放的历史由各自模块保留。

## 18. 已确认口径

1. 财务模块是轻财务：日常支出、资金流水投影和老板看板；不做资金账户、银行对账和会计凭证。

3. 资金流水是订单收款、退款、工资发放和日常支出的统一投影，来源事实归各业务模块。
4. 商品毛利 = 应收 − 商品成本（含标准人工）。
5. 经营利润 = 应收 − 非人工商品成本 − 实发工资 − 日常支出；标准人工和标准提成不重复扣。
6. 现金净额 = 收款 − 退款 − 工资发放 − 日常支出。
7. 看板同时展示三套口径，趋势按日/周/月，商品排行最多 20。
8. 看板和流水批量查询，不逐订单回查；日期跨度不超过 366 天。
9. 财务只读订单、工资和成本，不修改业务事实；不直接读业务表。
10. 不做多币种、发票、税务、预算、采购和库存。

## 19. 评审收口

- 本文是 V3 财务模块评审稿，覆盖需求、字段、规则、状态、2 张表、接口、事务、权限、页面和验收；
- 财务模块只做日常支出、资金流水投影和老板看板；
- 订单收退款和工资发放仍由各自模块拥有，财务只读汇总；
- 商品毛利、经营利润和现金净额三套口径分开，避免人工重复扣；
- 资金流水是投影，可按日期重建，不保存账户余额；
- 财务模块不做会计总账、凭证、税务和银行对账；
- 本模块暂无待确认项；
- 评审通过后进入老板看板/报表的页面细化。
