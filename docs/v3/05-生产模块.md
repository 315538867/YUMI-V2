# V3 生产模块

> 模块代码：`production`  
> 文档版本：V3.0  
> 编写日期：2026-10-29  
> 状态：V3 生产模块评审稿；评审通过前不进入页面实现

本文是 V3 生产模块的唯一需求与设计依据。生产模块统一管理排班计划、计划任务、生产记录、数量池台账、正常待排池、返工池和工序流转；不做小组、自定义任务、备货生产、成品库存和工资。

## 摘要

- 一个生产模块，两个工作区：排班计划、生产记录。
- 生产来源只有两种：订单商品、返工。
- 计划头是日期 + 员工 + 一道工序；同一员工、同一天、同一工序只能有一个活动计划。
- 制作计划新建时选择订单商品来源，每个商品生成一条计划任务；正常任务和返工任务可以在同一计划下并存。
- 捏毛装袋、缝边剪袋只排日期、员工和工序，不在计划里建正常任务；核验时从工序流程选择上游来源，生成生产记录。
- 生产记录是核验时生成的真实完成事实，不提前存在；没有计划不能登记生产记录。
- 计划可以提前排，不限定提前多久，不依赖实际产出；后续工序执行时才受上一工序实际合格数量限制。
- 正常待排池和返工池统一落在 `production_flow_pools` 数量池台账；普通池一行对应一个订单商品的一道工序，返工池按来源记录和返工工序分行，两者使用同一组数量列。
- 订单确认时按订单商品和工序链生成普通池行；订单加量、减量、取消同步台账，订单减量不能低于在制数量，有生产数量的订单不能取消。
- 正常待排池、返工池、工序流程和已排未核验之间保持数量守恒。
- 核验结果分为合格、返工、报废、未完成；返工进入返工池，报废和未完成回到正常待排池。
- 返工是在制品修补，不是重新制作；返工是计划任务类型，可以选前面已做过的工序。
- 其他任务排班只给非工序岗位员工安排日期和岗位，例如打包、发货、清洁；不填数量、不做完成确认、不生成生产记录。
- 生产模块自己保存计划、任务、生产记录、数量池台账和其他任务排班；订单、员工、商品只提供来源和快照引用。
- 数量计算在生产模块本地完成，不调用计算中心；计算中心只保留金额、成本、工资。

## 1. 模块说明

生产模块管理“计划谁哪天做哪道工序、实际完成了什么”。

排班计划负责安排日期、员工和工序；计划任务负责记录制作工序下具体要做的订单商品；生产记录负责记录核验时实际完成的数量和质量结果。打包、发货、清洁这类非工序岗位使用其他任务排班，只记录日期、员工和岗位。

制作工序必须知道做什么订单、什么商品、多少件，所以制作计划下面要有商品任务。捏毛装袋和缝边剪袋无法严格按照制作计划执行，只排谁哪天做哪道工序；实际完成哪些订单商品，在核验时从上游工序流程中选择。

生产模块回答“计划做了什么、实际做了什么、还差多少、返工和报废多少”；订单模块回答“客户和交付”；员工模块回答“谁能做哪个岗位”；商品模块回答“商品方案和工序链”。

## 2. 用户与使用场景

### 2.1 用户

| 用户 | 关心什么 | 在生产模块做什么 |
|---|---|---|
| 管理员 | 未来几天谁做哪道工序、订单还差多少、返工怎么处理 | 建制作计划、排后续工序、处理返工、查看缺口 |
| 生产负责人 | 今天实际完成了什么、合格多少、返工和报废多少 | 核验计划任务或后续计划，登记生产记录 |
| 老板 | 计划进度、实际产出、返工和报废 | 查看计划、生产记录和订单商品进度 |
| 订单 | 商品已合格数量和可发货数量 | 通过生产公开查询读取，不直接读生产表 |
| 工资 | 某员工某天实际完成的生产记录 | 通过生产公开查询读取，不直接读生产表 |
| 报表 | 生产、返工、报废和进度汇总 | 通过生产公开查询或后续报表投影读取 |

### 2.2 现状与目标

管理员现在用 Excel 记录订单、商品、兼职每日产出和排班。制作工序按订单排；捏毛装袋和缝边剪袋通常只排人，实际做完后再记录产出。

V3 把这个过程拆成计划和实际两层：

- 制作计划提前排，选多个订单商品，每个商品一条计划任务；
- 后续工序提前排人，不预先绑定订单商品；
- 核验时记录实际完成，后续工序从上游流程中选择订单商品；
- 没做完的回到待排池，返工的进入返工池；
- 订单进度以实际合格数量为准，不以计划数量为准。

## 4. 业务概念

| 术语 | 定义 |
|---|---|
| 计划 | 某员工某天做某一道工序的排班头 |
| 计划任务 | 计划下具体要做的订单商品工作，分为正常任务和返工任务 |
| 正常任务 | 制作计划下按订单商品生成的计划任务 |
| 返工任务 | 从返工池排进计划的修补任务 |
| 其他任务排班 | 给非工序岗位员工安排日期和岗位，例如打包、发货、清洁 |
| 生产记录 | 核验时生成的真实完成事实，记录合格、返工、报废和未完成 |
| 数量池台账 | 按订单商品 × 工序保存普通池和返工池余额的表；订单确认时生成普通池行 |
| 正常待排池 | 数量池台账中普通池的“待排”余额，只出现在制作工序 |
| 返工池 | 数量池台账中返工类型的池行，记录缺陷工序、返工工序和可用数量 |
| 工序流程 | 上一道工序已经合格、可以进入下一道工序的数量 |
| 合格 | 本道工序完成且质量合格的数量，进入下一道工序或达到目标工序 |
| 返工 | 本道工序完成后需要回到前面工序修补的数量 |
| 报废 | 制品损失、无法继续使用的数量 |
| 未完成 | 本次计划内没有完成的数量 |
| 目标工序 | 商品方案要求的最后一道工序；链在这一步结束 |
| 工序链 | 制作 → 捏毛装袋 → 缝边剪袋，按商品方案目标工序截断 |
| 已排未核验 | 已经进入计划任务、但还没有生产记录的数量 |
| 在制数量 | 已排未核验 + 已合格 + 已报废 + 已转返工 + 已流转下游 + 返工可用 + 返工已排；订单减量和取消按此口径校验 |

## 5. 核心数量模型

### 5.1 数量池台账

正常待排池和返工池不再按订单、计划任务和生产记录实时汇总，而是落在 `production_flow_pools` 一张台账里。台账使用固定数量列，不使用 JSON。

台账粒度：

- 先按订单里的商品明细拆分：一个订单商品明细就是订单中的一个商品行，不是订单头，也不是商品主数据；同一商品在订单中出现两次（方案或价格不同）也各算一条；
- 普通池再按工序拆：一个订单商品明细 × 一道工序一行，在订单确认时按工序链生成；
- 返工池：一个订单商品明细 × 缺陷工序 × 返工工序 × 来源生产记录一行，在核验产生返工数量时生成；
- 普通池和返工池共用同一张表、同一组数量列，用 `pool_type` 区分。

例如一个订单有 3 个商品、目标工序都是缝边剪袋，则生成 3 组普通池行，每组 3 行（制作、捏毛装袋、缝边剪袋），共 9 行；发生返工时再按缺陷工序和返工工序增加返工池行。

普通池行：

```text
待排 = 总量 − 已排未核验 − 已合格 − 已报废 − 已转返工
可流转 = 已合格 − 已流转下游
目标工序：可流转即待交付数量
```

返工池行：

```text
可用 = 总量 − 已排未核验 − 已返工合格 − 已报废 − 已转出
```

字段含义：

| 数量列 | 普通池 | 返工池 |
|---|---|---|
| 总量 | 本工序应处理的总量；制作工序初始为订单数量，报废补做和返工合格回流时增加 | 本次进入返工池的数量 |
| 已排未核验 | 已进入本工序计划任务、还没有生产记录的数量 | 已排进返工任务、还没有返工记录的数量 |
| 已合格 | 本工序核验合格的数量；返工合格也计入同工序普通池 | 返工核验合格的数量 |
| 已报废 | 本工序核验报废的数量 | 返工核验报废的数量 |
| 已转返工 | 本工序核验返工、离开普通池的数量；返工池固定为 0 | 不适用 |
| 已流转下游 | 已被下游工序取走处理的数量；目标工序固定为 0 | 再次返工时转到新返工池的数量 |

每个订单商品的当前数量守恒：

```text
当前订单数量
= 各工序正常待排之和
+ 各工序已排未核验之和
+ 各工序合格待流转之和（含目标工序待交付）
+ 返工池可用之和
+ 返工已排未核验之和
```

报废件离开流程后由制作池总量按报废数量补回，补做需求体现为制作待排增加；报废数量单列统计，不进入上面的守恒等式。

### 5.2 状态转移

| 操作 | 台账变化 |
|---|---|
| 订单确认 | 按工序链生成普通池行；制作普通池总量等于订单数量 |
| 订单增加数量 | 制作普通池总量增加，待排增加 |
| 订单减少数量 | 制作普通池总量减少，待排减少；减量不能超过待排 |
| 订单取消 | 所有池行都没有已排、已合格、已报废、已转返工、已流转下游和返工数量时，池行置为 `CANCELLED`；否则拒绝取消 |
| 订单新增明细 | 按工序链生成普通池行 |
| 订单移除明细 | 该明细没有生产数量时池行置为 `CANCELLED`；有生产数量时拒绝移除 |
| 制作计划新增正常任务 | 制作普通池已排未核验增加，待排减少 |
| 取消制作正常任务 | 制作普通池已排未核验减少，待排增加 |
| 制作任务核验合格 | 制作普通池已排未核验减少，已合格增加 |
| 制作任务核验返工 | 制作普通池已排未核验减少，已转返工增加；按返工工序生成返工池行 |
| 制作任务核验报废 | 制作普通池已排未核验减少，已报废增加，总量增加报废数量，待排增加 |
| 制作任务核验未完成 | 制作普通池已排未核验减少，待排增加 |
| 后续计划核验合格 | 上游普通池已流转增加；本工序普通池总量和已合格各增加处理数量 |
| 后续计划核验返工 | 上游普通池已流转增加；本工序普通池总量和已转返工各增加处理数量；按返工工序生成返工池行 |
| 后续计划核验报废 | 上游普通池已流转增加；本工序普通池总量和已报废各增加处理数量；制作普通池总量增加补做数量 |
| 后续计划核验未完成 | 上游和本工序普通池都不变，数量留在上游流程 |
| 返工任务核验合格 | 返工池已排减少、已返工合格增加；同工序普通池总量和已合格各增加 |
| 返工任务核验再次返工 | 原返工池已排减少、已转出增加；新返工池行总量增加 |
| 返工任务核验报废 | 返工池已排减少、已报废增加；制作普通池总量增加补做数量 |
| 返工任务核验未完成 | 返工池已排减少，可用数量恢复 |
| 生产记录作废重录 | 先反算原记录对台账的全部影响，再应用新记录；净变化等于新旧结果差异 |

“已流转增加”等于本次处理数量中的合格、返工和报废之和，未完成不扣减上游流程。

### 5.3 数量说明

- 正常待排只发生在制作工序；所有新制品都从制作开始，下游普通池行的待排恒为 0。
- 台账行在订单确认时创建，生产模块不再按当前订单商品临时聚合待排数量。
- 订单数量变化只同步制作普通池总量；已排计划、计划任务和生产记录不自动调整。
- 订单减少数量不能低于在制数量；在制数量等于已排、已合格、已报废、已转返工、已流转下游和返工数量的合计。
- 订单取消和明细移除只在没有任何生产数量时允许，避免已制作数量失去归属。
- 后续工序计划不占用待排，也不提前移动数量；计划创建时不改变台账。
- 后续工序核验按上游普通池行取数，取数范围是“已合格 − 已流转下游”。
- 返工池数量不属于正常待排，也不重复占用订单数量。
- 后续工序未完成的数量不写本工序台账，仍留在上游普通池的可流转数量里。
- 下游报废从制作重新补做，补做数量加在制作普通池总量和待排上。
- 计划数量不等于完成数量；订单进度由数量池台账的已合格和待交付数量汇总，通过生产公开查询返回，不取计划数量。
- 其他任务排班不进入台账、工序流程和订单进度，不影响数量守恒。
- 所有数量计算在生产模块本地完成，不调用计算中心。

### 5.4 返工流程

返工只处理有缺陷的在制品，不增加订单数量，也不重新从制作开始；只有返工工序选择制作时，才回到制作环节修补。

```mermaid
flowchart TD
    A[核验计划任务或后续计划] --> B{返工数量大于 0?}
    B -- 否 --> Z[按合格/报废/未完成处理]
    B -- 是 --> C[选择返工工序]
    C --> D[校验工序已做过且不晚于缺陷工序]
    D --> E[写入返工池]
    E --> F[管理员建返工计划任务]
    F --> G[返工核验]
    G --> H{核验结果}
    H -- 合格 --> I[进入返工工序合格流程]
    I --> J{返工工序是否目标工序?}
    J -- 是 --> K[进入待交付]
    J -- 否 --> L[继续后续工序]
    H -- 再次返工 --> M[重新选择返工工序]
    M --> T[原返工池转出，生成新返工池行]
    T --> F
    H -- 报废 --> N[回到正常待排池]
    N --> O[从制作重新补做]
    H -- 未完成 --> P[回到返工池可用数量]
```

返工流程说明：

- 返工数量进入返工池，不进入正常待排池；
- 返工任务必须从返工池创建，不能凭空新建；
- 返工工序可以选择制作、捏毛装袋或缝边剪袋中已经做过的工序；
- 返工合格后，从返工工序继续往目标工序走；
- 返工再次返工时，重新选择返工工序，原返工池已转出数量增加，并生成新的返工池行；
- 返工报废时，数量回到正常待排池，从制作重新做一件；
- 返工未完成时，数量回到原返工池可用数量；
- 返工不增加订单数量，不重复计入合格数量。

### 5.5 报废流程

报废件不能继续使用，订单数量不减少；报废数量回到正常待排池，从制作重新做一件。

```mermaid
flowchart TD
    A[核验计划任务或后续计划] --> B{报废数量大于 0?}
    B -- 否 --> Z[按其他结果处理]
    B -- 是 --> C{报废发生在哪道工序}
    C -- 制作 --> D[制作已排未核验减少]
    C -- 捏毛装袋/缝边剪袋 --> E[上游工序合格待流转减少]
    C -- 返工 --> F[返工池数量减少]
    D --> G[正常待排池增加]
    E --> G
    F --> G
    G --> H[管理员新建制作计划任务]
    H --> I[制作核验合格]
    I --> J[按商品方案工序链继续流转]
    J --> K[目标工序待交付]
```

报废流程说明：

- 报废数量不留在原工序，也不进入返工池；
- 制作报废：制作普通池已排减少、已报废增加，总量增加补做数量；
- 后续工序报废：上游普通池已流转增加，本工序普通池已报废增加，制作普通池总量增加补做数量；
- 返工报废：返工池已排减少、已报废增加，制作普通池总量增加补做数量；
- 报废不减少订单数量，补做仍属于同一个订单商品；
- 补做从制作重新开始，按商品方案工序链重新走一遍；
- 报废件不进入成品库存，也不进入售后流程。

### 5.6 返工与报废的区别

| 项目 | 返工 | 报废 |
|---|---|---|
| 对象 | 有缺陷的在制品 | 已经损失、不能继续使用的制品 |
| 是否重新制作 | 否，回选定工序修补 | 是，从制作重新做一件 |
| 数量去向 | 返工池 | 正常待排池 |
| 是否占订单数量 | 不重新占订单数量 | 不减少订单数量，补做仍属于原订单商品 |
| 修好后流向 | 从返工工序继续往目标工序走 | 按完整工序链重新走 |
| 再次失败 | 可以再次返工或报废 | 不再返工，直接补做 |

流程图只表达数量流向；计划取消、权限校验、审计和并发控制仍按第 7、11、13 节执行。

### 5.7 工作量提示

只有制作计划的正常任务需要提示员工当天的工作量；返工任务不计算工作时长，也不参与工作量提示。

```text
制作正常任务预计分钟 = 计划数量 × 商品方案制作工序标准分钟
当天预计分钟 = 员工当天所有制作正常任务的预计分钟合计
```

- 商品方案和制作工序标准分钟来自订单商品冻结的商品/方案快照，不读取商品当前值；
- 返工任务不计算预计分钟，预计分钟固定为 0；
- 后续工序计划没有正常任务，不计算预计分钟；
- 其他任务排班不计算预计分钟，不参与工作量提示；
- 当天预计分钟超过每日可用工作分钟时提示，但允许保存；
- 每日可用工作分钟来自全局模块参数 `DAILY_WORK_MINUTES`；按计划日期读取当时版本，未配置时只显示预计分钟，不做超出提示；
- 预计分钟是计划工作量，按计划任务计算，不按实际完成数量回算；
- 取消的计划或计划任务不再计入当天预计分钟；
- 工作量只做提示，不阻止计划创建或核验；
- 计算在生产模块本地完成，不调用计算中心。

## 6. 字段定义

### 6.1 计划

| 字段 | 必填 | 类型/精度 | 规则 |
|---|---|---|---|
| 计划业务标识 | 系统 | `VARCHAR(64)` | 稳定标识，不对外显示 |
| 计划日期 | 是 | `DATE` | 计划工作的日期 |
| 员工 | 是 | `VARCHAR(64)` | 必须是在职且岗位匹配的员工 |
| 员工快照引用 | 系统 | `VARCHAR(64)` + 版本 | 计划创建时冻结员工身份和岗位 |
| 工序 | 是 | `VARCHAR(32)` | `MAKING / BAGGING / SEAM_CUTTING` |
| 计划状态 | 系统 | `PLANNED / COMPLETED / CANCELLED` | 由任务和生产记录决定 |
| 备注 | 否 | `VARCHAR(500)` | 计划说明 |
| 行版本 | 系统 | `BIGINT` | 并发控制 |

### 6.2 计划任务

| 字段 | 必填 | 类型/精度 | 规则 |
|---|---|---|---|
| 任务业务标识 | 系统 | `VARCHAR(64)` | 稳定标识 |
| 所属计划 | 系统 | `VARCHAR(64)` | 计划业务标识 |
| 任务类型 | 是 | `NORMAL / REWORK` | 正常任务或返工任务 |
| 订单 | 正常/返工 | `VARCHAR(64)` | 订单业务标识 |
| 订单商品明细 | 正常/返工 | `VARCHAR(64)` | 订单商品明细业务标识 |
| 商品快照引用 | 正常/返工 | `VARCHAR(64)` + 版本 | 订单商品冻结的商品快照，保存业务标识和版本 |
| 方案快照引用 | 正常/返工 | `VARCHAR(64)` + 版本 | 订单商品冻结的方案快照，保存业务标识和版本 |
| 工序 | 系统 | `VARCHAR(32)` | 必须等于计划工序 |
| 计划数量 | 是 | `INT` | 大于 0 |
| 预计分钟 | 系统 | `INT` | 制作正常任务为计划数量 × 制作工序标准分钟；返工任务固定为 0，不参与工作量提示 |
| 数量池引用 | 是 | `VARCHAR(64)` | 正常任务为制作普通池行；返工任务为对应的返工池行 |
| 任务状态 | 系统 | `PLANNED / COMPLETED / CANCELLED` | 由核验或取消改变 |
| 备注 | 否 | `VARCHAR(500)` | 任务说明 |
| 行版本 | 系统 | `BIGINT` | 并发控制 |

规则：

- 正常任务只能出现在制作计划下，工序固定为 `MAKING`，数量池引用固定为制作普通池行；
- 返工任务可以出现在任意工序的计划下，工序必须等于计划工序，数量池引用为该工序的返工池行；
- 同一计划下同一订单商品只能有一条正常任务；
- 同一计划下同一返工池行只能有一条活动返工任务；
- 正常任务和返工任务可以在同一计划下并存；
- 计划数量不能超过对应池子的可用数量。

|---|---|---|---|

| 记录状态 | 系统 | `ACTIVE / VOIDED` | 正常记录或已作废 |
| 活动记录键 | 系统 | `VARCHAR(160)` | 同一计划任务/上游来源只允许一条活动记录 |
| 计划 | 是 | `VARCHAR(64)` | 所属计划 |
| 计划任务 | 制作/返工必填 | `VARCHAR(64)` | 来源计划任务；后续正常记录为空 |
| 记录类型 | 是 | `NORMAL / REWORK` | 正常生产或返工修补 |
| 订单 | 是 | `VARCHAR(64)` | 来源订单 |
| 订单商品明细 | 是 | `VARCHAR(64)` | 来源订单商品 |
| 商品快照引用 | 是 | `VARCHAR(64)` + 版本 | 来源商品快照，保存业务标识和版本 |
| 方案快照引用 | 是 | `VARCHAR(64)` + 版本 | 来源方案快照，保存业务标识和版本 |
| 工序 | 是 | `VARCHAR(32)` | 本次完成的工序 |
| 员工 | 是 | `VARCHAR(64)` | 计划员工 |
| 员工快照引用 | 系统 | `VARCHAR(64)` + 版本 | 复用计划创建时冻结的员工快照，不在核验时重新取资格快照 |
| 生产日期 | 是 | `DATE` | 计划日期 |
| 本工序数量池 | 是 | `VARCHAR(64)` | 本工序普通池行；返工记录为本工序的返工池行 |
| 上游数量池 | 后续正常必填 | `VARCHAR(64)` | 从哪个上游工序普通池行取得数量 |
| 来源数量 | 是 | `INT` | 本次处理数量；计划任务等于计划数量，后续计划等于选中的流程数量 |
| 合格数量 | 是 | `INT` | 大于等于 0 |
| 返工数量 | 是 | `INT` | 大于等于 0 |
| 报废数量 | 是 | `INT` | 大于等于 0 |
| 未完成数量 | 是 | `INT` | 大于等于 0 |
| 创建时间/操作人 | 系统 | `DATETIME(6)` / `VARCHAR(64)` | 核验时间和操作人 |

数量守恒：

```text
来源数量 = 合格数量 + 返工数量 + 报废数量 + 未完成数量
```

生产记录只追加，不编辑、不删除。制作和返工任务一条任务生成一条生产记录；后续计划一次核验每个选中的流程来源生成一条生产记录。

作废重录时，原记录业务数量不变，只把状态改为 `VOIDED`、写入作废原因和操作人，再生成一条新的 `ACTIVE` 记录；数量池台账只反映 `ACTIVE` 记录和订单同步的结果。

### 6.4 数量池台账

`production_flow_pools` 用一行保存一个池的余额；普通池按订单商品 × 工序一行，返工池按来源记录 × 缺陷工序 × 返工工序一行；普通池和返工池共用字段，用 `pool_type` 区分。

| 字段 | 必填 | 类型/精度 | 规则 |
|---|---|---|---|
| 池业务标识 | 系统 | `VARCHAR(64)` | 稳定标识，计划任务和生产记录引用 |
| 池类型 | 系统 | `NORMAL / REWORK` | 普通池或返工池 |
| 订单 | 是 | `VARCHAR(64)` | 来源订单 |
| 订单商品明细 | 是 | `VARCHAR(64)` | 来源订单商品 |
| 商品标识 | 是 | `VARCHAR(64)` | 商品业务标识，用于按商品筛选，不复制商品资料 |
| 方案标识 | 是 | `VARCHAR(64)` | 方案业务标识，用于按方案筛选，不复制方案资料 |
| 商品/方案快照引用 | 是 | `VARCHAR(64)` + 版本 | 订单商品冻结的商品快照和方案快照 |
| 工序 | 是 | `VARCHAR(32)` | 普通池为本工序；返工池为返工工序 |
| 目标工序 | 是 | `VARCHAR(32)` | 订单商品方案的目标工序；确认时冻结，用于工序链判断和展示 |
| 缺陷工序 | 返工必填 | `VARCHAR(32)` | 哪道工序发现返工；普通池固定为空 |
| 来源生产记录 | 返工必填 | `VARCHAR(64)` | 产生返工数量的生产记录；普通池固定为空，用于记录作废时精确反算 |
| 总量 | 系统 | `INT` | 大于等于 0；普通池为应处理总量，返工池为本次进入返工的数量 |
| 已排未核验 | 系统 | `INT` | 已进入计划任务、还没有生产记录的数量 |
| 已合格 | 系统 | `INT` | 普通池为本工序核验合格；返工池为返工核验合格 |
| 已报废 | 系统 | `INT` | 本池累计报废数量 |
| 已转返工 | 系统 | `INT` | 普通池核验返工离开的数量；返工池固定为 0 |
| 已流转下游 | 系统 | `INT` | 普通池为下游已取走数量；返工池为再次返工转出数量 |
| 状态 | 系统 | `ACTIVE / CLOSED / CANCELLED` | 返工池可用为 0 时 `CLOSED`；订单取消或来源记录作废时 `CANCELLED` |
| 行版本 | 系统 | `BIGINT` | 并发控制 |
| 创建/更新时间与操作人 | 系统 | `DATETIME(6)` / `VARCHAR(64)` | 审计字段 |

普通池和返工池的余额：

```text
普通池待排 = 总量 − 已排未核验 − 已合格 − 已报废 − 已转返工
普通池可流转 = 已合格 − 已流转下游
返工池可用 = 总量 − 已排未核验 − 已合格 − 已报废 − 已流转下游
```

规则：

- 普通池按订单商品和工序链生成，制作工序一行始终存在；普通池工序不能晚于目标工序，目标工序之后不再生成；
- 返工池按订单商品、缺陷工序、返工工序和来源生产记录生成；同一次核验的同一返工工序只有一行；
- 返工工序只能选择该订单商品已经做过的工序，且不能晚于缺陷工序；
- 返工池核验合格后，数量并入同工序普通池的已合格，并增加普通池总量，保证待排不被重复扣减；
- 普通池行和返工池行都不物理删除，取消和关闭保留历史。

## 7. 业务规则

### R1 计划创建

- 计划头由日期、员工、工序组成；
- 员工必须存在、在职且岗位匹配工序；
- 同一员工、同一天、同一工序只能有一个活动计划；已存在时直接打开原计划追加任务或核验；
- 制作计划新建时通常选择订单商品正常任务；如果本次只有返工，可以先创建空计划再追加返工任务；
- 后续工序计划创建时不需要订单来源，也不需要正常任务；
- 制作计划至少有一条任务才能核验；后续计划正常核验不要求计划任务，但必须选择上游来源；空计划可以取消；
- 计划创建时取得员工快照引用，之后员工调岗或离职不影响已有计划；
- 计划头的日期、员工、工序创建后不可修改；需要变更时取消计划后新建；
- 计划可以提前创建，不限定提前多久，不依赖实际产出。

### R2 制作计划正常任务

- 正常任务只能来自订单商品明细；
- 一个商品明细在制作计划中只能有一条活动正常任务；已完成或已取消的历史任务不阻止重新添加；
- 正常任务计划数量不能超过该订单商品的正常待排数量；
- 正常任务工序固定为 `MAKING`，且必须等于计划工序；
- 多个订单商品可以放在同一个制作计划下，共用一个员工和日期；
- 后续工序计划不能添加正常任务，只能添加返工任务；
- 正常任务创建或修改时，按计划数量和制作工序标准分钟计算预计分钟；
- 员工当天预计分钟合计超过每日可用工作分钟时提示，但不阻止保存；
- 计划任务合计数量只用于展示和核验，不直接进入订单进度。

### R3 后续工序计划

- 捏毛装袋、缝边剪袋计划只保存日期、员工和工序；
- 计划创建时不选订单、不建正常任务、不填计划数量；
- 后续计划创建时不绑定订单，因此不在创建时校验目标工序；
- 核验时按来源订单商品校验，目标工序不能早于当前工序；
- 后续计划可以提前排，不检查上游实际产出；
- 实际执行时，核验只能选择上游工序流程中当前可用的数量，且流程来源的目标工序不能早于当前工序。

### R4 返工任务

- 返工任务只能从返工池行创建；
- 返工任务工序必须等于计划工序，且等于返工池行的返工工序；
- 返工任务计划数量不能超过返工池可用数量；
- 返工任务不计算预计分钟，不参与员工当天工作量提示；
- 返工任务可以和正常任务在同一计划下并存；
- 创建返工任务时增加返工池已排数量，取消返工任务时减少已排数量；
- 返工任务核验合格后，数量并入同工序普通池的已合格，返工池已合格数量增加；
- 返工任务核验再次返工，原返工池已排数量减少、已转出数量增加，并生成新的返工池行；
- 返工任务核验报废，返工池已排数量减少、已报废数量增加，制作普通池总量增加补做数量；
- 返工任务核验未完成，返工池已排数量减少，可用数量恢复。

### R5 计划任务修改与取消

- 计划任务未产生生产记录前，可以修改计划数量、备注，可以取消；
- 修改正常任务数量时，不能超过正常待排数量加上本任务原计划数量；
- 修改返工任务数量时，不能超过返工池可用数量加上本任务原计划数量，并按差额同步调整返工池已排数量；
- 修改制作正常任务数量后重新计算预计分钟，并重新判断当天工作量提示；返工任务不计算；
- 计划任务产生生产记录后，不能修改、不能取消；
- 计划任务不能更换订单商品、工序或计划；
- 取消计划任务必须填写原因；
- 取消计划任务时，正常任务数量回到正常待排，返工任务数量回到返工池可用数量；
- 计划任务进入 `COMPLETED` 或 `CANCELLED` 时，`task_unique_key` 改为任务业务标识，释放同一计划同一来源的活动唯一键；
- 计划任务取消后保留历史，不物理删除。

### R6 计划取消与完成

- 计划没有任何生产记录时才能取消；
- 取消计划必须填写原因；
- 取消计划时同时取消全部未核验任务，数量回到对应池子；
- 计划存在生产记录时不能取消，只能继续完成剩余任务；
- 制作计划没有任务时保持 `PLANNED`，不自动完成，只能追加任务或取消；
- 制作计划在全部任务完成或取消后变为 `COMPLETED`；
- 后续计划没有正常任务也可以通过一次正常核验完成；
- 后续计划只有返工任务时，全部返工任务完成或取消后变为 `COMPLETED`，不需要正常核验；
- 后续计划在一次核验完成后，如果没有待完成的返工任务，变为 `COMPLETED`；
- 后续计划核验后仍有返工任务未完成时，计划保持 `PLANNED`，直到返工任务完成或取消；
- 计划完成后不能追加任务；需要继续工作必须新建计划；
- 取消后的计划变为 `CANCELLED`，不能重新打开；需要继续工作必须新建计划；
- 计划进入 `COMPLETED` 或 `CANCELLED` 时，`active_plan_key` 改为计划业务标识，释放同一员工、日期、工序的活动唯一键，允许以后新建计划。

### R7 制作任务核验

- 只能核验 `PLANNED` 且未产生生产记录的正常任务或返工任务；
- 来源数量等于任务计划数量；
- 填写合格、返工、报废、未完成，四项之和必须等于来源数量；
- 制作任务合格数量增加到制作普通池的已合格；返工任务合格数量并入同工序普通池的总量和已合格；
- 返工数量按选择的返工工序写入对应返工池行，拆分数量之和必须等于返工数量；
- 制作报废增加制作普通池总量和已报废；返工报废增加返工池已报废，并给制作普通池总量补做；
- 正常制作任务的未完成数量回到制作普通池待排；
- 返工任务的未完成数量回到返工池可用数量；
- 核验后任务变为 `COMPLETED`，生成一条生产记录；
- 任务核验后不能再次核验。

### R8 后续计划核验

- 只能核验 `PLANNED` 的捏毛装袋或缝边剪袋计划；
- 后续计划的正常核验只能提交一次；已经存在正常生产记录时，不能再次核验正常来源；返工任务单独核验；
- 核验时必须至少选择一个上游工序流程来源；
- 上游来源必须是当前工序的上一道工序普通池行，不能跳过中间工序；
- 同一核验内同一条上游池行只能出现一次；需要分多批时合并为一条记录；
- 每个来源填写本次处理数量，不能超过该池行当前可流转数量；
- 每个来源分别填写合格、返工、报废、未完成，四项之和等于本次处理数量；
- 合格数量增加本工序普通池总量和已合格；达到目标工序时即为待交付；
- 返工数量按选择的返工工序写入对应返工池行，拆分数量之和必须等于返工数量；
- 本工序报废增加本工序普通池总量和已报废，并增加制作普通池总量用于补做；
- 未完成数量留在上一工序流程，不移动；生产记录中的未完成只表示本次选中但未处理的数量；
- 上游普通池已流转下游数量增加，增加量等于本次处理数量中的合格、返工和报废之和；未完成不扣减上游流程；
- 一次核验可以生成多条生产记录；
- 核验完成后计划进入完成判断；有未完成返工任务时计划保持 `PLANNED`。

### R9 返工工序选择

- 返工工序必须是该订单商品已经做过的工序；
- 返工工序不能晚于缺陷工序；
- 制作工序返工只能选择制作；
- 捏毛装袋返工可以选择制作或捏毛装袋；
- 缝边剪袋返工可以选择制作、捏毛装袋或缝边剪袋；
- 一次核验的返工数量可以按返工工序拆成多条，分别进入不同返工池行；
- 同一次核验的返工拆分中，同一返工工序只保留一条，数量合并；
- 返工工序不改变订单数量，只改变在制品所在工序；
- 返工合格后继续按商品方案往目标工序走。

### R10 生产记录

- 生产记录只由核验产生，不能预先生成；
- 没有计划不能生成生产记录；
- 生产记录必须引用计划；制作和返工记录还必须引用计划任务；
- 制作正常记录：计划任务必填，上游数量池为空；
- 后续正常记录：计划任务为空，上游数量池必填；
- 返工记录：计划任务和本工序返工池行必填；
- 生产记录业务数量只追加，不编辑、不删除；作废重录只改原记录状态并生成新记录；
- 生产记录不能反向修改计划、计划任务或订单；
- 订单进度、可发货数量和工资来源只由生产公开查询返回，不直接暴露生产记录表；

### R11 数量守恒

- 所有计划任务、生产记录和数量池台账变更都在同一数量守恒下进行；
- 任何操作不能让任何池行的待排、已排、已合格、已报废或返工可用数量出现负数；
- 并发操作必须按订单商品串行化，避免同一数量被重复排入计划或重复核验；
- 数量计算在生产模块本地完成，不调用计算中心；
- 发现守恒不平返回 `PRODUCTION_QUANTITY_INCONSISTENT`，不能静默修正。

### R12 员工与岗位

- 计划员工必须与计划工序的岗位匹配；
- 后续工序计划的员工岗位必须匹配工序；
- 员工离职或调岗后，已有计划保持员工快照，不自动取消；
- 计划核验复用计划创建时保存的员工快照，不重新校验在职状态，也不重新获取资格快照；
- 员工离开后仍可通过 `EmployeeSnapshotService.resolve` 按版本解析历史快照；
- 新建计划只能选择当前在职且岗位匹配的员工；
- 生产模块不保存员工岗位主数据，只保存计划时的员工快照引用。

### R13 订单与商品快照

- 计划任务和生产记录引用订单商品明细，不复制订单条款；
- 商品快照和方案快照引用由订单商品提供，生产模块只保存引用；
- 工序链由方案快照的目标工序决定，生产模块不读取商品当前数据重新判断；
- 商品或方案后续修改不影响已有计划和生产记录；
- 生产模块不修改订单、商品和客户。

### R14 审计

- 计划创建、任务增加、修改、取消、计划取消写平台审计；
- 制作任务核验、后续计划核验、返工任务核验写平台审计；
- 生产记录创建写审计；
- 生产记录作废重录写作废原因、原记录、新记录和数量变化；
- 数量池台账创建、状态变化和每次余额变化写审计；
- 审计至少记录操作者、时间、计划、任务、生产记录、订单商品和数量变化。

### R15 其他任务排班

- 其他任务排班只用于岗位为 `OTHER` 的员工，具体工作（打包、发货、清洁等）写在备注；
- 只能选择在职且岗位为 `OTHER` 的员工；
- 岗位从员工快照带出，不能手工修改；
- 同一员工、同一天只能有一个活动其他任务排班；
- 只记录日期、员工、岗位和备注，不填数量、不做完成确认、不生成生产记录；
- 不进入正常待排池、返工池、工序流程和订单进度；
- 不计算预计分钟，不参与工作量提示；
- 其他任务排班的日期、员工、岗位创建后不可修改；需要变更时取消后新建；
- 备注可以修改；取消后保留历史，状态为 `CANCELLED`；
- 取消后同一员工、同一天可以重新创建其他任务排班。

### R16 生产记录作废重录

- 只有 `ACTIVE` 生产记录可以作废重录；
- 必须填写作废原因和期望行版本；
- 作废时先反算原记录对数量池台账的全部影响；反算后任一池行出现负数时不能作废；
- 原记录产生的返工池行已经被返工任务、返工记录或转出时，不能作废；
- 作废返工记录时，来源返工池行按原记录反算；来源返工池行已被后续返工任务或记录使用时不能作废；
- 订单商品已经发货时，不能作废；发货后的更正走售后或后续模块；
- 作废时原记录业务数量不变，状态改为 `VOIDED`，写入作废原因、作废时间和操作人；
- 原记录产生的未被使用返工池行一并标记 `CANCELLED`；
- 新记录使用同一活动记录键，按新的四项结果和返工拆分重新应用台账；
- 制作/返工记录的新来源数量必须等于计划任务数量；
- 后续正常记录的新来源数量不能超过作废后可用的上游流程数量；
- 计划任务和计划状态不回到未完成；作废重录只替换生产记录；
- 生产记录业务数量不可直接编辑、不可删除；
- 作废重录写平台审计，保留原记录、作废原因和操作人。

### R17 订单同步

- 订单确认、变更和取消由订单模块发布同步事件，生产模块在同一事务内处理；
- 订单确认：按每个订单商品的工序链生成普通池行，制作普通池总量等于订单数量，下游池行总量初始为 0；工序链按目标工序截断，目标工序之后不建行；
- 订单增加数量：制作普通池总量按差额增加；
- 订单减少数量：制作普通池总量按差额减少；差额不能超过制作待排，否则拒绝变更；
- 订单新增明细：按工序链生成普通池行；
- 订单移除明细：该明细所有池行都没有生产数量时置为 `CANCELLED`，否则拒绝移除；
- 订单取消：所有池行都没有生产数量时置为 `CANCELLED`，否则拒绝取消；
- 生产数量指已排未核验、已合格、已报废、已转返工、已流转下游和返工数量的合计；
- 订单事件处理失败时，订单确认、变更或取消整体回滚；
- 订单同步只改数量池台账，不改已有计划、计划任务和生产记录。

### R18 台账校验与重建

- 数量池台账是当前投影，权威事实是当前订单数量、活动计划任务和 `ACTIVE` 生产记录；
- 每次数量变更后校验本行守恒，订单商品维度校验总量守恒，发现不平返回 `PRODUCTION_QUANTITY_INCONSISTENT`，不静默修正；
- 支持按订单商品重建台账：锁定订单商品守卫，读取当前订单数量、未核验计划任务和全部 `ACTIVE` 生产记录，按时间顺序重放合格、返工、报废和未完成结果；
- 重建只在内存计算并与现有台账比较；一致时不写库，不一致时必须由管理员确认后覆盖余额并写审计；
- 重建不会删除或改写生产记录、计划任务和订单，只修正台账余额；
- 重建命令只能由运维/管理员权限调用，不能由普通业务操作自动触发；
- 每日对账任务按订单商品检查台账与事实是否一致，发现差异只告警，不自动改数。

## 8. 状态设计

### 8.1 计划状态

| 当前状态 | 操作 | 目标状态 | 说明 |
|---|---|---|---|
| `PLANNED` | 全部任务完成/取消，且后续核验完成 | `COMPLETED` | 计划结束 |
| `PLANNED` | 取消计划 | `CANCELLED` | 仅限没有任何生产记录 |
| `COMPLETED` | 任何修改 | 不允许 | 需要继续工作新建计划 |
| `CANCELLED` | 任何修改 | 不允许 | 历史保留 |

计划完成判定统一为：

- 制作计划：没有 `PLANNED` 任务；
- 后续计划：没有 `PLANNED` 任务，且正常核验已完成；只有返工任务的后续计划不要求正常核验；
- 所有返工任务完成或取消；
- 计划存在生产记录时只能完成，不能取消。

### 8.2 计划任务状态

| 当前状态 | 操作 | 目标状态 | 说明 |
|---|---|---|---|
| `PLANNED` | 核验 | `COMPLETED` | 生成生产记录 |
| `PLANNED` | 取消 | `CANCELLED` | 数量回到对应池子 |
| `COMPLETED` | 修改/取消 | 不允许 | 已产生生产记录 |
| `CANCELLED` | 修改/核验 | 不允许 | 历史保留 |

### 8.3 数量池行状态

| 当前状态 | 操作 | 目标状态 | 说明 |
|---|---|---|---|
| `ACTIVE` | 返工池可用为 0 且没有已排未核验 | `CLOSED` | 返工全部处理完 |
| `ACTIVE` | 返工任务核验未完成 | `ACTIVE` | 数量回到可用 |
| `ACTIVE` | 订单取消或移除明细，且没有生产数量 | `CANCELLED` | 订单侧终止 |
| `ACTIVE` | 来源生产记录作废，且返工池行未被使用 | `CANCELLED` | 随记录作废 |
| `CLOSED` | 任何操作 | 不允许 | 历史保留 |
| `CANCELLED` | 任何操作 | 不允许 | 历史保留 |

普通池行不进入 `CLOSED`：订单未取消时一直 `ACTIVE`，待排、已排和已合格按数量列表达。
`CANCELLED` 的池行不参与可用数量、计划任务创建和数量守恒。
`CLOSED` 表示返工已全部处理完，不能再操作；来源记录作废只能取消未被使用且尚未 `CLOSED` 的返工池行，`CLOSED` 行对应的来源记录不能作废。

### 8.4 其他任务排班状态

| 当前状态 | 操作 | 目标状态 | 说明 |
|---|---|---|---|
| `PLANNED` | 取消 | `CANCELLED` | 保留历史，释放当天员工排班 |
| `CANCELLED` | 任何操作 | 不允许 | 需要重新排班时新建 |
| `PLANNED` | 完成 | 不支持 | 其他任务不做完成确认 |

## 9. 数据模型与表设计

### 9.1 关系

```text
production_plans
├─ production_plan_tasks
└─ production_records

production_flow_pools         订单商品 × 工序数量池台账（普通池 + 返工池）
production_other_assignments  非工序岗位排班，不进入数量池
production_source_guards      按订单商品串行化数量变更
```

数量池余额只保存在 `production_flow_pools`；计划任务和生产记录通过池业务标识引用池行，不再按计划任务、生产记录临时汇总。数量变更前先锁 `production_source_guards` 中对应订单商品，再按固定顺序更新池行。

### 9.2 表清单

| 表 | 类别 | 用途 |
|---|---|---|
| `production_plans` | 当前根 | 计划日期、员工、工序和状态 |
| `production_plan_tasks` | 当前任务 | 制作正常任务和返工任务 |
| `production_records` | 不可变事实 | 核验产生的实际完成记录 |
| `production_flow_pools` | 当前台账 | 普通池和返工池的总量、已排、已合格、已报废、已转返工和已流转数量 |
| `production_other_assignments` | 当前排班 | 非工序岗位员工的日期和岗位安排 |
| `production_source_guards` | 并发守卫 | 按订单商品串行化计划、核验、返工和订单同步 |

### 9.3 计划表

```sql
CREATE TABLE production_plans (
    id BIGINT NOT NULL AUTO_INCREMENT,
    plan_business_id VARCHAR(64) NOT NULL,
    plan_date DATE NOT NULL,
    employee_business_id VARCHAR(64) NOT NULL,
    employee_snapshot_business_id VARCHAR(64) NOT NULL,
    employee_snapshot_version BIGINT NOT NULL,
    process_code VARCHAR(32) NOT NULL,
    status VARCHAR(16) NOT NULL,
    active_plan_key VARCHAR(160) NOT NULL,
    note VARCHAR(500) NULL,
    row_version BIGINT NOT NULL,
    created_at DATETIME(6) NOT NULL,
    created_by VARCHAR(64) NOT NULL,
    updated_at DATETIME(6) NOT NULL,
    updated_by VARCHAR(64) NOT NULL,
    PRIMARY KEY (id),
    UNIQUE KEY uk_production_plan_business_id (plan_business_id),
    UNIQUE KEY uk_production_plan_active (active_plan_key),
    KEY ix_production_plan_date (plan_date, process_code, status),
    KEY ix_production_plan_employee (employee_business_id, plan_date),
    CONSTRAINT ck_production_plan_process CHECK (
        process_code IN ('MAKING', 'BAGGING', 'SEAM_CUTTING')
    ),
    CONSTRAINT ck_production_plan_status CHECK (
        status IN ('PLANNED', 'COMPLETED', 'CANCELLED')
    )
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_0900_ai_ci;
```

`active_plan_key`：

- `PLANNED` 时为 `plan_date|employee_business_id|process_code`；
- `COMPLETED` 或 `CANCELLED` 时为 `plan_business_id`。

这样同一员工、同一天、同一工序只能有一个活动计划；历史计划不会阻止以后新建。

```sql

    scheme_snapshot_version BIGINT NOT NULL,

    planned_quantity INT NOT NULL,
    estimated_minutes INT NOT NULL,
    pool_business_id VARCHAR(64) NOT NULL,

    note VARCHAR(500) NULL,
    row_version BIGINT NOT NULL,
    created_at DATETIME(6) NOT NULL,
    created_by VARCHAR(64) NOT NULL,
    updated_at DATETIME(6) NOT NULL,
```

### 9.6 数量池台账表

```sql
CREATE TABLE production_flow_pools (
    id BIGINT NOT NULL AUTO_INCREMENT,
    pool_business_id VARCHAR(64) NOT NULL,
    pool_type VARCHAR(16) NOT NULL,
    source_record_business_id VARCHAR(64) NOT NULL,

    scheme_business_id VARCHAR(64) NOT NULL,
    product_snapshot_business_id VARCHAR(64) NOT NULL,
    product_snapshot_version BIGINT NOT NULL,
    scheme_snapshot_business_id VARCHAR(64) NOT NULL,
    scheme_snapshot_version BIGINT NOT NULL,
    process_code VARCHAR(32) NOT NULL,
    target_process_code VARCHAR(32) NOT NULL,
    defect_process_code VARCHAR(32) NOT NULL DEFAULT '',
    total_quantity INT NOT NULL,
    scheduled_quantity INT NOT NULL,
    completed_quantity INT NOT NULL,
    scrapped_quantity INT NOT NULL,
    rework_out_quantity INT NOT NULL,
    transferred_quantity INT NOT NULL,
    status VARCHAR(16) NOT NULL,
    row_version BIGINT NOT NULL,
    created_at DATETIME(6) NOT NULL,
    created_by VARCHAR(64) NOT NULL,
    updated_at DATETIME(6) NOT NULL,
    updated_by VARCHAR(64) NOT NULL,
    PRIMARY KEY (id),
    UNIQUE KEY uk_production_flow_pool_business_id (pool_business_id),
    UNIQUE KEY uk_production_flow_pool_key (
        order_item_business_id, pool_type, process_code,
        defect_process_code, source_record_business_id
    ),
    KEY ix_production_flow_pool_available (pool_type, status, process_code),
    KEY ix_production_flow_pool_order_item (
        order_item_business_id, status
    ),
    KEY ix_production_flow_pool_product (product_business_id, status),
    CONSTRAINT ck_production_flow_pool_type CHECK (
        pool_type IN ('NORMAL', 'REWORK')
    ),
    CONSTRAINT ck_production_flow_pool_process CHECK (
        process_code IN ('MAKING', 'BAGGING', 'SEAM_CUTTING')
        AND target_process_code IN (
            'MAKING', 'BAGGING', 'SEAM_CUTTING'
        )
        AND (
            (pool_type = 'NORMAL' AND defect_process_code = '')
            OR (
                pool_type = 'REWORK'
                AND defect_process_code IN (
                    'MAKING', 'BAGGING', 'SEAM_CUTTING'
                )
            )
        )
    ),
    CONSTRAINT ck_production_flow_pool_quantity CHECK (
        total_quantity >= 0
        AND scheduled_quantity >= 0
        AND completed_quantity >= 0
        AND scrapped_quantity >= 0
        AND rework_out_quantity >= 0
        AND transferred_quantity >= 0
        AND (
            (
                pool_type = 'NORMAL'
                AND completed_quantity >= transferred_quantity
                AND total_quantity >= scheduled_quantity
                    + completed_quantity + scrapped_quantity
                    + rework_out_quantity
            )
            OR (
                pool_type = 'REWORK'
                AND rework_out_quantity = 0
                AND total_quantity >= scheduled_quantity
                    + completed_quantity + scrapped_quantity
                    + transferred_quantity
            )
        )
    ),
    CONSTRAINT ck_production_flow_pool_status CHECK (
        status IN ('ACTIVE', 'CLOSED', 'CANCELLED')
    ),
    CONSTRAINT ck_production_flow_pool_source CHECK (
        product_snapshot_version > 0
        AND scheme_snapshot_version > 0
        AND (
            (pool_type = 'NORMAL' AND source_record_business_id = '')
            OR (
                pool_type = 'REWORK'
                AND source_record_business_id <> ''
            )
        )
    )
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_0900_ai_ci;
```

余额：

```text
普通池待排 = total_quantity - scheduled_quantity - completed_quantity
             - scrapped_quantity - rework_out_quantity
普通池可流转 = completed_quantity - transferred_quantity
返工池可用 = total_quantity - scheduled_quantity - completed_quantity
             - scrapped_quantity - transferred_quantity
```

说明：

- 唯一键保证一个订单商品同一工序只有一行普通池；返工池按来源记录、缺陷工序和返工工序各自一行，便于记录作废时精确反算；
- 普通池在订单确认时按工序链生成，下游普通池行初始总量为 0；
- `target_process_code` 从订单商品方案快照冻结，之后商品方案修改不改变已有池行；
- `source_record_business_id` 只对返工池有值，用于来源记录作废时定位返工池行；
- `CLOSED` 和 `CANCELLED` 池行不参与可用数量、任务创建和数量守恒；
- 池行余额只能通过生产模块命令和订单同步事件修改，不允许直接编辑。

- 作废重录把原记录标记 `VOIDED`，原记录产生的未使用返工池行标记 `CANCELLED`，再按新结果生成一条 `ACTIVE` 记录；

## 11. 事务与并发

### 11.1 创建制作计划

```text
校验员工和岗位
→ 取得员工快照
→ 按订单商品排序锁定 production_source_guards
→ 校验每个订单商品的正常待排数量
→ 写计划头
→ 写正常任务
→ 写审计
→ 一次提交
```

### 11.2 创建后续工序计划

```text
校验员工和岗位
→ 取得员工快照
→ 写计划头
→ 写审计
→ 一次提交
```

后续计划创建不锁订单商品，不改变任何数量池。

### 11.3 增加或修改计划任务

```text
锁定计划行，校验计划仍为 PLANNED
→ 锁定计划任务和对应订单商品守卫
→ 校验任务状态和版本
→ 校验池子可用数量
→ 更新任务或新增任务
→ 任务取消或完成时更新 task_unique_key
→ 写审计
→ 一次提交
```

新增、修改和取消任务都必须先锁计划行；计划已完成或已取消时不能再追加任务，避免任务挂到已结束计划。

取消整个计划时，先锁定计划，再按任务涉及的订单商品排序锁定全部 `production_source_guards`，然后取消全部未核验任务、更新计划和任务的活动唯一键，再写审计并提交。

### 11.4 核验制作任务或返工任务

```text
锁定计划、计划任务、数量池行和订单商品守卫
→ 校验任务状态和版本
→ 校验数量守恒
→ 写生产记录
→ 更新任务状态、计划状态和活动唯一键
→ 更新本工序数量池行，按返工拆分创建返工池行
→ 写审计
→ 一次提交
```

### 11.5 核验后续计划

```text
锁定计划
→ 按订单商品排序锁定全部 production_source_guards
→ 锁定上游和本工序数量池行
→ 逐池行校验可流转数量
→ 写多条生产记录
→ 更新上游已流转、本工序总量和结果数量，按返工拆分创建返工池行
→ 判断计划是否完成，更新计划状态和活动唯一键
→ 写审计
→ 一次提交
```

### 11.6 并发

- 同一订单商品的计划、核验、返工、发货校验和作废重录共用 `production_source_guards` 行锁；
- 多个订单商品按业务标识排序锁定；
- 锁顺序固定为：计划行 → 订单商品守卫 → 数量池行；订单发货先调用 `lockForShipment` 取得同一守卫，再写发货事实；
- 计划和计划任务使用 `row_version` 拒绝覆盖；
- 生产记录业务数量不修改；作废重录使用 `row_version` 拒绝并发覆盖；
- 死锁只允许重试整个幂等命令。

### 11.7 其他任务排班

```text
校验员工在职且岗位为 OTHER
→ 取得员工快照
→ 校验同一员工同一天没有活动其他任务排班
→ 写其他任务排班
→ 写审计
→ 一次提交
```

- 其他任务排班不锁订单商品守卫，不改变任何数量池；
- 修改备注或取消排班使用 `row_version` 并发控制；
- 取消时把活动唯一键改为排班业务标识，释放同一员工同一天的活动排班；
- 其他任务排班不生成生产记录，不参与工作量计算。

### 11.8 生产记录作废重录

```text
按订单商品排序锁定全部 production_source_guards
→ 锁定原生产记录、计划任务和涉及的池行
→ 校验记录 ACTIVE、版本和作废原因
→ 反算原记录对台账的影响，校验反算后没有任何负数
→ 校验原记录产生的返工池行没有被使用
→ 通过订单查询确认订单商品没有发货
→ 原记录标记 VOIDED，写入作废原因、时间和操作人
→ 原记录产生的未使用返工池行标记 CANCELLED
→ 按新结果生成新的 ACTIVE 生产记录
→ 撤销原记录台账影响并应用新记录台账影响
→ 写审计
→ 一次提交
```

- 原记录和新记录使用同一活动记录键；
- 原记录业务数量不变，只改变状态和作废信息；
- 新记录生成失败时整笔回滚，原记录仍为 `ACTIVE`；
- 作废重录不改变计划任务和计划状态。

### 11.9 订单同步

```text
订单模块在同一事务内发布订单确认/变更/取消事件
→ 生产模块按订单商品排序锁定 production_source_guards
→ 按事件类型生成、增加、减少或取消普通池行
→ 减量和取消前校验没有超出的在制数量
→ 写审计
→ 订单事务提交或整体回滚
```

- 订单确认、订单变更和订单取消的事件监听必须是同步的，并使用订单模块的同一事务；使用同步事件监听，不使用提交后监听、消息队列或后台补偿；
- 事件处理失败时抛出业务错误，由订单模块返回并回滚整笔操作；
- 订单同步只创建或调整普通池行，不创建、不修改、不取消计划、计划任务和生产记录；
- 订单模块的确认、变更和取消命令使用平台幂等键；事件在同一事务内只处理一次，不另建同步版本表；

### 11.10 台账校验与重建

```text
按订单商品锁定 production_source_guards
→ 读取当前订单数量、未核验计划任务和全部 ACTIVE 生产记录
→ 按时间顺序在内存重放台账
→ 与现有台账逐行比较
→ 一致：结束，不写库
→ 不一致：返回差异，等待管理员确认
→ 管理员确认后覆盖余额、写审计
→ 一次提交
```

- 重建命令需要 `production.flow.rebuild` 权限，只允许管理员/运维调用；
- 重建不修改计划任务、生产记录和订单，只覆盖数量池台账余额；
- 重建与正常计划、核验、订单同步共用订单商品守卫，不能并发执行；
- 每日对账只检查并告警，不自动触发重建。

## 12. 历史与追溯

- 计划、计划任务是当前记录，可以修改直到产生生产记录；
- 生产记录业务数量不可变，只追加；录错通过作废重录处理，原记录保留；
- 数量池台账由订单同步事件、计划任务和生产记录维护；
- 订单商品进度直接读取数量池台账余额，不再扫描生产记录汇总；
- 员工、商品、方案、订单变化不影响已有计划和生产记录；
- 生产记录保留订单商品、商品/方案快照引用、员工快照引用、计划任务和上下游池行；
- 其他任务排班是当前排班，取消后保留历史，不生成生产记录；
- 计划、生产记录和其他任务排班不物理删除，取消和终态保留历史。

## 14. 页面与交互要求

### 14.1 工作区

生产模块只有两个工作区：

| 工作区 | 目的 |
|---|---|
| 排班计划 | 创建计划、安排员工和日期、增加任务、查看计划状态 |
| 生产记录 | 核验计划任务或后续计划、查看实际完成、返工和报废 |

### 14.2 计划列表

- 页头使用紧凑页栏，不使用大标题；
- 列：日期、员工、岗位/工序、计划数量、合格数量、预计分钟、当天工作量、状态、任务数；
- 当天预计分钟超过每日可用分钟时，显示“工作量超出”提示，不阻止保存；
- 筛选：日期范围、员工、工序、状态；
- 默认按日期倒序；
- 点击进入计划详情；
- 新建计划按钮；
- 空状态提示“暂无计划”。

### 14.3 新建制作计划

- 选择日期、员工（只列制作岗位在职员工）、工序固定制作；
- 选择订单商品来源，可多选；
- 每个来源显示订单号、客户、商品、方案、订单数量、正常待排数量；
- 每个来源填写计划数量，不能超过正常待排；
- 每个来源显示按制作标准分钟计算的预计分钟；
- 页面显示员工当天预计分钟合计和每日可用分钟；超出时提示但允许保存；
- 支持一次添加多条来源；
- 保存后生成一个制作计划和多条正常任务；
- 员工当天已有活动制作计划时，直接进入原计划追加，不新建计划。

### 14.4 新建后续工序计划

- 选择日期、员工（只列对应岗位在职员工）、工序；
- 不选订单、不填计划数量；
- 保存后生成一个空计划；
- 员工当天同一工序已有活动计划时，直接进入原计划。

### 14.5 计划详情

- 页头：日期、员工、工序、状态；
- 制作计划：显示计划任务列表，每条任务显示订单、商品、方案、计划数量、合格数量、预计分钟、状态；
- 后续计划：显示核验入口和已生成的生产记录；
- 计划头显示计划预计分钟、员工当天预计分钟合计和每日可用分钟；
- 操作：追加正常任务（制作）、追加返工任务、修改任务、取消任务、取消计划、核验；
- 计划有生产记录后，取消计划入口隐藏或禁用；
- 任务有生产记录后，修改和取消入口隐藏或禁用。

### 14.6 返工池与返工任务

- 返工池列表显示订单、商品、方案、缺陷工序、返工工序、总量、可用数量、已排、已合格、已报废、已转出；
- 从返工池选择池行，加入计划成为返工任务；返工任务不显示预计分钟；
- 返工任务选择返工工序，只能选该商品已做过的工序且不晚于缺陷工序；
- 返工任务和正常任务在计划详情中按类型区分显示。

### 14.7 制作任务核验

- 从计划任务进入核验；
- 显示订单、商品、方案、计划数量；
- 填写合格、返工、报废、未完成；
- 四项合计必须等于计划数量；
- 返工数量大于 0 时选择返工工序，可拆分多条；
- 提交后任务完成，生成生产记录；
- 制作任务不能重复核验。

### 14.8 后续计划核验

- 从后续计划进入核验；
- 只显示上一道工序且目标工序不早于当前工序的流程池行；
- 先选择上游工序流程池行，可多选；
- 每个来源显示订单、商品、方案、可流转数量；
- 每个来源填写本次处理数量和四项结果；
- 处理数量不能超过可流转数量；
- 返工数量大于 0 时选择返工工序，可拆分多条；
- 一次提交生成多条生产记录；
- 正常核验提交后关闭正常核验入口；返工任务仍在计划详情单独核验；
- 核验后计划完成；仍有返工任务时计划保持未完成。

### 14.9 生产记录

- 按日期、员工、工序、订单、商品、记录状态筛选；
- 默认只显示 `ACTIVE`，可切换查看 `VOIDED`；
- 显示计划、任务、订单商品、工序、员工、四项数量、核验时间、作废原因；
- 生产记录业务数量只读，不提供直接编辑和删除；
- 支持从记录跳转到计划、订单商品和数量池行；
- 有 `production.record.correct` 权限时，`ACTIVE` 记录显示“作废重录”；
- 作废重录对话框要求填写作废原因和新的四项结果；原记录保留并标记已作废；
- 反算后台账会出现负数或订单已发货时，作废重录入口禁用并说明原因。

### 14.10 其他任务排班

- 在“排班计划”工作区增加“其他任务排班”页签或分区；
- 列：日期、员工、岗位、备注、状态；
- 筛选：日期范围、员工、岗位、状态；
- 新建时选择日期和员工，岗位从员工档案自动带出；
- 只列岗位为 `OTHER` 的在职员工；具体工作写在备注；
- 不填数量，不做完成确认，不显示预计分钟；
- 同一员工同一天已有活动其他任务排班时，直接打开原排班或提示重复；
- 可以修改备注，可以取消；
- 取消后保留历史，允许同一员工同一天重新排班。

### 14.11 全局交互原则

- 页面使用 V3 全站设计语言和现有组件；
- 计划与记录分两个工作区，不混在一张表；
- 数量输入即时校验，超过可用数量内联提示；
- 计划数量、实际数量、剩余数量分列显示，不把计划量显示成完成量；
- 生产记录不提供编辑和删除按钮；
- 不显示内部业务标识、行版本和堆栈；
- 英文枚举统一映射为中文工序和状态名称。

## 15. 验收标准

### 15.1 计划

- [ ] 同一员工、同一天、同一工序只能有一个活动计划；
- [ ] 已有活动计划时追加任务，不重复创建计划；
- [ ] 制作计划可以包含多条订单商品正常任务，也可以只有返工任务；
- [ ] 新增、修改或取消任务前锁计划行，计划完成后不能追加任务；
- [ ] 制作计划正常任务数量不能超过正常待排；
- [ ] 后续工序计划不选订单、不建正常任务；
- [ ] 计划员工必须岗位匹配；
- [ ] 计划可以提前创建，不检查实际产出；
- [ ] 计划完成后释放同一员工、日期、工序的活动唯一键；
- [ ] 制作计划正常任务按计划数量计算预计分钟；
- [ ] 员工当天预计分钟超过每日可用分钟时提示，但不阻止保存；
- [ ] 计划有生产记录后不能取消；
- [ ] 计划任务有生产记录后不能修改或取消。

### 15.2 计划任务

- [ ] 同一计划同一订单商品只有一条活动正常任务；
- [ ] 正常任务完成或取消后，可以在同一计划重新添加同一订单商品任务；
- [ ] 正常任务和返工任务可以同计划并存；
- [ ] 返工任务只能从返工池创建；
- [ ] 返工任务计划数量不能超过返工池可用数量；
- [ ] 返工任务不计算预计分钟，不参与工作量提示；
- [ ] 修改正常任务数量时正确考虑本任务原计划数量；
- [ ] 取消正常任务数量回到正常待排；
- [ ] 取消返工任务数量回到返工池可用数量。

### 15.3 核验

- [ ] 制作任务每条单独核验；
- [ ] 制作核验四项数量之和等于计划数量；
- [ ] 后续计划一次核验可多选来源并生成多条生产记录；
- [ ] 后续计划正常核验只能提交一次；
- [ ] 后续核验的上游池行必须是当前工序的上一道工序；
- [ ] 后续核验每个来源处理数量不超过可流转数量；
- [ ] 后续核验四项数量之和等于本次处理数量；
- [ ] 合格进入下一工序，目标工序进入待交付；
- [ ] 返工进入返工池行；
- [ ] 报废增加制作普通池补做数量；
- [ ] 未完成在后续工序留在上一工序流程；
- [ ] 生产记录业务数量只追加，不编辑、不删除；
- [ ] 没有计划不能生成生产记录。

### 15.4 数量守恒与台账

- [ ] 当前订单数量 = 各工序正常待排 + 各工序已排未核验 + 各工序合格待流转（含待交付）+ 返工可用 + 返工已排；
- [ ] 订单确认时按订单商品和工序链生成普通池行；
- [ ] 订单加量只增加制作普通池总量和待排；
- [ ] 订单减量不能超过制作待排，超过时拒绝变更；
- [ ] 订单有生产数量时不能取消或移除明细；
- [ ] 任何操作不会让任何池行出现负数；
- [ ] 并发排计划和核验不会重复占用同一数量；
- [ ] 取消计划或任务后数量正确回到对应池行；
- [ ] 下游报废后补做数量正确回到制作待排；
- [ ] 后续未完成数量仍留在上游可流转数量；
- [ ] 按订单商品重建台账的结果与事实一致，重建不改计划和生产记录。

### 15.5 返工

- [ ] 返工池按订单商品、缺陷工序和返工工序记录；
- [ ] 返工工序只能选已做过的工序且不晚于缺陷工序；
- [ ] 返工任务合格后并入同工序普通池，继续往目标工序走；
- [ ] 返工再次返工时原返工池转出数量增加，并生成新的返工池行；
- [ ] 原返工池转出后不会和新返工池重复计算可用数量；
- [ ] 返工报废增加制作普通池补做数量；
- [ ] 返工不增加订单数量，不重复计入合格。

### 15.6 其他任务排班

- [ ] 其他任务只能选岗位为 `OTHER` 的在职员工；
- [ ] 岗位从员工快照带出，不能手工修改；
- [ ] 同一员工同一天只能有一个活动其他任务排班；
- [ ] 其他任务排班不填数量、不做完成确认、不生成生产记录；
- [ ] 其他任务排班不进入正常待排、返工池、工序流程和订单进度；
- [ ] 其他任务排班不计算预计分钟，不参与工作量提示；
- [ ] 取消后保留历史，允许同一员工同一天重新排班。

### 15.7 生产记录作废重录

- [ ] 只有 `ACTIVE` 记录可以作废重录；
- [ ] 作废重录必须填原因；
- [ ] 反算后台账出现负数时不能作废；
- [ ] 返工池行已被使用时不能作废；
- [ ] 订单商品已发货时不能作废；
- [ ] 原记录保留并标记 `VOIDED`，业务数量不变；
- [ ] 未使用的原返工池行标记 `CANCELLED`；
- [ ] 新记录使用同一活动记录键，台账按新旧记录差异更新；
- [ ] 计划任务和计划状态不回到未完成。

### 15.8 数据与边界

- [ ] 生产模块不建小组、自定义任务、备货生产、纯手工任务和成品库存表；
- [ ] 生产模块不调用计算中心，不做工资、成本和金额计算；
- [ ] 生产模块不直接读写订单、商品、员工、全局和平台表；
- [ ] 生产表不建跨模块外键，不做跨模块 JOIN；
- [ ] 跨模块读取、写入和同步分别只走公开查询、公开命令和公开事件；
- [ ] 计划、任务、生产记录、数量池台账均支持权限校验；
- [ ] 核验复用计划创建时的员工快照，员工离职后仍可核验；
- [ ] 发货校验和作废重录共用订单商品守卫，锁顺序固定；
- [ ] 所有写操作写平台审计；
- [ ] 页面不显示英文枚举原文、内部标识和堆栈。

## 16. 明确不采用

- 不做小组、成员、组长和小组效率；
- 不做自定义任务、无订单备货生产和纯手工任务；
- 不做其他任务的完成确认、工时、生产记录和数量统计；
- 不做成品库存、入库、出库和库存占用；
- 不做发货、物流、收款和售后；
- 不做工资、成本、提成、考勤和工时结算；
- 不做自动排班、自动分配员工和排产优化；
- 不做班次、开始时间、结束时间和设备产能；
- 不做生产记录业务数量的直接编辑、删除；只允许作废重录；
- 不做订单变更、订单取消对已有计划和记录的自动调整；数量池台账随订单同步，计划和记录不动；

- 不做生产绩效和计件金额；

- 不做通用生产模板。

## 17. 与 V2 的主要差异

| V2 生产/排班 | V3 生产模块 |
|---|---|
| 排班和生产执行分属不同模块或合并方式反复调整 | 一个生产模块，两个工作区：排班计划、生产记录 |
| 有小组、成员和小组效率 | 不做小组，只按员工岗位排班 |

| 任务、计划、生产事实边界复杂 | 计划 / 计划任务 / 生产记录三层，术语固定 |

## 18. 外部依赖

生产模块不直接访问订单、员工、商品、全局和平台数据库；以下依赖全部通过目标模块的公开方法或公开事件完成。

### 18.1 平台能力

- 权限：`production.plan.read`、`production.plan.create`、`production.plan.update`、`production.plan.cancel`、`production.record.read`、`production.record.verify`、`production.record.correct`、`production.rework.read`、`production.rework.manage`、`production.other.read`、`production.other.manage`、`production.flow.rebuild`；
- 审计：计划、任务、生产记录、数量池台账、其他任务排班和数量变化；
- 幂等：所有写命令使用平台幂等键；
- 并发：由生产模块自己的订单商品守卫保证，不依赖平台锁。

### 18.2 订单模块

生产模块和订单模块允许双向公开契约，但不允许跨表：生产只调用订单 `OrderItemQuery` 并订阅订单事件；订单只调用生产 `ProductionQuery` / `lockForShipment`。两端不导入对方 Entity、Repository 或内部实现；拆独立服务时把共享 DTO 和事件下沉到 `contracts` 包。

生产模块需要订单提供查询和同步事件：

```java
interface OrderItemQuery {
    List<OrderItemSourceView> listConfirmedOrderItems(OrderItemSourceQuery query);
    List<OrderItemSourceView> listOrderItems(Collection<OrderItemRef> orderItemRefs);
    OrderItemSourceView getOrderItem(OrderItemRef orderItemRef);
    int getShippedQuantity(OrderItemRef orderItemRef);
}

record OrderItemSourceView(
    OrderRef orderRef, String orderNo, OrderItemRef orderItemRef,
    String customerName, String productBusinessId, String productName,
    String schemeBusinessId, String schemeName,
    SnapshotRef productSnapshotRef, SnapshotRef schemeSnapshotRef,
    String targetProcessCode, int orderedQuantity,
    LocalDate orderDate, LocalDate expectedDeliveryDate
) {}

record OrderConfirmedEvent(
    OrderRef orderRef, String orderNo, int contentVersion,
    List<OrderItemSourceView> items
) {}

record OrderChangedEvent(
    OrderRef orderRef, String orderNo, int contentVersion,
    List<OrderItemSourceView> addedItems,
    List<OrderItemQuantityChange> quantityChanges,
    List<OrderItemRef> removedItems
) {}

record OrderItemQuantityChange(
    OrderItemRef orderItemRef, int oldQuantity, int newQuantity
) {}

record OrderCancelledEvent(
    OrderRef orderRef, int contentVersion, List<OrderItemRef> items
) {}
```

要求：

- 订单商品必须已确认且可生产；
- 生产模块按需调用 `OrderItemQuery` 查询可排订单商品；
- `listConfirmedOrderItems` 只用于排班选择来源，只返回 `CONFIRMED` 订单的 `ACTIVE` 明细；
- `listOrderItems` 用于待排、工序流程和返工池列表批量补齐订单号、客户和商品名称，避免逐行回表；
- `getOrderItem` 按明细标识解析已有计划、生产记录和台账展示所需数据，订单状态可为 `CONFIRMED` 或 `COMPLETED`，明细必须 `ACTIVE`；
- `getShippedQuantity` 返回订单商品已发数量，生产模块作废生产记录前用它确认没有发货；
- 订单确认、变更和取消事件必须同步发送，在生产模块的监听器中使用订单模块同一事务，不使用消息队列或后台补偿；
- 订单确认事件按订单商品生成普通池行；订单变更事件处理新增明细、数量变化和移除明细；订单取消事件取消池行；
- 目标工序决定工序链，生产模块不重新计算；
- 订单加量增加制作普通池总量；订单减量减少制作普通池总量，不能低于在制数量；
- 订单取消或移除明细时，只要有已排、已合格、已报废、已转返工或返工数量就拒绝；
- 事件处理失败时抛出业务错误，订单确认、变更或取消整体回滚；订单侧映射为 `ORDER_PRODUCTION_QUANTITY_BELOW_IN_FLIGHT` 或 `ORDER_PRODUCTION_IN_FLIGHT`；
- 订单同步只改数量池台账，已有计划任务和生产记录不自动调整；
- 生产模块作废生产记录前，调用 `getShippedQuantity` 确认订单商品没有发货；
- 生产模块不修改订单和订单商品；订单模块不直接读写生产表。

### 18.3 员工模块

生产模块调用员工模块公开查询，不直接读员工表：

```java
interface EmployeeQuery {
    List<EmployeeOptionView> options(EmployeeOptionQuery query);
    EmployeeEligibilityView checkEligibility(
        EmployeeRef employeeRef, String positionCode, LocalDate workDate
    );
}

interface EmployeeSnapshotService {
    EmployeeSnapshotRef acquireEligibleForWork(
        EmployeeRef employeeRef, String positionCode, LocalDate workDate
    );
    EmployeeSnapshotView resolve(EmployeeSnapshotRef snapshotRef);
}
```

要求：

- 岗位是全局固定枚举 `MAKING / BAGGING / SEAM_CUTTING / OTHER`，生产工序分别对应前三者；
- 新建计划通过 `options` 和 `checkEligibility` 只选择在职且岗位匹配的员工；
- 计划通过 `EmployeeSnapshotService.acquireEligibleForWork` 取得员工快照引用，只保存引用，不复制员工姓名和岗位；
- 计划列表、详情和生产记录通过 `EmployeeSnapshotService.resolve` 读取员工姓名和岗位名称；
- 员工调岗或离职后，已有计划继续使用快照，不自动取消；
- 其他任务排班只选择岗位为 `OTHER` 的在职员工；
- 其他任务排班的岗位从员工快照带出；
- 生产模块不直接读员工表、员工快照表或员工岗位记录表。

### 18.4 商品模块

生产模块通过订单商品取得商品快照和方案快照引用，再调用商品模块公开快照方法解析，不直接读商品表或快照表：

```java
interface ProductSnapshotService {
    ProductSnapshotView resolveProductSnapshot(SnapshotRef productSnapshotRef);
    SchemeSnapshotView resolveSchemeSnapshot(SnapshotRef schemeSnapshotRef);
    ProductProductionWorkBasis resolveProductionWorkBasis(
        SnapshotRef productSnapshotRef,
        SnapshotRef schemeSnapshotRef,
        ProcessCode processCode
    );
}
```

生产模块只使用以下字段：

```text
ProductSnapshotView: name, mainImageFileBusinessId
SchemeSnapshotView: name, targetProcess, productSnapshotRef
ProductProductionWorkBasis: standardMinutes
```

要求：

- 制作正常任务的预计分钟通过 `resolveProductionWorkBasis(productRef, schemeRef, MAKING)` 取得 `standardMinutes`；
- 工序链只取 `SchemeSnapshotView.targetProcess`，不读取商品当前数据重新判断；
- 计划和生产记录列表中的订单号、客户、商品和方案名称通过 `OrderItemQuery.listOrderItems` 批量取得；
- 需要读取商品快照中的主图或方案快照中的目标工序时，调用 `resolveProductSnapshot` / `resolveSchemeSnapshot`；
- 商品或方案后续修改不影响已有计划和生产记录；
- 计划任务、生产记录和数量池行都按 `SnapshotRef` 保存商品/方案快照的业务标识和版本，不能只存业务标识；
- 生产模块不直接读 `product_*` 表、`product_snapshots` 或 `product_scheme_snapshots`，也不复制快照载荷。

### 18.5 计算中心

- 本期生产模块不调用计算中心；
- 计划数量、实际数量、合格、返工、报废、未完成、剩余、预计分钟和进度由生产模块本地计算；
- 计算中心只保留金额、成本、工资等计算；
- 后续如工资或成本需要生产数量，通过生产公开查询读取生产记录，不由生产模块计算金额。

### 18.6 报表与工资

- 报表通过生产公开查询读取计划、生产记录、返工、其他任务排班和进度；
- 工资模块通过生产公开查询读取生产记录，再结合考勤模块的打卡记录按岗位计薪规则计算工资；
- 工资和报表都不直接读生产表；
- 生产模块只提供生产数量，不提供打卡、工时、请假和加班；
- 生产模块不保存工资行、工时金额和成本金额。

### 18.7 全局模块

生产模块调用全局模块公开查询，不直接读全局表：

```java
interface GlobalParameterQuery {
    GlobalParameterView at(String parameterCode, LocalDate businessDate);
}

interface StaticDataQuery {
    StaticDataItemView get(String typeCode, String itemCode);
}
```

要求：

- 每日可用工作分钟通过 `GlobalParameterQuery.at("DAILY_WORK_MINUTES", planDate)` 读取；
- 工序和岗位显示名称通过 `StaticDataQuery.get("POSITION", positionCode)` 读取；
- 生产模块只读取上述参数和显示名称，不维护静态数据或参数；
- 参数未配置时，生产模块只显示预计分钟，不做超出提示；
- 返工任务不读取该参数，不参与工作量提示；
- 生产模块不提供设置入口；
- 生产模块不直接读 `global_parameters` 或 `global_static_items` 表。

## 19. 已确认口径

1. 不做小组；生产模块一个模块、两个工作区。
2. 生产来源只有订单商品和返工。
3. 计划 = 日期 + 员工 + 一道工序；同一员工、同一天、同一工序只能一个活动计划，已存在就追加。
4. 制作计划新建时选多个订单商品，每个商品生成一条正常任务；每条任务单独核验。
5. 捏毛装袋、缝边剪袋只排日期、员工、工序，不选订单、不建正常任务；核验时多选上游流程来源，逐条填数量。
6. 计划任务和生产记录分开；生产记录核验时生成，不提前存在；没有计划不能产出。
7. 正常任务和返工任务可以同计划并存；返工是计划任务类型。
8. 核验结果四类：合格、返工、报废、未完成。
9. 返工进入返工池，不重新占订单数量；返工可选前面已做过的工序；返工合格后继续往目标工序走。
10. 报废回到正常待排池，补做从制作重新开始；未完成回到对应池子或留在上一工序流程。
11. 正常待排池和返工池统一落在 `production_flow_pools` 台账；普通池一个订单商品一道工序一行，返工池按缺陷工序、返工工序和来源记录分行，共用数量列。
12. 计划可以提前排，不限定提前多久，不依赖实际产出；实际执行才受上游实际合格数量限制。
13. 数量计算在生产模块本地完成，不调用计算中心。
14. 本期不做自定义任务、备货生产、纯手工任务和成品库存。
15. 生产记录业务数量不直接编辑、不删除；录错走作废重录，原记录保留并标记作废。
16. 后续未完成数量留在上游可流转数量，返回来源处，不再排计划。
17. 订单确认时生成普通池行；订单加量、减量同步制作普通池总量；减量不能低于在制数量；有生产数量的订单不能取消或移除明细；订单同步不改已有计划和生产记录。
18. 制作正常任务按计划数量计算预计分钟；返工任务不计算工作时长，不参与工作量提示；当天预计分钟超出每日可用分钟只提示，不阻止保存。
19. 其他任务排班只给岗位为 `OTHER` 的员工排日期和岗位，具体工作在备注；不填数量、不做完成确认、不生成生产记录、不计工作量。
20. 工资计算通过生产公开查询读取生产记录，并结合考勤打卡记录；生产模块只提供生产事实，考勤和生产各自独立。
21. 生产记录录错允许作废重录；已有下游使用、返工池被使用或订单已发货时不能作废。

## 20. 评审收口

- 本文是 V3 生产模块评审稿，覆盖需求、字段、规则、状态、6 张表、接口、事务、权限、页面和验收；

- 评审通过后进入考勤模块，再进入工资与成本。
