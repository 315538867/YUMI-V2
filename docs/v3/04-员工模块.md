# V3 员工模块

> 模块代码：`employee`  
> 文档版本：V3.0  
> 编写日期：2026-10-29  
> 状态：V3 员工模块评审稿；评审通过前不进入页面实现

本文是 V3 员工模块的唯一需求与设计依据。员工模块只维护员工档案、在职与离职记录、工种资格和员工快照；小组、排班、每日产出、工资和生产事实均不属于本模块。

## 摘要

- 员工模块是一份简单的员工花名册：编号、姓名、电话、备注、在职状态和工种资格。
- 员工编号自动生成，格式 `E-000001`；创建后不可修改、不可复用，员工不硬删除。
- 员工姓名允许重复，电话可以留空且不要求唯一，以员工编号区分身份。
- 每次入职、离职和返聘都保留记录；员工返聘沿用原编号，不新建员工。
- 工种由设置模块的静态数据维护，员工只保存工种代码；员工模块不建工种配置表。
- 工种资格保留每次授予和撤销记录；离职不自动撤销资格，返聘后原有资格继续可用。
- 员工模块自己保存员工快照；排班、生产、工资只保存快照引用，按版本查询。
- 员工模块不管理小组、排班、每日产出、工资和考勤；离职或撤销资格不检查未来排班。
- 员工不是登录账号，不创建、不绑定平台用户。
- 本模块没有业务计算，不依赖计算模块。

## 1. 模块说明

员工模块管理“谁可以来上班、会做哪些工序，以及他什么时候在职”。

员工是生产执行的最小身份。排班模块只从在职且具备对应工种资格的员工中选择人员；生产任务和工资记录保存员工快照引用，之后员工改姓名、离职或撤销资格，不会改变已经发生的历史。

员工模块回答“这个员工是谁、现在是否在职、会做哪些工种、历史什么时候入离职、资格什么时候授予或撤销”；排班模块回答“哪天谁来、做什么”；每日产出模块回答“实际做了多少”；工资模块回答“这段期间该结算多少”。

## 2. 用户与使用场景

### 2.1 用户

| 用户 | 关心什么 | 在员工模块做什么 |
|---|---|---|
| 管理员 | 现在有哪些人能上班、各自会做什么 | 新建员工，维护电话和备注，授予或撤销工种，办理离职和返聘 |
| 老板 | 员工人数、在职情况和工种覆盖 | 查看员工列表、详情和历史 |
| 排班 | 某天有哪些在职且具备某工种的员工 | 通过员工查询和资格校验取得候选员工及员工快照引用 |
| 每日产出 | 产出登记对应哪个员工 | 保存员工快照引用，按版本解析员工姓名和编号 |
| 工资 | 某段期间员工身份和资格 | 保存员工快照引用，按版本解析历史员工资料 |
| 报表 | 员工维度汇总 | 通过员工公开查询或后续报表投影读取，不直接读员工表 |

### 2.2 现状与目标

管理员现在用 Excel 记录兼职员工和每日产出，员工姓名通常直接写在排班表或产出表里。

V3 把员工独立成一份可复用档案：

- 员工只录入一次，排班、产出和工资都引用同一个员工身份；
- 员工离职再回来，沿用原编号和历史，不重复建档；
- 工种资格单独维护，排班只选择有资格的人；
- 员工改资料或离职后，历史排班、产出和工资仍能还原当时的人；
- 小组和排班不塞进员工档案，避免员工页变成生产配置页。

## 3. 本期范围

### 3.1 本期提供

- 员工创建、编辑、查看；
- 员工编号自动生成；
- 员工姓名、电话、备注；
- 员工在职、离职和返聘；
- 每次入职、离职和返聘记录；
- 工种资格授予、撤销和资格变更记录；
- 员工快照创建、复用和按版本查询；
- 按工种和在职状态筛选员工，供排班选择；
- 员工资格校验；
- 员工列表搜索和分页。

### 3.2 本期不提供

- 小组、成员、组长、组内岗位和组内步骤；
- 小组效率因子、每日有效工作时间和活动占用；
- 排班、每日产出和生产任务；
- 工资、时薪、提成、考勤、请假和加班；
- 员工登录账号、角色权限和平台用户绑定；
- 组织架构、部门、岗位和职级；
- 员工级工资单价或个性化提成；
- 身份证号、住址、紧急联系人、银行卡、合同和附件；
- 员工头像和员工颜色字段；
- 员工删除、合并和批量导入导出；
- 未来生效的预约离职、预约返聘和预约资格变更；
- 员工字段级变更历史表和历史页；
- 通用“基础资料模块”。

## 4. 业务概念

| 术语 | 定义 |
|---|---|
| 员工 | 一个可复用的生产执行者身份，以员工编号区分 |
| 在职状态 | 员工当前是否可被安排新工作，只有在职和离职两种 |
| 就业记录 | 一次入职、离职或返聘事实，按生效日期保留 |
| 工种 | 员工可以承担的工作类别，由设置模块静态数据维护 |
| 工种资格 | 员工在某个工种上的当前资格状态，分为有效和已撤销 |
| 资格记录 | 一次授予或撤销工种资格的事实，按生效日期保留 |
| 员工快照 | 员工被排班、生产或工资引用时冻结的员工身份和资格 |
| 内容版本 | 员工姓名、在职状态或有效资格发生变化时递增的版本号 |
| 资格校验 | 判断某员工在某一天是否可以承担某工种 |

员工、就业记录、工种资格和资格记录的关系：

```text
员工 1 ── N 就业记录
员工 1 ── N 工种资格
员工 1 ── N 资格记录
员工 1 ── N 员工快照
```

## 5. 字段定义

### 5.1 员工基本信息

| 字段 | 必填 | 类型/精度 | 规则 |
|---|---|---|---|
| 员工编号 | 系统生成 | `VARCHAR(32)` | 格式 `E-000001`；创建后不可修改、不可复用 |
| 员工姓名 | 是 | `VARCHAR(40)` | 去首尾空格；不允许只输入空格、换行或控制字符；允许重名 |
| 联系电话 | 否 | `VARCHAR(30)` | 可空；填写时允许数字、`+`、括号、空格和短横线；6 至 30 字符且至少 6 位数字；不要求唯一 |
| 员工备注 | 否 | `VARCHAR(500)` | 可空；用于兼职时间、联系习惯或内部提醒；不参与排班和工资计算 |

员工不是平台登录账号。联系电话只作联系资料，不自动创建用户、不发送登录信息。

### 5.2 在职与就业信息

| 字段 | 必填 | 类型/精度 | 规则 |
|---|---|---|---|
| 在职状态 | 系统 | `EMPLOYED / LEFT` | 新建默认 `EMPLOYED`；只能通过离职和返聘改变 |
| 当前入职日期 | 是 | `DATE` | 首次入职日期；返聘后更新为最近一次入职日期；不得晚于当天 |
| 当前离职日期 | 否 | `DATE` | 在职时为空；离职后为最近一次离职生效日期；不得早于当前入职日期 |
| 离职原因 | 否 | `VARCHAR(300)` | 离职时必填；只写入就业记录，不放在员工根表 |

员工根表只保留当前在职状态和最近一次入离职日期；每次入职、离职、返聘过程保存在就业记录中。

### 5.3 工种资格

| 字段 | 必填 | 类型/精度 | 规则 |
|---|---|---|---|
| 工种代码 | 是 | `VARCHAR(64)` | 引用设置模块 `WORK_TYPE` 静态数据；授予时必须是启用项 |
| 资格状态 | 系统 | `ACTIVE / REVOKED` | 授予后为 `ACTIVE`；撤销后为 `REVOKED` |
| 生效日期 | 是 | `DATE` | 本次授予或撤销的生效日期；不得晚于当天 |
| 变更原因 | 否 | `VARCHAR(300)` | 撤销时可填写；只写入资格记录 |

员工可以有零个或多个有效工种资格。新建员工时不要求至少配置一个工种；排班时只选择在职且具备对应工种资格的员工。

### 5.4 系统字段

| 字段 | 说明 |
|---|---|
| `employee_business_id` | 稳定业务标识，不对外显示 |
| `content_version` | 员工姓名、在职状态或有效资格发生变化时递增；用于员工快照版本 |
| `row_version` | 并发编辑控制；任何员工根更新都递增 |
| `created_at/created_by` | 创建时间和操作人 |
| `updated_at/updated_by` | 最近修改时间和操作人 |

电话和备注修改只递增 `row_version`，不递增 `content_version`，因为电话和备注不进入员工快照。姓名、在职状态和有效资格变化会递增 `content_version`。

### 5.5 员工快照字段

| 字段 | 说明 |
|---|---|
| 员工快照引用 | 其他模块保存的稳定引用 |
| 员工编号 | 快照时的员工编号 |
| 员工姓名 | 快照时的员工姓名 |
| 在职状态 | 快照时的 `EMPLOYED / LEFT` |
| 当前入职日期 | 快照时的最近入职日期 |
| 当前离职日期 | 快照时的最近离职日期，可空 |
| 有效工种资格 | 快照时所有 `ACTIVE` 资格，包含工种代码、工种名称和生效日期 |
| 内容版本 | 快照对应的员工内容版本 |
| 内容指纹 | 校验快照载荷一致性 |

员工快照不保存电话、备注和已撤销资格，避免把不必要的联系方式复制到排班、生产和工资记录中。

## 6. 业务规则

### R1 员工编号

- 由平台编号能力生成，格式 `E-000001`；
- 员工编号全局唯一，创建后不可修改、不可复用；
- 事务回滚可能产生空号，但不会重复或复用编号。

### R2 创建员工

- 员工姓名必填；电话和备注可空；
- 当前入职日期默认当天，不得晚于当天；
- 新建员工状态为 `EMPLOYED`，`content_version = 1`；
- 创建时写入一条入职记录，生效日期等于当前入职日期；
- 创建时可以同时授予零个或多个工种资格；每个资格写入一条授予记录；
- 同一员工不能重复授予同一工种；
- 任一资格不合法时整笔创建失败，不保存员工。

### R3 编辑员工

- 只能修改姓名、电话和备注；
- 员工编号、在职状态、当前入职日期、当前离职日期和工种资格不能通过编辑表单直接覆盖；
- 修改携带 `rowVersion`，冲突返回 `EMPLOYEE_VERSION_CONFLICT`；
- 姓名允许重复，电话允许重复；
- 姓名修改递增 `content_version`；电话和备注修改不递增 `content_version`；
- 每次修改写平台审计。

### R4 离职

- 只有 `EMPLOYED` 员工可以办理离职；
- 离职生效日期不得晚于当天，且不得早于当前入职日期；
- 离职原因必填；
- 离职后状态变为 `LEFT`，当前离职日期写入员工根表，并追加一条离职记录；
- 离职递增 `content_version`；
- 离职不撤销工种资格，不删除员工，不改变历史就业和资格记录；
- 离职不检查未来排班或生产任务；已有任务继续使用员工快照，由排班模块负责提示或调整。

### R5 返聘

- 只有 `LEFT` 员工可以办理返聘；
- 返聘生效日期不得晚于当天，且必须晚于最近一次离职日期；
- 返聘后状态变为 `EMPLOYED`，当前入职日期更新为返聘日期，当前离职日期清空，并追加一条返聘记录；
- 返聘沿用原员工编号，不新建员工；
- 返聘递增 `content_version`；
- 返聘不自动授予或恢复已撤销的工种资格；离职前仍为 `ACTIVE` 的资格继续有效。

### R6 授予工种资格

- 员工必须存在；
- 授予时员工必须为 `EMPLOYED`；
- 工种必须是设置模块中启用的 `WORK_TYPE` 静态项；
- 生效日期不得晚于当天，且不得早于当前入职日期；
- 同一员工同一工种只能有一条当前资格记录；
- 该工种从未授予过时新增资格行；曾撤销过时把原资格行恢复为 `ACTIVE` 并更新生效日期；
- 授予递增 `content_version`，并追加一条授予记录。

### R7 撤销工种资格

- 资格必须存在且当前为 `ACTIVE`；
- 撤销生效日期不得晚于当天，且不得早于该资格的生效日期；
- 撤销把资格状态改为 `REVOKED`，保留原资格行，不物理删除；
- 撤销递增 `content_version`，并追加一条撤销记录；
- 员工已离职时仍可撤销剩余的有效资格，用于清理档案；
- 撤销不检查未来排班或生产任务，由排班模块负责提示或调整。

### R8 工种静态数据

- 工种由设置模块统一维护，类型代码为 `WORK_TYPE`；
- 员工模块只保存工种代码，不建工种配置表；
- 初始工种至少包括制作、捏毛装袋、缝边剪袋和其他任务，具体代码和名称由设置模块定义；
- 工种停用后不能再授予，已有资格保留；
- 已有资格是否还能继续排班，由排班模块结合工种启停判断，员工模块不替代设置模块做该判断；
- 员工当前页面显示工种当前名称；员工快照保存取得快照时的工种名称，之后工种改名不改变历史快照。

### R9 在职与资格的关系

员工可以被安排新工作的条件是：

- 员工当前为 `EMPLOYED`；
- 员工对该工种存在 `ACTIVE` 资格。

员工离职后不能进入新的排班选择；返聘后，未被撤销的资格自动恢复可用。资格校验结果只回答员工状态和资格是否满足，不判断工种本身是否停用。

### R10 与小组和排班解耦

- 员工模块不保存小组、成员关系、组长和小组效率；
- 员工模块不保存排班、日期负载、生产任务和每日产出；
- 员工模块不建立活动占用、预留或活动引用守卫；
- 离职、撤销资格和修改资料不会被未来排班阻断；
- 排班模块需要员工时，调用员工查询和快照接口，不直接读员工表。

### R11 员工快照

- 排班、生产、工资等模块引用员工时，由员工模块创建或复用员工快照；
- 快照按员工内容版本唯一；
- 同一员工、同一内容版本只保存一条快照；
- 同一版本并发创建时复用已有快照；发现载荷指纹不同返回 `EMPLOYEE_SNAPSHOT_CONFLICT`；
- 快照只插入，不更新、不删除；
- 当前页面读取员工当前资料，不读快照；历史记录通过快照引用解析。

### R12 历史与不回溯

- 就业记录和资格记录是不可变事实，不覆盖、不删除；
- 员工改名、换电话、离职、返聘或撤销资格，不改变已有就业记录和资格记录；
- 员工快照保留当时的姓名、在职状态和有效资格；
- 历史排班、生产、产出和工资继续使用原快照，不因员工当前资料变化而重新解释；
- 员工返聘沿用原编号，历史不断开。

### R13 审计

- 员工创建、编辑、离职、返聘、授予资格和撤销资格写平台审计；
- 员工快照创建和复用写审计；
- 电话属于联系资料，读取按平台敏感数据访问审计记录；
- 员工模块不建字段级变更历史表，也不提供字段级变更历史页；就业记录和资格记录是业务事实，不是审计替代品。

### R14 员工不是平台账号

- 员工模块不创建登录账号；
- 不提供员工与平台用户的绑定关系、绑定命令或绑定表；
- 员工姓名和电话不作为登录凭据；
- 权限由平台角色控制，不随员工档案自动授予。

### R15 重名与重复电话

- 员工姓名允许重复，以员工编号区分；
- 员工电话可以留空，也允许重复；
- 员工模块不自动合并重名或同电话员工；
- 列表和详情始终显示员工编号，避免只凭姓名选错人。

## 7. 状态设计

### 7.1 在职状态

| 当前状态 | 操作 | 目标状态 | 说明 |
|---|---|---|---|
| `EMPLOYED` | 离职 | `LEFT` | 写入离职日期和离职记录 |
| `LEFT` | 返聘 | `EMPLOYED` | 更新入职日期，写入返聘记录 |
| `LEFT` | 离职 | 不允许 | 已离职员工不能再次离职 |
| `EMPLOYED` | 返聘 | 不允许 | 在职员工不能重复返聘 |

员工没有启用/停用开关，也没有删除状态。离职是唯一让员工退出排班候选的方式。

### 7.2 工种资格状态

| 当前状态 | 操作 | 目标状态 | 说明 |
|---|---|---|---|
| 不存在 | 授予 | `ACTIVE` | 新增资格行和授予记录 |
| `ACTIVE` | 撤销 | `REVOKED` | 保留资格行，追加撤销记录 |
| `REVOKED` | 授予 | `ACTIVE` | 恢复原资格行，更新生效日期，追加授予记录 |
| `ACTIVE` | 授予 | 不允许 | 同一工种不能重复授予 |

资格状态与员工在职状态独立。员工离职不会自动把资格改为 `REVOKED`；资格撤销也不会让员工离职。

## 8. 数据模型与表设计

### 8.1 关系

```text
employee_employees
├─ employee_employment_records      就业记录
├─ employee_qualifications          当前资格
├─ employee_qualification_records   资格变更记录
└─ employee_snapshots               员工快照
```

员工模块不建小组、成员、效率标准、每日工时、排班和生产任务表。

### 8.2 表清单

| 表 | 类别 | 用途 |
|---|---|---|
| `employee_employees` | 当前根 | 员工当前资料和在职状态 |
| `employee_employment_records` | 不可变事实 | 每次入职、离职和返聘 |
| `employee_qualifications` | 当前关系 | 员工当前工种资格 |
| `employee_qualification_records` | 不可变事实 | 每次授予和撤销资格 |
| `employee_snapshots` | 不可变快照 | 按员工内容版本冻结的员工身份和有效资格 |

### 8.3 员工当前表

```sql
CREATE TABLE employee_employees (
    id BIGINT NOT NULL AUTO_INCREMENT,
    employee_business_id VARCHAR(64) NOT NULL,
    employee_no VARCHAR(32) NOT NULL,
    name VARCHAR(40) NOT NULL,
    phone VARCHAR(30) NULL,
    employment_status VARCHAR(16) NOT NULL,
    hired_on DATE NOT NULL,
    left_on DATE NULL,
    employee_note VARCHAR(500) NULL,
    content_version BIGINT NOT NULL,
    row_version BIGINT NOT NULL,
    created_at DATETIME(6) NOT NULL,
    created_by VARCHAR(64) NOT NULL,
    updated_at DATETIME(6) NOT NULL,
    updated_by VARCHAR(64) NOT NULL,
    PRIMARY KEY (id),
    UNIQUE KEY uk_employee_business_id (employee_business_id),
    UNIQUE KEY uk_employee_no (employee_no),
    KEY ix_employee_name (name),
    KEY ix_employee_phone (phone),
    KEY ix_employee_status (employment_status, employee_no),
    CONSTRAINT ck_employee_name CHECK (name <> ''),
    CONSTRAINT ck_employee_status CHECK (
        employment_status IN ('EMPLOYED', 'LEFT')
    ),
    CONSTRAINT ck_employee_phone CHECK (phone IS NULL OR phone <> ''),
    CONSTRAINT ck_employee_employment_dates CHECK (
        (employment_status = 'EMPLOYED' AND left_on IS NULL)
        OR (
            employment_status = 'LEFT'

        )
    )
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_0900_ai_ci;
```

说明：

- 员工姓名和电话不建唯一约束；
- 员工没有启用/停用列；
- 员工不硬删除；
- 当前入职日期和离职日期只表示最近一次就业，完整历史在就业记录表。

### 8.4 就业记录表

```sql
CREATE TABLE employee_employment_records (
    record_business_id VARCHAR(64) NOT NULL,
    employee_business_id VARCHAR(64) NOT NULL,
    record_type VARCHAR(16) NOT NULL,
    effective_date DATE NOT NULL,
    reason VARCHAR(300) NULL,
    operator_id VARCHAR(64) NOT NULL,

    KEY ix_employment_record_employee (
        employee_business_id, effective_date, created_at
    ),
    CONSTRAINT ck_employment_record_type CHECK (
        record_type IN ('HIRE', 'LEAVE', 'REHIRE')
    )
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_0900_ai_ci;
```

说明：

- 创建员工时写一条 `HIRE`；
- 离职写 `LEAVE`，必须带原因；
- 返聘写 `REHIRE`，原因可空；
- 记录只插入，不更新、不删除。

### 8.5 当前资格表

```sql
CREATE TABLE employee_qualifications (
    id BIGINT NOT NULL AUTO_INCREMENT,
    employee_business_id VARCHAR(64) NOT NULL,
    work_type_code VARCHAR(64) NOT NULL,
    status VARCHAR(16) NOT NULL,
    effective_from DATE NOT NULL,
    created_at DATETIME(6) NOT NULL,
    created_by VARCHAR(64) NOT NULL,
    updated_at DATETIME(6) NOT NULL,

    UNIQUE KEY uk_employee_qualification (
        employee_business_id, work_type_code
    ),
    KEY ix_qualification_work_type (work_type_code, status),
    CONSTRAINT ck_qualification_status CHECK (
        status IN ('ACTIVE', 'REVOKED')
    )
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_0900_ai_ci;
```

说明：

- 一名员工同一工种只有一条当前资格；
- 撤销不删除行，只把状态改为 `REVOKED`；
- 资格与员工根共用 `row_version` 控制并发，不单独维护资格行版本；
- 不保存工种名称，当前名称由设置模块解析；快照保存取得时的名称。

### 8.6 资格变更记录表

```sql
CREATE TABLE employee_qualification_records (
    record_business_id VARCHAR(64) NOT NULL,
    employee_business_id VARCHAR(64) NOT NULL,
    work_type_code VARCHAR(64) NOT NULL,
    record_type VARCHAR(16) NOT NULL,
    effective_date DATE NOT NULL,
    reason VARCHAR(300) NULL,
    operator_id VARCHAR(64) NOT NULL,
    created_at DATETIME(6) NOT NULL,
    PRIMARY KEY (record_business_id),
    KEY ix_qualification_record_employee (
        employee_business_id, effective_date, created_at
    ),
    CONSTRAINT ck_qualification_record_type CHECK (
        record_type IN ('GRANT', 'REVOKE')
    )
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_0900_ai_ci;
```

说明：

- 每次授予和撤销都追加记录；
- 撤销后再次授予也追加新的授予记录，不覆盖历史；
- 记录只插入，不更新、不删除。

### 8.7 员工快照表

```sql
CREATE TABLE employee_snapshots (
    snapshot_business_id VARCHAR(64) NOT NULL,
    employee_business_id VARCHAR(64) NOT NULL,
    employee_content_version BIGINT NOT NULL,
    employee_no VARCHAR(32) NOT NULL,
    name VARCHAR(40) NOT NULL,
    employment_status VARCHAR(16) NOT NULL,
    hired_on DATE NOT NULL,
    left_on DATE NULL,
    qualification_payload_json JSON NOT NULL,
    content_fingerprint CHAR(64) NOT NULL,
    created_at DATETIME(6) NOT NULL,
    created_by_command_execution_id VARCHAR(64) NULL,
    PRIMARY KEY (snapshot_business_id),
    UNIQUE KEY uk_employee_snapshot_version (
        employee_business_id, employee_content_version
    )
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_0900_ai_ci;
```

快照载荷至少包含：

- 员工编号、姓名、在职状态；
- 当前入职日期、当前离职日期；
- 快照时所有 `ACTIVE` 资格：工种代码、工种名称、生效日期。

快照不包含：

- 联系电话、员工备注；
- 已撤销资格；
- 当前页面上的临时筛选或展示状态。

同一员工、同一内容版本只创建一个快照；快照只插入，不更新、不删除。

## 9. 公开接口设计

### 9.1 命令

```java
interface EmployeeApplicationService {
    EmployeeRef create(CreateEmployeeCommand command);
    EmployeeRef update(UpdateEmployeeCommand command);
    EmployeeRef leave(LeaveEmployeeCommand command);
    EmployeeRef rehire(RehireEmployeeCommand command);
    void grantQualification(GrantQualificationCommand command);
    void revokeQualification(RevokeQualificationCommand command);
}
```

`CreateEmployeeCommand` 必须包含：

```text
name, phone, hiredOn, employeeNote,
qualifications: [{ workTypeCode, effectiveDate }]
```

`UpdateEmployeeCommand` 必须包含：

```text
employeeRef, name, phone, employeeNote, expectedRowVersion
```

`LeaveEmployeeCommand` 必须包含：

```text
employeeRef, effectiveDate, reason, expectedRowVersion
```

`RehireEmployeeCommand` 必须包含：

```text
employeeRef, effectiveDate, reason, expectedRowVersion
```

`GrantQualificationCommand` / `RevokeQualificationCommand` 必须包含：

```text
employeeRef, workTypeCode, effectiveDate, reason, expectedRowVersion
```

规则：

- 客户端不能提交员工编号、在职状态、内容版本和最近离职日期；即使提交也不接受；
- 员工编号由平台编号能力在创建事务内生成；
- 所有修改命令携带 `expectedRowVersion`，服务端以员工根行版本为准；
- 命令必须幂等，重复提交返回同一结果，不重复写就业记录或资格记录。

### 9.2 查询

```java
interface EmployeeQuery {
    EmployeePage search(EmployeeSearchQuery query);
    EmployeeDetailView detail(EmployeeRef employeeRef);
    EmployeeHistoryView history(EmployeeRef employeeRef);
    List<EmployeeOptionView> options(EmployeeOptionQuery query);
    EmployeeEligibilityView checkEligibility(
        EmployeeRef employeeRef, String workTypeCode, LocalDate workDate
    );
    EmployeeSnapshotView resolveSnapshot(EmployeeSnapshotRef snapshotRef);
}
```

`EmployeeSearchQuery`：

```text
keyword（姓名、员工编号或电话模糊匹配）,
employmentStatus（EMPLOYED / LEFT / ALL）,
workTypeCode（可选）,
page, size
```

`EmployeeSearchQuery` 在页面默认使用 `EMPLOYED`；查看历史时可以选择 `LEFT` 或 `ALL`。

`EmployeeOptionQuery`：

```text
employmentStatus（默认 EMPLOYED）,
workTypeCode（可选）,
keyword（可选）
```

`EmployeeOptionView` 供排班选择使用：

```text
employeeBusinessId, employeeNo, name,
employmentStatus, workTypeCodes, workTypeNames
```

`EmployeeEligibilityView`：

```text
employeeBusinessId, workTypeCode, workDate,
eligible, reasonCode
```

`reasonCode` 只使用：

- `OK`：在职且资格有效；
- `NOT_EMPLOYED`：员工已离职；
- `QUALIFICATION_MISSING`：没有有效工种资格。

员工不存在时直接返回 `EMPLOYEE_NOT_FOUND`，不作为资格结果。员工模块不返回“工种已停用”作为资格原因；工种启停由排班模块或设置模块判断。

### 9.3 快照服务

```java
interface EmployeeSnapshotService {
    EmployeeSnapshotRef acquireCurrent(EmployeeRef employeeRef);
    EmployeeSnapshotRef acquireEligibleForWork(
        EmployeeRef employeeRef, String workTypeCode, LocalDate workDate
    );
    EmployeeSnapshotView resolve(EmployeeSnapshotRef snapshotRef);
}
```

- `acquireCurrent` 冻结员工当前身份和全部有效资格，不校验具体工种；
- `acquireEligibleForWork` 先校验员工在职且具备指定工种资格，再返回快照引用；
- `resolve` 按快照引用和版本返回快照内容；
- 快照引用是其他模块唯一需要保存的员工历史依据。

### 9.4 读模型

`EmployeeListItem`：

```text
employeeBusinessId, employeeNo, name, phone,
employmentStatus, hiredOn,
workTypes（工种代码和当前名称）,
updatedAt
```

`EmployeeDetailView`：

```text
employeeBusinessId, employeeNo, name, phone, employeeNote,
employmentStatus, hiredOn, leftOn,
contentVersion, rowVersion, updatedAt,
qualifications（有效资格：工种代码、名称、生效日期）
```

`EmployeeHistoryView`：

```text
employeeBusinessId,
employmentRecords（类型、生效日期、原因、操作人、记录时间）,
qualificationRecords（工种代码、当前名称、类型、生效日期、原因、操作人、记录时间）
```

`EmployeeSnapshotView`：

```text
snapshotRef, employeeBusinessId, employeeContentVersion,
employeeNo, name, employmentStatus, hiredOn, leftOn,
qualifications（工种代码、工种名称、生效日期）
```

列表、详情和历史中的工种名称取设置模块当前名称；快照视图使用快照中冻结的名称。

### 9.5 快照所有权

- 员工快照只保存在员工模块；
- 排班、生产、工资、报表只保存 `EmployeeSnapshotRef`；
- 需要员工历史资料时调用 `EmployeeSnapshotService.resolve`，按版本解析；
- resolve 结果只用于当前读取或展示，不持久化为快照副本；
- 员工当前状态、电话和备注不写入员工快照。

## 10. 事务与并发

### 10.1 创建员工

```text
校验字段和工种静态项
→ 生成员工编号
→ 写员工根
→ 写入职记录
→ 写初始资格和授予记录
→ 写审计
→ 一次提交
```

任一步失败整体回滚。员工编号可能因回滚产生空号，但不会重复或复用。

### 10.2 编辑员工

```text
按 row_version 锁定员工根
→ 校验版本
→ 更新姓名、电话或备注
→ 姓名变化时递增 content_version
→ 更新 row_version
→ 写审计
→ 一次提交
```

### 10.3 离职

```text
按 row_version 锁定员工根
→ 校验当前状态为 EMPLOYED
→ 校验离职日期和原因
→ 更新状态、离职日期、content_version 和 row_version
→ 写离职记录
→ 写审计
→ 一次提交
```

### 10.4 返聘

```text
按 row_version 锁定员工根
→ 校验当前状态为 LEFT
→ 校验返聘日期
→ 更新状态、入职日期、清空离职日期、content_version 和 row_version
→ 写返聘记录
→ 写审计
→ 一次提交
```

### 10.5 授予或撤销资格

```text
按 row_version 锁定员工根
→ 校验员工和工种
→ 新增或更新资格行
→ 递增 content_version 和 row_version
→ 写资格记录
→ 写审计
→ 一次提交
```

同一员工的资格变更共用员工根行锁，避免两个管理员同时授予同一工种产生重复资格。

### 10.6 获取员工快照

```text
锁定员工根
→ 读取当前在状态和有效资格
→ 按 employee_business_id + content_version 查找快照
→ 已存在则校验载荷指纹并复用
→ 不存在则插入快照
→ 返回快照引用
```

- 员工查询和快照取得必须在同一事务内完成；
- 同一员工同一内容版本并发获取只能保留一条快照；
- 发现同版本载荷指纹不同返回 `EMPLOYEE_SNAPSHOT_CONFLICT`，不能覆盖旧快照；
- 快照取得失败时，引用方业务整体回滚。

### 10.7 并发与幂等

- 员工根使用 `row_version` 拒绝并发覆盖；
- 同一员工的所有变更先锁员工根，保证状态和资格变更串行；
- 资格表使用 `(employee_business_id, work_type_code)` 唯一键防止重复；
- 就业记录和资格记录只追加，不更新；
- 所有命令使用平台幂等键，重复提交不重复写记录；
- 死锁只允许重试整个幂等命令。

## 11. 历史与追溯

### 11.1 当前记录与历史事实

- 员工根、当前资格是当前记录，可以修改；
- 就业记录、资格记录是不可变事实，只追加；
- 员工快照是不可变历史，按内容版本保存；
- 排班、生产、工资、报表保存员工快照引用，不复制员工快照载荷。

### 11.2 快照取得时机

- 排班安排员工时，取得并保存员工快照引用；
- 生产任务和个人产出需要员工身份时，保存员工快照引用；
- 工资结算需要员工历史身份时，保存员工快照引用；
- 页面预览和员工列表不创建快照。

### 11.3 追溯内容

平台审计至少记录：

- 操作者、时间、动作；
- 员工业务标识和员工编号；
- 修改前后内容版本；
- 修改字段摘要；
- 离职、返聘、授予和撤销的生效日期与原因；
- 快照创建或复用。

### 11.4 不回溯

- 员工改名不影响历史就业记录和资格记录；
- 员工离职或返聘不影响历史排班和产出；
- 撤销资格不影响已经使用旧快照的生产和工资记录；
- 工种改名或停用不影响历史快照中的工种名称；
- 员工当前资料变化不重新解释历史记录。

## 12. 权限、审计与错误

### 12.1 权限

| 权限 | 能力 |
|---|---|
| `employee.read` | 查看员工列表、详情、就业记录和资格记录 |
| `employee.create` | 新建员工 |
| `employee.update` | 编辑员工姓名、电话和备注 |
| `employee.employment.manage` | 办理离职和返聘 |
| `employee.qualification.manage` | 授予和撤销工种资格 |
| `employee.snapshot.read` | 直接读取员工快照；排班、生产、工资内部调用按调用方权限鉴权 |

角色建议：

- 管理员：全部员工权限；
- 老板：`employee.read`；
- 排班：`employee.read`，内部调用员工选项和快照接口；
- 工资：通过内部快照查询读取员工历史身份，不授予员工编辑权限。

员工模块不直接读其他模块表。

### 12.2 审计

必须审计：

- 员工创建、编辑；
- 离职、返聘；
- 授予、撤销工种资格；
- 员工快照创建、复用；
- 敏感员工资料读取（电话）按平台敏感数据访问审计记录。

员工模块不建字段级变更历史表，也不提供字段级变更历史页；就业记录和资格记录用于业务追溯，平台审计记录操作和访问。

### 12.3 错误码

| 错误码 | 含义 |
|---|---|
| `EMPLOYEE_NOT_FOUND` | 员工不存在 |
| `EMPLOYEE_FIELD_INVALID` | 员工字段不合法 |
| `EMPLOYEE_NO_CONFLICT` | 员工编号生成冲突 |
| `EMPLOYEE_VERSION_CONFLICT` | 员工资料版本冲突 |
| `EMPLOYEE_NOT_EMPLOYED` | 员工当前不在职 |
| `EMPLOYEE_ALREADY_EMPLOYED` | 员工当前已在职 |
| `EMPLOYEE_EMPLOYMENT_DATE_INVALID` | 入职、离职或返聘日期不合法 |
| `EMPLOYEE_LEAVE_REASON_REQUIRED` | 离职原因为空 |
| `EMPLOYEE_WORK_TYPE_INVALID` | 工种不存在或已停用 |
| `EMPLOYEE_QUALIFICATION_NOT_FOUND` | 员工没有该工种资格 |
| `EMPLOYEE_QUALIFICATION_EXISTS` | 员工已具备该工种有效资格 |
| `EMPLOYEE_QUALIFICATION_DATE_INVALID` | 资格生效日期不合法 |
| `EMPLOYEE_SNAPSHOT_CONFLICT` | 员工快照并发冲突且无法复用 |
| `EMPLOYEE_SNAPSHOT_NOT_FOUND` | 员工快照不存在 |
| `EMPLOYEE_SNAPSHOT_INVALID` | 员工快照类型、版本或指纹不匹配 |

前端提示：

- 字段错误在输入框内联显示；
- 员工不存在提示返回列表；
- 版本冲突提示刷新后重试，不覆盖服务端资料；
- 已离职员工再次离职、已撤销资格重复撤销时提示当前状态，不显示英文错误原文；
- 快照版本不存在或不匹配提示“数据已失效，请刷新后重试”；
- 不显示内部 ID、指纹和版本号。

### 13.1 页面清单

离职、返聘、授予资格和撤销资格使用详情页内的短对话框，不单独占用页面。

### 13.2 员工列表

- 页头使用紧凑页栏，不使用大标题；
- 列：员工姓名、员工编号、联系电话、工种资格、在职状态、入职日期、更新时间；
- 工种资格以标签展示当前有效工种；
- 搜索：员工姓名、编号或电话；
- 筛选：在职状态（默认在职）、工种；
- 默认按员工编号升序，支持分页；
- 行点击进入员工详情；
- 新建按钮进入新建员工页；
- 空状态提示“暂无员工”，提供新建入口；
- 离职员工默认不显示，切换到“离职”或“全部”后可见。

### 13.3 员工详情

按“先结论、后明细”组织：

1. 页头：员工姓名、员工编号、在职状态；操作：编辑、办理离职或返聘；
2. 基本信息：联系电话、当前入职日期、当前离职日期、员工备注、更新时间；
3. 当前工种资格：有效工种标签、生效日期；操作：授予资格、撤销资格；
4. 就业记录：入职、离职、返聘的生效日期、原因、操作人和记录时间；
5. 资格记录：工种、授予/撤销、生效日期、原因、操作人和记录时间。

详情页默认只读，操作通过明确的按钮进入；不在详情页直接编辑字段。

### 13.4 新建员工

- 页面为独立全页表单，不使用抽屉；
- 字段：姓名、联系电话、入职日期、员工备注；
- 工种资格为可多选，可以不选；资格生效日期默认等于入职日期；
- 入职日期默认当天，最大为当天；
- 员工编号显示“保存后自动生成”，不允许手工填写；
- 保存前校验姓名、电话、日期和工种；
- 保存成功后进入员工详情，显示自动生成的员工编号；
- 取消返回员工列表，不保留草稿。

### 13.5 编辑员工

- 只能修改姓名、联系电话和员工备注；
- 员工编号、在职状态、入职日期、离职日期和工种资格只读展示；
- 保存携带当前 `rowVersion`；
- 版本冲突提示刷新后重试，不覆盖服务端修改；
- 取消返回详情，不保存修改。

### 13.6 离职与返聘

离职对话框：

- 生效日期默认当天，最大当天，不得早于当前入职日期；
- 离职原因必填，最多 300 字；
- 确认前提示“离职后该员工不再出现在排班候选中，历史记录保留”；
- 存在未来排班时不阻断，由排班模块提示调整。

返聘对话框：

- 生效日期默认当天，最大当天，必须晚于最近离职日期；
- 原因可空；
- 确认后员工恢复在职，沿用原编号；
- 已撤销的资格不自动恢复。

### 13.7 授予与撤销资格

授予资格对话框：

- 工种从设置模块启用的 `WORK_TYPE` 中选择；
- 只显示员工当前没有有效资格的工种；
- 生效日期默认当天，最大当天，不得早于当前入职日期；
- 确认后资格立即生效。

撤销资格对话框：

- 只对当前有效资格显示撤销入口；
- 生效日期默认当天，最大当天，不得早于该资格生效日期；
- 原因可空；
- 确认后资格变为已撤销，历史记录保留。

### 13.8 全局交互原则

- 页面使用 V3 全站设计语言和现有组件，不新造一套员工专用控件；
- 字段校验内联显示，提交失败不丢失已填内容；
- 所有时间显示为本地日期，不显示微秒时间戳；
- 不显示内部业务标识、内容版本和指纹；
- 员工颜色不是员工字段；排班需要颜色时，由排班模块按员工编号稳定生成；
- 列表和详情不出现英文枚举原文，统一使用中文状态名称。

## 14. 验收标准

### 14.1 员工主数据

- [ ] 新建员工后自动生成 `E-000001` 格式编号，且不可修改；
- [ ] 员工编号唯一，回滚可产生空号但不重复；
- [ ] 员工姓名必填，姓名可以重复；
- [ ] 员工电话可以为空，填写时格式校验生效，且不要求唯一；
- [ ] 新建员工可以不配置任何工种资格；
- [ ] 编辑员工只能修改姓名、电话和备注，不能绕过表单修改在职状态和资格；
- [ ] 员工不能硬删除。

### 14.2 在职与就业记录

- [ ] 新建员工写入一条入职记录；
- [ ] 离职必须填写原因，离职日期不晚于当天且不早于当前入职日期；
- [ ] 离职后员工状态为 `LEFT`，当前离职日期正确；
- [ ] 已离职员工不能再次离职；
- [ ] 返聘沿用原员工编号，写入返聘记录并恢复 `EMPLOYED`；
- [ ] 返聘日期必须晚于最近离职日期；
- [ ] 离职和返聘不修改历史就业记录；
- [ ] 离职不撤销工种资格，返聘后原有有效资格继续可用；
- [ ] 离职不检查未来排班，员工模块不依赖排班模块。

### 14.3 工种资格

- [ ] 授予资格时工种必须来自启用的 `WORK_TYPE` 静态项；
- [ ] 同一员工同一工种不能重复授予有效资格；
- [ ] 撤销资格保留原资格行，状态变为 `REVOKED`，历史记录可查；
- [ ] 撤销后再次授予会恢复原资格行并追加新的授予记录；
- [ ] 资格生效日期不得晚于当天；
- [ ] 工种停用后不能新授予，已有资格保留；
- [ ] 员工模块不建工种配置表，不直接维护工种静态数据；
- [ ] 资格校验只依据在职状态和资格状态，不替代设置模块判断工种启停。

### 14.4 员工快照

- [ ] 排班、生产或工资取得员工快照后只保存快照引用；
- [ ] 同一员工同一内容版本只创建一条快照；
- [ ] 同一版本并发获取复用已有快照，不覆盖；
- [ ] 同版本载荷指纹不同返回 `EMPLOYEE_SNAPSHOT_CONFLICT`；
- [ ] 员工改名、离职或撤销资格后，旧快照内容不变；
- [ ] 快照不保存电话、备注和已撤销资格；
- [ ] 快照中的工种名称冻结，之后工种改名不影响历史快照；
- [ ] 员工当前页面不读快照，历史记录通过快照解析。

### 14.5 数据与边界

- [ ] 员工模块不建小组、成员、效率标准、每日工时、排班和生产任务表；
- [ ] 员工模块不调用计算模块，不含任何工资、成本或效率公式；
- [ ] 员工不是平台登录账号，不创建、不绑定平台用户；
- [ ] 员工模块不保存员工级时薪或提成；
- [ ] 员工模块不保存身份证号、住址、银行卡、合同和附件；
- [ ] 员工模块不提供批量导入导出和员工合并；
- [ ] 员工列表、详情和历史均支持权限校验；
- [ ] 创建、编辑、离职、返聘、授予和撤销资格均写平台审计；
- [ ] 电话读取按平台敏感数据访问审计记录；
- [ ] 字段错误内联显示，不出现英文错误原文和内部标识。

## 15. 明确不采用

- 不把小组、成员、组长、小组效率和每日有效工作时间放进员工模块；
- 不把排班、日期负载、生产任务和每日产出放进员工模块；
- 不把工资、时薪、提成、考勤、请假和加班放进员工模块；
- 不做员工登录账号、角色权限和平台用户绑定；
- 不做组织架构、部门、岗位和职级；
- 不做员工级工资单价和个性化提成；
- 不做身份证号、住址、紧急联系人、银行卡、合同和附件；
- 不做员工头像和员工颜色字段；
- 不做员工删除、合并和批量导入导出；
- 不做未来生效的预约离职、预约返聘和预约资格变更；
- 不做活动占用、活动引用守卫和预留记录；
- 不做员工字段级变更历史表和历史页；
- 不做通用“基础资料模块”。

## 16. 与 V2 的主要差异

| V2 人员与小组 | V3 员工模块 |
|---|---|
| 员工和小组在同一个模块 | 员工单独成模块，小组和排班拆出 |
| 员工、就业事实、工种表、资格、小组、效率、每日工时、活动占用 | 员工、就业记录、当前资格、资格记录、员工快照 |

| 小组有成员关系和效率标准 | 不包含小组和效率 |
| 人员变更受活动占用守卫阻止 | 员工模块不检查排班和活动占用，由排班模块负责 |

## 17. 外部依赖

### 17.1 平台能力

- 员工编号：`nextNumber("EMPLOYEE", "E-", 6)` 生成 `E-000001`；唯一、不可修改、不可复用；
- 权限：`employee.read`、`employee.create`、`employee.update`、`employee.employment.manage`、`employee.qualification.manage`、`employee.snapshot.read`；
- 审计：员工创建、编辑、离职、返聘、授予、撤销和快照操作；
- 敏感数据访问审计：电话读取；
- 幂等：所有命令使用平台幂等键；
- 平台不替员工模块管理在职状态和工种资格。

### 17.2 设置模块

员工模块依赖通用静态数据查询：

```java
interface StaticDataQuery {
    List<StaticDataItemView> list(String typeCode, boolean includeInactive);
    StaticDataItemView get(String typeCode, String itemCode);
}
```

- 工种类型代码为 `WORK_TYPE`；
- 授予资格时校验工种存在且启用；
- 当前页面显示工种当前名称；
- 快照取得时把工种名称冻结到快照；
- 员工模块不维护、不新增、不删除工种静态项；
- 静态数据的权限、审计和停用规则由设置模块负责；已被资格引用的工种只应停用，不物理删除。

### 17.3 排班与生产模块

排班和生产模块通过员工公开接口获取候选员工和员工快照：

```java
List<EmployeeOptionView> options(EmployeeOptionQuery query);
EmployeeEligibilityView checkEligibility(
    EmployeeRef employeeRef, String workTypeCode, LocalDate workDate
);
EmployeeSnapshotRef acquireEligibleForWork(
    EmployeeRef employeeRef, String workTypeCode, LocalDate workDate
);
EmployeeSnapshotView resolveSnapshot(EmployeeSnapshotRef snapshotRef);
```

要求：

- 排班只选择在职且具备对应工种资格的员工；
- `acquireEligibleForWork` 在员工已离职时返回 `EMPLOYEE_NOT_EMPLOYED`，在缺少对应工种资格时返回 `EMPLOYEE_QUALIFICATION_NOT_FOUND`；
- 排班和生产只保存员工快照引用，不复制员工姓名和资格；
- 员工离职或撤销资格后，已有排班和生产继续使用原快照；
- 排班模块负责在调整排班时提示员工已离职或资格已撤销；
- 员工模块不建立排班、生产任务和活动占用。

### 17.4 工资模块

- 工资模块保存员工快照引用，按版本解析员工编号、姓名和资格；
- 工资模块不直接读员工表；
- 员工模块不保存工资、时薪、提成、考勤和结算数据；
- 员工离职和返聘历史通过就业记录和快照追溯。

### 17.5 报表模块

- 报表通过员工公开查询或后续报表投影读取员工维度和工种维度；
- 报表不直接读员工表；
- 员工模块不提供报表专用汇总表。

## 18. 已确认口径

1. 员工模块只负责员工档案和工种资格；小组、排班、每日产出和工资独立。
2. 员工字段只保留姓名、电话、工种资格、入职日期、在职状态和备注；身份证号、住址、紧急联系人、时薪和工资标准不保存。
3. 工种由设置模块静态数据维护，员工模块不建工种配置表。
4. 保留每次入职、离职和返聘记录，返聘沿用原员工编号。
5. 员工离职或撤销资格不检查未来排班，由排班模块负责提示或调整。
6. 员工不是平台登录账号，不创建、不绑定平台用户。
7. 员工编号格式为 `E-000001`，自动生成、不可修改、不可复用。
8. 员工模块不建小组、效率标准、每日工时和活动占用。
9. 员工模块没有业务计算，不依赖计算模块。
10. 员工快照归员工模块所有，其他模块只保存 `EmployeeSnapshotRef`。
