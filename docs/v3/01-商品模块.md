# V3 商品模块

> 模块代码：`product`  
> 文档版本：V3.0  
> 编写日期：2026-10-29  
> 状态：V3 商品模块评审稿；评审通过前不进入页面实现

本文是 V3 商品模块的唯一需求与设计依据。V2 的商品规则可作为业务参考，但页面结构、字段组织和表冗余按本文重新收敛。

## 摘要

- 一个商品就是一张表单：主图、基本信息、三道工序、基础材料、其他成本。
- 三道工序都用星级带出标准分钟；人工成本 = 基本人工成本 + 提成，基本人工成本由计算模块按岗位时薪计算，提成按“元/件”直接维护。
- 基本人工成本和提成分别形成 `LABOR` / `COMMISSION` 成本行，但提成计入人工成本合计。
- 捏毛装袋的袋子与装饰品合成综合材料小计；缝边剪袋的综合材料成本手工录入。
- 商品模块不实现任何公式：产能、材料小计、人工成本、成本、利润全部调用计算模块，商品模块只保存结果。
- 星级由全局静态数据统一管理，使用通用字段和 attributes；胶水/色浆由全局物料主数据管理；岗位时薪由全局模块按岗位维护，计算模块读取。
- 每个商品必须有主图；商品只保存平台文件引用，列表、详情和快照都使用这张主图。
- 每个商品自动生成一个标准方案；自定义方案只改允许调整的售价、目标工序、供料方和部分材料费。
- 胶水/色浆来源只在方案上；袋子/装饰品在商品上有默认来源，方案可覆盖。
- 修改商品会生成新的内容版本并重算方案；历史订单只认快照，不回头改。

### 评审重点

1. 每道工序人工成本 = 基本人工成本 + 提成；基本人工成本由计算模块按岗位时薪计算，提成是商品直接维护的“元/件”金额，两项分别形成成本行。
2. 商品选择胶水、色浆物料；物料提供名称、规格、单价（元/克）和损耗率；商品只能冻结值，不能覆盖；供料方放在方案。
3. 袋子成本、装饰品单价在商品上维护；综合材料小计由计算模块返回；袋子/装饰来源在商品上有默认值，方案可覆盖。
4. 标准方案固定缝边剪袋；自定义方案可改目标工序、售价、供料方和部分材料费。
5. 表结构收敛为：三类星级放全局静态数据、三张工序表、方案只存覆盖值，不再复制商品继承字段。
6. 商品/方案修改递增内容版本，并调用计算模块重算预算；历史订单、生产计划和生产记录只使用快照。
7. 商品模块不实现任何公式，产能、材料小计、人工成本、提成、成本、利润全部由计算模块提供方法。
8. 每个商品必须有主图；主图存平台文件引用，列表、详情和快照共用。
9. 基本人工成本和提成都作为预算输入传给计算模块，计算模块分别返回 `LABOR` 和 `COMMISSION` 成本行；`labor_unit_cost` 是两者合计，`commission_unit_cost` 是其中提成拆分。
10. 星级放入全局静态数据（typeCode/itemCode/attributes）；胶水/色浆放入全局物料主数据；岗位时薪由全局模块按岗位维护。

## 1. 模块说明

商品模块维护“商品现在是什么、三道工序怎么做、每件成本是多少、以什么价格和供料方式成交”。

它是订单、生产排班、工资与成本、报表的标准来源，但不是库存模块：

- 不记录材料采购、领用和库存；
- 不记录制品生产数量和在制状态；
- 不记录订单成交事实；
- 不记录工资发放。

商品模块自己拥有并保存商品/方案快照；订单、生产、工资等模块只保存快照引用，读取时调用商品模块的版本化查询接口，不复制快照载荷，也不直接读商品表。

商品模块不拥有计算公式、文件存储和静态参数：

- 单日产能、袋子与装饰品综合材料、人工成本、胶水/色浆成本、工序成本、总成本、利润和利润率全部由 `calculation` 模块提供计算方法和版本；
- 商品模块只校验输入、组装计算输入、保存计算结果，不在本模块内写公式、常量或舍入逻辑；
- 前端也不自行计算，成本、产能和预览值都由服务端返回；
- 主图上传、正式化、引用和读取由 `platform` 文件能力负责，商品模块只保存文件引用；
- 星级由全局静态数据统一管理，全局表只使用通用字段和 attributes；胶水/色浆由全局物料主数据管理；商品模块只读取并冻结选择值，不建专用字段配置表；

V3 把商品拆成三层：

```text
商品当前定义
├─ 基本信息
├─ 三道工序参数
├─ 基础材料参数
└─ 其他单件成本

成交方案
├─ 标准方案（系统生成，随商品）
└─ 自定义方案（按客户/工艺调整）

历史快照
└─ 订单确认、生产安排时冻结的商品与方案版本
```

商品回答“怎么做、成本多少”；方案回答“这一单按什么工艺范围、什么供料方式、卖多少钱”；快照回答“历史订单当时按什么标准执行”。

## 2. 用户与使用场景

### 2.1 用户

| 用户 | 关心什么 | 在商品模块做什么 |
|---|---|---|
| 管理员 | 商品资料是否准确、成本和售价是否合理 | 新建/编辑商品，建立自定义方案；星级和默认值来自全局静态数据 |
| 老板 | 每件成本、售价、预计利润 | 查看商品成本与方案预算，判断接单价格 |
| 生产 | 每道工序标准分钟、单日产能 | 通过商品快照取得工时与产能，不直接编辑商品 |
| 工资/成本 | 每道工序人工成本、提成、材料标准 | 通过商品快照取得计件、人工和成本依据，不直接编辑商品 |

### 2.2 现状与目标

管理员现在用 Excel 记录商品、订单、兼职每日产出和排班。商品表通常包含：

- 名称、编号、克重、售价、模具数量、每日批次；
- 三道工序各自的星级、人工成本、提成、材料费；
- 其他单件成本；
- 针对不同客户或工艺的报价方案。

V3 要减少重复录入：星级带出标准分钟，袋子与装饰品自动形成材料小计，模具数量与批次自动形成单日产能，保存后自动形成标准方案和预算。

### 2.3 核心任务

1. 新建一个商品，一次录完基本信息和三道工序；
2. 修改商品价格或工序参数，系统同步标准方案并重算预算；
3. 为特殊客户建立自定义方案，只改允许调整的部分；
4. 停用不再生产的商品，但历史订单仍能按旧快照执行；
5. 使用全局静态数据中的星级和全局物料主数据中的胶水/色浆。

## 4. 业务概念

| 术语 | 定义 |
|---|---|
| 商品 | 一个可生产、可报价的制品定义，包含主图、基本信息、三道工序和其他单件成本 |
| 商品主图 | 每个商品唯一的一张展示图片，用于商品列表、商品详情和订单识别；只保存平台文件引用，不保存二进制 |
| 商品当前定义 | 商品现在可编辑的完整内容，修改后影响后续新方案和新订单 |
| 星级 | 某道工序的静态难度档位；全局静态数据只保存通用记录，商品模块用 attributes 解释标准分钟；商品只选择和冻结 |
| 标准分钟 | 星级带出的单件标准作业时间，用于排产和工时参考 |
| 提成 | 该道工序每完成一件支付给作业人员的金额；由商品直接维护，不由标准分钟计算 |
| 人工成本 | 基本人工成本 + 提成；基本人工由计算模块按岗位时薪计算 |
| 岗位时薪 | 制作、捏毛装袋、缝边剪袋各自的每小时人工单价，由全局模块按岗位维护，计算模块读取；本模块不维护该值 |
| 标准方案 | 商品创建时自动生成的方案，目标工序固定为缝边剪袋，售价保存在标准方案自己的 `sale_price` |
| 自定义方案 | 管理员为特定客户、工艺范围或供料方式建立的方案 |
| 目标工序 | 方案覆盖的最后一道生产工序，只能为制作、捏毛装袋或缝边剪袋 |
| 供料方 | 某类材料由工作室提供还是客户提供 |
| 综合材料成本 | 捏毛装袋中袋子成本与装饰品单价之和；缝边剪袋中手工录入的合并材料成本 |
| 预算 | 由计算模块按方案目标工序和供料方计算的单件成本、收入、利润和利润率 |
| 快照 | 由拥有模块保存的不可变版本；其他模块只保存引用，通过拥有模块的版本化查询读取 |
| 内容版本 | 商品或方案正式内容每次变化后递增的版本号 |
| 乐观版本 | 防止并发覆盖的 `row_version`，与内容版本用途不同 |

## 5. 字段定义

### 5.1 基本信息

| 字段 | 必填 | 类型/精度 | 规则 |
|---|---|---|---|
| 商品编号 | 系统生成 | `VARCHAR(32)` | 格式 `P-000001`，创建后不可修改、不可复用 |
| 商品名称 | 是 | `VARCHAR(80)` | 可重名，以商品编号区分 |
| 商品主图 | 是 | 文件引用 `VARCHAR(64)` | 唯一一张；保存平台正式文件业务标识；创建时必须提供，替换时保留历史快照引用 |
| 主图文件引用 | 系统 | `VARCHAR(64)` | 平台文件引用业务标识；替换主图时用于释放旧引用 |
| 商品说明 | 否 | `VARCHAR(500)` | 不参与任何计算 |
| 标准克重 | 是 | `DECIMAL(19,4)` 克 | 大于 0；用于胶水和色浆成本 |
| 模具数量 | 是 | `INT` | 大于 0 |
| 每次批次 | 是 | `INT` | 大于 0；含义为每个模具每天可生产的批次数 |
| 状态 | 是 | `ACTIVE / INACTIVE` | 新建默认 `ACTIVE` |

商品本身不保存售价。售价只保存在方案上：标准方案有自己的 `sale_price`，自定义方案各自维护售价。商品创建/编辑时填写的“标准方案售价”作为标准方案字段提交，不写入商品根表。

单日最大产能由计算模块计算，商品模块只保存结果，不由用户录入。

### 5.2 基础材料

| 字段 | 必填 | 类型/精度 | 规则 |
|---|---|---|---|
| 胶水物料 | 是 | `VARCHAR(64)` | 从全局物料主数据选择 `GLUE` 物料；停用物料不能新建引用 |
| 胶水物料名称 | 系统冻结 | `VARCHAR(100)` | 保存时从物料复制；页面只读 |
| 胶水物料规格 | 系统冻结 | `VARCHAR(200)` | 保存时从物料复制；可为空 |
| 色浆物料 | 是 | `VARCHAR(64)` | 从全局物料主数据选择 `COLOR_PASTE` 物料；停用物料不能新建引用 |
| 色浆物料名称 | 系统冻结 | `VARCHAR(100)` | 保存时从物料复制；页面只读 |
| 色浆物料规格 | 系统冻结 | `VARCHAR(200)` | 保存时从物料复制；可为空 |
| 胶水损耗率 | 系统冻结 | `DECIMAL(12,8)` | 保存时从所选胶水物料复制；范围 `[0, 1)` |
| 胶水单价 | 系统冻结 | `DECIMAL(19,4)` 元/克 | 保存时从所选胶水物料复制；大于 0 |
| 色浆损耗率 | 系统冻结 | `DECIMAL(12,8)` | 保存时从所选色浆物料复制；范围 `[0, 1)` |
| 色浆单价 | 系统冻结 | `DECIMAL(19,4)` 元/克 | 保存时从所选色浆物料复制；大于 0 |

商品只选择胶水和色浆物料，不能覆盖物料的单价和损耗率。保存商品时把物料的名称、规格、单价和损耗率冻结到商品快照；之后物料调价不影响已保存商品和快照。

胶水与色浆的供料方不在商品上维护，放在方案上。

### 5.3 制作工序

| 字段 | 必填 | 类型/精度 | 规则 |
|---|---|---|---|
| 制作星级 | 是 | `VARCHAR(32)` | 从全局静态数据 `PRODUCT_MAKING_STAR` 选择；保存时同时写入名称和 `attributes.standardMinutes` |
| 制作标准分钟 | 系统写入 | `INT` | 由所选星级带出，大于 0；页面只读 |
| 制作基本人工成本 | 计算模块返回 | `DECIMAL(19,4)` 元/件 | 由计算模块按制作岗位时薪计算；页面只读 |
| 制作提成 | 是 | `DECIMAL(19,4)` 元/件 | 大于等于 0；单独成本行，但计入人工成本合计 |
| 制作其他材料费 | 是 | `DECIMAL(19,4)` 元/件 | 大于等于 0；胶水、色浆之外的材料费 |

制作是唯一完成“从 0 到 1 形成物理制品”的工序。返工只做修补，不重复创造制品数量。

### 5.4 捏毛装袋工序

| 字段 | 必填 | 类型/精度 | 规则 |
|---|---|---|---|
| 捏毛装袋星级 | 是 | `VARCHAR(32)` | 从全局静态数据 `PRODUCT_BAGGING_STAR` 选择 |
| 捏毛装袋标准分钟 | 系统写入 | `INT` | 由星级带出，大于 0；页面只读 |
| 捏毛装袋基本人工成本 | 计算模块返回 | `DECIMAL(19,4)` 元/件 | 由计算模块按捏毛装袋岗位时薪计算；页面只读 |
| 捏毛装袋提成 | 是 | `DECIMAL(19,4)` 元/件 | 大于等于 0；单独成本行，但计入人工成本合计 |
| 袋子成本 | 是 | `DECIMAL(19,4)` 元/件 | 大于等于 0 |
| 袋子来源 | 是 | `STUDIO / CUSTOMER` | 默认 `STUDIO`；作为新建方案时的默认供料方 |
| 装饰品单价 | 是 | `DECIMAL(19,4)` 元/件 | 大于等于 0 |
| 装饰品来源 | 是 | `STUDIO / CUSTOMER` | 默认 `STUDIO`；作为新建方案时的默认供料方 |
| 综合材料成本 | 计算模块返回 | `DECIMAL(19,4)` 元/件 | 由计算模块根据袋子成本和装饰品单价计算；页面只读，不单独录入，商品模块不自行计算 |
| 捏毛装袋其他费用 | 是 | `DECIMAL(19,4)` 元/件 | 大于等于 0 |

袋子来源和装饰品来源是商品的默认供料方：

- 标准方案直接使用商品默认值；
- 新建自定义方案时带出默认值，可以修改；
- 已有自定义方案保留自己的供料方，不随商品默认值变化。

### 5.5 缝边剪袋工序

| 字段 | 必填 | 类型/精度 | 规则 |
|---|---|---|---|
| 缝边剪袋星级 | 是 | `VARCHAR(32)` | 从全局静态数据 `PRODUCT_SEAM_CUTTING_STAR` 选择 |
| 缝边剪袋标准分钟 | 系统写入 | `INT` | 由星级带出，大于 0；页面只读 |
| 缝边剪袋基本人工成本 | 计算模块返回 | `DECIMAL(19,4)` 元/件 | 由计算模块按缝边剪袋岗位时薪计算；页面只读 |
| 缝边剪袋提成 | 是 | `DECIMAL(19,4)` 元/件 | 大于等于 0；单独成本行，但计入人工成本合计 |
| 综合材料成本 | 是 | `DECIMAL(19,4)` 元/件 | 大于等于 0；缝线等材料合并录入 |
| 缝边剪袋其他费用 | 是 | `DECIMAL(19,4)` 元/件 | 大于等于 0 |

缝边剪袋没有客户供料来源字段。

### 5.6 其他单件成本

以下字段均为已经分摊到每件商品的金额，直接录入，不再二次分摊：

| 字段 | 说明 |
|---|---|
| 其他任务人工费 | 打包、发货等非三道生产工序的单件人工费，不是制作提成 |
| 运输包装费 | 外层运输包装等单件费用 |
| 日常杂费 | 已分摊的单件金额 |
| 房租水电费 | 已分摊的单件金额 |
| 模具单件摊销费 | 已计算完成的单件摊销金额 |
| 其他费用 | 不能归入以上项目的单件金额 |

其他任务人工费（`other_task_labor_cost`）按 `LABOR` 成本性质计入人工成本合计，不归入 `EXTRA_COST`；其余五项额外费用按 `EXTRA_COST`。

### 5.7 计算模块方法

商品模块不定义任何公式，也不在字段说明里写算式。需要计算模块提供的方法、输入和输出统一见第 7.7 节；商品模块只负责传入输入、保存返回结果和展示。

## 6. 业务规则

### R1 商品是唯一的当前定义

- 一个商品只有一套当前定义；
- 商品编号全局唯一、自动生成、不可修改；
- 商品不保存服务端草稿，用户一次提交完整商品；
- 商品不硬删除，只停用。

### R2 星级是静态数据，选择时冻结名称和分钟

- 三类星级由全局静态数据统一维护；商品模块定义类型代码和 attributes 结构（`standardMinutes`），全局模块不解释这些属性；商品模块只读取，不提供维护入口；
- 星级代码创建后不可修改；名称和标准分钟可以修改；
- 新建或编辑商品时，选择星级后把当时的星级名称和标准分钟写入商品；
- 编辑商品时，如果星级代码没有变化，保留商品上已保存的名称和分钟，不重新读取静态数据；
- 只有更换星级代码时，才重新读取当前星级并更新名称和分钟；
- 之后修改星级静态数据，不回溯已有商品；
- 商品更换星级时，更新商品上的星级名称和标准分钟，并重算预算；
- 已停用的星级不能被新选择，但已有商品可以保留；编辑时保持原星级代码不变允许保存，改选其他星级时只能选启用项；
- 新建商品时，每道工序至少要有一个启用星级可供选择；没有可选星级时不能新建商品；

### R3 人工成本分基本人工和提成

- 每道工序人工成本 = 基本人工成本 + 提成；
- 基本人工成本由计算模块按该工序岗位时薪和标准分钟计算，商品上只读；
- 提成是商品上直接维护的“元/件”金额，不随星级或标准分钟自动变化；
- 基本人工成本和提成分别生成 `LABOR` 和 `COMMISSION` 成本行，但提成计入人工成本合计；
- 方案继承商品的基本人工成本和提成，只读；
- 需要重算基本人工成本时，由计算模块按该工序岗位时薪计算；岗位时薪未配置时计算模块返回错误，商品保存回滚；
- 新建商品时，商品模块调用计算模块得到基本人工成本；
- 编辑商品时，星级或标准分钟变化则调用计算模块重算该工序基本人工成本；未变化则沿用已保存值；
- 岗位时薪变化不回溯已有商品，商品重新保存且星级/分钟变化时才采用新岗位时薪。

### R4 袋子与装饰品综合材料成本

- 综合材料成本由计算模块根据袋子成本和装饰品单价计算并返回；
- 商品模块只保存结果，不自行计算；
- 小计只读，不能单独录入，避免与袋子/装饰品重复；
- 缝边剪袋的综合材料成本是独立录入的合并金额，不与袋子/装饰品合并。

### R5 产能由计算模块提供

- 商品模块传入模具数量和每次批次；
- 单日最大产能由计算模块返回，商品模块保存结果，不能手工覆盖；
- 商品模块和数据库都不实现产能计算；
- 生产安排读取安排当时的商品产能，并把商品内容版本固化到产能占用记录中。

### R6 基础材料成本来自预算计算

- 商品模块把标准克重、物料冻结的胶水/色浆损耗率和单价、供料方传入 `calculateProductBudget`；
- 基础材料成本由计算模块返回的成本行提供；
- 商品模块不实现材料用量或材料成本计算；
- 供料方由方案决定。

### R7 标准方案

每个商品创建时自动生成一个标准方案：

- `scheme_type = SYSTEM_STANDARD`；
- 名称固定为“标准方案”；
- 目标工序固定为 `SEAM_CUTTING`；
- 标准方案售价由商品创建/编辑时填写的“标准方案售价”写入自己的 `sale_price`；商品根表不保存售价；
- 胶水来源、色浆来源固定为 `STUDIO`；
- 袋子来源、装饰品来源取商品默认值；
- 三道工序的标准分钟、基本人工成本和提成继承商品；
- 其他单件成本继承商品；
- 用户不能独立编辑、删除标准方案；

商品修改时，标准方案自动同步并重算预算。

### R8 自定义方案

- `scheme_type = CUSTOM`；
- 新建自定义方案时，目标工序默认缝边剪袋，售价默认带出标准方案售价，可修改；
- 可修改：名称、目标工序、售价、胶水来源、色浆来源、袋子来源、装饰品来源；
- 可覆盖：制作其他材料费、袋子成本、装饰品单价、捏毛装袋其他费用、缝边剪袋综合材料成本、缝边剪袋其他费用；
- 不可修改：商品克重、三类星级、标准分钟、三类人工成本、三类提成、胶水/色浆物料及冻结损耗率和单价、六项其他单件成本；
- 自定义方案创建时，袋子/装饰品来源带出商品默认值，胶水/色浆来源默认工作室；
- 自定义方案创建时，把可覆盖字段的当前商品值写入方案；此后商品修改不自动覆盖这些值，需要时在方案中手工调整；
- 商品后续修改继承字段时，自定义方案同步继承值并重算预算，但保留自己的可覆盖字段和供料方；
- 自定义方案不单独设置启停状态，跟随商品是否可引用；

### R9 目标工序是方案输入

- 目标工序是方案字段，取值为制作、捏毛装袋或缝边剪袋；
- 标准方案固定缝边剪袋，自定义方案可以选择；
- 目标工序如何影响预算范围由计算模块负责，商品模块不定义成本范围，也不判断哪些成本项应纳入。

### R10 商品修改不影响历史

- 商品或方案修改只影响后续新订单和新安排；
- 已确认订单、已安排生产、已产生工资/成本的记录继续使用当时取得的快照；
- 商品停用或方案修改不影响历史快照解析；
- 订单调整数量、价格或收货信息时沿用原依据；供料或其他生产定义变化时按订单继任规则取得新依据。

### R11 快照由拥有模块保存，其他模块只保存引用

- 商品快照和方案快照由商品模块拥有，载荷只保存在 `product_snapshots` 和 `product_scheme_snapshots`；
- 订单、生产、工资、成本等模块只保存快照引用，不复制快照 JSON，也不直接读取商品模块的表；
- 快照引用统一为：

```text
ownerModule + snapshotType + snapshotBusinessId + snapshotVersion
```

- 商品模块的快照引用取值为：
  - `ownerModule = product`；
  - `snapshotType = PRODUCT` 或 `PRODUCT_SCHEME`；
  - `snapshotBusinessId` 为快照业务标识；
  - `snapshotVersion` 等于商品或方案的内容版本；
- 其他模块读取商品/方案快照时，必须调用商品模块的版本化查询接口，按引用中的版本解析；
- 版本不存在、引用类型不匹配或内容指纹不一致时明确失败，不能回退到商品当前值；
- 快照在订单确认、生产安排等调用方事务中，通过商品模块的参与端口创建或复用；创建失败时调用方事务回滚；
- 同一商品/方案版本已存在快照时复用，不重复创建；
- 快照不可修改、不可删除；
- 这条规则适用于所有模块：订单、生产等模块也各自拥有自己事实的快照，商品模块不保存它们的快照，其他模块也不保存商品快照。

### R12 预算必须与当前内容一致

- 商品或方案正式修改时，在同一事务内重算预算；
- 计算失败则整个修改回滚，不能留下“内容已更新但预算仍旧”的状态；
- 预算结果保存输入指纹、公式版本和舍入版本；
- 页面预览只用于录入辅助，不作为正式结果；正式结果以保存后服务端计算为准。

### R13 停用不等于删除

- 停用商品只禁止新订单、新方案和新生产安排引用；
- 停用商品仍允许编辑；编辑只影响后续新方案和新订单，不回溯历史快照；
- 已有方案、历史订单和历史任务不受影响；
- 重新启用后恢复可引用；
- 商品编号不复用。

### R14 商品模块不读取其他模块的表

- 商品模块不访问客户、订单、生产、工资、财务表；
- 下游通过公开查询或快照引用取得商品标准；
- 跨模块事务由命令所有者开启，商品模块只提供参与端口。

### R15 所有计算由计算模块提供

- 商品模块不实现业务计算用的公式、费率常量或舍入逻辑；字段取值范围校验不属于计算，仍由商品模块执行；
- 单日产能、袋子与装饰品小计、三类人工成本、胶水/色浆成本、工序成本、总成本、利润和利润率，全部调用 `calculation` 模块的公开方法；
- 商品模块负责校验输入、组装计算输入、保存计算结果和返回读模型；
- 预算计算返回公式版本、舍入版本和输入指纹，商品模块原样保存；
- 前端不自行计算成本、产能或预览值，统一调用服务端预览接口；
- 计算失败时商品/方案保存整体回滚，不能保存未计算或部分计算的结果。

### R16 商品主图

- 每个商品必须有且只有一张主图；
- 主图使用 `platform` 文件能力：先上传为临时文件并预览；保存商品时在商品事务内正式化并建立引用；
- 商品当前主图引用使用 `ownerType = PRODUCT`、`purposeCode = MAIN_IMAGE`；快照主图引用使用 `ownerType = PRODUCT_SNAPSHOT`、`purposeCode = MAIN_IMAGE`；
- 商品表只保存主图文件业务标识，不保存图片二进制、存储路径或缩略图；
- 商品列表、商品详情、订单商品行和商品快照都使用这张主图；
- 替换主图时建立新文件引用，释放商品当前旧引用；快照引用不释放，历史快照继续使用旧主图；
- 主图变化属于商品正式内容变化，递增商品内容版本和方案内容版本；后续取得快照时生成新版本，不修改已有快照；
- 商品停用或编辑其他字段时不清空主图；
- 主图支持 JPEG、PNG、WebP，具体大小限制由平台文件策略决定；页面按容器裁切显示，不修改原图；
- 本期不做多图、图库和图片排序。

## 7. 方案与预算

### 7.1 方案类型

| 类型 | 生成方式 | 目标工序 | 售价 | 可编辑 |
|---|---|---|---|---|
| 标准方案 | 商品创建时自动生成 | 固定缝边剪袋 | 标准方案自己的 `sale_price` | 否 |
| 自定义方案 | 管理员创建 | 可选三道之一 | 单独填写 | 允许字段内可编辑 |

### 7.2 方案级字段

| 字段 | 必填 | 规则 |
|---|---|---|
| 方案名称 | 是 | 标准方案固定“标准方案”；自定义方案由管理员填写 |
| 方案类型 | 系统 | `SYSTEM_STANDARD / CUSTOM` |
| 目标工序 | 是 | `MAKING / BAGGING / SEAM_CUTTING`；标准方案固定 `SEAM_CUTTING` |
| 售价 | 是 | 大于等于 0；每个方案独立保存；标准方案由商品创建/编辑时维护，自定义方案可单独定价 |
| 胶水来源 | 是 | `STUDIO / CUSTOMER`；标准方案固定工作室 |
| 色浆来源 | 是 | `STUDIO / CUSTOMER`；标准方案固定工作室 |
| 袋子来源 | 是 | `STUDIO / CUSTOMER`；标准方案取商品默认值 |
| 装饰品来源 | 是 | `STUDIO / CUSTOMER`；标准方案取商品默认值 |

### 7.3 继承与覆盖

自定义方案不复制商品的继承字段，读取时按以下规则组装：

方案有效值由三部分组成：商品继承值、方案级字段（目标工序、售价、四项供料方）和方案覆盖值（制作其他材料费、袋子成本、装饰品单价、捏毛装袋其他费用、缝边剪袋综合材料成本、缝边剪袋其他费用）。

- 继承字段在页面上集中展示为“来自商品”，只读；
- 覆盖字段在“本方案可调整”区域编辑；
- 标准方案没有覆盖值，全部取商品和固定规则；
- 方案读模型同时返回继承值、覆盖值和有效值，前端据此标记只读，不自行推断。

### 7.4 预算计算依赖

商品模块不计算预算，也不定义成本范围、承担方拆分、利润或利润率。它只把以下输入传给计算模块：

- 目标工序；
- 标准克重、胶水/色浆损耗率、胶水/色浆单价；
- 基本人工成本、提成；
- 袋子成本、装饰品单价、缝边剪袋综合材料成本、工序其他费用；
- 六项其他单件成本；
- 四项供料方；
- 售价。

需要计算模块提供 `calculateProductBudget`，返回预算汇总、成本行、人工成本合计（含提成）、提成合计、预计利润、利润率和版本信息。方法契约见第 7.7 节。

预算输出字段（商品模块只保存和展示）：

| 输出 |
|---|
| 全资源单件成本 |
| 工作室承担单件成本 |
| 客户供料标准价值 |
| 人工成本合计（含提成） |
| 其中：提成合计 |
| 预计单件收入 |
| 预计单件利润 |
| 预计利润率 |
| 分项成本明细 |

成本范围、供料方如何影响承担成本、利润和利润率的口径，全部由计算模块文档定义，商品模块不重复描述。

### 7.5 精度与舍入

计算结果的小数精度、舍入和版本由 `calculation` 模块负责；商品模块和前端不自行处理，按计算模块返回的结果保存。

### 7.6 成本行

- 预算成本行由计算模块返回，商品模块按 `product_budget_result_lines` 原样保存，不解释或重算金额；
- 成本行必须分别保留基本人工成本和提成（`LABOR` / `COMMISSION`），不得合并；提成计入人工成本合计，`commission_unit_cost` 只是其中提成拆分；
- 成本项代码、成本性质、承担方、数量和单价的定义由计算模块文档负责。

### 7.7 计算模块接口

商品模块只依赖 `calculation` 模块的公开接口，不直接依赖计算公式实现：

```java
interface ProductCalculation {
    DailyCapacityResult calculateDailyCapacity(DailyCapacityInput input);

    BaggingMaterialSubtotal calculateBaggingMaterialSubtotal(BaggingMaterialInput input);

    ProcessLaborCost calculateProcessLaborCost(ProcessLaborInput input);

    ProductBudgetResult calculateProductBudget(ProductBudgetInput input);
}
```

商品模块需要计算模块提供以下方法；商品模块只调用方法，不关心内部公式。

| 方法 | 输入 | 输出 |
|---|---|---|
| `calculateDailyCapacity` | 模具数量、每次批次 | 单日产能 |
| `calculateBaggingMaterialSubtotal` | 袋子成本、装饰品单价 | 综合材料小计 |
| `calculateProcessLaborCost` | 工序、标准分钟、业务日期、岗位时薪（hourlyRate）、岗位时薪版本（hourlyRateVersion）；商品模块读取后传入 | 该工序基本人工成本 |
| `calculateProductBudget` | 目标工序；标准克重、胶水/色浆损耗率、胶水/色浆单价；基本人工成本、提成；袋子成本、装饰品单价、缝边剪袋综合材料成本、工序其他费用；六项其他单件成本；四项供料方；售价 | 预算汇总、成本行、人工成本合计（含提成）、提成合计、预计利润、利润率、公式版本、舍入版本、输入指纹 |

- 商品模块不得自行实现上述任何方法，也不得用数据库生成列替代；
- 商品模块只传入输入、保存输出；
- 计算模块的实现可以复用现有 `CapacityCalculator`、`ProductBudgetCalculator`，但预算输入必须扩展为基本人工成本和提成两套字段。

## 8. 状态设计

### 8.1 商品状态

| 当前 | 事件 | 下一状态 | 条件 |
|---|---|---|---|
| `ACTIVE` | 停用 | `INACTIVE` | 操作者有停用权限 |
| `INACTIVE` | 启用 | `ACTIVE` | 操作者有启用权限 |

- 新建默认 `ACTIVE`；
- 停用不删除任何数据；
- 启停只改变状态，不递增内容版本，也不创建快照；
- 停用商品不能被新订单、新方案、新生产安排引用；
- 停用商品仍允许编辑；
- 商品启用状态控制整个商品，包括其全部标准方案和自定义方案；
- 历史快照不受影响。

### 8.2 方案没有独立状态

方案不单独设置启停状态，商品启用状态是唯一开关。

- 商品为 `ACTIVE`：全部方案可以被新订单引用；
- 商品为 `INACTIVE`：全部方案都不能建立新引用，包括原本存在的自定义方案；
- 已有自定义方案可以查看和编辑；标准方案只读；
- 商品重新启用后，全部方案恢复可引用；
- 历史订单继续使用原快照；
- 标准方案仍不能由用户编辑或删除；
- 方案不硬删除。

### 8.3 星级状态（全局静态数据维护）

星级选项作为通用静态数据记录，由全局模块维护 `status`、`sortOrder`、`name` 和 `attributes`；商品模块只读取状态。

- 商品只能新选择 `ACTIVE` 星级；
- 已停用星级不能被新选择，但已有商品保留已写入的名称和分钟；
- 修改星级名称或分钟只影响后续选择；
- 商品模块不提供星级状态变更入口，也不校验“最后一个启用星级”。

### 8.4 预算与快照

- 预算结果没有业务状态，始终对应当前方案内容版本；
- 快照没有业务状态，不可修改，只能产生新版本。

```text
name, specification, unitPrice, lossRate, status
```

- 商品只保存 `glue_material_business_id`、`color_paste_material_business_id`；
- 商品保存时从物料复制名称、规格、单价和损耗率到商品快照；
- 商品当前保存冻结后的 `glue_loss_rate`、`glue_unit_price`、`color_paste_loss_rate`、`color_paste_unit_price`，计算时不再读取物料当前值；
- 物料调价或改名不影响已保存商品和快照；
- 商品模块通过 `GlobalMaterialQuery` 读取，不直接读全局物料表；
- 停用物料不能被新建商品选择，已有商品保留。

```sql
    product_business_id VARCHAR(64) NOT NULL,
    product_content_version BIGINT NOT NULL,
    base_payload_json JSON NOT NULL,
    process_payload_json JSON NOT NULL,
    extra_cost_payload_json JSON NOT NULL,
    daily_capacity INT NOT NULL,
    main_image_file_reference_business_id VARCHAR(64) NOT NULL,
    content_fingerprint CHAR(64) NOT NULL,
    created_at DATETIME(6) NOT NULL,
    PRIMARY KEY (snapshot_business_id),
    UNIQUE KEY uk_product_snapshot_version (product_business_id, product_content_version)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_0900_ai_ci;
```

快照载荷至少包含：

- 商品编号、名称、说明、主图文件引用、克重；
- 胶水物料引用、名称、规格、损耗率、单价；
- 色浆物料引用、名称、规格、损耗率、单价；
- 模具数量、每次批次、单日产能；
- 三道工序的星级代码、星级名称、标准分钟、人工成本、提成、材料成本和供料方默认值；
- 六项其他单件成本。

所有权：`product_snapshots` 只由商品模块写入和读取；其他模块只保存 `SnapshotRef`，通过 `resolveProductSnapshot` 按版本查询。

快照创建时为主图建立平台文件引用（`ownerType = PRODUCT_SNAPSHOT`、`purposeCode = MAIN_IMAGE`），保证历史快照的主图不会被文件清理提前删除。

快照的业务版本直接使用 `product_content_version`；消费者取得的 `snapshotVersion` 与该版本一致。快照读取视图返回 `mainImageFileBusinessId`，取图片内容仍需通过平台文件权限校验。

快照不包含商品启停状态：启停只影响后续引用，不属于快照定义内容，因此不会造成同一内容版本出现不同快照载荷。

### 9.4 更新与版本规则

| 表 | 可否更新 | 版本规则 |
|---|---|---|
| `product_masters` | 是 | 正式内容变化时内容版本递增；并发用 `row_version` |
| 三道工序表 | 是，随商品整体保存 | 不单独维护版本；商品内容变化即更新 |
| `product_extra_costs` | 是，随商品整体保存 | 同上 |
| `product_schemes` | 是 | 方案字段或覆盖值变化时内容版本递增；商品内容变化同步递增 |
| 三张方案覆盖表 | 是，随方案整体保存 | 不单独维护版本 |
| `product_budget_results` | 整体替换 | 保存对应的商品/方案内容版本和指纹 |
| `product_budget_result_lines` | 随预算整体替换 | 不单独维护版本 |
| `product_snapshots` | 否 | 只插入，不更新、不删除 |
| `product_scheme_snapshots` | 否 | 只插入，不更新、不删除 |

商品内容变化时，必须同步处理所有方案：

```text
商品内容版本递增
→ 标准方案同步售价、袋子/装饰品来源和 source_product_content_version，方案内容版本递增
→ 每个自定义方案同步 source_product_content_version，方案内容版本递增
→ 重算标准方案和所有自定义方案预算
→ 一次事务提交
```

为保持版本语义简单，商品任何正式内容变化都使所有方案产生新内容版本，即使某个方案当前不取用该字段；这样快照和预算不会出现“商品已变、方案版本未变”的歧义。主图替换属于正式内容变化，同样递增商品内容版本。

库表中的 `daily_capacity` 和 `material_subtotal` 是计算模块返回的结果列，商品模块写入后不能由用户覆盖；商品模块和数据库都不实现这两个公式。

### 9.5 与 V2 表结构的收敛

| V2 | V3 | 原因 |
|---|---|---|
| `product_making_star_options` + `product_process_time_options` | 移入全局静态数据，使用通用 `typeCode/itemCode/attributes` | 静态数据全局统一管理，商品模块不建专用字段表 |
| `product_entry_defaults` | 移入全局物料主数据 | 胶水/色浆作为物料选择，不在商品重复维护价格和损耗率 |
| 方案独立启停状态 | 删除 | 商品启用状态统一控制整个商品；方案不单独建状态列 |
| 制作星级/分钟/提成在商品根 | 移入 `product_making_processes` | 三道工序结构一致，商品根只保留商品级字段 |
| 制作只有提成，包装/缝边只有人工成本 | 三道工序都保存 `labor_cost` 和 `commission` | 人工成本 = 基本人工 + 提成，成本行分开但提成计入合计 |
| 商品根 `mould_daily_batches` | `batches_per_day` | 与“每次批次”业务叫法一致 |
| 商品根 `daily_capacity` 普通列 | 普通结果列 | 保留普通列，但值由计算模块返回后写入，商品模块和数据库都不做业务计算 |
| 捏毛装袋无综合材料小计列 | 工序表新增 `material_subtotal` 结果列 | 由计算模块返回，页面只读，避免前端求和 |
| `product_extra_unit_costs` | `product_extra_costs` | 简化命名 |
| 方案保存克重、分钟、人工成本、提成、额外成本副本 | 方案只保存覆盖值和方案级字段 | 继承值从商品读取，避免双份数据漂移 |
| `product_scheme_extra_unit_costs` | 删除 | 其他单件成本永远继承商品，不需要方案副本 |
| 方案袋子/装饰来源在覆盖表 | 方案根统一保存四项供料方 | 供料方是方案级成交条件，读取和预算只查方案根 |
| 商品无袋子/装饰来源 | 商品保存默认来源 | 满足录入需要，并作为标准方案和新方案的默认值 |
| 商品主图 | 商品根保存主图文件引用，平台文件表管理引用生命周期；本期不做图库 | 满足“商品需要主图”，又不让商品模块保存图片二进制或自建文件表 |

## 10. 公开接口设计

### 10.1 命令

```java
interface ProductApplicationService {
    ProductRef create(CreateProductCommand command);
    ProductRef update(UpdateProductCommand command);
    void changeStatus(ChangeProductStatusCommand command);
}

interface ProductSchemeApplicationService {
    SchemeRef createCustom(CreateCustomSchemeCommand command);
    SchemeRef updateCustom(UpdateCustomSchemeCommand command);
}
```

`CreateProductCommand` / `UpdateProductCommand` 必须包含：

```text
productBusinessId（更新时）, name, description, mainImageFileBusinessId,
standardWeightGrams, standardSchemeSalePrice,
glueMaterialBusinessId, colorPasteMaterialBusinessId,
mouldCount, batchesPerDay,
makingStarCode, baggingStarCode, seamStarCode,
makingCommission, baggingCommission, seamCommission,
makingOtherMaterialCost,
baggingBagUnitCost, baggingBagSource,
baggingDecorationUnitPrice, baggingDecorationSource, baggingOtherCost,
seamCombinedMaterialCost, seamOtherCost,
extraOtherTaskLaborCost, extraTransportPackagingCost, extraDailyMiscCost,
extraRentUtilitiesCost, extraMouldAmortizationCost, extraOtherCost,
rowVersion（更新时）
```

服务端规则：

- 客户端提交的星级名称和标准分钟不作为可信输入；
- 创建商品时，服务端按星级代码和工序类型读取当前启用星级，写入名称和分钟；
- 编辑商品时，如果星级代码与商品当前值相同，保留原名称和分钟；如果星级代码变化，按新代码读取当前启用星级并写入；
- 原星级已停用时，保持原代码不变允许保存；改选其他星级必须是启用项；
- `standardSchemeSalePrice` 写入标准方案自己的 `sale_price`，商品根不保存售价；更新商品时只同步标准方案价格，自定义方案售价不变；
- 主图必须先上传为平台临时文件，保存时在商品事务内正式化并建立引用；不能直接引用未正式化文件；
- 生成快照时对同一正式文件调用 `attach` 建立快照引用；
- 服务端通过平台文件能力建立主图引用，商品模块不保存图片二进制；
- 客户端不能提交商品编号、内容版本、单日产能、综合材料小计、三道工序人工成本；即使提交也不接受，服务端以 `calculation` 模块结果为准；
- 更新时校验 `rowVersion`，冲突返回 `PRODUCT_VERSION_CONFLICT`；
- 创建时由平台编号能力生成商品编号。

`CreateCustomSchemeCommand` / `UpdateCustomSchemeCommand` 只接受：

```text
productBusinessId, schemeBusinessId（更新时）, expectedProductContentVersion,
name, targetProcess, salePrice,
glueSource, colorPasteSource, bagSource, decorationSource,
makingOtherMaterialCost,
baggingBagUnitCost, baggingDecorationUnitPrice, baggingOtherCost,
seamCombinedMaterialCost, seamOtherCost,
rowVersion（更新时）
```

`ChangeProductStatusCommand`：

```text
productBusinessId, targetStatus（ACTIVE/INACTIVE）, rowVersion, reason（可选）
```

`expectedProductContentVersion` 由客户端在打开方案编辑页时带回；服务端先与当前商品内容版本比较，不一致返回 `PRODUCT_SCHEME_PRODUCT_CHANGED`；更新时再校验方案 `rowVersion`，不一致返回 `PRODUCT_SCHEME_VERSION_CONFLICT`。

不存在的继承字段不能出现在命令中；即使客户端提交，服务端也忽略，不把它当作覆盖值。

### 10.2 查询

```java
interface ProductQuery {
    ProductPage search(ProductSearchCriteria criteria);
    ProductDetailView get(ProductId productId);
    SchemeView getScheme(SchemeId schemeId);
}

interface ProductBudgetQuery {
    SchemeBudgetView getCurrentBudget(SchemeId schemeId);
}

interface ProductPreviewQuery {
    ProductDraftPreview previewProduct(ProductDraftPreviewCommand command);
    SchemeBudgetPreview previewScheme(SchemeDraftPreviewCommand command);
}

interface ProductStandardQuery {
    ProductWorkStandardView getCurrentWorkStandard(ProductId productId, ProcessCode processCode);
    ProductCapacityView getCurrentCapacity(ProductId productId);
}

interface ProductSnapshotService {
    ProductSnapshotRefBundle acquireCurrentSnapshotRefs(ProductId productId, SchemeId schemeId);
    ProductOtherTaskSnapshotRef acquireCurrentOtherTaskSnapshotRef(ProductId productId);
    ProductSnapshotView resolveProductSnapshot(SnapshotRef ref);
    SchemeSnapshotView resolveSchemeSnapshot(SnapshotRef ref);
    ProductProductionWorkBasis resolveProductionWorkBasis(
        SnapshotRef productSnapshotRef,
        SnapshotRef schemeSnapshotRef,
        ProcessCode processCode
    );
}

record ProductSnapshotRefBundle(SnapshotRef productSnapshotRef, SnapshotRef schemeSnapshotRef) {}

record ProductOtherTaskSnapshotRef(SnapshotRef productSnapshotRef) {}

```

`SnapshotRef` 由快照业务标识和快照版本组成；其他模块保存引用时必须同时保存这两部分，解析时按版本读取，不能只存业务标识。

跨模块读取商品/方案快照只允许通过 `ProductSnapshotService.resolveProductSnapshot` 和 `resolveSchemeSnapshot`，按 `SnapshotRef` 中的版本解析。其他模块不得直接读 `product_snapshots`、`product_scheme_snapshots`，也不得在自己的表中保存快照载荷副本。`acquireCurrentSnapshotRefs` 只返回 `ProductSnapshotRefBundle`，不返回快照内容；调用方持久化引用，需要内容时再按版本查询。所有 resolve 结果只用于当前读取或展示，不得作为快照副本持久化。

`resolveProductSnapshot` 默认只返回商品身份、工序和展示字段；成本、单价、利润相关字段仅在调用方拥有 `product.budget.read` 时返回，否则省略，避免快照解析接口绕过预算权限。

商品编辑器读取星级和物料时，调用全局模块的公开查询：

- `StaticDataQuery.list("PRODUCT_MAKING_STAR", includeInactive)`；
- `StaticDataQuery.list("PRODUCT_BAGGING_STAR", includeInactive)`；
- `StaticDataQuery.list("PRODUCT_SEAM_CUTTING_STAR", includeInactive)`；
- `GlobalMaterialQuery.list("GLUE", false)`；
- `GlobalMaterialQuery.list("COLOR_PASTE", false)`。

商品模块定义这些 typeCode 和 attributes 结构；全局模块只返回通用记录，不解释商品字段。商品模块不提供静态数据写接口。

预览接口用于未保存的商品和方案：

- `ProductDraftPreviewCommand` 使用与创建商品相同的数值和星级字段，不需要主图；新建预览可不带商品 ID，编辑预览带 `productBusinessId` 用于权限和商品版本校验；
- `ProductDraftPreview` 返回单日产能、袋子与装饰品小计、三类人工成本、标准方案预算和成本行；
- `SchemeDraftPreviewCommand` 使用 `productBusinessId`、`expectedProductContentVersion` 和方案可编辑字段；
- `previewScheme` 同样校验 `expectedProductContentVersion`；商品已变化时返回 `PRODUCT_SCHEME_PRODUCT_CHANGED`，不返回基于新商品的预览；
- `SchemeBudgetPreview` 返回方案预算和成本行；
- 预览只调用计算模块，不落库、不创建快照，也不替代保存后的正式结果。

快照相关查询的职责分工：

- `acquireCurrentSnapshotRefs` / `acquireCurrentOtherTaskSnapshotRef` 只返回快照引用，不返回读取视图、金额或载荷副本；
- `acquireCurrentOtherTaskSnapshotRef`：为关联商品的其他任务取得商品快照引用，不返回可复制的当前金额；
- `resolveProductionWorkBasis`：从商品/方案快照解析指定工序的标准分钟、基本人工成本和提成，供生产安排使用；
- `resolveProductSnapshot` / `resolveSchemeSnapshot`：按快照引用返回商品/方案快照内容，供订单和生产展示使用；

`ResolvedProductionBasis`、`ProductReferenceCostLines`、`ProductionProcessCostBasis` 不再作为本期跨模块接口；工资/成本模块需要时另定契约，商品模块不保存解析副本。

订单只保存商品/方案快照引用；供料方由方案快照决定，订单不做供料覆盖，也不调用商品模块解析订单成本依据。

`getCurrentWorkStandard`、`getCurrentCapacity` 等当前查询只用于新建、编辑预览和尚未冻结的安排；已确认订单、已安排生产、工资和成本历史必须使用版本化快照查询，不能使用当前查询。

```text
  productBusinessId, processCode, starCode, starName, standardMinutes,
  laborCost, commission, contentVersion

ProductProductionWorkBasis:
  productBusinessId, schemeBusinessId, processCode,
  starCode, starName, standardMinutes, laborCost, commission

ProductCapacityView:
  productBusinessId, mouldCount, batchesPerDay, dailyCapacity, contentVersion

ProductSnapshotView:
  snapshotRef, productBusinessId, productContentVersion,
  mainImageFileBusinessId, productNo, name, description, standardWeightGrams,
  glueMaterialBusinessId, colorPasteMaterialBusinessId,

  colorPasteMaterialName, colorPasteMaterialSpec,

  effective 工序值, extraCosts, budget（SchemeBudgetPreview）,
  schemeContentVersion, productContentVersion, contentFingerprint
```

`ProductSnapshotView` 中的 `making`、`bagging`、`seamCutting` 使用与 `ProductView` 相同的工序字段结构；`SchemeSnapshotView.effective` 使用与 `SchemeView.effective` 相同的结构。`SchemeSnapshotView` 的 `schemeContentVersion`、`productContentVersion` 是快照冻结的源内容版本，对应 `product_scheme_snapshots` 的 `scheme_content_version`、`product_content_version`。

### 10.4 与 V2 接口的主要差异

| V2 | V3 |
|---|---|
| `SaveProcessTimeOptionCommand` 单独维护包装/缝边时间 | 由全局静态数据统一维护，商品模块定义 typeCode/attributes，不提供静态数据写命令 |
| 商品根返回 `makingStarCode`、`makingStandardMinutes`、`makingCommission` | 移入 `making` 对象，三道工序结构一致；每道工序同时返回 `laborCost` 和 `commission` |
| 制作提成与包装/缝边人工成本分开 | 三道工序同时返回 `laborCost` 和 `commission`，二者都进入预算 |
| `ProductView.bagging` 包含 `bagSource`、`decorationSource` | 保留商品默认来源，方案根保存最终来源 |
| 商品视图没有 `materialSubtotal` | 返回计算模块给出的 `materialSubtotal`，页面只读 |
| 方案返回大量继承字段副本 | 返回 `inherited / overrides / effective` 三组，语义明确 |
| 方案覆盖表保存袋子/装饰来源 | 来源统一在方案根 |
| 方案保存其他单件成本副本 | 删除，预算从商品组装 |
| 商品无主图字段 | 商品根新增 `mainImageFileBusinessId`，主图由平台文件模块管理 |
| 商品模块自行组装公式 | 只依赖 `ProductCalculation` 公开方法，不实现公式 |

### 10.5 全局静态数据依赖契约

全局静态数据由全局模块统一存储和返回，但不能在全局表里放商品专用字段。全局表只保存通用结构：

```text
typeCode, itemCode, name, sortOrder, status, attributes,
id, row_version, created_at, created_by, updated_at, updated_by
```

- `typeCode`：数据类型，由业务模块定义并注册；
- `itemCode`：数据项代码；
- `name`：显示名称；
- `sortOrder`：排序；
- `status`：启用/停用；
- `attributes`：通用属性集合，具体键值由业务模块定义，全局模块不解释。

商品模块只调用通用查询：

```java
interface StaticDataQuery {
    List<StaticDataItemView> list(String typeCode, boolean includeInactive);

    StaticDataItemView get(String typeCode, String itemCode);
}
```

`StaticDataItemView`：

```text
typeCode, itemCode, name, sortOrder, active, attributes (Map<String, String>)
```

商品模块定义的类型代码和属性：

| typeCode | itemCode | attributes |
|---|---|---|
| `PRODUCT_MAKING_STAR` | 星级代码 | `standardMinutes` |
| `PRODUCT_BAGGING_STAR` | 星级代码 | `standardMinutes` |
| `PRODUCT_SEAM_CUTTING_STAR` | 星级代码 | `standardMinutes` |

约束：

- 全局模块只存储、排序、启停和返回通用记录，不解释商品属性，也不新增 `standardMinutes` 这类专用列；
- 商品模块负责解析和校验 `attributes`，解析失败视为静态数据无效，商品保存失败；
- 商品模块不建静态数据表，不提供静态数据写接口；
- 全局模块提供通用静态数据维护页，按 typeCode 展示通用记录，并以键值方式编辑 attributes；商品模块负责说明属性键的含义和校验规则，不提供维护页；
- 商品新建时读取启用星级和物料；编辑时只在更换星级代码或物料时读取对应项；
- 默认值只用于新建预填，不回溯已有商品；
- 星级代码创建后不可修改；商品保存时冻结 `starCode`、`starName`、`standardMinutes`；
- 岗位时薪由全局模块按岗位提供，计算模块读取；商品模块不调用、不缓存；
- 全局模块修改静态数据不触发商品批量更新。

## 11. 事务与并发

### 11.1 创建商品

```text
生成商品编号
→ 校验商品字段、三类星级和主图文件
→ 保存时正式化主图并建立平台文件引用
→ 调用计算模块计算单日产能、袋子与装饰品小计和三类人工成本
→ 写商品根、三道工序、其他单件成本
→ 生成标准方案
→ 调用计算模块计算标准方案预算
→ 写预算结果和分项行
→ 写审计
→ 一次提交
```

任一步失败整体回滚，主图正式化和文件引用一并回滚。商品编号可能因回滚产生空号，但不会重复或复用。

### 11.2 编辑商品

```text
按 row_version 锁定商品
→ 校验星级、字段和主图文件
→ 如更换主图，建立新文件引用；更新成功后释放商品当前旧引用
→ 调用计算模块重算单日产能、袋子与装饰品小计和受影响工序的人工成本（仅星级或标准分钟变化的工序）
→ 更新商品根、三道工序、其他单件成本
→ 商品内容版本递增
→ 同步标准方案售价、袋子/装饰品来源和 source_product_content_version，方案内容版本递增
→ 同步每个自定义方案的 source_product_content_version，方案内容版本递增
→ 调用计算模块重算所有方案预算
→ 写审计
→ 一次提交
```

锁顺序固定为：商品根 → 三道工序 → 其他成本 → 方案根 → 方案覆盖值 → 预算结果，避免并发死锁。主图文件正式化和引用加入同一事务，失败时一并回滚。星级或标准分钟未变化的工序沿用已保存基本人工成本；只有变化的工序按当前岗位时薪重算。

### 11.3 创建或编辑自定义方案

```text
读取并锁定商品；创建时校验商品启用，编辑时允许商品已停用
→ 校验客户端带来的 expectedProductContentVersion 与当前商品内容版本一致；不一致返回 PRODUCT_SCHEME_PRODUCT_CHANGED
→ 按 row_version 校验方案（编辑时）；不一致返回 PRODUCT_SCHEME_VERSION_CONFLICT
→ 校验目标工序、售价、四项供料方和覆盖字段
→ 写方案根和三张覆盖表
→ 方案内容版本递增
→ 调用计算模块重算预算
→ 写审计
→ 一次提交
```

商品停用时不能新建自定义方案；已有自定义方案可以查看和编辑，但不能用于新订单。商品内容版本已变化时提示刷新商品和方案；方案已被其他人修改时提示刷新方案；两种情况都不能提交部分覆盖值。

### 11.4 全局静态数据

- 星级保存在全局静态数据的通用记录中，商品模块不写入这些数据；
- 胶水/色浆保存在全局物料主数据中，商品模块不写入这些数据；
- 商品模块定义星级 typeCode 和 attributes 结构；
- 修改静态数据或物料不触发商品批量更新；
- 新建商品时通过 `StaticDataQuery` 读取当前启用星级，通过 `GlobalMaterialQuery` 读取物料；编辑时只在更换星级或物料时读取；
- 岗位时薪由计算模块读取，商品模块不直接读写；
- 全局静态数据的权限、审计和停用规则由全局模块负责。

### 11.5 快照

- 快照由商品模块创建和保存，其他模块只保存引用；
- 订单确认、生产安排需要快照时，通过商品模块的参与端口在调用方事务内创建或复用；
- 快照创建失败时调用方事务回滚，不能以商品当前值或无快照状态继续；
- 快照创建使用唯一键防重复；
- 并发创建同一版本快照时，冲突方在唯一键冲突后使用当前读或短事务重试按唯一键重新查询已创建快照并复用；不能依赖 MySQL RR 快照普通读；
- 快照只插入，不更新、不删除。

### 11.6 幂等

- 商品创建、编辑、启停、方案创建/编辑、快照创建/复用全部接入平台幂等能力；
- 相同幂等键重复提交返回第一次成功结果；
- 更新命令以 `row_version` 判断重复提交，不能把旧版本请求当成成功。

### 11.7 启停商品

```text
按 row_version 锁定商品
→ 校验操作权限
→ 更新商品状态，不递增内容版本
→ 写审计
→ 一次提交
```

商品状态是唯一开关；方案没有独立状态。商品停用后所有方案都不能建立新引用，已有方案和历史快照仍可读取。

## 12. 历史与追溯

### 12.1 当前记录与历史事实

- 商品、工序、额外成本、方案、覆盖值都是当前记录，可以修改；
- 预算结果是当前派生结果，不是历史事实；
- 商品快照、方案快照是不可变历史，由商品模块自己保存；
- 订单、生产、工资、成本保存快照引用，通过商品模块的版本化查询读取，不复制商品当前值或快照载荷。

### 12.2 快照取得时机

- 订单确认时，订单模块保存商品/方案快照引用；商品模块在订单事务中创建或复用快照；
- 生产安排需要工时、人工成本、提成、材料依据时，生产模块保存快照引用，调用商品模块的版本化查询解析；
- 商品关联的其他任务在安排时取得商品快照引用并保存；其他任务单件人工费需要时通过商品模块版本化查询从快照解析，不复制当前值或快照载荷；
- 页面预览不创建快照。

### 12.3 追溯内容

审计至少记录：

- 操作者、时间、动作；
- 商品或方案业务标识；
- 修改前后内容版本；
- 修改字段摘要；
- 预算结果版本和输入指纹；
- 停用/启用原因（如有填写）。

### 12.4 不回溯

- 修改商品不影响已确认订单；
- 修改方案不影响已确认订单；
- 修改星级静态数据不影响已保存商品；
- 修改胶水/色浆物料不影响已保存商品和快照；
- 停用商品或星级不影响历史快照解析。

## 13. 权限、审计与错误

### 13.1 权限

| 权限 | 能力 |
|---|---|
| `product.read` | 查看商品列表、详情、主图和工序参数 |
| `product.create` | 新建商品 |
| `product.update` | 编辑商品和替换主图 |
| `product.status` | 启用/停用商品 |
| `product.scheme.manage` | 新建、编辑自定义方案 |
| `product.budget.read` | 查看成本、利润和预算明细 |
| `product.snapshot.read` | 读取商品/方案快照 |

角色建议：

- 管理员：全部商品权限；
- 老板：`product.read`、`product.budget.read`；
- 生产、工资、成本：只通过内部查询或快照取得标准，不授予商品编辑权限。

主图读取以 `product.read` 作为平台文件授权码；替换主图需要 `product.update`。商品模块不绕开平台文件权限直接读取存储路径。

接口权限对应：

| 接口 | 权限 |
|---|---|
| `ProductQuery.search/get/getScheme` | `product.read`；成本/利润字段另需 `product.budget.read` |
| `ProductPreviewQuery.previewProduct` | 新建预览 `product.create`，编辑预览 `product.update`；预算字段另需 `product.budget.read` |
| `ProductPreviewQuery.previewScheme` | `product.scheme.manage`；预算字段另需 `product.budget.read` |
| `ProductBudgetQuery.getCurrentBudget` | `product.budget.read` |
| `ProductStandardQuery` | 商品页面直接读取需 `product.read`；生产/订单内部调用按调用方业务权限鉴权 |
| `ProductSnapshotService.resolve*` | 商品页面直接读取需 `product.snapshot.read`；订单/生产/工资通过内部查询调用时按调用方业务权限鉴权 |
| `ProductSnapshotService.acquire*` | 内部参与端口，按调用方业务权限鉴权，不额外要求 `product.snapshot.read` |
| 商品创建/编辑/启停 | `product.create` / `product.update` / `product.status` |
| 自定义方案创建/编辑 | `product.scheme.manage` |
| `StaticDataQuery` | 全局模块的静态数据读权限 |

全局静态数据（星级）、胶水/色浆物料和岗位时薪的维护权限由全局模块管理，商品模块不授予这些写权限。

### 13.2 审计

必须审计：

- 商品创建、编辑、启停；
- 主图替换和文件引用变化；
- 自定义方案创建、编辑；
- 预算重算失败和版本冲突；
- 快照创建和复用。

成本/利润读取和快照解析属于敏感数据访问，由平台敏感数据访问审计记录；商品模块不重复写业务审计。全局静态数据（星级）、胶水/色浆物料和岗位时薪的变更审计由全局模块负责，不在商品模块审计。

### 13.3 错误码

以下错误码在平台错误码目录登记 `category` 和 HTTP 映射，规则见平台模块 10.3。

| 错误码 | 含义 |
|---|---|
| `PRODUCT_NOT_FOUND` | 商品不存在 |
| `PRODUCT_INACTIVE` | 商品已停用，不能新建方案或引用 |
| `PRODUCT_FIELD_INVALID` | 商品字段不合法 |
| `PRODUCT_STATUS_INVALID` | 商品状态值不合法或状态命令不允许 |
| `PRODUCT_STATIC_DATA_INVALID` | 全局静态数据缺失或 attributes 解析失败 |
| `PRODUCT_MATERIAL_INVALID` | 胶水/色浆物料不存在、已停用或类型不匹配 |
| `PRODUCT_MAIN_IMAGE_INVALID` | 主图缺失、临时文件无效或不是允许的图片类型 |
| `PRODUCT_STAR_INVALID` | 星级不存在、已停用或不属于该工序 |
| `PRODUCT_SCHEME_SYSTEM_MANAGED` | 标准方案不允许用户编辑或删除 |
| `PRODUCT_SCHEME_NOT_FOUND` | 方案不存在 |
| `PRODUCT_SCHEME_INVALID` | 方案字段、目标工序或供料方不合法 |
| `PRODUCT_CALCULATION_FAILED` | 产能、材料小计或预算计算失败 |
| `PRODUCT_LABOR_RATE_MISSING` | 需要重算基本人工成本，但对应岗位时薪未配置或不为正数 |
| `PRODUCT_VERSION_CONFLICT` | 商品内容版本或商品 row_version 冲突 |
| `PRODUCT_SCHEME_PRODUCT_CHANGED` | 方案保存时商品内容版本已变化 |
| `PRODUCT_SCHEME_VERSION_CONFLICT` | 方案 row_version 冲突，方案已被其他人修改 |
| `PRODUCT_SNAPSHOT_CONFLICT` | 快照并发冲突且无法复用 |
| `PRODUCT_SNAPSHOT_NOT_FOUND` | 快照不存在 |
| `PRODUCT_SNAPSHOT_INVALID` | 快照类型、版本或指纹不匹配 |
| `PRODUCT_NO_CONFLICT` | 商品编号生成冲突 |

前端错误展示规则：

- 字段错误在对应输入框内联显示；
- 权限不足由平台统一提示，不暴露资源是否存在；
- 商品/方案不存在时提示并引导返回列表；
- 快照版本缺失、类型或指纹不匹配时提示“数据已失效，请刷新后重试”；
- 全局静态数据无效时提示联系管理员检查设置；
- 商品内容版本冲突提示刷新商品和方案；方案 `row_version` 冲突提示刷新方案；都引导刷新，不覆盖服务端值；
- 不显示英文错误原文、内部 ID、指纹和版本号。

## 14. 页面与交互要求

### 14.1 页面清单

| 页面 | 建议路由 | 目的 |
|---|---|---|
| 商品列表 | `/products` | 搜索、筛选、进入详情、新建、启停 |
| 商品详情 | `/products/:id` | 只读查看商品、工序、成本、方案 |
| 新建商品 | `/products/new` | 一次录入完整商品 |
| 编辑商品 | `/products/:id/edit` | 修改商品并查看预算变化 |
| 新建方案 | `/products/:id/schemes/new` | 建立自定义方案 |
| 编辑方案 | `/products/:id/schemes/:schemeId/edit` | 修改自定义方案 |

商品详情默认只读，编辑和方案操作通过明确按钮进入，不在详情页直接改值。全局静态数据和全局参数的维护入口属于全局模块，不在商品模块页面内。

### 14.2 商品列表

- 页头使用紧凑页栏，不使用大标题；
- 列：主图缩略图、商品编号、商品名称、标准克重、标准方案售价、单日产能、状态、更新时间；
- 有 `product.budget.read` 权限时，增加标准方案成本、预计利润两列；
- 搜索：商品名称或编号；
- 筛选：状态；
- 操作：查看、编辑、启用/停用、新建商品；
- 启用/停用需要二次确认；停用后新建方案、订单引用和生产安排被禁止；
- 状态标签清晰区分启用/停用，停用商品仍可进入详情和编辑；
- 不展示内部业务 ID、内容版本、指纹和成本性质代码；
- 默认按商品编号升序，支持分页；
- 空状态提供“新建商品”。

### 14.3 商品详情

按“先结论、后明细”组织：

1. 页头：商品主图、商品名称、编号、状态、标准方案售价；
2. 摘要：标准克重、单日产能、模具数量、每次批次；标准方案成本、预计利润仅有 `product.budget.read` 时显示；
3. 分区：制作、捏毛装袋、缝边剪袋、其他单件成本、基础材料；有 `product.budget.read` 时每道工序显示基本人工成本、提成和人工成本合计；
4. 方案列表：标准方案和自定义方案，显示类型、目标工序、售价；工作室成本、预计利润仅有 `product.budget.read` 时显示；
5. 操作：编辑商品、新建方案、启用/停用商品。

商品停用时，“新建方案”按钮禁用并提示“商品已停用”；商品仍可编辑或重新启用。标准方案只显示“系统方案”标识。启用/停用同样需要二次确认；主图读取失败时显示占位图，不阻塞详情读取。

只读字段不使用禁用输入框伪装成可编辑控件；用文本和单位展示。

### 14.4 新建/编辑商品

使用全页表单，不使用抽屉，不拆成多步向导。商品是一次性定义，分步会增加录入负担。

分区顺序：

```text
商品主图
→ 基本信息
→ 基础材料
→ 制作
→ 捏毛装袋
→ 缝边剪袋
→ 其他单件成本
→ 成本与产能摘要
```

交互要求：

- 商品编号在新建时显示“保存后自动生成”；
- 状态不在编辑表单中修改，使用列表或详情的启用/停用操作；
- 主图是必填项：支持 JPEG、PNG、WebP，上传后先预览，保存时正式化并建立引用；
- 编辑时替换主图只影响当前商品和后续快照，不修改历史订单已冻结的图片；
- 星级下拉显示“名称 · 标准分钟”，选择后标准分钟只读带出；
- 每道工序同时显示“基本人工成本”“提成”和“人工成本合计”：基本人工成本只读、由计算模块按岗位时薪计算；提成是独立输入，不随星级变化；合计 = 基本人工 + 提成；
- 基本人工成本、提成和成本摘要仅有 `product.budget.read` 时显示；提成输入由 `product.update` 控制；
- 基本人工成本旁提示“由计算模块按岗位时薪计算；岗位时薪调整不回溯已保存商品”；
- 编辑已有商品时，如果当前星级已停用，下拉保留该星级并标注“已停用”，允许不改星级保存；改选时只能选择启用星级；
- 袋子成本和装饰品单价可编辑，综合材料成本只读，由服务端计算返回；
- 袋子来源、装饰品来源为默认供料方，标注“新方案默认使用，可在方案中修改”；
- 胶水、色浆从物料主数据选择，单价和损耗率只读带出，不允许在商品上覆盖；
- 单日产能只读，由服务端预览返回，不随前端即时计算；
- 右侧或顶部固定“成本与产能”摘要，滚动时保持可见；摘要至少显示人工成本、提成、材料成本、其他成本、总成本和单日产能；
- 预算预览通过 `ProductPreviewQuery.previewProduct` 刷新，前端不自行计算，标注“预览，保存后以服务端结果为准”；预算预览仅有 `product.budget.read` 时显示；
- 保存前校验所有必填和数值范围，字段错误内联显示；
- 计算或预算失败时保存失败并提示重试，不保留半成品；
- 离开未保存表单时确认；
- 更新时携带 `rowVersion`，冲突后提示刷新；
- 在 1600×900 下，页头、摘要和主要操作首屏可见；表单可滚动，摘要不随内容滚走。

### 14.5 方案编辑

方案编辑也使用全页表单，与商品编辑保持同一套视觉语言。

页面结构：

```text
商品摘要（主图、名称、编号、状态）
→ 来自商品（只读）：
    克重、三类星级与标准分钟、三类人工成本、三类提成、六项其他单件成本
→ 本方案可调整：
    方案名称、目标工序、售价、四项供料方、
    制作其他材料费、袋子成本、装饰品单价、捏毛装袋其他费用、
    缝边剪袋综合材料成本、缝边剪袋其他费用
→ 预算结果（服务端计算）
```

交互要求：

- 继承字段集中展示，不提供编辑控件；人工成本、提成和额外费用仅有 `product.budget.read` 时显示；
- 目标工序变化时，通过 `ProductPreviewQuery.previewScheme` 重新请求预算，预算范围随之变化；目标工序之后的参数仍保留但标注“当前不参与预算”；
- 切换目标工序时，目标范围内的覆盖值沿用方案已保存值，不自动重新带出商品当前值；需要时手工调整；
- 客户供料是方案输入，具体成本影响由计算模块返回，商品模块不判断。
- 标准方案不显示编辑入口，只显示“系统方案”标识；
- 方案没有独立启停按钮；商品停用后全部方案都不能建立新引用；
- 方案列表不显示“设为默认”；
- 打开方案编辑页时记录 `currentProductContentVersion` 和方案 `rowVersion`，保存时分别作为 `expectedProductContentVersion` 和 `rowVersion` 提交；商品版本冲突提示“商品已更新，请刷新方案”，方案版本冲突提示“方案已被其他人修改，请刷新方案”，两者都不覆盖服务端新值；
- 方案保存后显示服务端返回的正式预算，不用前端预览替代；预算结果仅有 `product.budget.read` 时显示，无权限时可编辑方案但不显示金额。

### 14.6 全局静态数据来源

商品编辑器中的星级来自全局静态数据，胶水和色浆来自全局物料主数据；商品页面不提供这些数据的新增、编辑或停用入口。

- 星级下拉通过 `StaticDataQuery.list(typeCode, includeInactive)` 读取启用项；编辑已有商品时保留当前星级值，已停用星级标注“已停用”；
- 胶水、色浆下拉通过 `GlobalMaterialQuery.list(materialType, false)` 读取启用物料；
- 商品模块负责解释星级 attributes 中的 `standardMinutes`；
- 商品保存时冻结所选物料的名称、规格、单价和损耗率；
- 岗位时薪由全局模块按岗位维护、计算模块读取，商品页面只展示计算后的人工成本；
- 修改静态数据或物料不改变已保存商品；基本人工成本只在重新选择星级或标准分钟变化时按当前岗位时薪重算。

### 14.7 全局交互原则

- 不出现“DMND”“PSRC”“物理根”“内容指纹”等内部术语；
- 不把版本号、业务 ID 作为主信息展示；
- 成本、利润只对有 `product.budget.read` 的用户显示；
- 无 `product.update` 不显示编辑入口，无 `product.status` 不显示启停，无 `product.scheme.manage` 不显示方案新建/编辑；
- 列表、详情、编辑页统一 loading、空态和错误态；接口错误用 toast，字段错误内联；
- 主图读取失败显示占位图，不阻塞页面；
- 使用项目既有设计令牌和组件，不为商品模块单独造一套视觉；
- 控件按内容定宽，不横向拉满；
- 高频列表和详情尽量一屏，长表单在内容区滚动，操作和摘要保持可见；
- 材料单价带“元/克”，其余单件金额带“元/件”，克重带“克”，分钟带“分钟”；
- 所有校验提示使用中文，字段级错误就地显示；
- 商品主图的 `alt` 使用商品名称，列表缩略图和详情大图保持一致。

- [ ] 方案没有独立状态，商品停用后全部方案不可建立新引用；
- [ ] 每个商品最多一个标准方案，数据库唯一约束生效；
- [ ] 自定义方案只能修改允许字段，继承字段服务端忽略客户端提交值；
- [ ] 自定义方案保留自己的供料方和覆盖值，商品修改不覆盖它们；

### 15.3 预算集成

- [ ] 商品/方案保存时调用 `calculateProductBudget`，并原样保存返回的预算汇总、成本行和版本信息；
- [ ] 人工成本 = 基本人工 + 提成；`labor_unit_cost` 含提成，`commission_unit_cost` 是其中拆分；
- [ ] 预算成本行分别保留 `LABOR` 和 `COMMISSION`，不合并；
- [ ] 商品模块不自行计算、修改或重算预算金额；
- [ ] 预算计算失败时商品/方案修改整体回滚；
- [ ] 页面预览与保存后的正式预算都来自计算模块，前端不自行计算；
- [ ] 成本范围、供料方承担、利润和利润率的口径由计算模块测试覆盖，不在商品模块重复断言。

### 15.4 快照与历史

- [ ] 同一商品内容版本只创建一个商品快照；
- [ ] 同一方案内容版本和商品内容版本只创建一个方案快照；
- [ ] 商品内容变化后，方案产生新的内容版本；后续取得快照时生成新版本；
- [ ] 快照不能更新或删除；
- [ ] 修改商品当前值不影响已取得的快照；
- [ ] 商品/方案快照只保存在商品模块，其他模块只保存 `SnapshotRef`；
- [ ] `acquireCurrentSnapshotRefs`、`acquireCurrentOtherTaskSnapshotRef` 只返回引用，不返回快照内容或当前金额；
- [ ] 订单只保存商品/方案快照引用，不做供料覆盖，不保存解析后的完整成本行副本；
- [ ] 快照成本字段只有拥有 `product.budget.read` 的调用方可见；
- [ ] 快照唯一键冲突后使用当前读或重试复用，不能依赖 RR 普通读；
- [ ] 其他模块通过商品模块的版本化查询读取快照，不直接读快照表、不复制快照载荷；
- [ ] resolve 返回的内容只用于当前读取或展示，其他模块不把它持久化为快照副本；
- [ ] 快照版本不存在或引用不匹配时明确失败，不回退到商品当前值；
- [ ] 快照创建失败时调用方事务回滚；
- [ ] 历史订单、历史生产记录继续使用原快照引用。

### 15.5 数据与边界

- [ ] 商品模块不访问客户、订单、生产、工资、财务表；
- [ ] 商品表不建跨模块外键，不做跨模块 JOIN；
- [ ] 商品模块不建星级/默认值配置表，不提供静态数据写接口；新建商品通过通用 `StaticDataQuery` 读取全局静态数据；
- [ ] 全局静态数据只使用通用字段和 attributes，不新增商品专用列；商品模块负责解释自己的 typeCode 和 attributes；
- [ ] 全局模块修改静态数据的 name、status 或 attributes，不改变已保存商品；
- [ ] 方案表不保存商品继承字段副本；
- [ ] 方案表和方案读模型没有独立状态字段；商品状态是唯一开关；
- [ ] 表、读模型和命令字段按 9.6 对照，没有孤儿字段或读模型字段缺失；
- [ ] 方案覆盖表只保存允许覆盖的字段；
- [ ] 标准方案不写覆盖行；
- [ ] 商品和方案的所有金额、分钟和商品状态约束在数据库和应用层都生效；
- [ ] 并发编辑使用 `row_version` 拒绝后提交者；
- [ ] 商品/方案的修改都有审计记录；全局静态数据审计由全局模块负责；
- [ ] 成本/利润读取和快照解析有平台敏感数据访问审计；
- [ ] 接口按权限表鉴权，未授权请求被拒绝；
- [ ] 商品/方案不存在、状态非法、静态数据无效、快照缺失或不匹配时返回稳定错误码；
- [ ] 页面按权限隐藏成本/利润和编辑、启停、方案操作；列表空态、加载失败和字段错误有明确反馈。

## 16. 明确不采用

- 不采用通用材料目录、材料库存、采购和领料；
- 不采用任意增加工序或动态字段；
- 不把装箱作为第四道生产工序；
- 不采用服务端草稿和半成品保存；
- 不采用方案“默认选择”字段；
- 不采用方案独立启停状态；商品启用状态统一控制整个商品；
- 不允许用户独立编辑或删除标准方案；
- 不采用商品多图、图库和图片排序；只保留一张主图；
- 商品模块内不实现计算公式，不使用数据库生成列做业务计算；
- 不把基本人工成本和提成合并成一个存储字段，也不用其中一项替代另一项；
- 前端不自行计算成本、产能和预算；
- 不对商品、方案做硬删除；全局静态数据按全局模块规则管理；
- 不把成本、利润、内部版本号作为无权限用户的列表主信息；有 `product.budget.read` 时可作为可选列；
- 不把商品当前值直接提供给历史订单使用；
- 不在 V3 中设计 V2 到 V3 的数据迁移，开发/验收库可重建。

## 17. 已确认口径

- 提成是商品上直接维护的“元/件”金额，不是按标准分钟计算出来的；
- 人工成本 = 基本人工成本 + 提成；基本人工由计算模块按岗位时薪计算；
- 基本人工成本和提成分别作为预算输入，计算模块分别返回 `LABOR` 和 `COMMISSION` 成本行；提成计入人工成本合计；
- 商品主图必填：每个商品一张主图，本期不做图库；
- 商品启用是唯一开关，方案不单独设置启停状态；商品停用后全部方案不能建立新引用；

- 岗位时薪由全局模块按岗位维护，计算模块读取，商品模块不接触。

本模块暂无待确认项。

## 20. 外部依赖对接要求

三类外部依赖的共同边界：

- 商品模块不直接读写依赖模块的表；
- 依赖模块不反向依赖商品模块；
- 商品模块只传输入、保存返回值，不复制依赖模块的内部结构；
- 任一步失败，商品保存或快照创建整体回滚。

| 依赖 | 提供方 | 商品侧用途 | 主要失败语义 |
|---|---|---|---|
| 全局静态数据、物料与全局参数 | 全局模块 | 读取星级、胶水/色浆物料和岗位时薪 | `PRODUCT_STATIC_DATA_INVALID`、`PRODUCT_MATERIAL_INVALID`、`PRODUCT_LABOR_RATE_MISSING` |
| 计算公式 | 计算模块 | 产能、材料小计、人工成本和预算 | `PRODUCT_CALCULATION_FAILED` |
| 平台能力 | 平台 | 文件、编号、权限、审计、幂等 | 平台错误，商品侧按业务码映射 |

### 20.1 全局模块

提供方职责：

- 使用通用静态数据表：`typeCode`、`itemCode`、`name`、`sortOrder`、`status`、`attributes`，以及通用 id、`row_version` 和审计字段；
- 不新增 `standardMinutes` 等商品专用列；
- 提供通用维护页、权限、审计和启停规则；
- 提供胶水/色浆物料查询和启停规则；
- 提供四个岗位时薪参数：`HOURLY_RATE_MAKING`、`HOURLY_RATE_BAGGING`、`HOURLY_RATE_SEAM_CUTTING`、`HOURLY_RATE_OTHER`。

消费契约（以下为商品侧使用的字段视图，完整定义以全局模块公开契约为准）：

```java
interface StaticDataQuery {
    List<StaticDataItemView> list(String typeCode, boolean includeInactive);
    StaticDataItemView get(String typeCode, String itemCode);
}

record StaticDataItemView(
    String typeCode, String itemCode, String name,
    int sortOrder, boolean active, Map<String, String> attributes
) {}

record GlobalMaterialRef(String materialBusinessId) {}

interface GlobalMaterialQuery {
    List<GlobalMaterialView> list(String materialType, boolean includeInactive);
    GlobalMaterialView get(GlobalMaterialRef materialRef);
}

record GlobalMaterialView(
    String materialRef, String materialNo, String materialType,
    String name, String specification, BigDecimal unitPrice,
    BigDecimal lossRate, boolean active
) {}

interface GlobalParameterQuery {
    GlobalParameterView current(String parameterCode);
    GlobalParameterView at(String parameterCode, LocalDate businessDate);
}

record GlobalParameterView(
    String parameterCode, String name, String valueType,
    String value, String unit, long versionNo, LocalDate effectiveFrom
) {}
```

商品定义的类型和 attributes：

| typeCode | itemCode | attributes |
|---|---|---|
| `PRODUCT_MAKING_STAR` | 星级代码 | `standardMinutes` |
| `PRODUCT_BAGGING_STAR` | 星级代码 | `standardMinutes` |
| `PRODUCT_SEAM_CUTTING_STAR` | 星级代码 | `standardMinutes` |

职责划分：

- 商品模块调用 `StaticDataQuery`，解析并校验星级 attributes；
- 商品模块调用 `GlobalMaterialQuery`，读取胶水和色浆物料；
- 商品模块只在新建或更换物料时读取物料，只在更换星级代码时读取星级；
- 商品模块冻结 `starCode`、`starName`、`standardMinutes` 和所选物料的名称、规格、单价、损耗率；
- 全局模块不解释 attributes，不回溯修改商品；
- 商品模块通过 `GlobalParameterQuery` 按工序读取岗位时薪和版本，作为输入传给计算模块；商品模块不缓存时薪；
- 商品模块不提供静态数据写接口。

失败语义：

- 静态数据缺失、attributes 解析失败 → `PRODUCT_STATIC_DATA_INVALID`；
- inactive 星级被新选择、星级不属于该工序 → `PRODUCT_STAR_INVALID`；
- 胶水/色浆物料不存在、已停用或类型不匹配 → `PRODUCT_MATERIAL_INVALID`；
- 岗位时薪缺失或不为正数 → 计算模块失败，商品映射 `PRODUCT_LABOR_RATE_MISSING`；
- 全局模块不可用 → 商品保存失败并回滚，不写入半成品。

对接验收：

- 全局静态数据表没有商品专用列；
- 商品模块只通过 `StaticDataQuery` 读取；
- 全局模块修改 name/status/attributes 不改变已保存商品；
- 商品模块不写静态数据，不调用全局模块的写接口；
- 岗位时薪只由计算模块读取。

### 20.2 计算模块

需要计算模块提供以下方法；商品模块只调用方法，不关心内部公式：

| 方法 | 输入 | 输出 |
|---|---|---|
| `calculateDailyCapacity` | 模具数量、每次批次 | 单日产能 |
| `calculateBaggingMaterialSubtotal` | 袋子成本、装饰品单价 | 综合材料小计 |
| `calculateProcessLaborCost` | 工序、标准分钟、业务日期、岗位时薪、岗位时薪版本；商品模块读取后传入 | 该工序基本人工成本 |
| `calculateProductBudget` | 目标工序；标准克重、胶水/色浆损耗率、胶水/色浆单价；基本人工成本、提成；袋子成本、装饰品单价、缝边剪袋综合材料成本、工序其他费用；六项其他单件成本；四项供料方；售价 | 预算汇总、成本行、人工成本合计（含提成）、提成合计、预计利润、利润率、公式版本、舍入版本、输入指纹 |

职责划分：

- 计算模块拥有公式、成本范围、供料方承担、利润/利润率、精度和舍入；
- 计算模块是无状态纯计算，不写数据库、不读商品表、不产生副作用；
- 商品模块只组装输入、调用方法、保存返回结果，不自行计算或舍入；
- 预览和正式保存使用同一计算方法；
- 商品编辑重算多个方案时，计算模块必须支持同一事务内多次调用。

失败语义：

- 计算失败 → `PRODUCT_CALCULATION_FAILED`；
- 岗位时薪缺失或非法 → `PRODUCT_LABOR_RATE_MISSING`；
- 计算失败时商品/方案保存整体回滚，不留“内容已保存、预算仍旧”的状态；
- 计算业务错误映射：
  - `CALCULATION_PRICE_INVALID`、`CALCULATION_TARGET_PROCESS_INVALID` → `PRODUCT_SCHEME_INVALID`；
  - `CALCULATION_INPUT_INVALID`、`CALCULATION_INPUT_SCALE_INVALID`、`CALCULATION_OVERFLOW`、`CALCULATION_CONSERVATION_INVALID` → `PRODUCT_CALCULATION_FAILED`（500）。

对接验收：

- 商品模块不含公式，预算和成本行全部来自计算方法；
- 成本行分别保留 `LABOR`、`COMMISSION`；
- 返回值带公式版本、舍入版本和输入指纹，商品模块原样保存；
- 预览与正式保存调用同一方法；
- 公式正确性由计算模块测试覆盖，商品模块只验证调用、保存和回滚。

### 20.3 平台能力

#### 20.3.1 文件

接口：

```java
PlatformFileService.uploadTemp(UploadTempFileCommand command);
PlatformFileService.formalize(FormalizeFileCommand command);
PlatformFileService.attach(AttachFileCommand command);
PlatformFileService.release(FileReferenceRef referenceRef, String reason);
PlatformFileService.readContent(FileReferenceRef referenceRef, String permissionCode);
```

商品侧引用：

| 场景 | ownerType | purposeCode |
|---|---|---|
| 商品当前主图 | `PRODUCT` | `MAIN_IMAGE` |
| 商品快照主图 | `PRODUCT_SNAPSHOT` | `MAIN_IMAGE` |

要求：

- 主图先上传为临时文件；保存商品时在同一事务内正式化并建立 `PRODUCT / MAIN_IMAGE` 引用，返回的引用标识写入商品根；
- 生成商品快照时，对同一正式主图调用 `attach` 建立 `PRODUCT_SNAPSHOT / MAIN_IMAGE` 引用，快照保存文件业务标识和引用标识；
- 替换主图时用商品根保存的引用标识释放旧引用，不释放快照引用；
- 已引用文件不能被平台删除；快照引用保护历史主图；
- 商品模块保存 `fileBusinessId` 和 `fileReferenceBusinessId`，不存二进制、存储路径或缩略图；
- 文件类型和大小由平台策略限制；
- 读取文件时使用 `product.read` 作为平台文件读取权限码；上传、正式化、追加引用和释放由商品模块的 `product.create` / `product.update` 校验后调用平台文件接口。

失败语义：

- 正式化或引用失败 → 商品保存回滚；
- 文件缺失、临时文件无效、类型不允许 → `PRODUCT_MAIN_IMAGE_INVALID`；
- 平台文件错误按平台错误码返回，商品不伪造文件结果。

#### 20.3.2 编号

接口：

```java
PlatformNumberService.nextNumber("PRODUCT", "P-", 6);
```

- 返回 `P-000001` 格式；

- 事务回滚可产生空号，但不重复、不复用。

#### 20.3.3 权限与审计

- 平台提供认证上下文和权限点校验；
- 商品模块使用 `product.read/create/update/status/scheme.manage/budget.read/snapshot.read`；

- 商品创建、编辑、启停、主图替换、方案创建/编辑、预算失败、快照创建/复用由商品模块写业务审计；
- 全局静态数据和岗位时薪变更审计由全局模块负责；
- 商品模块不直接读平台权限表或审计表。

#### 20.3.4 幂等

- 商品创建、编辑、启停、自定义方案创建/编辑、快照创建/复用接入平台幂等；

平台对接验收：

- 主图正式化/引用失败时商品保存整体回滚；
- 商品编号唯一且不复用；
- 未授权请求被拒绝；
- 成本/利润读取和快照解析有敏感访问审计；
- 商品创建、编辑、启停、方案创建/编辑、快照创建重复提交幂等；
- 商品模块不直接访问平台文件表、编号表、权限表或审计表。
