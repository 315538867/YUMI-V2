# V3 平台模块

> 模块代码：`platform`  
> 文档版本：V3.0  
> 编写日期：2026-10-29  
> 状态：V3 平台模块评审稿；评审通过前不进入页面实现

本文是 V3 平台模块的唯一需求与设计依据。平台模块是所有业务模块的技术底座，负责账号、角色权限、编号、审计、文件和幂等；不拥有商品、客户、订单、员工、生产、全局配置或任何业务规则。

> 平台模块不参与业务模块序号。全局模块仍是业务配置的第一个模块（`00`），平台模块位于所有模块之下，被所有模块调用。

## 摘要

- 平台模块只管技术能力，不管业务数据和业务规则。
- 账号模型支持 `ADMIN` 和 `EMPLOYEE` 两类主体；本期只开放管理员和老板登录，员工账号模型预留但不创建登录。
- 角色权限使用“角色 + 权限代码 + 数据范围”模型；权限代码由业务模块声明，平台保存授权关系、数据范围和账号绑定；默认拒绝、无通配符，员工账号只能拿员工可授权权限和 `OWN` 数据范围。
- 业务编号统一由平台生成，格式固定：商品 `P-000001`、客户 `C-000001`、订单 `SO-000001`、发货 `SH-000001`、员工 `E-000001`、胶水 `GL-000001`、色浆 `CP-000001`。
- 业务操作审计和敏感数据访问审计由平台记录；业务模块不建审计表。
- 文件由平台统一管理：临时上传、正式化、引用和释放；业务模块只保存文件引用。
- 所有写命令支持幂等键，重复提交不重复产生业务结果。
- 所有接口使用统一响应信封和登记式错误码；`code` 映射 HTTP 状态，2xx 只能是 `OK`，未捕获异常统一 500。
- 平台模块不计算金额、成本、工资、产能，也不管理静态数据和全局参数。

## 1. 模块说明

平台模块管理“所有业务模块都要用、但不属于任何业务模块的技术能力”。

它回答：

- 当前是谁在操作，有什么权限；
- 这个业务编号是多少；
- 这次操作有没有被审计；
- 这张图片或附件存在哪里、被谁引用；
- 同一次提交重复发送会不会重复执行；
- 接口成功或失败统一怎么返回。

它不回答：

- 商品怎么定价、怎么算成本；
- 订单怎么履约；
- 员工怎么排班；
- 静态数据有哪些、全局参数是多少；
- 客户和订单业务字段是什么。

平台模块不能导入任何业务模块的 Entity、DTO、Repository 或业务类型；业务模块也不能把平台当作业务配置中心。

## 2. 用户与场景

### 2.1 用户

| 用户 | 关心什么 | 在平台模块做什么 |
|---|---|---|
| 管理员 | 登录、账号、权限、审计、编号和文件是否正常 | 登录，管理账号和角色，查看审计 |
| 老板 | 只读查看业务和关键操作记录 | 登录，按只读角色查看 |
| 业务模块 | 当前用户、权限、编号、审计、文件和幂等 | 调用平台公开接口，不直接读平台表 |
| 运维 | 服务健康、日志和备份 | 使用平台运维能力，不进入业务数据 |

### 2.2 现状与目标

现在账号、权限、编号、文件和审计散落在业务模块里，容易出现权限绕过、编号重复、文件被提前清理和重复提交。

V3 把这些技术能力集中到平台模块：

- 账号和角色统一管理；
- 业务模块只声明权限代码，平台负责鉴权；
- 编号统一生成，业务模块不自己拼编号；
- 审计统一记录，业务模块不建审计表；
- 文件统一管理生命周期；
- 写命令统一幂等；
- 接口统一响应和错误格式。

### 2.3 模块边界与数据访问

模块边界同时约束代码和数据，所有 V3 模块统一遵守：

1. 每张表只属于一个模块，只有所属模块可以读写；其他模块不得通过 SQL、JPA/MyBatis Mapper、JdbcTemplate、数据库视图或数据库账号直接访问。
2. 模块之间不共享表、不建跨模块外键、不做跨模块 JOIN；需要在列表里展示对方数据时，由提供方在查询方法内完成关联并返回只读视图。
3. 同步读取调用提供方公开查询方法；写入调用提供方公开命令；状态变化通过提供方公开事件通知。
4. 消费方只保存业务标识和快照引用，不复制对方的表结构、Entity 或载荷；返回给其他模块的只能是契约视图（record/DTO）。
5. 批量页面由提供方提供批量查询方法，消费方不得按 ID 循环回表或自己拼接对方表。
6. 同一事务内的跨模块操作用方法调用参与，由命令所有者开启事务；事件监听必须在同一事务内同步执行；任何一方都不得在事务中直接改对方表。
7. 报表、工资、成本等下游模块通过提供方公开查询或自己的订阅投影读取；投影只保存业务标识和展示所需值，不反向写回源模块。
8. 即使多个模块部署在同一个数据库实例，也按模块表边界管理账号权限；不能以“同一个库”为理由跨模块直接查表。
9. 允许两个模块通过公开查询和公开事件形成双向契约协作，但不能出现跨模块表访问；如果拆成独立服务，把共享契约下沉到契约模块，而不是改成跨库查询。

## 4. 业务概念

| 术语 | 定义 |
|---|---|
| 平台账号 | 登录身份；类型为 `ADMIN` 或 `EMPLOYEE`，本期只创建 `ADMIN` |
| 账号主体 | 账号对应的业务主体；`ADMIN` 无主体，`EMPLOYEE` 对应一名员工 |
| 角色 | 一组权限代码和数据范围的集合 |
| 数据范围 | 某个权限的可见范围，`ALL` 全部或 `OWN` 仅本人；按权限单独配置 |
| 权限代码 | 业务模块声明的能力标识，例如 `product.read` |
| 编号序列 | 按业务类型维护的自增序号和固定前缀 |
| 操作审计 | 业务写操作的追加记录 |
| 敏感数据访问审计 | 对电话、地址、成本、利润等敏感字段的读取记录 |
| 临时文件 | 已上传但尚未被业务正式引用的文件 |
| 正式文件 | 已被业务模块正式引用、不能被临时清理的文件 |
| 文件引用 | 业务模块对文件的引用关系，包含所有者、用途和状态 |
| 幂等键 | 客户端为一次写命令提供的唯一键 |
| 请求指纹 | 幂等键对应请求体的稳定摘要 |
| 请求上下文 | 当前用户、权限、请求 ID 和业务时区 |

## 5. 账号、角色与权限

### 5.1 账号

- 账号类型只有 `ADMIN / EMPLOYEE`；本期只创建 `ADMIN` 账号，员工账号只预留模型，不开放创建和登录入口；
- `EMPLOYEE` 账号必须绑定一名员工，一名员工最多一个账号；`ADMIN` 账号不绑定员工；
- 平台不读取员工表，也不校验员工是否存在；员工账号绑定的候选员工由员工模块公开查询提供，平台只保存员工标识；
- 员工离职、返聘时由员工模块调用平台账号服务禁用或启用绑定账号，平台只按主体标识处理；
- 用户名唯一，登录密码只保存哈希，不保存明文；密码使用 Argon2id 或同等级慢哈希，禁止可逆加密；
- 密码策略：至少 10 位，包含大小写字母、数字和符号中的三类；重置密码后撤销该账号全部会话；
- 账号状态只有 `ACTIVE / DISABLED`；禁用账号立即不能登录，已登录会话在下一次鉴权时失效；
- 连续登录失败 5 次锁定 15 分钟，锁定不影响已存在会话；锁定和失败次数写安全审计；
- 登录生成服务端会话，令牌只保存哈希；令牌只通过 `Authorization: Bearer` 传递，不放在 URL、日志或 localStorage；
- 会话有绝对过期时间和空闲超时；退出登录撤销当前会话；
- 账号不物理删除，保留审计；
- 管理员可以创建账号、禁用账号、重置密码和调整角色；不能修改自己的角色，避免自我提权；
- 系统必须至少保留一个启用且拥有 `platform.user.manage` 和 `platform.role.manage` 的管理员账号；禁用或移除最后一个管理员返回 `PLATFORM_LAST_ADMIN_REQUIRED`；
- 老板默认只读，不授予维护权限；
- 初始管理员账号由部署初始化命令创建，不在页面公开注册。

### 5.2 角色

- 角色由管理员维护，包含角色代码、名称、状态和权限集合；每个权限分配单独带数据范围；
- 角色本身不再有统一数据范围，避免一个 `ALL` 角色放大其他角色的 `OWN` 权限；
- 角色状态只有 `ACTIVE / DISABLED`；禁用角色后，该角色不再授予权限，并立即撤销受影响账号的会话；
- 角色不物理删除；角色名称可以修改，角色代码创建后不可修改；
- 一个账号可以绑定多个角色；账号的有效权限是全部启用角色的并集；
- 同一权限的生效数据范围取该权限在各角色中的最宽值：有 `ALL` 即 `ALL`，否则 `OWN`；
- 数据范围只有 `ALL / OWN`；`EMPLOYEE` 账号的每个权限都只能是 `OWN`；
- 初始角色至少包括管理员和老板；管理员角色保存显式权限清单，不使用通配符；
- 角色权限必须来自已声明的权限目录；角色权限变化立即撤销受影响账号的全部会话；
- 不能通过角色组合让 `EMPLOYEE` 账号获得 `platform.*` 管理权限或 `global.*` 管理权限；
- 角色分配和角色权限变化写平台审计。

### 5.3 权限

- 权限代码由业务模块声明，格式为 `module.action`，例如 `product.read`；
- 权限目录记录 `code`、所属模块、说明、是否敏感、可授权账号类型（`ADMIN / EMPLOYEE / BOTH`）；未标注的权限默认只允许 `ADMIN`；
- 平台只保存角色和权限代码的授权关系，不解释业务含义；权限目录在代码中维护，平台不提供新增业务权限的页面；
- 默认拒绝：没有声明权限的接口默认拒绝；启动时校验所有接口都已绑定权限代码，发现未绑定、重复或未注册权限直接启动失败；
- 接口在进入业务逻辑前校验权限；没有权限返回 403，且不先查询资源，避免暴露资源是否存在；
- 管理员角色保存全部已声明权限的显式清单，不使用 `*`；新增权限后需要管理员显式授权；
- 老板角色默认只有读取权限；
- `EMPLOYEE` 账号只能被授予可授权类型为 `EMPLOYEE` 或 `BOTH` 的权限，且每个权限的数据范围只能是 `OWN`；
- `RequestContext` 保存“权限代码 → 数据范围”的映射，业务模块按当前权限落实 `OWN` 过滤，不能只靠前端隐藏；
- 权限变更立即撤销受影响账号的会话，重新登录后按新权限生效；
- 权限矩阵测试必须覆盖每个接口：有权限通过、无权限 403、越权访问他人数据被拒绝。

## 6. 编号

### 6.1 编号序列

| 序列代码 | 前缀 | 宽度 | 示例 | 使用模块 |
|---|---|---|---|---|
| `PRODUCT` | `P-` | 6 | `P-000001` | 商品 |
| `CUSTOMER` | `C-` | 6 | `C-000001` | 客户 |
| `ORDER` | `SO-` | 6 | `SO-000001` | 订单 |
| `SHIPMENT` | `SH-` | 6 | `SH-000001` | 发货 |
| `EMPLOYEE` | `E-` | 6 | `E-000001` | 员工 |
| `GLUE` | `GL-` | 6 | `GL-000001` | 胶水物料 |
| `COLOR_PASTE` | `CP-` | 6 | `CP-000001` | 色浆物料 |

### 6.2 编号规则

- 业务模块在创建事务内调用 `nextNumber(sequenceCode, prefix, width)`；
- 平台锁定序列行并递增，返回格式化编号；
- 编号全局唯一，不重复、不复用；
- 事务回滚可能产生空号，空号不补发；
- 序列达到宽度上限时返回 `PLATFORM_NUMBER_OVERFLOW`，不能截断或复用；
- 业务模块不能自己拼接编号，也不能修改已生成编号；
- 编号只用于业务识别，不承载状态或业务含义。

## 7. 审计

### 7.1 操作审计

- 业务模块写操作必须调用平台审计；
- 审计至少记录操作者、请求 ID、模块、动作、目标类型、目标业务标识、结果摘要和时间；
- 审计只追加，不更新、不删除；
- 审计和业务写入在同一事务内提交；
- 审计失败时业务整体回滚；
- 审计不保存完整业务快照，只保存必要摘要和稳定业务标识；
- 查询审计按权限和日期范围过滤。

### 7.2 敏感数据访问审计

- 电话、地址、成本、利润、工资等敏感字段读取必须记录访问审计；
- 记录操作者、请求 ID、目标类型、目标标识、访问字段和时间；
- 列表批量读取可以按查询条件和结果数量记录，不逐行复制敏感值；
- 敏感访问审计只追加，不更新、不删除；
- 没有权限不能读取敏感字段。

## 8. 文件

### 8.1 文件生命周期

```text
上传为临时文件
→ 业务保存时正式化
→ 建立业务文件引用
→ 业务替换或删除时释放当前引用
→ 历史快照引用不释放
```

### 8.2 文件规则

- 文件内容由平台保存，业务模块只保存文件业务标识；
- 文件状态为 `TEMP / FORMAL / RELEASED`；
- 临时文件只允许上传者访问，超过保留时间未正式化会被清理；
- 业务保存时在业务事务内正式化文件并建立引用；
- 文件引用包含所有者模块、所有者类型、所有者业务标识和用途代码；
- 业务模块不能直接引用未正式化文件；
- 替换文件时建立新引用并释放旧引用；历史快照引用继续有效；
- 文件不保存公开 URL，只能通过平台鉴权读取；
- 平台不保存业务缩略图；图片裁切由页面完成；
- 平台文件策略决定允许的 MIME 类型、最大大小和临时保留时间；
- 业务模块不能绕过平台文件接口访问存储路径。

## 9. 幂等

- 所有业务写命令和平台账号/角色写命令必须携带幂等键；登录、退出、查询和文件读取不要求；
- 平台按操作者、操作类型、幂等键和请求指纹识别重复提交；
- 相同幂等键、相同请求指纹：返回第一次成功结果；
- 相同幂等键、不同请求指纹：返回 `PLATFORM_IDEMPOTENCY_CONFLICT`；
- 同一幂等键正在处理且租约未过期：返回 `PLATFORM_IDEMPOTENCY_IN_PROGRESS`；
- 处理中租约过期后允许接管，`attempt_no` 递增；
- 失败命令标记 `FAILED`，允许同指纹重试，不保存成功结果；
- 成功结果保存时间可配置，过期后清理；
- 幂等记录只用于命令结果复用，不作为业务事实。

## 10. 统一响应与错误

### 10.1 响应信封

成功和失败都返回：

```json
{
  "code": "OK",
  "message": "",
  "fieldErrors": [],
  "requestId": "req-...",
  "data": {}
}
```

- `code`：稳定业务码，来自错误码目录；成功只能是 `OK`，失败不能是 `OK`；
- `message`：按 `code` 的中文提示；前端不解析文案，只按 `code` 分支；
- `fieldErrors`：字段级错误列表，元素为 `{ field, message }`；只用于字段校验；
- `requestId`：请求追踪标识；所有 5xx 必须返回；
- `data`：成功结果或 `null`；
- 响应体不重复携带 HTTP 状态码；HTTP 状态由 `code` 所属类别统一映射，Controller 不手写状态码。

分页结果放在 `data` 内：

```text
items, total, page, size
```

### 10.2 HTTP 映射

`code` 在错误码目录中登记，并按下表映射 HTTP 状态：

| code 类别 | 示例 | HTTP | 是否可重试 |
|---|---|---:|---|
| 成功 `OK` | `OK` | 200 / 201 | — |
| 请求或字段错误 `VALIDATION` | `*_FIELD_INVALID` | 400 | 否，修正后提交 |
| 未登录 `AUTH` | `PLATFORM_UNAUTHORIZED` | 401 | 否，重新登录 |
| 无权限 `FORBIDDEN` | `PLATFORM_FORBIDDEN` | 403 | 否 |
| 不存在 `NOT_FOUND` | `*_NOT_FOUND` | 404 | 否 |
| 状态、版本、幂等冲突 `CONFLICT` | `*_VERSION_CONFLICT` | 409 | 可刷新后重试 |
| 业务规则不满足 `BUSINESS` | `PRODUCTION_NORMAL_PENDING_INSUFFICIENT` | 422 | 否，按提示调整 |
| 频率限制 `LIMIT` | `PLATFORM_RATE_LIMITED` | 429 | 可按退避时间重试 |
| 依赖不可用 `DEPENDENCY` | `PLATFORM_DEPENDENCY_UNAVAILABLE` | 502 / 503 / 504 | 是 |
| 未预期异常 `INTERNAL` | `PLATFORM_INTERNAL_ERROR` | 500 | 是，附 requestId |

规则：

- 成功响应必须是 2xx 且 `code = OK`；失败响应不能是 2xx，也不能出现 2xx + 非 `OK` 的组合；
- 任何未捕获异常、空指针、数据库异常、序列化异常都属于 `INTERNAL`，返回 500 `PLATFORM_INTERNAL_ERROR`，不回 200；
- 500 不返回 SQL、堆栈、类名和内部路径，只返回 `code`、中文提示和 `requestId`；
- 业务错误码由所属模块登记，平台按登记映射传递，不改写成同义错误码；
- 依赖超时或不可用使用 502/503/504，不伪装成业务 4xx 或 500；
- 批量接口部分成功不返回 200；要么整笔成功，要么按失败类别返回非 2xx。

### 10.3 错误码注册与映射

每个错误码在代码中登记为一条目录项：

```text
code, category, httpStatus, ownerModule, messageKey, retryable, logLevel
```

- `code`：模块前缀加原因，大写蛇形，例如 `ORDER_VERSION_CONFLICT`；全局唯一、永不复用；
- `category`：`OK / VALIDATION / AUTH / FORBIDDEN / NOT_FOUND / CONFLICT / BUSINESS / LIMIT / DEPENDENCY / INTERNAL`；
- `httpStatus`：由 category 默认映射，特殊码可以覆盖，但同一 code 只能映射一个状态；
- `ownerModule`：错误码归属模块，业务模块只登记自己的错误码；
- `messageKey`：中文提示的资源键；文案可改，`code` 不可改；
- `retryable`：前端是否显示重试；4xx 默认否，409 和 5xx 默认是；
- `logLevel`：预期 4xx 用 info/warn，5xx 用 error 并在服务端记录堆栈，堆栈不进响应。

目录规则：

- 各模块文档里的错误码表就是登记来源，新增错误码必须同时登记所属类别和 HTTP 映射；
- 模块业务错误默认登记 4xx；表示数据不一致、内部状态损坏、计算或序列化失败的 code 必须登记 `INTERNAL 500`，不能伪装成 422 或 409；
- 例如 `PRODUCTION_QUANTITY_INCONSISTENT`、`PRODUCT_CALCULATION_FAILED`、`ORDER_CALCULATION_FAILED` 属于内部失败，返回 500 并记录 requestId；
- 启动时校验：重复 code、未登记 code、接口未绑定权限、未映射 HTTP 状态直接失败；
- 前端错误码映射由目录生成，不手写散落判断；未识别 code 显示通用提示并附 `requestId`，不显示英文原文；
- 审计和幂等记录保存 `code`，便于按错误码统计；
- 不允许把“HTTP 200 + 错误提示”当作业务失败；发现即按契约违规阻断发布；
- 测试必须覆盖：成功只有 `OK`、未捕获异常返回 500、依赖失败返回 503、限流返回 429、未知 code 前端降级。

## 13. 公开接口设计

### 13.1 登录与上下文

```java
interface PlatformAuthService {
    LoginResult login(LoginCommand command);
    void logout(String token);
}
```

- `LoginCommand`：用户名、密码；
- `LoginResult`：访问令牌、绝对过期时间、空闲超时、账号类型、员工主体（员工账号）、权限集合和权限数据范围映射；
- 登录成功创建 `platform_sessions` 会话，令牌只保存哈希；
- `logout` 撤销当前会话，之后同一令牌失效；
- 登录失败统一提示用户名或密码错误，不区分账号是否存在、禁用或锁定；禁用和锁定只写安全审计；
- 禁用账号、锁定账号不能登录；连续失败达到阈值时写安全审计并锁定；
- 登录成功后返回当前权限集合和每个权限的数据范围；
- 本期只有 `ADMIN` 账号可以登录；`EMPLOYEE` 账号存在但登录入口关闭，返回 `PLATFORM_EMPLOYEE_LOGIN_DISABLED`；
- 登录成功、失败、锁定和退出都写安全审计，不写业务审计。

员工登录启用后，员工模块通过平台账号主体服务同步账号状态：

```java
interface PlatformAccountSubjectService {
    void disableBySubject(
        String subjectType, String subjectBusinessId, String reason
    );
    void enableBySubject(
        String subjectType, String subjectBusinessId, String reason
    );
}
```

- 只允许受信任业务模块内部调用，不暴露为前端接口；
- `subjectType` 只支持 `EMPLOYEE`，按员工业务标识查找绑定账号；
- 本期员工不登录，不调用该服务；启用员工登录后由员工模块在离职/返聘时调用；
- 操作幂等并写平台安全审计。

```text
ResetPasswordCommand: accountRef, newPassword, expectedRowVersion
AssignRolesCommand: accountRef, roleRefs, expectedRowVersion
CreateRoleCommand: roleCode, name, permissions: [{ permissionCode, dataScope }]
UpdateRoleCommand: roleRef, name, expectedRowVersion
ChangeRoleStatusCommand: roleRef, targetStatus, reason, expectedRowVersion
ReplaceRolePermissionsCommand: roleRef, permissions: [{ permissionCode, dataScope }], expectedRowVersion
```

规则：

- 只有 `platform.user.manage` / `platform.role.manage` 可以调用；
- `subjectBusinessId` 由调用方从员工模块查询后提交，平台只保存标识，不读取员工表；
- 不能修改自己的角色；不能禁用或移除最后一个启用管理员；
- 禁用管理员、移除管理员角色等操作必须在账号管理事务内串行化校验，防止并发同时移除最后一个管理员；
- 员工账号不能获得 `platform.*` 或 `global.*` 管理权限，数据范围只能是 `OWN`；
- 角色权限必须来自已声明目录，不能提交未登记权限；
- 账号状态、密码、角色和权限变化立即撤销受影响账号的会话；
- 所有命令写平台审计，必须幂等。

### 13.2 权限

```java
interface PlatformAuthorization {
    RequestContext require(String permissionCode);
    boolean has(String permissionCode);
}
```

- 业务 Controller 在进入业务逻辑前调用 `require`；
- `RequestContext` 包含账号、账号类型、员工主体、请求 ID、权限集合、权限数据范围映射和业务时区；
- 权限不足返回 `PLATFORM_FORBIDDEN`；
- 未登录返回 `PLATFORM_UNAUTHORIZED`；
- 平台不把权限代码解释成业务规则，但负责校验权限代码存在、账号类型可授权和数据范围；
- 业务模块必须在查询和写入时落实 `OWN` 数据范围，不能只靠页面隐藏。

### 13.3 编号

```java
interface PlatformNumberService {
    String nextNumber(String sequenceCode, String prefix, int width);
}
```

- 序列代码、前缀和宽度必须与平台配置一致；
- 不匹配返回 `PLATFORM_NUMBER_CONFIG_INVALID`；
- 在业务事务内生成，失败随业务回滚；
- 编号不复用。

### 13.4 审计

```java
interface PlatformAuditRecorder {
    void record(PlatformAuditEntry entry);
    void recordFailure(PlatformAuditEntry entry);
    void recordSecurity(PlatformAuditEntry entry);
    void recordSensitiveAccess(SensitiveAccessEntry entry);
}
```

- `record` 使用 `MANDATORY` 事务，加入成功的业务事务；审计失败业务回滚；
- `recordFailure` 使用 `REQUIRES_NEW`，用于业务失败、登录失败和权限拒绝；不能加入会被回滚的业务事务；
- `recordSecurity` 使用 `REQUIRES_NEW`，记录登录成功、退出、锁定等安全事件；
- `recordSensitiveAccess` 使用独立事务，记录敏感字段读取，不记录敏感值；
- 业务模块不直接写审计表；
- 敏感访问审计只记录字段名，不记录敏感值。

### 13.5 文件

```java
interface PlatformFileService {
    TempFileRef uploadTemp(UploadTempFileCommand command);
    FileReferenceRef formalize(FormalizeFileCommand command);
    FileReferenceRef attach(AttachFileCommand command);
    void release(FileReferenceRef referenceRef, String reason);
    FileContentView readContent(FileReferenceRef referenceRef, String permissionCode);
}
```

- `uploadTemp` 返回临时文件引用；
- `formalize` 在业务事务内把临时文件转正式并建立所有者引用；
- `attach` 给已正式文件追加一个新的所有者引用，返回引用标识；快照等历史引用使用它，不重复上传文件；
- `AttachFileCommand`：`fileBusinessId, ownerType, ownerBusinessId, purposeCode`；一个所有者同一用途只允许一个活动引用；
- `release` 按引用标识释放当前业务引用，正式文件仍保留给其他引用或历史快照；
- `readContent` 校验权限、引用状态和文件所有者；不能只凭文件业务标识跨模块读取；
- 业务模块先校验自己的业务权限（例如 `product.update` / `product.read`），再调用平台文件接口；平台文件接口不要求调用者额外拥有 `platform.file.manage`；
- `platform.file.read` / `platform.file.manage` 只用于平台自己的文件管理页，不替代业务读取权限；
- 临时文件超过保留时间由平台清理；
- 业务模块不访问存储路径。

### 13.6 幂等

```java
interface PlatformIdempotencyService<T> {
    IdempotentResult<T> execute(
        IdempotencyKey key,
        String operationCode,
        String requestFingerprint,
        Supplier<T> command
    );
}
```

- 幂等键、操作者和操作类型组成唯一键；
- 命令入口先在平台独立短事务写入或接管 `PROCESSING`，设置租约，再执行业务；
- 成功响应和业务结果在同一业务事务内更新为 `SUCCEEDED`；失败用独立事务标记 `FAILED`；
- 所有业务写命令和平台账号/角色写命令必须带幂等键；登录、退出、查询和文件读取不要求；
- 相同键和指纹返回第一次成功结果；
- 相同键不同指纹返回 `PLATFORM_IDEMPOTENCY_CONFLICT`；
- 处理中且租约未过期返回 `PLATFORM_IDEMPOTENCY_IN_PROGRESS`；
- 处理中租约过期后允许接管，`attempt_no` 递增；原处理者不能提交旧结果；
- 失败标记 `FAILED`，同键同指纹允许重新尝试；成功结果保留到 `expires_at`；
- 成功响应和业务结果在同一业务事务内更新幂等记录；失败状态和失败审计用独立事务写入；
- 过期记录由清理任务删除，不删除仍在租约内的记录。

### 13.7 响应

- 所有 HTTP 接口使用统一信封；
- 平台提供 `ApiResponse<T>` 和 `FieldError`；
- 业务错误码使用所属模块登记的错误码，并按 10.3 的目录映射 HTTP 状态；
- 请求 ID 由平台生成并写入响应和审计；
- 未捕获异常统一转成 500 `PLATFORM_INTERNAL_ERROR`，不返回内部异常、SQL、堆栈和存储路径。

## 14. 事务与并发

### 14.1 登录

```text
校验用户名和密码
→ 校验账号锁定、账号状态和账号类型
→ 生成访问令牌和令牌哈希
→ 写会话记录
→ 重置连续失败次数
→ 返回账号类型、员工主体、权限和权限数据范围
```

登录不写业务数据；登录成功、失败、锁定和退出都写安全审计。登录失败累计连续失败次数，达到阈值写锁定截止时间；退出登录把当前会话改为 `REVOKED`，之后同一令牌鉴权失败。

### 14.2 权限校验

- 每次请求解析令牌并校验会话状态、空闲超时和绝对过期时间；通过后更新 `last_seen_at` 和滑动 `expires_at`；
- 会话撤销、过期、账号禁用、角色禁用或角色权限变化立即失效；
- 权限校验在业务事务之前；
- 权限不足不进入业务逻辑；
- 权限数据范围随 `RequestContext` 传给业务模块，业务模块按当前权限负责行级过滤。

### 14.3 编号

```text
锁定序列行
→ 读取 next_value
→ 校验宽度
→ 递增 next_value
→ 返回格式化编号
```

- 序列行使用 `FOR UPDATE`；
- 编号在业务事务内生成；
- 业务回滚不回收编号。

### 14.4 审计

- 成功业务审计加入业务事务；失败审计、登录/安全审计和敏感访问审计使用独立事务；
- 审计记录只插入；
- 敏感访问审计在读取成功后插入；
- 审计失败不吞掉成功业务审计；失败审计写入失败记录服务端日志，不阻断原失败响应。

### 14.5 文件

- 上传临时文件不进入业务事务；
- 正式化和文件引用加入业务事务；
- 替换文件时先建立新引用，再释放旧引用；
- 历史快照引用不释放；
- 临时文件清理不影响已正式文件。

### 14.6 幂等

- 幂等键和指纹在命令入口校验；
- 同一幂等键并发只允许一个处理；
- 处理中带租约，过期可接管并递增尝试号；
- 成功后在同一业务事务保存响应；
- 失败标记 FAILED 并允许同指纹重试；
- 过期记录由清理任务删除。

## 15. 历史与追溯

- 操作审计和敏感访问审计只追加，不更新、不删除；
- 文件释放保留记录，不物理删除已正式文件；
- 编号空号保留，不补发；
- 账号和角色不物理删除；
- 权限变更写审计；
- 平台不保存业务快照和业务历史，业务历史由业务模块负责。

## 18. 验收标准

### 18.1 账号与权限

- [ ] 本期管理员和老板可以登录；员工登录入口关闭，`EMPLOYEE` 账号不能登录；

- [ ] 退出登录后同一令牌立即失效；
- [ ] 会话过期后不能继续访问；
- [ ] 禁用账号后不能登录，已登录会话失效；
- [ ] 连续登录失败达到阈值后账号被临时锁定；
- [ ] 密码只保存哈希，不保存明文；
- [ ] 角色可以绑定多个账号，一个账号可以绑定多个角色；
- [ ] 禁用角色或修改角色权限后，受影响账号的会话立即失效；
- [ ] 无权限请求返回 403，不泄露资源是否存在；
- [ ] 管理员角色保存显式权限清单，不使用通配符；
- [ ] 老板角色默认只读；
- [ ] `EMPLOYEE` 账号只能获得员工可授权权限，且每个权限只能是 `OWN` 数据范围；
- [ ] 数据范围按权限计算，不能因一个角色 `ALL` 放大另一角色的 `OWN` 权限；
- [ ] 不能修改自己的角色，不能禁用或移除最后一个启用管理员；
- [ ] 业务查询按 `RequestContext` 的数据范围落实 `OWN` 过滤；
- [ ] 权限矩阵覆盖每个接口的有权限、无权限和越权访问。

### 18.2 编号

- [ ] 七个编号序列按固定前缀和宽度生成；
- [ ] 编号唯一、不重复、不复用；
- [ ] 业务回滚产生空号但不补发；
- [ ] 业务模块不能自行拼接编号；
- [ ] 超过宽度返回 `PLATFORM_NUMBER_OVERFLOW`。

### 18.3 审计

- [ ] 业务写操作审计和业务写入同事务提交；
- [ ] 审计失败时业务回滚；
- [ ] 审计只追加，不更新、不删除；
- [ ] 敏感字段读取记录访问审计，不记录敏感值；
- [ ] 业务失败、登录失败和权限拒绝的审计用独立事务写入，不随业务回滚。
- [ ] 审计日志按权限和日期筛选。

### 18.4 文件

- [ ] 临时文件可以上传和预览，不能直接被业务引用；
- [ ] 已正式文件可以通过 `attach` 追加所有者引用，快照不重复上传文件；
- [ ] 业务保存时在事务内正式化文件并建立引用；
- [ ] 替换文件释放旧引用，历史快照引用继续有效；
- [ ] 文件只能通过鉴权读取，不暴露存储路径；
- [ ] 临时文件超时清理不影响正式文件；
- [ ] 文件类型和大小限制生效；
- [ ] 业务模块只保存文件业务标识，不保存二进制。

### 18.5 幂等与响应

- [ ] 相同幂等键和请求指纹重复提交返回第一次结果；
- [ ] 处理中带租约，过期可接管，失败可同指纹重试；
- [ ] 相同幂等键不同请求指纹返回冲突；
- [ ] 同一幂等键处理中返回处理中错误；
- [ ] 失败命令可以修正后重试；
- [ ] 所有接口使用统一响应信封；
- [ ] 错误响应包含 requestId、code、message 和 fieldErrors；
- [ ] 2xx 响应的 code 只能是 `OK`；非 `OK` code 不能返回 2xx；
- [ ] 未捕获异常返回 500 `PLATFORM_INTERNAL_ERROR`，附 requestId，不返回堆栈；
- [ ] 依赖不可用返回 502/503/504，限流返回 429；
- [ ] 所有错误码已登记且只有一个 HTTP 映射；重复、未登记或未映射启动失败；
- [ ] 前端按 code 映射处理，未识别 code 显示通用提示和 requestId；
- [ ] 不返回堆栈、SQL 和内部路径。

### 18.6 边界

- [ ] 平台模块不保存商品、客户、订单、员工、生产和全局配置业务数据；
- [ ] 平台模块不计算金额、成本、工资和产能；
- [ ] 平台模块不管理静态数据和全局参数；
- [ ] 业务模块不直接读平台表；
- [ ] 业务模块之间不共享表、不建跨模块外键、不做跨模块 JOIN，读取和写入只走目标模块公开方法；
- [ ] 本期员工不登录，账号模型预留 `EMPLOYEE` 主体；

## 20. 与 V2 的主要差异

| V2 平台能力 | V3 平台模块 |
|---|---|
| 账号、权限、编号、审计、文件分散在平台和业务模块 | 统一收口到平台模块 |
| 员工可能绑定登录账号 | 本期员工不登录；账号模型预留 `EMPLOYEE` 主体和员工绑定 |
| 编号由各模块自行生成 | 平台统一序列和固定前缀 |
| 审计由各模块自行记录 | 平台统一操作审计和敏感访问审计 |
| 文件由业务模块保存路径或二进制 | 平台统一文件生命周期和引用 |
| 幂等和响应格式不统一 | 统一幂等键、响应信封和错误码 |
| 全局配置和平台能力混在一起 | 平台只做技术底座，全局模块单独管业务配置 |

## 21. 外部依赖

### 21.1 业务模块

所有业务模块通过平台公开接口使用：

```text
PlatformAuthService
PlatformAuthorization
PlatformAccountSubjectService（启用员工登录后由员工模块调用）
PlatformNumberService
PlatformAuditRecorder
PlatformFileService
PlatformIdempotencyService
ApiResponse / FieldError
```

要求：

- 业务模块只声明权限代码，不管理账号和角色；
- 业务模块只调用编号、审计、文件和幂等服务，不直接读平台表；
- `PlatformAccountSubjectService` 只在员工登录启用后由员工模块调用，用于按员工主体禁用/启用账号；
- 业务模块不把平台错误改写成业务错误；
- 业务模块不把业务数据塞进平台表；
- 平台模块不导入业务模块的任何类型。

### 21.2 运行环境

- 平台账号、角色和权限数据需要在部署初始化时创建管理员；
- 文件存储、数据库和日志由运行环境提供；
- 平台模块不负责部署、备份和恢复；
- 平台模块不负责对象存储厂商选型。

## 22. 已确认口径

1. 平台模块是技术底座，不参与业务模块序号；全局模块仍是 `00`。
2. 平台和全局模块后端分开，页面入口可以合并到“设置”菜单。
3. 本期账号只给管理员和老板登录；账号模型支持 `ADMIN / EMPLOYEE`，员工账号和绑定预留但不开放。
4. 权限使用角色 + 权限代码 + 数据范围模型，权限代码由业务模块声明；默认拒绝，不使用通配符。
5. 员工账号只能获得员工可授权权限和 `OWN` 数据范围；不能获得平台或全局管理权限。
6. 编号统一由平台生成：`P/C/SO/SH/E/GL/CP`。
7. 审计、敏感访问审计、文件生命周期和幂等统一由平台负责。
8. 所有接口使用统一响应信封和登记式错误码；HTTP 状态由 code 类别映射，2xx 只能是 `OK`。
9. 平台不保存业务数据，不做业务计算。
10. 业务模块只通过公开接口调用平台，不直接读平台表。
