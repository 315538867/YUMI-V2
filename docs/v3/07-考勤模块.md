# V3 考勤模块

> 模块代码：`attendance`  
> 文档版本：V3.0  
> 编写日期：2026-10-30  
> 状态：V3 考勤模块评审稿；评审通过前不进入页面实现

本文是 V3 考勤模块的唯一需求与设计依据。考勤模块只记录员工在某一天实际出勤、请假和加班的时间事实，并向工资模块提供逐日记录和期间汇总；不做排班、不做生产记录、不计算工资、不判断迟到早退和缺勤。

## 摘要

- 考勤记录按“员工 × 工作日期”唯一，一天一条；多段工作用休息分钟合并，不拆成多条记录。
- 每条记录保存上班时间、下班时间、休息分钟、请假分钟、请假类型和加班分钟。
- 出勤分钟 = 上下班跨度 − 休息分钟 − 请假分钟；分钟为权威，页面按小时展示。
- 加班分钟是出勤分钟的子集，不额外加到出勤上；工资按“出勤 − 加班”和加班分钟分别结算。
- 请假按分钟和类型记录；本期不判断缺勤、迟到、早退，因为这些都需要班次基准，排班不是考勤依据。
- 工作日期当天的岗位由员工模块的岗位记录解析并冻结到考勤记录；工资不再按员工当前岗位重新解释历史。
- 员工身份保存员工快照引用；员工改名、调岗或离职不改变已经登记的考勤。
- 考勤独立于排班和生产：没有计划也能登记；计划不会自动生成考勤；生产记录不写考勤。
- 考勤记录可以更正，错录可以作废；不硬删除，作废记录保留。
- 内容版本在记录变化时递增；工资结算保存逐日内容版本和期间汇总指纹，之后修改考勤不回溯已结算工资。
- 出勤分钟和期间汇总在考勤模块本地计算，不调用计算中心；金额、工资和成本公式仍归计算中心。
- 考勤不读取任何全局数值参数，只读取岗位显示名称；工资按出勤分钟和考勤记录中的岗位代码读取岗位时薪。
- 本期由管理员手工登记，员工不登录，也不依赖打卡机；后续接入设备或员工自助登记时只增加数据来源，不改考勤记录模型。
- 本模块 1 张表。

## 1. 模块说明

考勤模块管理“谁在哪一天来了多久、请了多久假、其中多少时间算加班”。

考勤记录是一条时间事实，不是排班结果，也不是工资结果。管理员按天登记员工的上下班跨度、休息、请假和加班；考勤模块只做时间相减和期间汇总，不判断员工当天是否应该上班，也不计算应发金额。

考勤模块回答“某员工某天出勤多少分钟、请假多少分钟、加班多少分钟”；生产模块回答“某员工某天完成了多少合格数量”；工资模块回答“按岗位规则应发多少工资”。三者通过公开查询组合，不互相写表。

## 2. 用户与使用场景

### 2.1 用户

| 用户 | 关心什么 | 在考勤模块做什么 |
|---|---|---|
| 管理员 | 每天谁来了、来了多久、请了多少假、加了多少班 | 按月逐个员工登记和更正考勤 |
| 生产负责人 | 当天实际到岗和工作时长 | 查看月度考勤，补充或更正当天记录 |
| 老板 | 月度出勤天数、出勤小时、请假和加班情况 | 查看考勤汇总 |
| 工资 | 某员工某期间逐日出勤、请假、加班和岗位 | 通过考勤公开查询读取，保存结算指纹 |
| 报表 | 员工维度、岗位维度的考勤汇总 | 通过考勤公开查询或后续报表投影读取 |

### 2.2 现状与目标

管理员现在用 Excel 按月记录兼职员工的上班时间、下班时间、请假和加班，月底再手工汇总。

V3 把这张表变成可查询的考勤事实：

- 每名员工每天一条记录，按月份网格登记，不再维护多份 Excel；
- 出勤分钟由上下班跨度自动计算，减少手算错误；
- 请假和加班单独记录，工资可以按不同口径取数；
- 岗位按工作日期确定，调岗后历史考勤不会被新岗位覆盖；
- 员工改名或离职后，历史考勤仍显示登记当时的员工身份；
- 工资结算保存考勤指纹，月底结算后修改考勤不会悄悄改变已发工资。

本期没有打卡机也能完整使用：管理员按当天实际情况登记上下班时间、休息、请假和加班；系统不要求设备流水，也不校验登记来源。以后买了打卡机，只增加导入或对接来源，考勤记录仍按员工和工作日期保存。

## 4. 业务概念

| 术语 | 定义 |
|---|---|
| 考勤记录 | 一名员工在一个工作日的出勤、请假和加班事实 |
| 工作日期 | 考勤归属的自然日，使用本地日期 |
| 上下班跨度 | 当天从上班时间到下班时间的连续时间段，包含中间的休息和请假 |
| 休息分钟 | 跨度内不计入工作的休息时间，例如午休 |
| 请假分钟 | 跨度内不计入工作的请假时间；全天请假时可以没有上下班时间 |
| 出勤分钟 | 跨度扣除休息和请假后的实际工作时长 |
| 加班分钟 | 出勤分钟中经管理员确认需要按加班口径结算的部分，是出勤分钟的子集 |
| 记录状态 | 考勤记录当前是否有效，只有 `ACTIVE` 和 `VOIDED` |
| 内容版本 | 记录时间或状态变化时递增的版本号，供工资识别考勤是否变化 |
| 员工快照 | 登记考勤时冻结的员工身份引用 |
| 就业期间 | 员工某一段在职区间，由员工就业记录推导 |
| 岗位期间 | 员工在某段日期内承担的岗位，由员工岗位记录推导 |
| 期间汇总指纹 | 按期间逐日记录和内容版本生成的内容指纹，供工资冻结 |

考勤记录与员工、岗位和工资的关系：

```text
员工 1 ── N 考勤记录
员工岗位期间 1 ── N 考勤记录（按工作日期取当天岗位）
考勤记录 1 ── 1 员工快照引用
考勤记录 N ── 1 期间汇总（按员工和日期范围汇总）
期间汇总 ── 1 汇总指纹（供工资结算冻结）
```

## 5. 字段定义

### 5.1 考勤记录

| 字段 | 必填 | 类型/精度 | 规则 |
|---|---|---|---|
| 记录业务标识 | 系统 | `VARCHAR(64)` | 稳定标识，不对外显示 |
| 员工 | 是 | `VARCHAR(64)` | 员工业务标识；员工必须存在 |
| 员工快照引用 | 系统 | `VARCHAR(64)` + 版本 | 登记时冻结员工身份，只保存引用 |
| 工作日期 | 是 | `DATE` | 本地自然日；不得晚于当天 |
| 上班时间 | 条件 | `TIME` | 当天考勤跨度起点；全天请假时可为空；精确到分钟 |
| 下班时间 | 条件 | `TIME` | 当天考勤跨度终点；必须晚于上班时间且同一天；全天请假时可为空 |
| 休息分钟 | 是 | `INT` | 大于等于 0 且不超过跨度；没有上下班时间时固定为 0 |
| 出勤分钟 | 系统 | `INT` | 大于等于 0；由服务端计算，不接受客户端提交 |
| 请假分钟 | 是 | `INT` | 大于等于 0；有上下班时间时不超过“跨度 − 休息分钟” |
| 请假类型 | 条件 | `VARCHAR(16)` | `PERSONAL / SICK / OTHER`；请假分钟大于 0 时必填，否则为空 |
| 加班分钟 | 是 | `INT` | 大于等于 0 且不超过出勤分钟；是出勤分钟的子集 |
| 岗位代码 | 系统 | `VARCHAR(64)` | 工作日期当天员工岗位；由服务端解析并冻结 |
| 备注 | 否 | `VARCHAR(500)` | 记录说明；不参与计算 |
| 记录状态 | 系统 | `ACTIVE / VOIDED` | 新建为 `ACTIVE`；只有作废能变为 `VOIDED` |
| 内容版本 | 系统 | `BIGINT` | 新建为 1；任何更新或作废都递增 |
| 行版本 | 系统 | `BIGINT` | 并发控制；任何更新或作废都递增 |
| 作废原因 | 作废必填 | `VARCHAR(300)` | 作废时填写 |
| 作废时间/操作人 | 作废必填 | `DATETIME(6)` / `VARCHAR(64)` | 作废时记录 |
| 创建/更新时间与操作人 | 系统 | `DATETIME(6)` / `VARCHAR(64)` | 审计字段 |

同一员工、同一工作日期只能有一条 `ACTIVE` 记录；作废后可以重新登记同一天考勤。

### 5.2 请假与加班

| 类型 | 代码 | 说明 |
|---|---|---|
| 事假 | `PERSONAL` | 个人原因请假 |
| 病假 | `SICK` | 因病请假 |
| 其他 | `OTHER` | 其他请假 |

规则：

- 请假只记录分钟和类型，不记录审批状态、审批人和请假余额；
- 一天只记录一种请假类型；同一天存在多种请假类型时，本期不做拆分；
- 请假分钟是当天考勤跨度内未工作的时间，不是独立于考勤的请假单；
- 加班分钟是出勤分钟中需要按加班口径结算的部分，不额外增加出勤分钟；
- 加班原因写在备注，不建加班事由字典；
- 请假是否带薪、加班是否加倍，由工资模块按工资规则判断，考勤模块不判断。

### 5.3 岗位与员工身份

| 字段 | 说明 |
|---|---|
| 员工 | 考勤归属的员工业务标识 |
| 员工快照引用 | 登记时的员工身份，包含员工编号、姓名、岗位代码和岗位名称 |
| 岗位代码 | 工作日期当天该员工承担的岗位，冻结在考勤记录上 |

规则：

- 岗位按工作日期从员工岗位期间解析，不使用员工当前岗位；
- 员工当天存在多个岗位期间时属于数据异常，拒绝保存并返回 `ATTENDANCE_POSITION_NOT_FOUND`；
- 岗位代码冻结后，员工以后调岗不改变已有考勤；
- 岗位显示名称按全局模块当前名称展示，不另存名称；
- 员工快照只用于身份展示和工资追溯，不用考勤快照判断员工当天是否在职；
- 考勤展示岗位名称时使用全局当前名称，不使用员工快照中的岗位名称；
- 员工姓名变化不改变已有考勤记录中解析出的员工快照。

### 5.4 系统字段

| 字段 | 说明 |
|---|---|
| `record_business_id` | 稳定的记录业务标识，不对外显示 |
| `active_record_key` | 活动记录唯一键；`ACTIVE` 时为员工和日期，`VOIDED` 时为记录标识 |
| `content_version` | 记录时间或状态变化时递增；工资用它识别考勤变化 |
| `row_version` | 并发编辑控制；任何记录更新都递增 |
| `created_at / created_by` | 创建时间和操作人 |
| `updated_at / updated_by` | 最近修改时间和操作人 |

### 5.5 分钟计算与显示口径

```text
跨度分钟 = 下班时间（clockOutTime） − 上班时间（clockInTime）

出勤分钟（workedMinutes）
= 跨度分钟 − 休息分钟（breakMinutes） − 请假分钟（leaveMinutes）
```

示例：

```text
当天考勤跨度 09:00–18:00，午休 60 分钟，上午请假 120 分钟
→ 出勤分钟 = 540 − 60 − 120 = 360 分钟（6 小时）
```

约束：

- 上下班时间必须精确到分钟，不允许秒；带秒的输入返回 `ATTENDANCE_TIME_INVALID`；
- 下班时间必须晚于上班时间，且必须在同一天，不支持跨天；
- 有上下班时间时：
  - `0 < 跨度分钟 ≤ 1440`；
  - `0 ≤ 休息分钟 ≤ 跨度分钟`；
  - `0 ≤ 请假分钟 ≤ 跨度分钟 − 休息分钟`；
- `出勤分钟 + 请假分钟 ≤ 1440`；
- `出勤分钟 ≥ 0`；
- `0 ≤ 加班分钟 ≤ 出勤分钟`；
- 全天请假允许不填上下班时间，此时出勤分钟固定为 0，休息分钟和加班分钟必须为 0，请假分钟必须大于 0；
- 有上下班时间且请假分钟等于“跨度 − 休息分钟”时，出勤分钟为 0，视为当天全部请假；
- 出勤分钟和请假分钟不能同时为 0；只记录加班不记录出勤不成立。

时间精度：

- 存储和工资结算都以分钟为权威；
- 页面可以按小时展示，保留两位小数，例如 7.50 小时；
- 工资不得使用页面四舍五入后的小时数反推金额，必须使用考勤分钟；
- 不按工作日小时数或有效工时率反推出勤分钟，这些参数不参与考勤时间计算。

## 6. 业务规则

### R1 记录粒度与唯一性

- 一名员工一个工作日期只能有一条 `ACTIVE` 考勤记录；
- 一天内的多段工作用休息分钟合并为一条记录，不拆成多条；
- 同一员工同一日期重复登记返回 `ATTENDANCE_RECORD_DUPLICATE`；
- 记录作废后，同一员工同一日期可以重新登记；
- 工作日期使用本地日期，不使用时间戳日期；
- 工作日期不得晚于当天，未来日期不能登记；
- 本期不支持跨天班次；跨天工作由管理员按自然日拆分并备注，系统不自动拆分；
- 考勤记录只按员工和日期识别，不要求先有排班计划或生产任务。

### R2 创建考勤记录

- 员工必须存在，否则返回 `ATTENDANCE_EMPLOYEE_NOT_FOUND`；
- 工作日期必须落在员工某一段就业期间内，否则返回 `ATTENDANCE_WORK_DATE_OUT_OF_EMPLOYMENT`；
- 就业期间按入职、离职和返聘记录推导；离职日期当天算在就业期间内，返聘后新期间从返聘日期开始；
- 按工作日期解析员工岗位，必须恰好落在一条岗位期间内，否则返回 `ATTENDANCE_POSITION_NOT_FOUND`；
- 取得员工当前快照引用，员工快照只用于身份展示和工资追溯；
- 校验时间、休息、请假和加班字段，计算并写入出勤分钟；
- 新建记录状态为 `ACTIVE`，`content_version = 1`，`row_version = 1`；
- 写入平台审计；
- 任一步失败整体回滚，不保存记录，也不留下孤立快照。

### R3 更正考勤记录

- 只有 `ACTIVE` 记录可以更正；已作废记录不能更正，返回 `ATTENDANCE_RECORD_NOT_ACTIVE`；
- 更正必须携带 `expectedRowVersion`，与记录行版本不一致返回 `ATTENDANCE_RECORD_VERSION_CONFLICT`；
- 可以更正上班时间、下班时间、休息分钟、请假分钟、请假类型、加班分钟和备注；
- 可以更正员工和工作日期；员工或工作日期变化时，重新校验就业期间、解析岗位并取得员工快照；
- 更正后重新计算出勤分钟，更新 `active_record_key`、递增 `content_version` 和 `row_version`；
- 更正后与其他活动记录冲突时返回 `ATTENDANCE_RECORD_DUPLICATE`，原记录不变；
- 每次更正写平台审计，保存修改前后字段摘要；
- 更正不修改已作废记录和其他日期的记录。

### R4 作废考勤记录

- 只有 `ACTIVE` 记录可以作废；
- 作废必须填写原因和 `expectedRowVersion`；
- 作废后状态变为 `VOIDED`，`active_record_key` 改为记录业务标识，写入作废原因、作废时间和操作人；
- 作废递增 `content_version` 和 `row_version`；
- 作废不删除记录，不修改业务字段和出勤分钟；
- 作废记录不参与默认查询和期间汇总，但可以在明细中按“包含已作废”查看；
- 作废写平台审计。

### R5 工作时间与出勤分钟

- 上下班时间表示当天的考勤跨度，不是多次上下班流水；
- 跨度内的午休和其他休息填休息分钟，不拆分记录；
- 跨度内的请假填请假分钟和请假类型，从跨度中扣除；
- 出勤分钟由服务端计算，客户端提交的出勤分钟忽略；
- 出勤分钟最大值不超过 1440 分钟；
- 上下班时间带秒、下班早于或等于上班、时间差为 0 时返回 `ATTENDANCE_TIME_INVALID`；
- 休息、请假或加班超出范围，或出勤分钟计算为负时返回 `ATTENDANCE_MINUTES_INVALID`；
- 服务端写入的出勤分钟与时间跨度不一致时返回 `ATTENDANCE_MINUTES_INCONSISTENT`，不能静默修正。

### R6 请假

- 请假分钟大于 0 时必须填写请假类型，否则返回 `ATTENDANCE_LEAVE_TYPE_REQUIRED`；
- 请假类型必须是 `PERSONAL / SICK / OTHER` 之一，否则返回 `ATTENDANCE_LEAVE_TYPE_INVALID`；
- 请假分钟为 0 时请假类型必须为空；
- 一天只允许一种请假类型；
- 请假不做审批流，登记即生效；
- 请假是否带薪、按什么比例带薪，由工资模块决定；
- 考勤模块不保存年假、调休和请假余额。

### R7 加班

- 加班分钟必须小于等于出勤分钟，否则返回 `ATTENDANCE_MINUTES_INVALID`；
- 加班分钟是出勤分钟的子集，不额外增加出勤分钟；
- 加班原因写在备注，不单独建加班记录表；
- 加班倍率、加班费和调休由工资模块决定；
- 考勤模块不判断加班是否经过审批。

### R8 员工、岗位与就业期间

- 工作日期必须落在员工就业期间内；就业期间包含离职日期当天，返聘后的新期间从返聘日期开始；
- 岗位按工作日期从员工岗位期间解析，只有一条岗位期间覆盖该日期时才允许保存；
- 岗位代码由服务端写入并冻结，客户端提交的岗位代码忽略；
- 员工改名、调岗、离职或返聘不修改已有考勤记录；
- 员工岗位记录事后补录或调整不修改已有考勤的岗位代码；确需变更时由管理员更正考勤记录；
- 离职员工可以在就业期间内补录历史考勤；
- 员工当前是否在职不作为登记历史考勤的阻断条件；
- 考勤模块不保存员工档案、岗位期间或就业期间，只保存员工标识、员工快照引用和岗位代码。

### R9 与排班、生产解耦

- 考勤不需要排班计划即可登记；
- 排班计划不自动生成考勤记录；
- 生产记录不生成考勤记录，考勤记录不生成生产记录；
- 考勤不校验当天是否有计划、计划是否完成、生产数量多少；
- 生产模块不读取考勤记录，工资模块分别读取生产和考勤；
- 考勤不修改订单、商品、员工、生产和工资数据。

### R10 与工资边界

- 考勤只提供逐日时间事实和期间汇总，不计算工资、金额、成本和提成；
- 工资通过考勤公开查询读取 `ACTIVE` 记录，不直接读考勤表；
- 工资参考运行指纹包含逐日 `contentVersion` 或期间 `summaryFingerprint`，用于识别结算后考勤是否变化；
- 考勤模块不知道工资期间和结算状态，也不提供月结锁定；
- 考勤记录在工资结算后仍可更正；已结算工资不自动回调，差异和新版本由工资模块处理；
- 工资按工资周期间开始日和岗位代码读取岗位时薪；工作日小时数和有效工时率不参与工资，考勤也不读取这些数值参数；
- 工资的金额公式仍归工资模块和计算中心，考勤模块不调用计算中心。

### R11 与全局参数边界

- 考勤不读取 `WORKDAY_HOURS`、`PRODUCTIVE_WORK_RATE`、`DAILY_WORK_MINUTES` 和岗位时薪；
- 出勤分钟完全由上下班跨度、休息和请假计算，不由工作日参数推导；
- 考勤只读取岗位显示名称，不维护岗位静态数据；
- 修改全局参数不回溯已有考勤记录。

### R12 审计

- 考勤记录创建、更正和作废必须写平台审计；
- 审计记录操作者、时间、记录标识、员工、工作日期、修改前后摘要和作废原因；
- 考勤模块不建字段级变更历史表，平台审计是操作追溯依据；
- 考勤记录本身保留作废状态和原因，作为业务追溯依据；
- 考勤不记录敏感数据访问审计，因为考勤不保存电话、住址等敏感字段。

### R13 权限

- 查看考勤网格、明细和汇总需要 `attendance.read`；
- 创建、更正和作废考勤需要 `attendance.manage`；
- 工资通过内部公开查询读取，按调用方权限鉴权；
- 考勤模块不管理角色和权限，只声明权限代码；
- 本期员工不登录，不提供员工本人查看或登记入口。

### R14 查询与汇总

- 默认只返回 `ACTIVE` 记录；查看已作废记录必须显式选择；
- 按期间查询时，日期范围不得超过 366 天；
- 期间查询一次最多读取 200 名员工，超过返回 `ATTENDANCE_PERIOD_RANGE_INVALID`；
- 期间汇总只累加 `ACTIVE` 记录；
- 出勤天数按出勤分钟大于 0 的日期数统计；
- 请假天数按请假分钟大于 0 的日期数统计；
- 加班分钟按逐日加班分钟求和，不重复计入出勤小时；
- 汇总按员工、工作日期稳定排序；
- 汇总指纹由逐日记录标识、工作日期、岗位代码、出勤分钟、请假分钟、请假类型、加班分钟和内容版本生成；
- 相同记录和相同内容版本必须生成相同指纹；
- 记录更正或作废后，指纹必须变化；
- 汇总指纹只用于工资冻结和变化识别，不是工资金额或业务状态的替代。

## 7. 状态设计

### 7.1 记录状态

| 当前状态 | 操作 | 目标状态 | 说明 |
|---|---|---|---|
| `ACTIVE` | 作废 | `VOIDED` | 写入作废原因、时间和操作人 |
| `ACTIVE` | 更正 | `ACTIVE` | 更新业务字段，递增内容版本和行版本 |
| `VOIDED` | 更正 | 不允许 | 已作废记录不能恢复或修改 |
| `VOIDED` | 作废 | 不允许 | 不能重复作废 |
| `VOIDED` | 重新登记 | 新建 `ACTIVE` | 同一员工同一日期重新创建记录 |

考勤没有审批状态、锁定状态和删除状态。工资结算状态归工资模块，不写回考勤。

### 7.2 单日考勤形态

单日考勤形态由记录内容派生，不单独存储：

| 形态 | 条件 | 页面表现 |
|---|---|---|
| 出勤 | 出勤分钟大于 0 | 显示出勤小时；有加班时追加加班标记 |
| 仅请假 | 出勤分钟等于 0 且请假分钟大于 0 | 显示请假和请假类型 |
| 无记录 | 没有 `ACTIVE` 记录 | 显示空单元格 |

本期没有“缺勤”形态。没有记录只表示没有登记，不代表员工应当出勤或工资应扣款。

## 8. 数据模型与表设计

### 8.1 关系

```text
attendance_records
└─ 员工（employee_business_id）
   ├─ 员工快照引用（employee_snapshot_business_id + version）
   └─ 岗位代码（position_code，按工作日期解析）
```

考勤模块只建一张考勤记录表。员工、岗位期间、就业期间、工资期间和生产记录都由对应模块保存，考勤只保存引用和当天岗位代码。

### 8.2 表清单

| 表 | 类别 | 用途 |
|---|---|---|
| `attendance_records` | 当前记录 + 作废历史 | 员工每日出勤、休息、请假和加班事实 |

不建以下表：

- 不建原始打卡流水表，考勤记录就是管理员登记后的时间事实；
- 不建请假单表，请假分钟和类型直接记录在当天考勤上；
- 不建加班单表，加班分钟和备注直接记录在当天考勤上；
- 不建考勤快照表，员工身份用员工快照引用，岗位代码随记录冻结；
- 不建月结锁定表，结算状态归工资模块；
- 不建考勤汇总表，汇总按需从考勤记录计算。

### 8.3 考勤记录表

```sql
CREATE TABLE attendance_records (
    id BIGINT NOT NULL AUTO_INCREMENT,
    record_business_id VARCHAR(64) NOT NULL,
    active_record_key VARCHAR(160) NOT NULL,
    employee_business_id VARCHAR(64) NOT NULL,
    employee_snapshot_business_id VARCHAR(64) NOT NULL,
    employee_snapshot_version BIGINT NOT NULL,
    position_code VARCHAR(64) NOT NULL,
    work_date DATE NOT NULL,
    clock_in_time TIME NULL,
    clock_out_time TIME NULL,
    break_minutes INT NOT NULL,
    worked_minutes INT NOT NULL,
    leave_minutes INT NOT NULL,
    leave_type VARCHAR(16) NULL,
    overtime_minutes INT NOT NULL,
    note VARCHAR(500) NULL,
    record_status VARCHAR(16) NOT NULL,
    content_version BIGINT NOT NULL,
    row_version BIGINT NOT NULL,
    void_reason VARCHAR(300) NULL,
    voided_at DATETIME(6) NULL,
    voided_by VARCHAR(64) NULL,
    created_at DATETIME(6) NOT NULL,
    created_by VARCHAR(64) NOT NULL,
    updated_at DATETIME(6) NOT NULL,
    updated_by VARCHAR(64) NOT NULL,
    PRIMARY KEY (id),
    UNIQUE KEY uk_attendance_record_business_id (record_business_id),
    UNIQUE KEY uk_attendance_active_record (active_record_key),
    KEY ix_attendance_employee_date (
        employee_business_id, work_date, record_status
    ),
    KEY ix_attendance_position_date (
        position_code, work_date, record_status
    ),
    KEY ix_attendance_date_status (work_date, record_status),
    CONSTRAINT ck_attendance_clock CHECK (
        (clock_in_time IS NULL AND clock_out_time IS NULL)
        OR (
            clock_in_time IS NOT NULL
            AND clock_out_time IS NOT NULL
            AND clock_out_time > clock_in_time
            AND SECOND(clock_in_time) = 0
            AND SECOND(clock_out_time) = 0
        )
    ),
    CONSTRAINT ck_attendance_clock_break CHECK (
        clock_in_time IS NOT NULL OR break_minutes = 0
    ),
    CONSTRAINT ck_attendance_minutes CHECK (
        break_minutes >= 0 AND break_minutes <= 1440
        AND worked_minutes >= 0 AND worked_minutes <= 1440
        AND leave_minutes >= 0 AND leave_minutes <= 1440
        AND worked_minutes + leave_minutes <= 1440
        AND overtime_minutes >= 0 AND overtime_minutes <= worked_minutes
    ),
    CONSTRAINT ck_attendance_full_leave CHECK (
        clock_in_time IS NOT NULL OR worked_minutes = 0
    ),
    CONSTRAINT ck_attendance_span CHECK (
        clock_in_time IS NULL
        OR (
            worked_minutes
            = TIME_TO_SEC(TIMEDIFF(clock_out_time, clock_in_time)) / 60
              - break_minutes - leave_minutes
            AND leave_minutes + break_minutes
            <= TIME_TO_SEC(TIMEDIFF(clock_out_time, clock_in_time)) / 60
            AND TIME_TO_SEC(TIMEDIFF(clock_out_time, clock_in_time))
            <= 86400
        )
    ),
    CONSTRAINT ck_attendance_effective CHECK (
        worked_minutes > 0 OR leave_minutes > 0
    ),
    CONSTRAINT ck_attendance_leave_type CHECK (
        (leave_minutes = 0 AND leave_type IS NULL)
        OR (
            leave_minutes > 0
            AND leave_type IN ('PERSONAL', 'SICK', 'OTHER')
        )
    ),
    CONSTRAINT ck_attendance_position CHECK (
        position_code IN ('MAKING', 'BAGGING', 'SEAM_CUTTING', 'OTHER')
    ),
    CONSTRAINT ck_attendance_status CHECK (
        record_status IN ('ACTIVE', 'VOIDED')
    ),
    CONSTRAINT ck_attendance_void CHECK (
        (
            record_status = 'ACTIVE'
            AND void_reason IS NULL
            AND voided_at IS NULL
            AND voided_by IS NULL
        )
        OR (
            record_status = 'VOIDED'
            AND void_reason IS NOT NULL
            AND void_reason <> ''
            AND voided_at IS NOT NULL
            AND voided_by IS NOT NULL
        )
    ),
    CONSTRAINT ck_attendance_snapshot CHECK (
        employee_snapshot_business_id <> ''
        AND employee_snapshot_version > 0
    )
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_0900_ai_ci;
```

说明：

- `active_record_key` 为 `ACTIVE` 时是 `employee_business_id|work_date`，作废后改为记录业务标识；
- 同一员工同一日期只能有一条活动记录，但可以保留多条已作废记录；
- 上下班时间精确到分钟，`TIME_TO_SEC(...) / 60` 必须等于整数分钟；
- 出勤分钟由服务端计算，数据库校验跨度守恒、范围和非负；
- `content_version` 和 `row_version` 都从 1 开始，每次更正或作废都递增；
- 岗位代码由服务端按工作日期解析，不接受客户端提交；
- 考勤记录不物理删除。

### 8.4 索引与查询

| 索引 | 用途 |
|---|---|
| `uk_attendance_record_business_id` | 记录标识唯一 |
| `uk_attendance_active_record` | 同一员工同一日期只有一条活动记录 |
| `ix_attendance_employee_date` | 员工月度明细和期间查询 |
| `ix_attendance_position_date` | 按冻结岗位筛选和汇总 |
| `ix_attendance_date_status` | 按月网格和按日期汇总 |

查询不按员工姓名、岗位名称等展示字段扫描；这些字段通过员工和全局公开查询解析。

### 8.5 数据边界

- 考勤不保存员工姓名、电话、岗位名称和就业期间；
- 考勤不保存排班计划、生产记录、订单和商品；
- 考勤不保存工资规则、岗位时薪、金额和提成；
- 考勤不保存全局参数值；
- 考勤不建立跨模块外键，员工标识、快照引用和岗位代码都是业务引用。

## 9. 公开接口设计

### 9.1 命令

```java
interface AttendanceApplicationService {
    AttendanceRecordRef create(CreateAttendanceRecordCommand command);
    AttendanceRecordRef update(UpdateAttendanceRecordCommand command);
    AttendanceRecordRef voidRecord(VoidAttendanceRecordCommand command);
}
```

`CreateAttendanceRecordCommand` 必须包含：

```text
employeeRef, workDate,
clockInTime, clockOutTime（可空；全天请假时为空）,
breakMinutes, leaveMinutes, leaveType, overtimeMinutes, note
```

`UpdateAttendanceRecordCommand` 必须包含：

```text
attendanceRecordRef, employeeRef, workDate,
clockInTime, clockOutTime,
breakMinutes, leaveMinutes, leaveType, overtimeMinutes, note,
expectedRowVersion
```

`VoidAttendanceRecordCommand` 必须包含：

```text
attendanceRecordRef, reason, expectedRowVersion
```

规则：

- 客户端不能提交岗位代码、员工快照、出勤分钟、内容版本、行版本和记录状态；
- 岗位、员工快照和出勤分钟由服务端解析和计算；
- 所有时间输入精确到分钟；
- 所有命令使用平台幂等键，重复提交返回同一结果，不重复写记录；
- 更正和作废必须携带期望行版本；
- 命令失败整体回滚。

### 9.2 查询

```java
interface AttendanceQuery {
    AttendancePage search(AttendanceSearchQuery query);
    AttendanceRecordView detail(AttendanceRecordRef recordRef);
    AttendanceMonthView getMonth(AttendanceMonthQuery query);
    List<AttendanceDayView> listPeriodRecords(AttendancePeriodQuery query);
    List<AttendancePeriodSummary> summarizePeriod(AttendancePeriodQuery query);
}
```

`AttendanceSearchQuery`：

```text
dateFrom, dateTo,
employeeRef（可选）,
positionCode（可选）,
includeVoided（默认 false）,
page, size
```

`AttendanceMonthQuery`：

```text
month（yyyy-MM）,
employeeKeyword（可选，员工编号或姓名）,
positionCode（可选，按当前岗位筛选）,
includeLeft（默认 false，是否包含离职员工）
```

`AttendancePeriodQuery`：

```text
employeeRefs（可空；最多 200 名）,
dateFrom, dateTo（跨度不超过 366 天）
```

查询口径：

- `search` 按工作日期倒序、员工编号升序返回；`positionCode` 按考勤记录冻结的岗位筛选；
- `detail` 可返回 `ACTIVE` 或 `VOIDED` 记录；
- `getMonth` 只返回 `ACTIVE` 记录，按员工行和日期列组织；
- `listPeriodRecords` 只返回 `ACTIVE` 记录，按员工和日期升序返回；`employeeRefs` 为空表示期间内有考勤记录的全部员工；
- `summarizePeriod` 只汇总 `ACTIVE` 记录；
- 已作废记录不进入工资读取和默认汇总；
- 考勤不直接查询员工表、岗位记录表或全局参数表。

### 9.3 读模型

`AttendanceListItem`：

```text
recordRef, employeeRef, employeeNo, employeeName,
positionCode, positionName, workDate,
clockInTime, clockOutTime, breakMinutes,
workedMinutes, leaveMinutes, leaveType, overtimeMinutes,
status, updatedAt
```

`AttendanceRecordView`：

```text
recordRef, employeeRef, employeeNo, employeeName,
employeeSnapshotRef, positionCode, positionName, workDate,
clockInTime, clockOutTime, breakMinutes,
workedMinutes, leaveMinutes, leaveType, overtimeMinutes,
note, status, contentVersion, rowVersion,
voidReason, voidedAt, voidedBy, updatedAt
```

`AttendanceMonthView`：

```text
month, days（当月日期列表）,
rows: [{
  employeeRef, employeeNo, employeeName,
  currentPositionCode, currentPositionName,
  cells: [{
    workDate, recordRef（无记录为空）,
    workedMinutes, leaveMinutes, leaveType, overtimeMinutes,
    dayState（WORKED / LEAVE_ONLY / NONE）
  }],
  totals: {
    workedMinutes, leaveMinutes, overtimeMinutes, workedDays, leaveDays
  }
}],
dailyTotals: [{
  workDate, workedMinutes, leaveMinutes, overtimeMinutes, headcount
}],
summary: {
  employeeCount, totalWorkedMinutes, totalLeaveMinutes, totalOvertimeMinutes
}
```

`AttendanceDayView`：

```text
recordRef, employeeRef, employeeNo, employeeName,
employeeSnapshotRef,
positionCode, positionName, workDate,
clockInTime, clockOutTime, breakMinutes,
workedMinutes, leaveMinutes, leaveType, overtimeMinutes,
contentVersion
```

`AttendancePeriodSummary`：

```text
employeeRef, employeeNo, employeeName,
dateFrom, dateTo,
workedMinutes, leaveMinutes, overtimeMinutes,
workedDays, leaveDays,
byPosition: [{
  positionCode, positionName, workedMinutes, overtimeMinutes, leaveMinutes
}],
leaveMinutesByType: [{
  leaveType, leaveMinutes
}],

```

`summaryFingerprint` 生成规则：

```text
按工作日期升序，逐条取
recordBusinessId|workDate|positionCode|workedMinutes|leaveMinutes|leaveType|overtimeMinutes|contentVersion
以换行连接后取 SHA-256
```

- `positionName` 取全局模块当前显示名称；
- 员工姓名在逐条记录视图中取员工快照，在月度网格员工行中取员工当前资料；
- 列表和网格中的当前岗位取员工当前资料，只用于筛选和展示；
- 逐日记录中的岗位取考勤记录冻结的岗位代码；
- `dailyTotals.headcount` 为当天有活动记录的人数；
- `summary.employeeCount` 为返回的员工行数；
- 不向页面返回员工快照内部标识、行版本和汇总指纹；内容版本只在明细和工资读取契约中返回。

### 9.4 员工与岗位依赖

考勤模块调用员工模块公开查询，不直接读员工表：

```java
interface EmployeeQuery {
    List<EmployeeOptionView> options(EmployeeOptionQuery query);
    List<EmployeeEmploymentPeriodView> listEmploymentPeriods(
        EmployeeRef employeeRef, LocalDate from, LocalDate to
    );
    List<EmployeePositionPeriodView> listPositionPeriods(
        EmployeeRef employeeRef, LocalDate from, LocalDate to
    );
}

interface EmployeeSnapshotService {
    EmployeeSnapshotRef acquireCurrent(EmployeeRef employeeRef);
    EmployeeSnapshotView resolve(EmployeeSnapshotRef snapshotRef);
}

interface StaticDataQuery {
    StaticDataItemView get(String typeCode, String itemCode);
}
```

`EmployeeEmploymentPeriodView`：

```text
employeeBusinessId, effectiveFrom,
effectiveTo（当前在职期间为 null）,
entryType（HIRE / REHIRE）
```

要求：

- `listEmploymentPeriods` 返回与查询区间相交的就业期间，按开始日期升序；
- 就业期间包含离职日期当天；返聘后从返聘日期开始新期间；
- 考勤用 `listEmploymentPeriods(employeeRef, workDate, workDate)` 校验工作日期是否在就业期间内；
- 考勤用 `listPositionPeriods(employeeRef, workDate, workDate)` 解析当天岗位；
- 新建和更正员工或日期时取得员工快照引用，只保存引用；
- 网格员工行和员工搜索通过 `options` 读取，离职员工按 `includeLeft` 显式选择；
- 员工编号和姓名通过员工快照解析，岗位名称通过全局静态数据解析；
- 考勤模块不直接读 `employee_masters`、`employee_employment_records`、`employee_position_records` 和 `employee_snapshots` 表。

### 9.5 工资读取契约

工资模块只通过考勤公开查询读取：

```java
AttendanceQuery.listPeriodRecords(AttendancePeriodQuery query);
AttendanceQuery.summarizePeriod(AttendancePeriodQuery query);
```

要求：

- 工资按员工和日期范围读取，不直接读 `attendance_records`；
- 工资参考运行指纹包含考勤逐日 `contentVersion` 或期间 `summaryFingerprint`；
- 工资使用 `AttendanceDayView.employeeSnapshotRef` 作为计时参考行的员工身份，不重新取当前快照；
- 工资使用 `AttendanceDayView.positionCode` 确定当天岗位，并按该岗位读取工资周期间开始日生效的岗位时薪；
- 工资按出勤分钟计算计时工资，不使用页面展示的小时数；
- 工资的工序提成从生产记录和商品快照读取，不由考勤模块提供；
- 考勤内容变化后指纹变化，工资据此判断是否需要重算；
- 考勤不保存工资期间、结算状态、工资行和金额；
- 工资不把结算状态写回考勤。

## 10. 事务与并发

### 10.1 创建考勤记录

```text
校验字段和工作日期
→ 查询就业期间（包含工作日期）
→ 查询岗位期间，取当天岗位代码
→ 取得员工快照引用
→ 计算出勤分钟并校验守恒
→ 写考勤记录（ACTIVE，content_version = 1，row_version = 1）
→ 写平台审计
→ 一次提交
```

- 就业期间、岗位期间和员工快照必须在同一事务内读取和保存；
- 员工快照获取失败时整体回滚；
- 唯一键冲突返回 `ATTENDANCE_RECORD_DUPLICATE`；
- 任一步失败不保存考勤记录。

### 10.2 更正考勤记录

```text
按 row_version 锁定考勤记录
→ 校验记录状态为 ACTIVE
→ 校验字段
→ 员工或日期变化时重查就业期间、岗位期间和员工快照
→ 重新计算出勤分钟
→ 更新业务字段、active_record_key、content_version 和 row_version
→ 写平台审计
→ 一次提交
```

- 更正后与其他活动记录冲突时整体回滚；
- 已作废记录不能更正；
- 并发更正只有一方成功，另一方返回版本冲突。

### 10.3 作废考勤记录

```text
按 row_version 锁定考勤记录
→ 校验记录状态为 ACTIVE
→ 校验作废原因
→ 改为 VOIDED
→ active_record_key 改为记录业务标识
→ 写入作废原因、作废时间、作废人
→ 递增 content_version 和 row_version
→ 写平台审计
→ 一次提交
```

### 10.4 并发与幂等

- 创建依赖 `active_record_key` 唯一键防止同一员工同一日期重复登记；
- 更正和作废使用 `row_version` 拒绝并发覆盖；
- 所有写命令使用平台幂等键；
- 相同幂等键和相同请求指纹返回第一次成功结果；
- 相同幂等键不同请求指纹返回平台幂等冲突；
- 死锁只允许重试整个幂等命令；
- 查询不加业务锁，不做跨表一致性快照。

## 11. 历史与追溯

### 11.1 当前记录与历史

- `ACTIVE` 记录是当前考勤事实，可以更正；
- `VOIDED` 记录保留原业务字段、作废原因、作废时间和操作人；
- 考勤不硬删除记录；
- 同一员工同一日期可以保留一条活动记录和多条已作废记录；
- 考勤不建字段级变更历史表，平台审计记录每次变更。

### 11.2 员工与岗位变化

- 员工改名、调岗、离职或返聘不修改已有考勤记录；
- 已有考勤记录中的岗位代码保持登记时解析的当天岗位；
- 员工岗位记录事后补录或调整不回写已有考勤，确需变更时由管理员更正考勤；
- 员工快照引用保留登记当时的员工身份；
- 岗位显示名称按全局当前名称展示，岗位改名不影响工资取数；
- 工资按考勤记录中的岗位代码取岗位规则，不按员工当前岗位。

### 11.3 工资结算后的更正

- 考勤模块不知道工资是否已结算，允许继续更正；
- 工资结算保存逐日内容版本和期间指纹；
- 已结算工资不因考勤后改自动变化；
- 工资模块通过指纹差异识别考勤变化，并决定重算、补差或留存；
- 考勤模块不生成工资差异，不写工资状态。

### 11.4 审计内容

平台审计至少记录：

- 操作者、时间、动作；
- 考勤记录标识、员工标识和工作日期；
- 修改前后的上下班时间、休息、请假、加班和出勤分钟摘要；
- 作废原因；
- 内容版本变化。

## 12. 权限、审计与错误

### 12.1 权限

| 权限 | 能力 |
|---|---|
| `attendance.read` | 查看月度考勤、考勤明细、员工考勤和期间汇总 |
| `attendance.manage` | 创建、更正和作废考勤记录 |

角色建议：

- 管理员：全部考勤权限；
- 生产负责人：`attendance.read`、`attendance.manage`；
- 老板：`attendance.read`；
- 工资：通过内部公开查询读取，不授予考勤编辑权限；
- 报表：只读公开查询，不直接读考勤表。

### 12.2 审计

必须审计：

- 考勤记录创建；
- 考勤记录更正；
- 考勤记录作废；
- 审计失败时业务回滚，不出现无审计的考勤写入。

考勤不记录敏感数据访问审计，因为不保存电话、住址、银行卡等敏感资料。

### 12.3 错误码

以下错误码在平台错误码目录登记 `category` 和 HTTP 映射，规则见平台模块 10.3。

| 错误码 | 含义 |
|---|---|
| `ATTENDANCE_RECORD_NOT_FOUND` | 考勤记录不存在 |
| `ATTENDANCE_RECORD_DUPLICATE` | 同一员工同一日期已有活动考勤记录 |
| `ATTENDANCE_RECORD_VERSION_CONFLICT` | 考勤记录版本冲突 |
| `ATTENDANCE_RECORD_NOT_ACTIVE` | 考勤记录已作废，不能更正或再次作废 |
| `ATTENDANCE_FIELD_INVALID` | 考勤字段不合法 |
| `ATTENDANCE_TIME_INVALID` | 上下班时间缺失、带秒、顺序错误或跨天 |
| `ATTENDANCE_MINUTES_INVALID` | 休息、请假或加班分钟超出范围 |
| `ATTENDANCE_MINUTES_INCONSISTENT` | 出勤分钟与时间跨度不一致 |
| `ATTENDANCE_LEAVE_TYPE_REQUIRED` | 请假分钟大于 0 但未填写请假类型 |
| `ATTENDANCE_LEAVE_TYPE_INVALID` | 请假类型不合法 |
| `ATTENDANCE_WORK_DATE_INVALID` | 工作日期晚于当天或格式不合法 |
| `ATTENDANCE_WORK_DATE_OUT_OF_EMPLOYMENT` | 工作日期不在员工就业期间内 |
| `ATTENDANCE_POSITION_NOT_FOUND` | 工作日期没有唯一岗位期间 |
| `ATTENDANCE_EMPLOYEE_NOT_FOUND` | 员工不存在 |
| `ATTENDANCE_VOID_REASON_REQUIRED` | 作废未填写原因 |
| `ATTENDANCE_PERIOD_RANGE_INVALID` | 日期跨度超过 366 天或员工数量超过 200 |

前端提示：

- 字段错误在输入框内联显示；
- 同一员工同一日期重复登记时提示“该员工当天已有考勤记录”，并提供打开已有记录；
- 未来日期不能选择，提示“不能登记未来日期”；
- 下班时间不晚于上班时间时提示“下班时间必须晚于上班时间”；
- 请假分钟大于 0 时必须选择请假类型；
- 作废必须填写原因；
- 版本冲突提示刷新后重试，不覆盖服务端记录；
- 不显示内部业务标识、快照标识、内容版本和堆栈。

## 13. 页面与交互要求

### 13.1 页面清单

### 13.2 月度考勤工作区

- 页头使用紧凑页栏，不使用大标题；
- 页头控件：月份选择、员工搜索、岗位筛选、是否包含离职员工、保存状态提示；
- 默认显示当月，默认只显示在职员工；
- 表格左侧固定员工列：员工编号、姓名、当前岗位；
- 日期列按当月自然日生成，未来日期置灰且不可编辑；
- 单元格显示出勤小时，保留两位小数；仅有请假时显示“请假”；同时有出勤和请假时追加请假标记；有加班时追加加班标记；
- 没有记录显示空单元格，不使用自绘大空态图；
- 每行右侧显示月合计：出勤天数、出勤小时、请假小时、加班小时；
- 表格底部显示每日合计：人数、出勤小时、请假小时、加班小时；
- 员工列和合计列固定，日期区域在卡片内横向滚动；
- 默认按员工编号升序；
- 点击单元格打开编辑对话框；双击或回车进入编辑，不使用整页跳转；
- 周末列使用弱化背景，不判断法定节假日；
- 不显示英文枚举原文、内部标识和版本号。

### 13.3 单元格编辑

编辑对话框字段：

- 上班时间、下班时间；
- 休息分钟；
- 请假分钟、请假类型；
- 加班分钟；
- 备注。

交互：

- 字段按内容紧凑排列，不使用长表单；
- 提供“全天请假”开关；开启后隐藏上下班时间、休息和加班，只填写请假分钟和类型；
- 未开启时按当天考勤跨度填写上下班时间，休息和请假从跨度中扣除；
- 实时显示“本次出勤 X 小时 Y 分钟”；
- 加班分钟必须包含在上下班跨度内，只标记为加班口径，不额外延长出勤；
- 保存前内联校验时间顺序、休息和请假范围、加班不超过出勤；
- 已有记录显示当前值，并显示“作废此记录”次要危险操作；
- 作废必须填写原因，确认后单元格恢复为空；
- 保存成功后关闭对话框并局部刷新当前行和合计，不整页刷新；
- 提交失败保留已填内容，字段错误内联显示；
- 非 `attendance.manage` 用户只能查看，不显示编辑入口。

### 13.4 员工考勤

- 页头显示员工姓名、员工编号、当前岗位和在职状态；
- 月份切换；
- 汇总卡片：出勤天数、出勤小时、请假小时、加班小时；
- 逐日列表：工作日期、岗位、上班时间、下班时间、休息、出勤、请假、加班、备注、更新时间；
- 支持显示已作废记录；
- 点击日期进入与月度网格相同的编辑对话框；
- 作废记录显示作废原因和作废时间，不显示编辑入口。

### 13.5 全局交互原则

- 页面使用 V3 全站设计语言和现有组件，不新造考勤专用控件；
- 字段校验内联显示，接口错误统一使用全站提示；
- 所有时间显示为本地日期和 `HH:mm`，不显示微秒时间戳；
- 出勤和请假小时保留两位小数，明细中同时显示分钟；
- 不显示内部业务标识、快照标识、内容版本、行版本和指纹；
- 不出现英文枚举原文，请假类型统一使用中文名称；
- 未保存关闭编辑对话框前提示“修改尚未保存”；
- 页面不提供导入导出、批量删除和月结操作。

## 14. 验收标准

### 14.1 登记与计算

- [ ] 同一员工同一日期只能保存一条活动考勤记录，重复登记被拒绝；
- [ ] 工作日期不能晚于当天；
- [ ] 工作日期不在员工就业期间内时拒绝保存；
- [ ] 工作日期落在员工历史就业期间内时允许补录，包括离职员工；
- [ ] 岗位按工作日期解析，调岗后历史日期使用当时岗位；
- [ ] 上班时间和下班时间必须成对出现，精确到分钟，下班时间晚于上班时间；
- [ ] 出勤分钟等于上下班跨度减去休息和请假；
- [ ] 出勤分钟与请假分钟合计不超过 1440 分钟；
- [ ] 休息分钟、请假分钟和加班分钟超出范围时被拒绝；
- [ ] 请假分钟大于 0 时必须填写请假类型；
- [ ] 请假分钟为 0 时不能填写请假类型；
- [ ] 加班分钟不能超过出勤分钟；
- [ ] 全天请假可以没有上下班时间，出勤为 0；
- [ ] 只记录加班不记录出勤或请假时被拒绝；
- [ ] 跨天上下班时间被拒绝；
- [ ] 客户端提交的出勤分钟、岗位和员工快照被忽略。

### 14.2 更正与作废

- [ ] 只有活动记录可以更正；
- [ ] 更正携带行版本，冲突时拒绝覆盖；
- [ ] 更正后出勤分钟、内容版本和行版本正确更新；
- [ ] 更正员工或日期时重新校验就业期间、岗位和快照；
- [ ] 更正后与其他活动记录冲突时整体回滚；
- [ ] 作废必须填写原因；
- [ ] 作废后状态为 `VOIDED`，活动唯一键释放，可以重新登记同一天考勤；
- [ ] 作废记录保留原业务字段和出勤分钟；
- [ ] 已作废记录不能更正或再次作废；
- [ ] 考勤记录不能硬删除。

### 14.3 查询与汇总

- [ ] 月度考勤按员工行和日期列返回，未来日期不可编辑；
- [ ] 月度网格只显示活动记录，已作废记录不占单元格；
- [ ] 员工考勤可以查看已作废记录；
- [ ] 期间逐日查询只返回活动记录，按员工和日期排序；
- [ ] 期间汇总的出勤分钟、请假分钟、加班分钟和天数正确；
- [ ] 汇总按岗位拆分正确；
- [ ] 请假按类型汇总正确；
- [ ] 汇总指纹在记录更正或作废后变化；
- [ ] 相同记录和相同内容版本生成相同指纹；
- [ ] 日期跨度超过 366 天或员工数量超过 200 时返回范围错误；
- [ ] 工资只通过公开查询读取考勤，不直接读考勤表。

### 14.4 权限、审计与边界

- [ ] 查看考勤需要 `attendance.read`；
- [ ] 创建、更正和作废需要 `attendance.manage`；
- [ ] 创建、更正和作废都写平台审计；
- [ ] 审计失败时业务回滚；
- [ ] 考勤不读取岗位时薪、工作日小时数、有效工时率和每日可用工作分钟；
- [ ] 考勤只读取岗位显示名称；
- [ ] 考勤不需要排班计划即可登记；
- [ ] 排班和生产不自动生成考勤，考勤不生成生产记录；
- [ ] 考勤不计算工资、金额、成本和提成，不调用计算中心；
- [ ] 考勤不直接读写员工、全局、生产、订单、商品和工资表；
- [ ] 本期员工不登录，不提供员工自助入口；
- [ ] 字段错误内联显示，接口错误不出现英文原文和内部标识。

- 不做员工自助登记、移动登记、打卡机、定位和人脸识别；
- 不做考勤机对接和原始打卡流水；
- 不做考勤与排班计划、生产计划自动对账；
- 不做工资、金额、成本、提成和工资期间；

- 不做员工登录入口和员工账号；
- 不做通用审批流和工作流。

## 16. 与 V2 的主要差异

| V2 人员与工资 | V3 考勤模块 |
|---|---|
| 没有独立考勤模块，兼职出勤和工时靠 Excel 或生产数据参考 | 独立考勤记录，按员工和日期登记时间事实 |
| 工资直接参考生产记录和工时标准 | 工资读取考勤分钟、岗位和生产记录，分别取数 |
| 没有请假和加班事实 | 记录请假分钟、类型和加班分钟 |
| 员工岗位变化后历史工时口径依靠人工判断 | 按工作日期解析并冻结岗位，工资不再重解 |
| 月底修改 Excel 后无法判断工资是否受影响 | 内容版本和期间指纹标识考勤变化 |
| 出勤、请假和加班分散在 Excel，月底靠人工汇总 | 考勤独立成模块，按员工和日期保存可查询事实 |

## 17. 外部依赖

考勤模块不直接访问员工、全局、生产、订单、商品和工资数据库；以下依赖全部通过目标模块的公开方法完成。

### 17.1 平台能力

- 权限：`attendance.read`、`attendance.manage`；
- 审计：`PlatformAuditRecorder.record` 记录创建、更正和作废；
- 幂等：所有写命令使用平台幂等键；
- 考勤不需要平台编号，记录标识由考勤模块生成；
- 考勤不需要平台文件、登录、账号和权限维护；
- 考勤不直接写平台审计表。

### 17.2 员工模块

- 员工列表和网格行通过 `EmployeeQuery.options` 读取；
- 工作日期校验通过 `EmployeeQuery.listEmploymentPeriods` 读取就业期间；
- 当天岗位通过 `EmployeeQuery.listPositionPeriods` 读取；
- 员工身份通过 `EmployeeSnapshotService.acquireCurrent` 取得快照引用，通过 `resolve` 解析员工编号和姓名；岗位显示名称通过 `StaticDataQuery` 读取；
- 员工查询和快照内部调用按考勤权限鉴权，不要求额外授予员工维护权限；
- 考勤只保存员工标识、员工快照引用和岗位代码，不复制员工档案；
- 考勤不直接读员工表、就业记录表、岗位记录表和员工快照表。

### 17.3 全局模块

- 通过 `StaticDataQuery.get("POSITION", positionCode)` 读取岗位显示名称；
- 考勤不读取岗位时薪、工作日小时数、有效工时率和每日可用工作分钟；
- 考勤不维护岗位和静态数据；
- 考勤不直接读 `global_static_items` 或 `global_parameters` 表。

### 17.4 工资模块

- 工资通过 `AttendanceQuery.listPeriodRecords` 和 `summarizePeriod` 读取考勤；
- 考勤提供逐日员工快照引用、岗位代码、出勤分钟、请假分钟、加班分钟和内容版本；
- 工资按工资周期间开始日和岗位代码读取岗位时薪，按时薪和出勤分钟计算计时工资；
- 工序提成由工资模块从生产记录和商品快照读取，不由考勤提供；
- 工资结算保存内容版本或汇总指纹；
- 工资金额公式归工资模块和计算中心；
- 考勤不保存工资期间、工资行、结算状态和金额；
- 考勤不反向读取工资表。

### 17.5 生产、订单与计算

- 考勤与生产模块相互独立，不读取对方数据，也不生成对方记录；
- 考勤不读取订单、商品和方案；
- 考勤不调用计算中心；出勤分钟是时间事实，与生产数量一样在业务模块本地计算；
- 计算中心只负责金额、成本、工资等公式；
- 工资分别读取生产记录和考勤记录，再由计算中心计算金额。

### 17.6 报表模块

- 报表通过考勤公开查询或后续报表投影读取考勤汇总；
- 报表不直接读考勤表；
- 考勤不提供报表专用汇总表。

## 18. 已确认口径

1. 考勤独立于排班和生产；没有计划也能登记，计划不生成考勤，生产记录不写考勤。
2. 考勤记录按员工 × 工作日期唯一，一天一条；多段工作用休息分钟合并。
3. 出勤分钟 = 上下班跨度 − 休息分钟 − 请假分钟；分钟是工资取数依据，页面按小时展示。
4. 加班分钟是出勤分钟的子集，不额外增加出勤；请假按分钟和类型记录。
5. 本期不判断迟到、早退和缺勤，不支持跨天班次和一天多段独立登记。
6. 工作日期当天岗位由员工岗位期间解析并冻结；工资不按员工当前岗位重解历史。
7. 员工身份保存员工快照引用；员工资料变化不改变已登记考勤。
8. 工作日期必须落在员工就业期间内；离职员工可以补录历史考勤，返聘期间按新期间校验。
9. 考勤记录可以更正，错录可以作废；不硬删除；作废记录保留。
10. 内容版本和期间汇总指纹用于工资识别考勤变化；工资结算后修改考勤不回溯已结算工资。
11. 考勤不读取全局数值参数，只读取岗位显示名称；出勤分钟在考勤模块本地计算。
12. 考勤不计算工资和金额，不调用计算中心；工资金额由工资模块和计算中心负责。
13. 本期管理员手工登记，员工不登录，也不依赖打卡机；后续接入设备或员工自助登记时只增加数据来源，不改考勤记录模型。
