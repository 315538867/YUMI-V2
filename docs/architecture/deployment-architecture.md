# YUMI V2 部署架构

## 1. 目标与范围

首期采用单云服务器部署，服务对象为管理员，要求始终联网。目标是在不引入集群和分布式系统的前提下，保证数据库不暴露公网、迁移可控、备份可恢复、业务操作可审计。

首期不建设 Kubernetes、服务网格、消息队列、多节点高可用、跨地域容灾或离线同步。

## 2. 运行拓扑

```text
管理员浏览器 / Electron
          │
          │ HTTPS 443
          ▼
反向代理（TLS、静态资源、请求限制）
          │
          │ localhost / 私有端口
          ▼
Spring Boot 模块化单体（非特权账户）
          ├── JDBC ──> MySQL 8.x（仅本机或私有网络）
          └─────────> 文件存储目录或对象存储适配器
```

浏览器和 Electron 使用相同 API。Electron 不保存数据库凭据、不直连 MySQL，也不内置权威业务规则。

## 3. 服务器边界

- 公网仅开放 HTTPS；SSH 仅允许受控来源并使用密钥认证；
- MySQL 不开放公网端口，只监听本机回环地址或私有网络；
- Spring Boot 使用独立非特权系统账户运行；
- 应用、数据库、备份和上传文件使用不同目录和最小权限；
- 数据库密码、会话密钥和存储凭据通过环境变量或受控秘密文件注入，不写入仓库；
- 反向代理限制请求体大小、连接数和上传类型，并保留请求 ID；
- 操作系统、JDK、MySQL 和反向代理按维护窗口安装安全更新。

## 4. 构建与制品

后端使用 Maven Wrapper 和固定 Java 21 工具链构建可执行 JAR。前端构建生成静态制品，可由反向代理托管；Electron 使用同一套 React 源码构建桌面安装包。

每次发布保留：

- 后端 JAR 及版本号；
- 前端静态制品及版本号；
- Electron 安装包版本；
- Flyway 迁移集合校验值；
- 发布说明和数据库备份标识。

## 5. 数据库迁移与启动顺序

Flyway 是数据库结构唯一来源，迁移文件随 Spring Boot 制品交付。Hibernate 固定使用 `ddl-auto: validate`。

发布顺序：

```text
1. 验证配置、磁盘空间和数据库连接
2. 创建 MySQL 与业务文件一致性备份
3. 在同版本 MySQL 临时库执行 flyway validate 和 migrate
4. 停止旧应用或进入受控维护窗口
5. 对正式库执行 flyway validate 和 migrate
6. 启动新 Spring Boot 制品
7. Hibernate 验证实体映射
8. 检查存活、就绪和数据库健康状态
9. 执行订单查询与只读冒烟验证
10. 恢复外部流量
```

首期允许应用启动时自动执行 Flyway，但生产发布必须先在临时库验证同一迁移集合。不得通过 Hibernate `update`、数据库管理工具手工改表或修改 `flyway_schema_history` 绕过迁移。

失败处理：

- 迁移开始前失败：保留旧版本继续运行；
- 迁移执行失败：停止应用，诊断失败迁移，不重复修改已执行版本脚本；
- 已完成不可逆迁移后应用失败：优先修复并发布前向兼容版本；只有经验证的整库和文件恢复方案才能回退数据；
- 已发布迁移文件不可改写，修正必须新增版本迁移。

## 6. 健康检查与日志

Spring Boot 暴露受保护的 Actuator 存活和就绪端点。就绪检查至少覆盖应用启动、数据库连接和 Flyway 状态；文件存储不可写时必须告警。

日志要求：

- JSON 或稳定结构化格式；
- 每个请求携带请求 ID；
- 关键命令记录业务编号、操作者、结果和耗时；
- 禁止记录密码、完整令牌、数据库凭据和敏感认证头；
- 应用、反向代理和 MySQL 日志轮转并设置保留周期；
- 磁盘、CPU、内存、连接池、慢查询、HTTP 5xx 和备份失败设置告警。

## 7. 备份与恢复

业务恢复点必须同时包含 MySQL 和文件存储。不能只恢复数据库而遗漏商品图片、业务附件或生成文件。

首期最低要求：

- 每日 MySQL 全量备份；
- 发布迁移前额外备份；
- 文件存储每日增量或快照备份；
- 备份加密并复制到与业务服务器不同的存储位置；
- 记录备份时间、数据库版本、应用版本和文件快照标识；
- 定期执行恢复演练，而不是只检查备份文件存在；
- 恢复后执行 Flyway 校验、事实与投影一致性检查以及关键业务只读验证。

恢复顺序：

```text
停止写入
→ 恢复 MySQL 到选定恢复点
→ 恢复匹配的文件快照
→ 校验 Flyway 历史
→ 启动匹配的应用版本
→ 校验履约、库存、发货和收退款投影
→ 通过冒烟验证后恢复访问
```

## 8. 环境与配置

至少区分本地开发、自动化测试和生产环境。测试使用 Testcontainers MySQL，不以 H2 替代需要验证的 MySQL 约束、锁和迁移行为。

生产配置包括数据库连接池、时区、文件存储位置、上传限制、日志级别、会话安全和允许来源。所有环境保持同一套 Flyway 迁移历史，不为生产维护手工分叉脚本。

## 9. 上线门禁

发布前必须通过：

1. Maven 全量测试；
2. Spring Modulith 模块边界验证；
3. Testcontainers MySQL 空库迁移；
4. 旧版本结构升级到新版本的迁移测试；
5. 核心业务集成测试和并发测试；
6. 前端构建与关键页面测试；
7. Electron 打印和文件选择验证；
8. 备份生成和恢复演练证据；
9. 生产配置和秘密扫描；
10. 发布后只读冒烟验证。
