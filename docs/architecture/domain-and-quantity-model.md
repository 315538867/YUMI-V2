# YUMI V2 领域与数量模型

## 1. 设计目标

本模型把订单需求、逐工序生产、库存接入、可发货、发货和售后分成可追溯但不重复计算的事实。它是数据库设计和业务接口的共同约束。

## 2. 聚合与所有权

### 2.1 订单模块聚合

`Order` 拥有订单主状态、当前有效订单数据、确认快照、金额汇总和关闭规则。`OrderItem` 是订单内的独立履约单位，拥有当前有效订购数量、缝边数量、冻结流程和商品/成本快照。

订单模块还拥有以下内部聚合和事实：

- `FulfillmentEntry` 与 `OrderItemFulfillmentBalance`：履约事实和当前数量投影；
- `Shipment`：发货状态、确认快照、发货明细和物流修改历史；
- `Payment` 与 `Refund`：不可变收退款事实；
- `AfterSalesCase`：售后需求、退回核验、可补发数量、已补发数量和处理状态。

这些对象可以使用独立数据库表和内部包，但均属于 `orders` 顶级模块。售后台账引用原订单和原发货，却不回写原订单履约数量或主状态。

### 2.2 InventoryBatch

属于 `inventory` 模块，拥有库存批次身份和当前数量。数量变化只能由 `InventoryMovement` 产生，批次不拥有目标订单。

### 2.3 ProductionPlan

属于 `production` 模块，拥有计划类型、计划日期、执行员工、订单商品明细、工序、计划数量和来源关系。每张计划最多有一次有效核验。

### 2.4 模块协作

订单模块通过公开应用服务请求库存领用和生产计划；库存与生产模块通过明确结果接口向订单履约台账登记来源事实。任何模块都不得直接访问其他模块的 JPA 实体或 Repository。跨模块强一致命令在一个 Spring `@Transactional` 事务中完成。

## 3. 数量分层

对每条订单商品明细，数量分为四层：

1. **客户需求层**：当前有效订购数量、累计有效发货数量、未交付需求数量；
2. **工序处理层**：各工序流入、计划、核验、合格、返工、报废和未完成；
3. **最终产品层**：订单可发货数量和成品余量；
4. **售后层**：售后补发需求、可补发和已补发。

这四层不能相加。客户需求层回答“客户还差多少”；工序层回答“同一批需求在哪个阶段”；最终产品层回答“现在能发多少”；售后层回答“已确认发货后额外需要补发多少”。

## 4. 客户需求层

```text
未交付需求数量
= 当前有效订购数量 - 累计有效发货数量
```

约束：

```text
0 <= 累计有效发货数量 <= 当前有效订购数量
0 <= 未交付需求数量
```

订单变更减少当前有效订购数量时，不得低于累计有效发货数量。生产报废不会自动改变当前有效订购数量。

## 5. 流程分流

设订单商品明细数量为 `Q`，缝边数量为 `E`：

```text
不缝边需求 = Q - E
缝边需求 = E
制作共同需求 = Q
捏毛装袋共同需求 = Q
缝边裁剪需求 = E
最终交付需求 = Q
```

制作、捏毛装袋和缝边裁剪是阶段，不得计算为 `Q + Q + E`。

捏毛装袋合格后才按冻结的缝边数量分流：

- 不缝边部分进入订单可发货；
- 缝边部分进入缝边裁剪有效流入；
- 缝边裁剪合格后进入订单可发货。

## 6. 工序有效流入

除首道制作外：

```text
工序有效流入
= 上游生产合格流入
+ 兼容库存领用接入
+ 合法返工流入
+ 合法报废重做流入
```

首道制作的正常流入来自订单实际生产缺口；返工和报废重做仍作为独立来源追加。

每一笔来源数量必须有唯一来源记录，并只能接入一个工序一次。

### 6.1 可安排和可执行

为支持提前排班，区分：

```text
待安排数量
= 当前工序总需求 - 有效待执行计划占用数量 - 已核验处理数量
```

```text
当前可执行数量
= 当前工序有效流入累计
- 当前工序已核验处理数量
- 已分配给其他待执行计划且当前已具备执行条件的数量
```

创建计划可以使用待安排数量，即使当前可执行数量不足；不足部分显示等待上游。核验时必须重新计算当前可执行数量，实际完成数量不能超过它。

返工和报废重做分别维护来源余额，创建对应计划时扣减可安排余额；取消计划时恢复余额；核验未完成时未完成部分恢复来源余额。

## 7. 生产核验

```text
本次完成数量 = 合格数量 + 返工数量 + 报废数量
未完成数量 = 计划数量 - 本次完成数量
```

- 合格：进入冻结流程的下一节点或最终可发货；
- 返工：生成待安排返工来源，不自动进入普通计划；
- 报废：终止原件流转，并按订单需求决定是否创建报废重做；
- 未完成：恢复该计划类型对应的待安排来源；
- 核验结果不可修改，错误使用更正事实处理。

报废重做产生的是替代品生产，不恢复原报废数量。原报废事实永久保留。

## 8. 库存接入

库存领用发生时：

1. 生成库存出库流水并减少原批次；
2. 生成订单履约接入事实；
3. 根据库存阶段进入捏毛装袋、缝边裁剪或可发货；
4. 后续发货不再次扣减原库存。

同一领用数量不能同时作为生产合格流入。取消领用必须反向库存流水并撤销尚未被后续事实消费的履约接入。

## 9. 可发货与发货

```text
可发货流入
= 不缝边捏毛装袋合格
+ 缝边裁剪合格
+ 兼容最终阶段库存接入
```

```text
当前可发货数量
= 可发货流入累计
- 有效发货消耗累计
- 已转成品余量数量
```

确认发货：

```text
本次发货数量 <= 当前可发货数量
累计有效发货数量 + 本次发货数量 <= 当前有效订购数量
```

发货作废恢复订单可发货数量，不自动恢复原库存。若需要撤销库存领用，必须另行满足取消领用条件并生成反向库存流水。

## 10. 减单和成品余量

减单后超出新需求的在制或最终产品必须逐项处理：

- 继续完成并转成品余量；
- 立即报废。

只有订单变更确认后，相关数量才从客户当前有效需求中取消。

成品余量库存保存原订单明细作为来源，但不再计入原订单未交付需求、可发货数量或关闭条件。

## 11. 超额任务

超额任务引用未来正常计划并记录预占数量：

```text
同一未来计划的有效超额预占总量 <= 未来计划当前可选数量
```

预占不修改未来计划原始数量，不产生工序流入或完成。核验后只有合格数量形成正常履约事实，并对未来计划产生调整提醒。

## 12. 售后数量

售后层与原订单层完全分离：

```text
客户退回数量 = 售后返工数量 + 售后报废数量
```

```text
售后可补发数量
= 库存补发接入
+ 售后返工最终合格
+ 售后补发生产最终合格
- 已确认售后补发发货数量
```

```text
售后待补发数量
= 售后补发需求数量 - 售后已确认补发数量
```

售后补发不改变原订单订购数量、累计发货数量和未交付需求。

## 13. 状态视图

不要用一个状态表达所有含义：

- 订单主状态：草稿、已确认、已取消、已关闭；
- 排产状态：未排产、已排产；
- 执行条件：可执行、等待上游；
- 生产进度：未开始、生产中、部分完成、生产处理完成；
- 需求处理状态：仍有待履约、部分处理、全部处理；
- 发货进度：未发货、部分发货、全部发货；
- 计划状态：待执行、已核验、已取消；
- 售后状态：独立于订单状态维护。

所有状态均由事实派生或通过明确命令转换，不提供手工下拉框直接改状态。

## 14. 不变量

实现和测试必须保证：

1. 各工序数量不相加为订单数量；
2. 同一来源数量不能被两个计划或两个订单重复消费；
3. 库存领用与发货不能重复扣库存；
4. 发货不能超过可发货或当前有效需求；
5. 报废不自动减少客户需求；
6. 返工和报废重做不增加订单数量；
7. 售后补发不回写原订单发货统计；
8. 已确认事实不通过物理删除修正；
9. 关闭订单必须同时重新校验履约和款项；
10. 所有汇总均可从来源事实重建。
