# 小组变更协调模块

> 模块代码：`workforce-coordination`

## 1. 模块说明

小组变更协调模块只负责“小组当前定义变更”和“排班活动引用守卫”之间的强一致编排，解决 `team` 与 `scheduling` 不能互相访问底层数据的问题。它不拥有业务数据。

## 2. 一期需求、范围与模块功能

- 修改小组名称或完整成员集合前，确认小组没有活动排班引用；
- 停用小组前，确认小组没有活动排班引用；
- 活动任务取消或核验结束后，允许后续小组修改；
- 使“小组修改”和“并发创建排班任务”竞争同一活动引用守卫；
- 任一参与模块失败时整体回滚。

一期不提供通用工作流、审批流、业务表、快照、事实或报表数据。

## 3. 模块边界

### 3.1 本模块拥有

仅拥有明确的跨模块用例、事务边界、调用顺序和错误映射。

### 3.2 本模块不拥有

- 小组、成员、效率和快照：由 `team` 拥有；
- 任务和活动引用：由 `scheduling` 拥有；
- 员工资格：由 `base-data` 拥有；
- 任何数据库表、Repository、事实或快照。

本模块只能依赖 `team.api.participant`、`scheduling.api.participant` 及必要的公开模型，不能依赖两个模块的内部包。

### 3.3 数据模型与表设计

本模块无业务表、无 Repository、无 Flyway、无快照和事实表。协调结果由 `team` 与 `scheduling` 各自保存，本模块只返回组合业务引用；幂等和审计使用 `platform` 公共能力。

## 4. 模块功能与公开接口

```java
interface WorkforceCoordinationService {
    TeamRef updateTeam(UpdateTeamCommand command);
    void deactivateTeam(DeactivateTeamCommand command);
}
```

不提供 `execute(type, payload)` 或任意编排接口。

## 5. 参与接口

```java
interface TeamActiveReferenceGuardPort {
    PreparedReferenceGuard lockAndCheckNoActiveReferences(TeamId teamId);
    void complete(PreparedReferenceGuard prepared);
}
interface TeamMutationParticipant {
    PreparedTeamMutation prepare(UpdateTeamCommand command);
    TeamRef commit(PreparedTeamMutation prepared);
    PreparedTeamMutation prepareDeactivate(DeactivateTeamCommand command);
}
```

准备令牌只在当前事务中有效，不持久化、不跨请求复用。

## 6. 修改小组流程

```text
workforce-coordination 开启事务和幂等命令
→ scheduling 锁定该小组的活动引用守卫
→ scheduling 确认不存在 ARRANGED/IN_PROGRESS 活动引用
→ team 锁定小组根并校验 row_version
→ team 重新校验完整成员集合和人数效率标准
→ team 追加成员变化事实、替换当前成员、递增 content_version
→ scheduling 完成守卫
→ 写审计和幂等结果
→ 一次提交
```

页面上的“当前无任务”只是预检查；正式命令必须执行以上事务内检查。

## 7. 停用小组流程

使用与修改相同的活动引用守卫和锁序。排班存在活动引用时返回 `TEAM_ACTIVE_PLAN_REFERENCED`；不存在时由 `team` 把状态改为 `INACTIVE` 并递增内容版本。历史快照和历史任务不受影响。

## 8. 事务、锁序和并发

固定锁序：

```text
scheduling 小组活动引用守卫
→ team 小组根
→ team 成员关系（按员工稳定业务标识排序）
→ 事实、审计和幂等结果
```

- 排班创建小组任务时必须先竞争同一个“小组活动引用守卫”，再取得小组快照并建立活动引用；
- 小组修改持有守卫期间，新排班创建必须等待；
- 排班先成功时，小组修改看到活动引用并拒绝；
- 小组修改先成功时，排班等待后取得新的小组快照；
- 不允许先锁 `team` 再锁 `scheduling`，避免形成相反锁序；
- 可重试死锁只能重试整个幂等命令，不能局部重试 SQL。

## 9. 错误语义

本模块不吞掉参与模块错误，统一增加上下文并保留稳定原因码：

- `TEAM_ACTIVE_PLAN_REFERENCED`：存在活动排班引用；
- `TEAM_VERSION_CONFLICT`：小组已被其他命令修改；
- `WORKFORCE_COORDINATION_CONFLICT`：参与模块状态在准备过程中变化；
- `WORKFORCE_COORDINATION_FAILED`：未预期事务失败。

## 10. 验收标准

- 本模块无业务表、Repository 和快照；
- `team` 与 `scheduling` 不形成直接双向依赖；
- 活动任务存在时修改和停用都被拒绝；
- 活动任务取消或核验后可以修改；
- 并发排班创建与小组修改不会出现遗漏引用或旧成员无快照；
- 任一参与端口失败，两侧均无部分提交；
- Spring Modulith 和 ArchUnit 验证只能依赖参与模块公开端口。
