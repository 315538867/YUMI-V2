# 报表模块

> 模块代码：`reporting`

## 1. 模块说明

报表模块通过各业务模块公开的只读数据源建立可重建投影，用于经营看板、统计和对账。报表不是业务事实来源，任何业务命令不得依赖报表结果作权威判断。

## 2. 一期需求、报表范围与模块功能

- 订单履约：数量、发货、收款和完成；
- 生产进度：需求、在制、合格、不合格和报废；
- 排班负载：个人/小组标准分钟、有效分钟和评估结果；
- 小组效率：按人数和实际任务的计划/完成对比；
- 售后：受理、未完成义务、处理时长和金额；
- 工资：期间人数、工资、扣款、补差和支付；
- 成本：订单/商品/期间分类成本；
- 现金：账户和日现金流；
- 订单利润：收入、成本、售后成本和毛利；
- 数据对账：来源事实与报表投影差异。

## 3. 模块边界

- 各业务模块提供 `changedSince(cursor, limit)` 类型的公开数据源；
- 报表不得读取其他模块数据库表，不得要求开放 Repository；
- 报表只拥有自己的水位、重建批次、差异和投影表；
- 报表延迟或失败不能阻止业务写入；
- 页面涉及操作资格时必须回到业务模块实时查询。

## 4. 更新规则

- 稳定游标：`occurredAt + businessId + version`；
- 水位只在整批成功后推进；
- 同一投影同一来源仅一个 worker 持有租约；
- 重复、乱序和来源更正必须幂等处理；
- 全量重建写影子版本，核对通过后切换；
- 删除投影后可从公开数据源重建；
- 页面显示最新成功时间和延迟状态。

## 5. 数据模型与表设计

### 5.1 管理表

| 表 | 类别 | 关键字段 | 关键约束与索引 |
|---|---|---|---|
| `reporting_watermarks` | 水位 | `projection_code, source_module, last_cursor, last_occurred_at, last_success_at, lag_seconds, status, row_version` | 复合主键 |
| `reporting_rebuild_batches` | 运行记录 | `batch_business_id, projection_code, rebuild_type, from_cursor, to_cursor, status, processed_count, error_count, started_at, finished_at` | `UK(batch_business_id)`, `IX(projection_code, started_at)` |
| `reporting_reconciliation_runs` | 对账记录 | `run_business_id, reconciliation_code, business_date, source_fingerprint, projection_fingerprint, status, started_at, finished_at` | 对账代码/日期/来源指纹唯一 |
| `reporting_reconciliation_differences` | 差异 | `difference_business_id, run_business_id, dimension_key, source_value, projection_value, difference_value, severity, status, resolution_note` | `UK(difference_business_id)` |

### 5.2 业务投影

| 表 | 主键/维度 | 核心指标 |
|---|---|---|
| `report_order_fulfillment_daily` | 日期、订单 | 应收、数量、发货、收款、履约状态 |
| `report_production_progress_daily` | 日期、商品、需求类型 | 需求、在制、合格、不合格、报废 |
| `report_scheduling_load_daily` | 日期、主体 | 标准分钟、有效分钟、计划/核验分钟、评估结果 |
| `report_team_efficiency_daily` | 日期、人数 | 计划数量、完成数量、标准时长、实际时长 |
| `report_after_sales_daily` | 日期、案例类型 | 新增、完成、待处理、金额 |
| `report_payroll_period_summary` | 工资期间 | 人数、毛额、扣款、补差、净额、已付 |
| `report_order_cost_summary` | 订单 | 直接材料、人工、经营分摊、售后、总成本 |
| `report_cash_flow_daily` | 日期、账户 | 期初、流入、流出、期末 |
| `report_order_profit_summary` | 订单 | 收入、成本、利润、利润率 |
| `report_reconciliation_summary` | 日期、对账代码 | 检查数、差异数、未解释差异数 |

所有投影包含 `source_watermark` 和 `updated_at`。

## 6. 公开接口设计

```java
interface ReportingQuery {
    ReportPage query(ReportCode code, ReportCriteria criteria);
    ReportingFreshness getFreshness(ReportCode code);
}
interface ReportingAdministrationService {
    RebuildRef rebuild(RebuildProjectionCommand command);
    ReconciliationRef reconcile(RunReconciliationCommand command);
}
```

各来源模块提供自己的 `ReportingFeed`，报表模块不定义通用数据库读取接口。

## 7. 事务、并发与历史

- 单批拉取、投影写入和水位推进在同一事务中完成；任一行失败，本批水位不得推进。
- 同一 `projection_code + source_module` 通过租约或行锁保证同一时刻只有一个增量 worker。
- 重建写入独立影子版本，完成对账后以短事务切换当前版本；失败时继续使用旧版本。
- 来源事实发生更正或失效时，以来源业务标识和版本幂等重放，不直接覆盖来源历史。
- 报表投影可删除重建；水位、重建批次和对账差异作为报表自身追溯记录保留。

## 8. 权限、页面和错误

权限按内容拆分：`report.order.read`、`report.production.read`、`report.scheduling.read`、`report.after-sales.read`、`report.payroll.read`、`report.cost.read`、`report.finance.read`、`report.admin`。工资、成本和现金继续受敏感资源范围限制。

页面：经营总览、各主题报表、数据时效提示、对账差异、重建管理。

错误码：`REPORT_CODE_INVALID`、`REPORT_CRITERIA_INVALID`、`REPORT_PROJECTION_LAGGING`、`REPORT_REBUILD_ALREADY_RUNNING`、`REPORT_SOURCE_QUERY_FAILED`、`REPORT_RECONCILIATION_DIFFERENCE`。

## 9. 验收标准

- 报表 SQL 只访问 reporting 自有表；
- 重复和乱序数据不会重复累计；
- 失败批次不推进水位；
- 全量影子重建不影响在线旧投影；
- 投影与来源可自动对账并定位差异维度；
- 删除投影后可重建一致结果；
- 报表延迟明确显示；
- 业务模块不依赖 reporting。

## 10. 待确认问题

本模块当前无阻塞一期开发的结构问题；各报表具体列顺序和导出样式属于页面详细设计。
