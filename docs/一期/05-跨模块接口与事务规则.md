# 跨模块接口与事务规则

## 1. 基本原则

所有跨模块协作只能通过提供方公开接口完成。调用方使用的是业务能力，不是提供方的表、Repository 或内部领域对象。

## 2. 公开接口类型

| 类型 | 用途 | 是否写入 | 是否加入调用方事务 |
|---|---|---:|---:|
| Application Service | 完整正式业务命令，自己是命令所有者 | 是 | 自己开启事务 |
| Participant Port | 被另一个命令所有者调用的受限写能力 | 是 | 必须加入现有事务 |
| Query | 读取当前资料、事实或历史结果 | 否 | 不要求写事务 |
| Snapshot Acquisition | 取得当前不可变快照，创建或复用 | 可能 | 加入正式业务事务 |
| Reporting Feed | 按稳定游标提供只读变化数据 | 否 | 否 |

## 3. 接口命名和模型

接口必须使用明确业务名称，例如：

```java
ProductSnapshotRef acquireCurrentProductSnapshot(...);
WorkloadAssessment assessWorkload(...);
PreparedProductionReservation prepareTaskReservation(...);
void commitTaskReservation(...);
PaymentEligibility checkPaymentEligibility(...);
```

跨模块模型只能包含：

- 稳定业务标识；
- 不可变值对象；
- 必要业务参数；
- 结果、规则版本和输入指纹；
- 类型化 `SnapshotRef`。

禁止暴露 Entity、数据库行对象、Repository、懒加载对象或通用 JSON 命令。

## 4. 命令所有者

一次正式业务动作只能有一个命令所有者。命令所有者负责：

1. 协议和权限校验；
2. 幂等开始；
3. 固定顺序调用参与模块；
4. 保存自己的事实、当前记录和引用；
5. 完成审计和幂等结果；
6. 任一步失败时使整个事务回滚。

参与模块不得在回调中继续调用第三个模块写接口，避免隐藏事务链和依赖环。

## 5. 两阶段参与模式

高风险跨模块写入采用同一事务内的 prepare/commit 语义：

```text
命令所有者锁定自己的根
→ participant.prepare：校验、锁定并返回准备结果
→ 命令所有者写入自身数据
→ participant.commit：使用准备令牌写入参与模块事实
→ 幂等和审计成功
→ 一次提交
```

准备令牌只在当前事务有效，不允许持久化后跨请求复用。

## 6. 固定锁序

为避免死锁，跨模块命令必须声明固定锁序。公共原则：

1. 先锁命令所有者业务根；
2. 再按接口文档顺序锁参与模块守卫或来源；
3. 再锁明细和投影；
4. 最后写事实、快照和幂等结果。

典型锁序：

| 业务动作 | 锁序 |
|---|---|
| 订单确认 | orders 根/编号 → product 快照唯一键 → production 需求守卫 |
| 排班创建 | scheduling 任务守卫 → 小组活动引用守卫 → 员工日期负载（稳定标识升序）→ 商品日期产能 → production 来源 → 上游快照唯一键 |
| 小组修改 | scheduling 小组活动引用守卫 → team 根 → team 成员投影 |
| 生产核验 | scheduling 任务 → production 来源/阶段 → 两模块事实和投影 |
| 发货 | orders 发货根 → production 可交付来源 → 订单履约投影 |
| 工资封账 | payroll 期间 → 工资结果 → cost-ledger 来源守卫 |
| 现金支付 | 业务应付/应收对象 → finance 账户 → 现金事实 |

真实 MySQL 测试必须验证锁序和死锁重试策略。

## 7. 幂等

- 所有正式写请求携带幂等键；
- 幂等范围至少包含操作者、命令类型和业务根；
- 相同幂等键、相同输入返回原结果；
- 相同幂等键、不同输入返回冲突；
- 幂等成功记录与业务事务一起提交；
- 失败事务不留下成功结果；
- 只读查询和预览不写幂等记录。

## 8. 失败语义

| 类型 | 含义 | HTTP 建议 |
|---|---|---:|
| VALIDATION | 输入结构或字段不合法 | 400 |
| BUSINESS_REJECTION | 当前业务状态不允许 | 409 或 422 |
| NOT_FOUND | 稳定业务对象不存在 | 404 |
| FORBIDDEN | 权限不足 | 403 |
| CONCURRENT_CONFLICT | 版本冲突或并发状态变化 | 409 |
| IDEMPOTENCY_CONFLICT | 幂等键重复但输入不同 | 409 |
| SYSTEM_FAILURE | 未预期系统失败 | 500 |

错误响应必须包含稳定 `errorCode`、用户可读信息、`requestId` 和可选字段错误。

## 9. 查询一致性

- 写命令内需要决策的数据必须重新查询并锁定，不能信任页面预检查结果；
- 历史解释使用当时保存的事实或快照引用，不改读当前定义；
- 列表投影允许最终一致，但操作资格必须由权威模块实时校验；
- 报表不能被业务写入流程反向调用作为判断依据。

## 10. 禁止事项

- 直接查询其他模块表；
- 建立跨模块数据库外键；
- 共享 Repository；
- 复制对方公式；
- 用数据库触发器完成跨模块业务；
- 通过通用事件总线掩盖强一致写入；
- 参与模块再次调用协调器或命令所有者；
- 在 Query 中隐式修改业务状态。
