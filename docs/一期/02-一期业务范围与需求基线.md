# 一期业务范围与需求基线

## 1. 建设目标

YUMI V2 一期用于管理工作室从商品预算、客户订单、生产安排、实际生产、售后处理，到工资、成本、收付款和经营报表的完整闭环。系统必须能解释每一项业务结果来自什么事实、使用什么历史依据、由谁操作以及如何更正。

## 2. 一期核心业务闭环

```text
维护客户、商品、人员和小组
→ 建立商品标准方案和可选自定义方案
→ 创建并确认订单及交付约定
→ 建立生产需求和作业任务
→ 个人或小组完成工序并核验生产事实
→ 发货并完成订单履约
→ 必要时建立售后案例，登记退回制品重入，再处理返工、补发、退款或赔付
→ 财务结算模块核算工资、归集成本并登记真实收付
→ 报表模块形成经营分析
```

## 3. 一期需求范围

### 3.1 客户、人员与平台能力

- 客户资料、联系信息、地址、状态和跨模块快照；
- 员工、工种资格、每日有效工作时间；
- 无组长的小组、成员、按人数配置的全局效率标准；
- 身份、权限、文件、审计、幂等、编号和提交后任务。

### 3.2 商品与预算

- 商品基本字段、模具数量、模具每日生产批次；
- 制作、捏毛装袋、缝边剪袋等工序字段；
- 人工费、运输包装费、日常杂费、房租水电、模具单件摊销和其他材料费用；
- 标准方案自动生成，自定义方案与标准方案使用同一结构；
- 自定义方案继承商品人工工时且只读，可覆盖非人工工序成本及材料来源；
- 胶水损耗率、胶水单价、色浆单价等录入默认值在创建商品时复制写入商品，不作为运行时引用；
- 商品内容版本及按需快照。

### 3.3 订单、履约与售后

- 一次创建并确认订单，不保存订单草稿；
- 冻结客户、商品、方案和交付约定；
- 订单变更按价格/地址、数量、生产定义变化分类处理；生产定义变化为可迁移数量建立继任订单项和新生产需求，不覆盖旧快照；
- 订单取消、发货、完成和已有订单接管；
- 订单应收、退款义务和支付履约；
- 已完成订单的售后案例、可追溯最近交付来源与物理根的退回接收、生产退回重入、返工需求、原样退还、转线下库存、报废、补发、退款、赔付和结案；返工修复原制品，修复失败转补发时必须建立独立新制需求；
- 售后不覆盖原订单、原发货和原生产事实。

### 3.4 生产作业和小组

- 订单及售后产生生产需求；
- 个人任务和小组共同任务；
- 任务安排、调整、取消、核验和更正；
- 标准工作量、实际工作量、超时/少时评价；
- 小组效率用于提高共同任务标准，不等同于成员分别独立生产；
- 商品单日产能上限必须使用模具数量和模具每日生产批次，并且只约束产生新制品的制作明细；
- 质量、返工、报废、交付来源和数量守恒；需求义务账与物理制品账分别守恒，生产需求区分新制与退回制品修复，售后退回和修复只移动原制品，不增加制作产量；
- 生产事实保留完整追溯链。

### 3.5 财务结算和报表

- 按独立游标自动读取生产劳动与责任来源；劳动按完成数量形成个人和小组到人工资，未完成不计入；
- 工资复核、调整、封账、应付和支付状态；
- 归集生产材料、生产人工、售后和经营费用成本；
- 成本分摊、冲销、更正和按业务对象查询；
- 现金、银行和平台账户；
- 订单收款、退款、售后赔付、工资付款和经营费用付款；
- 现金冲销、余额和账户对账；
- 订单、生产、工资、成本、现金和经营汇总报表。

## 4. 一期明确不做

- 服务端业务草稿；
- 材料目录、库存、采购、领料、批次价格和设备自动采集；
- 独立客服工单平台、无订单售后和跨订单售后案例；
- 物流平台自动同步；
- 考勤、社保、个税和完整人力资源系统；
- 会计总账、会计科目、借贷凭证、发票和税务申报；
- 通用工作流、通用规则引擎和通用事件总线；
- 微服务拆分和跨库事务。

## 5. 关键业务原则

1. 所有模块只能通过公开接口调用其他模块能力，禁止访问其他模块底层表或 Repository。
2. 事实、快照和投影必须区分：事实记录发生过什么，快照冻结外部定义，投影用于查询并可重建。
3. 业务定义模块自己管理快照，其他模块只保存快照引用。
4. 计算公式属于计算中心代码能力；业务模块保存输入、规则版本、结果和指纹，不复制公式。
5. 金额使用十进制定点数，数量和工时必须有明确单位及舍入规则。
6. 订单应收、工资应付、成本发生和真实现金是不同事实。
7. 模块合并不改变聚合边界；售后、工资、成本、现金仍分别维护自己的规则和数据。
8. 生产核验成功不因下游成本归集暂时失败而回滚；可重建派生数据通过幂等来源 Feed 补偿。

## 6. 一期成功标准

- 标准订单、自定义方案、客户供料、个人生产、小组生产、售后、工资、成本和收付款形成完整闭环；
- 历史订单、生产、工资和成本不被当前商品、人员或规则变化重新解释；
- 并发操作不造成超排、超产、超发、超收、超付或重复入账；
- 关键跨模块事务任一步失败时不留下部分数据；
- 所有正式修改、冲销和更正均可追溯；
- 报表能从权威事实和公开数据源重建。
