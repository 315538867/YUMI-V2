# 一期业务范围与需求基线

## 1. 建设目标

YUMI V2 一期用于管理工作室从商品预算、客户下单、制作、排班、质量核验、发货、收付款、售后、工资到经营分析的完整业务链。系统的首要目标不是建立通用制造平台，而是准确表达当前工作室的真实业务。

## 2. 一期核心业务闭环

```text
基础资料与商品预算
→ 订单确认与交付约定
→ 生产需求与制品来源
→ 个人或小组排班
→ 制作/修复执行与核验
→ 合格数量交付及发货
→ 客户收付款与订单完成
→ 售后处理
→ 工资结算、成本归集、现金记录
→ 经营报表与对账
```

## 3. 一期需求范围

### 3.1 基础资料

- 客户资料和默认收货信息；
- 员工、在职状态和工种资格；
- 制作星级、标准时长等固定静态选项；
- 商品录入默认值，仅用于新建商品预填；
- 文件、账号、角色、权限、审计和幂等。

### 3.2 商品与预算

- 商品基本信息、制作规格、产能参数；
- 制作、捏毛装袋、缝边剪袋三类工序字段；
- 单件额外费用；
- 自动生成不可独立编辑的内置标准方案；
- 建立多个与标准方案同结构的自定义方案；
- 按目标工序、材料来源和成交价格试算预计成本与利润；
- 对外提供商品及方案当前快照。

### 3.3 订单与履约

- 新订单直接创建并确认，不经过草稿；
- 订单商品、交付约定、数量、价格和客户供料约定；
- 已确认订单的正式变更；
- 普通发货直接确认；
- 客户付款履约、交付履约和订单完成；
- 已有订单接管录入及后续追溯。

### 3.4 生产、排班和小组

- 生产需求、制品物理阶段、质量、责任、处置和来源链；
- 个人任务和小组共同产出任务；
- 小组成员配置、按人数的统一效率标准；
- 排班任务创建、调整、取消和核验；
- 工作量是否低于、符合或超过标准，由公开评估接口计算；
- 制作、修复和其他任务的事实记录。

### 3.5 财务、成本、工资和报表

- 真实现金收入、支出、退款和分配；
- 人工、材料、经营费用和售后成本台账；
- 生产结果到人的工资结算；
- 小组共同工资按历史成员均分；
- 订单、生产、排班、售后、工资、成本、现金和利润报表。

## 4. 一期明确不做

- 微服务拆分、消息队列、分布式事务；
- 通用材料目录、库存、采购、领料和仓库管理；
- 动态工序设计器、动态字段/EAV、通用工作流引擎；
- 服务端业务草稿、草稿发布流程；
- 小组组长、组内岗位、可承接范围和组内步骤拆分；
- 根据效率因子分配小组工资；
- 把装箱定义为生产工序；
- 动态公式编辑器或数据库脚本公式；
- 把报表投影作为业务事实来源；
- 跨模块数据库联表或直接访问其他模块 Repository。

## 5. 关键业务原则

1. 商品、方案、客户、员工和小组等当前定义可以修改；已发生业务通过事实或快照保留当时依据。
2. 公式只在计算中心实现；业务模块准备输入并保存自己需要的业务数据和结果。
3. 生产事实不覆盖，错误通过更正事实形成可追溯链。
4. 小组共同完成一项任务时，产出属于小组整体，不在生产和排班模块虚构成员个人产量。
5. 工资结算负责把共同产出分配到人；其他模块不得提前分摊。
6. 所有正式写入均一次提交完整命令，不允许半成品长期停留。

## 6. 一期成功标准

- 关键业务从录入到结算可以闭环；
- 任一订单、生产结果、工资和现金记录都能追溯来源；
- 修改当前主数据不会改写历史业务依据；
- 模块边界可由自动化架构测试验证；
- 并发、重复提交或中途失败不会造成数量、金额或状态部分成功；
- 业务人员能从页面看懂当前状态、阻塞原因和历史变化。
