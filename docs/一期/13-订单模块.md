# 订单模块

> 模块代码：`orders`

## 1. 模块说明

订单模块管理客户交易、交付约定、数量与价格、订单变更、普通发货、应收退款决定、付款履约、订单完成和已有订单接管。订单是交易事实所有者，不拥有生产物理事实和现金流水。

## 2. 一期需求、范围与模块功能

- 新订单一次创建并确认；
- 选择商品和标准/自定义方案作为录入起点；
- 取得商品、方案和客户当前快照；
- 冻结本次成交价格、目标工序、材料来源和交付信息；
- 建立生产需求；
- 已确认订单的数量、约定和金额正式变更；
- 直接确认发货；
- 应收、退款义务、收付款关联和履约状态；
- 双向履约满足后完成订单；
- 录入已有订单的当前事实并继续管理。

一期不提供订单草稿、发货草稿、库存出库和物流平台自动同步。

## 3. 业务概念

- **订单项**：同一商品的交易明细。
- **交付约定组**：订单项中共享同一目标工序、材料来源、价格和交付要求的一组数量。
- **约定版本**：每次正式变更后不可变的交付约定。
- **当前有效应收**：原始应收加有效调整后的金额。
- **交付履约**：有效发货数量满足当前交付义务。
- **付款履约**：有效净收款满足当前应收。

## 4. 模块边界

### 4.1 订单拥有

订单、订单项、交付约定、变更、应收和退款决定、普通发货、付款业务关联、完成和取消事实。

### 4.2 订单不拥有

商品当前定义、生产阶段和数量、排班任务、真实现金、售后案例。

### 4.3 跨模块协作

- 从 `base-data` 和 `product` 取得当前快照；
- 调用 `production` 建立或调整生产需求；
- 复杂需求/排班联动通过 `fulfillment-coordination`；
- 发货调用 `production` 消费合格来源；
- 收退款资格由订单提供，真实现金由 `finance` 保存；
- 订单完成后售后由 `after-sales` 独立管理。

## 5. 业务规则

1. 新订单不保存半成品，创建命令成功即为 `CONFIRMED`。
2. 商品方案只作为录入模板；订单保存自己的不可变交付约定版本。
3. 一个约定组的数量、目标工序、材料来源、价格和收货信息必须完整。
4. 订单变更不能覆盖原约定，必须生成新约定版本和变更事实。
5. 减量或取消不得小于已完成、已发货或无法撤销的数量。
6. 发货必须消费达到约定目标工序且质量合格的生产来源。
7. 发货命令直接确认，不建立发货草稿或长期预留。
8. 已确认发货不能直接编辑，错误通过发货更正事实。
9. 订单完成必须同时满足交付履约和付款履约，并且不存在阻塞完成的有效义务。
10. 当前客户、商品或方案变化不影响已确认订单。
11. 订单资金决定与真实现金事实分开。

## 6. 状态设计

- 订单：`CONFIRMED / IN_FULFILLMENT / COMPLETED / CANCELLED`；
- 交付约定组：`ACTIVE / FULFILLED / CANCELLED`；
- 变更：正式命令成功即为有效记录，不使用草稿状态；
- 发货：事实通过有效性和更正链管理；
- 完成：由完成事实表达；后续有效变更或售后义务不直接改写原完成事实，必要时追加完成失效事实。

## 7. 业务流程

### 7.1 新订单确认

```text
校验完整输入和幂等
→ 取得客户当前快照
→ 为每个订单项取得商品及方案当前快照
→ 形成订单自己的交付约定版本和预计成本结果
→ 写订单、订单项、应收事实
→ production 建立生产需求
→ 审计并一次提交
```

取得快照接口保证引用的是调用时最新 `content_version`；订单只保存快照引用和自己的交易约定。

### 7.2 订单变更

```text
锁定订单和受影响约定组
→ 计算允许变更的剩余数量
→ 建立新约定版本和金额调整
→ 原子调整 production 需求及必要的 scheduling 活动任务
→ 写变更确认事实
```

已有活动排班的影响通过公开接口校验，订单不得直接查询排班表。

### 7.3 发货

```text
锁定订单和约定组
→ production 校验并锁定合格可交付来源
→ 写发货事实和明细
→ production 写来源消费事实
→ 更新交付履约投影
→ 如满足双向履约则允许确认完成
```

### 7.4 收付款

财务模块发起现金命令时，订单提供可收/可退资格并在同事务写支付关联；订单当前应收和真实现金分开保存。

### 8.4 已有订单接管

`orders_legacy_intakes`、`orders_legacy_intake_items`、`orders_legacy_state_lines`、`orders_legacy_financials` 保存接管时已经确认的当前事实和来源说明；后续变化仍使用正常订单、生产和财务事实。接管记录不可覆盖，更正使用差额事实。

## 10. 事务与并发

- 订单确认：订单编号/根→商品快照唯一键→生产需求守卫；
- 订单变更：订单根→约定组（稳定顺序）→排班/生产参与守卫；
- 发货：订单根→约定组→生产来源（稳定顺序）；
- 支付：订单应收/退款义务→财务账户；
- 所有跨模块动作任一步失败全事务回滚；
- 订单行和组使用 `row_version`，金额和数量使用数据库检查约束及应用不变量双重保护。

## 11. 权限、页面和错误

权限：`order.create`、`order.change`、`order.ship`、`order.complete`、`order.cancel`、`order.read`、`order.legacy.intake`。

页面：订单列表、直接确认新订单、订单详情、正式变更、直接发货、付款履约、已有订单接管。

错误码：`ORDER_PRODUCT_SNAPSHOT_INVALID`、`ORDER_AGREEMENT_INVALID`、`ORDER_CHANGE_EXCEEDS_REMAINING`、`ORDER_HAS_ACTIVE_FULFILLMENT`、`ORDER_SHIPMENT_SOURCE_INSUFFICIENT`、`ORDER_PAYMENT_NOT_FULFILLED`、`ORDER_DELIVERY_NOT_FULFILLED`、`ORDER_ALREADY_COMPLETED`、`ORDER_VERSION_CONFLICT`。

## 12. 验收标准

- 新订单没有草稿，成功即同时形成订单、约定、应收和生产需求；
- 商品后续修改不改变已确认约定；
- 订单变更保留旧版本并正确调整生产/排班；
- 并发发货不会超出可交付数量；
- 发货中途失败时订单和生产都不提交；
- 交付和付款均满足前不能完成；
- 现金事实冲销后付款履约正确回退；
- 已有订单接管满足数量和金额守恒并可继续正常履约。
