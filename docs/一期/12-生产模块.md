# 生产模块

> 模块代码：`production`

## 1. 模块说明

生产模块保存生产需求、制品来源、物理加工阶段、质量、责任、处置、数量变化和来源消费事实。它描述真实生产发生了什么，不负责排班计划，也不负责把小组产出分配到成员工资。

## 2. 一期需求、范围与模块功能

- 根据订单、售后或已有订单接管建立生产需求；
- 维护每个生产来源需要的数量和目标工序；
- 为排班任务预占和释放可执行数量；
- 记录制作、捏毛装袋、缝边剪袋和修复结果；
- 记录质量核验、责任认定、返工、报废和更正；
- 计算各阶段可用数量、在制数量、合格数量和缺口；
- 为发货和售后交付消费合格来源；
- 为工资提供有效核验事实。

装箱不是生产工序；打包发货可作为排班“其他任务”，不改变制品物理阶段。

## 3. 业务概念

- **生产需求**：某业务来源要求形成的产品数量及最终目标工序。
- **生产来源**：可独立追溯、占用和消费的一组数量来源。
- **物理阶段**：`MAKING / BAGGING / SEAM_CUTTING` 的完成位置。
- **质量状态**：`PENDING / QUALIFIED / DEFECTIVE`。
- **处置状态**：`AVAILABLE / RESERVED / REWORK_REQUIRED / SCRAPPED / CONSUMED`。
- **生产事实**：一次数量移动、核验、责任或处置的不可覆盖记录。
- **数量投影**：从有效事实计算出的当前余额，可重建。

生产事实是数据库追溯记录，不是快照。

## 4. 模块边界

### 4.1 生产拥有

生产需求、来源、占用、执行事实、核验事实、质量、责任、处置、来源消费和数量投影。

### 4.2 生产不拥有

订单交付约定、商品当前定义、排班任务、员工/小组当前资料、工资分配、现金和成本分类。

### 4.3 协作关系

- `orders` 或 `after-sales` 调用生产参与端口建立/调整需求；
- `scheduling` 调用生产参与端口预占或释放来源数量；
- 核验由排班命令入口发起，但生产模块写入生产事实；
- 发货由订单命令入口消费生产合格来源；
- `payroll` 读取有效生产核验事实；
- 生产实际成本通过 `cost-ledger` 参与端口登记。

## 5. 业务规则

1. 任一来源的有效数量必须满足守恒：初始需求和有效增加 = 各当前阶段余额 + 报废 + 已消费 + 有效减少。
2. 排班占用不能超过来源当前可排数量。
3. 取消排班只释放对应活动占用，不删除历史占用事实。
4. 核验数量不能超过任务有效占用数量。
5. 小组任务核验形成小组共同产出，不生成成员个人产量。
6. 质量不合格不等于报废；必须通过返工、继续使用或报废处置决定。
7. 责任认定与质量事实分开，可以后补或更正。
8. 已被发货/售后消费的来源不能直接回退阶段；必须先更正消费业务。
9. 原事实不可覆盖；录错通过更正事实使原事实失效并形成替代链。
10. 生产模块不得重新计算商品标准工时或排班工作量。

## 6. 典型流程

### 6.1 建立需求

```text
业务所有者锁定订单/售后对象
→ production.ProductionDemandParticipant.prepareCreate 校验来源唯一性
→ 写业务所有者事实
→ production.ProductionDemandParticipant.commitCreate 建立需求和来源
→ 同事务提交
```

### 6.2 排班占用

```text
scheduling 锁定任务
→ production.ProductionReservationParticipant.prepareReserve 锁定来源余额
→ 校验可排数量和目标阶段
→ scheduling 写任务
→ production.ProductionReservationParticipant.commitReserve 追加占用事实并更新投影
```

### 6.3 核验

```text
锁定排班任务和生产来源
→ 校验完成数量、合格/不合格数量
→ 追加执行和质量事实
→ 更新来源阶段及数量投影
→ 写排班核验事实
→ 必要时登记成本
→ 一次提交
```

### 6.4 更正

更正命令必须引用原事实，计算差额影响，检查后续消费和状态约束，追加失效/替代事实并重建受影响投影。

## 7. 状态设计

- 需求：`ACTIVE / SATISFIED / CANCELLED`；状态由有效数量推导，可保存投影；
- 占用：`ACTIVE / RELEASED / VERIFIED / VOIDED`；
- 质量：由最新有效质量事实决定；
- 责任：`UNDETERMINED / EMPLOYEE / TEAM / STUDIO / EXTERNAL / WAIVED`；
- 处置：`AVAILABLE / REWORK_REQUIRED / SCRAPPED / CONSUMED`。

不同维度不得压缩为单一巨大状态枚举。

## 10. 事务与并发

- 来源余额修改按 `production_source_business_id` 固定顺序加锁；
- 多来源操作按稳定标识升序锁定；
- 事实写入和数量投影更新同事务；
- 投影更新使用“读取锁定余额→校验→追加事实→更新余额”，不得先减后补；
- 占用、核验和消费必须通过条件约束保证数量不为负；
- 更正命令锁定原事实和全部受影响后续事实；
- 与排班、订单跨模块失败时全部回滚。

## 11. 历史、权限和错误

生产历史通过事实链展示；商品和执行主体的历史定义通过当时保存的快照引用解析。

权限：`production.read`、`production.verify`、`production.quality.manage`、`production.responsibility.manage`、`production.correct`。

错误码：`PRODUCTION_DEMAND_DUPLICATED`、`PRODUCTION_QUANTITY_INSUFFICIENT`、`PRODUCTION_STAGE_INVALID`、`PRODUCTION_RESERVATION_CONFLICT`、`PRODUCTION_VERIFY_EXCEEDS_RESERVED`、`PRODUCTION_FACT_HAS_DOWNSTREAM_USAGE`、`PRODUCTION_TRACE_BROKEN`。

## 12. 页面与交互要求

- 生产需求列表和缺口看板；
- 来源详情和完整追溯时间线；
- 核验页面显示任务占用、已核验和剩余数量；
- 不合格项必须选择缺陷和后续处置；
- 更正页面明确展示原事实、后续影响和禁止原因；
- 小组结果显示小组快照，不虚构成员个人产量。

## 13. 验收标准

- 所有数量场景满足守恒且不会出现负数；
- 并发排班不能超占；
- 并发核验不能超过占用；
- 取消任务正确释放数量；
- 不合格、返工、报废和重新合格链可追溯；
- 已消费来源不能被非法回退；
- 更正不会覆盖原事实；
- 小组共同产出只形成一条主体为小组的生产结果；
- 生产模块不读取排班、商品或工资表。
