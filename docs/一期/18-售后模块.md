# 售后模块

> 模块代码：`after-sales`

## 1. 模块说明

售后模块管理订单完成后的问题受理、双方义务、退回、返工、重新交付、额外补发、收费/退款/赔付决定和售后结案。售后不能覆盖原订单和原生产事实。

## 2. 一期需求、范围与模块功能

- 针对已完成订单创建售后案例；
- 记录问题类型、数量、证据和说明；
- 建立客户配合、退回、返工、补发、收费、退款和赔付义务；
- 接收退回实物并建立生产处理来源；
- 创建售后生产需求和修复排班；
- 记录重新交付或额外补发；
- 关联真实现金收付；
- 全部有效义务完成后结案。

一期不提供独立客服工单平台、自动物流同步、覆盖原订单金额或覆盖原生产质量事实。

## 3. 业务概念

- **售后案例**：一次售后问题的业务根。
- **义务**：客户或工作室必须完成的动作或金额责任。
- **处理路线**：退回返工、直接补发、退款、赔付或混合处理。
- **售后金额决定**：收费、退款、赔付的业务义务，不等于现金事实。
- **售后交付**：本案例产生的重新交付或额外补发。

## 4. 模块边界

- 只受理已完成订单，订单资格通过 `orders` 公开接口校验；
- 生产需求和来源由 `production` 保存；
- 修复任务由 `scheduling` 保存，必要时通过履约协调模块原子建立；
- 真实现金由 `finance` 保存；
- 实际售后成本提交 `cost-ledger`；
- 售后只保存跨模块稳定标识和事实引用。

## 5. 业务规则

1. 一个案例必须引用一个已完成订单。
2. 案例创建一次提交完整问题信息，不保存草稿。
3. 义务只能追加、完成、失效或更正，不能覆盖历史。
4. 客户配合义务未完成时，依赖该配合的工作室义务不能完成。
5. 退回实物只有形成退回接收事实后，才能进入生产处理。
6. 返工、重新交付和补发数量不得超过有效义务数量。
7. 金额决定与真实现金分离；现金关联失败不得把义务标为已支付。
8. 所有有效义务完成且金额义务满足后才能结案。
9. 已结案后发现新问题，追加结案失效事实并恢复处理，不覆盖原结案事实。
10. 售后处理不修改原订单、原发货和原生产事实。

## 6. 状态设计

- 案例：`OPEN / PROCESSING / COMPLETED`；
- 义务：`PENDING / IN_PROGRESS / FULFILLED / VOIDED`；
- 路线：`RETURN_AND_REWORK / DIRECT_REPLACEMENT / REFUND_ONLY / COMPENSATION_ONLY / MIXED`；
- 金额义务：`PENDING / PARTIALLY_SETTLED / SETTLED / VOIDED`。

## 7. 业务流程

### 7.1 受理

校验订单已完成，写案例和问题事实；根据确定路线建立初始义务。

### 7.2 退回和返工

记录退回接收事实，通过履约协调建立生产需求和修复任务；核验完成后记录售后交付。

### 7.3 退款或赔付

写金额决定事实；由财务命令调用售后支付资格并原子写现金事实和支付关联。

### 7.4 结案

锁定案例和全部有效义务，确认数量、客户配合、交付和金额均满足，写结案事实和当前状态。

## 10. 事务与并发

- 案例操作锁定案例根和受影响义务；
- 数量履行通过条件更新防止超过义务；
- 建立返工需求和任务通过履约协调同事务完成；
- 售后支付锁序：金额义务→财务账户；
- 结案时重新查询全部有效义务，页面预检查不构成授权；
- 重复交付和支付通过来源唯一键与幂等防重。

## 11. 权限、页面和错误

权限：`after-sales.open`、`after-sales.handle`、`after-sales.settle`、`after-sales.complete`、`after-sales.read`。

页面：售后列表、受理、案例详情时间线、义务看板、退回接收、返工/补发、金额处理、结案。

错误码：`AFTER_SALES_ORDER_NOT_COMPLETED`、`AFTER_SALES_OBLIGATION_BLOCKED`、`AFTER_SALES_QUANTITY_EXCEEDED`、`AFTER_SALES_RETURN_NOT_RECEIVED`、`AFTER_SALES_SETTLEMENT_INCOMPLETE`、`AFTER_SALES_CASE_ALREADY_COMPLETED`。

## 12. 验收标准

- 未完成订单不能创建售后；
- 原订单和生产事实不会被售后覆盖；
- 客户义务能正确阻塞后续动作；
- 返工需求和任务要么同时成功要么同时失败；
- 补发数量不超义务；
- 金额决定和现金事实可分别追溯；
- 所有义务满足前不能结案；
- 结案失效和重新处理保留完整历史。
