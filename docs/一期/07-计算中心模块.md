# 计算中心模块

> 模块代码：`calculation`

## 1. 模块说明

计算中心是无数据库、无业务状态的纯代码模块，统一实现系统数值公式、精度、舍入和规则版本。业务模块负责取得输入、调用公式、解释业务含义并保存自己的结果。

## 2. 一期需求与模块功能

- 商品材料用量、成本、预计利润和利润率；
- 商品单日最大产能；
- 个人任务标准工作量；
- 小组协作任务标准工作量；
- 工作量、已占用分钟与剩余有效工作时间比较；
- 金额按人数均分和最小货币单位余数分配；
- 通用金额合计、比例和舍入。

## 3. 模块边界

### 3.1 计算中心拥有

- 公式实现；
- 输入输出值对象；
- 精度和舍入策略；
- 稳定公式代码和规则版本；
- 公式单元测试和示例数据。

### 3.2 计算中心不拥有

- 数据库、表、Repository 和 Flyway；
- 商品、人员、小组、订单或工资数据；
- 当前时间、用户、权限和文件；
- HTTP Controller；
- 业务快照、生产事实和报表投影；
- 动态公式编辑。

### 3.3 数据模型与表设计、事务和历史

本模块无业务表、无 Repository、无 Flyway、无独立事务，也不创建公式快照。每次计算返回稳定公式代码、代码规则版本、舍入版本和输入指纹，由调用方在自己的事实、快照或结果记录中保存；同一输入和同一规则版本必须得到相同结果。

## 4. 公式目录

### 4.1 商品产能

```text
单日最大产能 = 模具数量 × 每个模具每日生产批次
```

两个输入都来自商品基本字段，必须大于 0。

### 4.2 商品材料和预算

计算中心接收商品/方案已经确定的重量、损耗率、单价、来源、工序费用和额外单件费用。示意关系：

```text
胶水标准用量（克） = 商品单件标准克重 × (1 + 胶水损耗率)
胶水成本 = 胶水标准用量 × 胶水每克单价
色浆成本 = 胶水标准用量 × 色浆每克单价
工作室承担材料成本 = 来源为工作室的材料标准成本之和
单件预计总成本 = 基础材料成本 + 目标工序范围内的工序成本 + 商品额外单件费用
预计利润 = 方案售价 - 工作室承担单件成本
预计利润率 = 预计利润 ÷ 方案售价；售价为 0 时返回空
```

胶水损耗只计算一次；色浆直接引用已经包含损耗的胶水标准用量，不再次乘损耗率。上述专用公式固定在计算中心，不能散落在商品或页面代码中。

### 4.3 个人工作量

```text
个人任务标准分钟 = 任务数量 × 商品单件标准分钟
个人剩余有效分钟 = max(0, 每日有效分钟 - 当日已占用分钟)
```

不同任务类型使用对应标准分钟；每日有效分钟由基础资料提供，已占用分钟由排班根据自己的有效任务汇总。

### 4.4 小组工作量

小组效率用于体现流水线协作带来的效率提升，不能按“每个人各自独立完成全部产品”计算：

```text
小组基准分钟 = 任务数量 × 商品单件标准分钟
小组任务标准分钟 = 小组基准分钟 ÷ 小组效率因子
成员剩余分钟 = max(0, 每日有效分钟 - 该成员当日已占用分钟)
小组可用分钟 = min(所有成员剩余分钟)
```

- 效率因子按小组人数取得，全局统一；
- 启用的效率因子必须大于 1；
- 小组任务标准分钟代表小组整体完成该任务所需的经过时间；
- 生产/修复任务由商品标准分钟和效率因子推导；其他任务直接录入的标准分钟已经是整个执行主体的预计经过时间，不再除以效率因子；
- 同一个小组任务标准分钟会占用每名成员的当日时间，但不产生成员个人产量；
- 不能把每日有效分钟乘以成员人数；
- 效率因子不用于工资分配。

### 4.5 工作量比较

```text
任务标准分钟 < 剩余有效分钟  → UNDER_STANDARD
任务标准分钟 = 剩余有效分钟  → WITHIN_STANDARD
任务标准分钟 > 剩余有效分钟  → OVER_STANDARD
输入缺失、负载异常或主体不可用 → UNAVAILABLE
```

计算结果必须同时返回任务标准分钟、比较前已占用分钟、剩余有效分钟和比较结果；小组还要返回每名成员的占用与剩余分钟明细。

### 4.6 小组工资均分

```text
总金额转换为币种最小单位整数
基础份额 = 整数总额 ÷ 成员数
余数 = 整数总额 % 成员数
按员工稳定业务标识升序，前“余数”名各增加一个最小单位
```

分配总和必须严格等于总金额。

## 5. 规则版本

每个公开公式返回：

- `formulaCode`；
- `ruleVersion`；
- `roundingVersion`；
- 规范化输入指纹；
- 计算结果和必要明细。

公式版本是代码发布标识，不是数据库业务快照。历史业务模块保存当次返回的规则版本即可。

## 6. 公开接口设计

```java
interface ProductBudgetCalculator {
    ProductBudgetResult calculate(ProductBudgetInput input);
}
interface CapacityCalculator {
    DailyCapacityResult calculate(DailyCapacityInput input);
}
interface WorkloadCalculator {
    IndividualWorkloadResult assessIndividual(IndividualWorkloadInput input);
    TeamWorkloadResult assessTeam(TeamWorkloadInput input);
}
interface MoneyAllocationCalculator {
    AllocationResult splitEqually(Money total, List<String> orderedEmployeeIds);
}
```

所有输入输出不可变，不接受 Entity 或 Repository。

## 7. 异常和边界

- 负数量、负金额、零成员、效率因子小于等于 1、除数为零均返回明确校验错误；
- 公式不擅自补默认值；缺失参数由调用方处理为业务拒绝；
- 输入顺序不应影响合计结果，除明确用于余数分配的稳定员工排序；
- 不使用二进制浮点数；
- 不读取系统时间和随机数。

## 8. 验收标准

- 每个公式有正常、零值、边界、精度和非法输入测试；
- 胶水用量只计算一次损耗，色浆成本不会重复乘损耗率；
- 商品预算明细之和等于汇总；
- 两个不同模块不能存在同名公式的复制实现；
- 个人已有任务后的剩余分钟和超排结果可重复计算；
- 2/3/4 人小组效率及“最小成员剩余分钟”样例可重复计算；
- 小组效率不会进入工资均分；
- 金额分配无分币差；
- ArchUnit 验证本模块不依赖业务模块、Spring 持久化和数据库。

## 9. 明确不采用

不建设公式表、公式脚本、表达式执行器、动态规则编辑器和计算快照表。
