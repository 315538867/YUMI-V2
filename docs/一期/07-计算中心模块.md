# 计算中心模块

> 模块代码：`calculation`

## 1. 模块说明

计算中心是无数据库、无业务状态的纯代码模块，统一实现系统数值公式、精度、舍入和规则版本。业务模块负责取得输入、调用公式、解释业务含义并保存自己的结果。

## 2. 一期需求与模块功能

- 商品材料用量、成本、预计利润和利润率；
- 商品单日最大产能；
- 个人任务标准工作量；
- 小组协作任务标准工作量；
- 工作量、已占用秒数与剩余有效工作时间比较；
- 金额按人数均分和最小货币单位余数分配；
- 通用金额乘数量、合计、比例和舍入。

## 3. 模块边界

### 3.1 计算中心拥有

- 公式实现；
- 输入输出值对象；
- 精度和舍入策略；
- 稳定公式代码和规则版本；
- 公式单元测试和示例数据。

### 3.2 计算中心不拥有

- 数据库、表、Repository 和 Flyway；
- 商品、人员、小组、订单或工资数据；
- 当前时间、用户、权限和文件；
- HTTP Controller；
- 业务快照、生产事实和报表投影；
- 动态公式编辑。

### 3.3 数据模型与表设计、事务和历史

本模块无业务表、无 Repository、无 Flyway、无独立事务，也不创建公式快照。每次计算返回稳定公式代码、代码规则版本、舍入版本和输入指纹，由调用方在自己的事实、快照或结果记录中保存；同一输入和同一规则版本必须得到相同结果。

## 4. 公式目录

本节是一期由 `calculation` 拥有的纯计算公式目录。生产来源余额、订单履约、工资期间汇总和账户余额等依赖业务事实有效性的聚合公式，仍由对应业务模块拥有；计算中心只提供其中可复用的定点数运算、比较、舍入和分配能力。其他模块不得复制本节的纯计算实现。所有公式均使用十进制定点数；输入单位必须随值对象传入，不能依靠字段名猜测。

### 4.1 商品单日最大产能

```text
单日最大产能（件/日）
= 模具数量（个） × 模具每日生产批次（批/个/日）
```

- 两个输入都来自商品基本字段，必须是正整数。
- 该结果只表示新制制作上限，不乘小组效率、不乘员工人数，也不约束修补、捏毛装袋、缝边剪袋和其他任务。
- 生产模块只按商品编号读取该结果；当日上限由生产模块按“已核验新制完成数量 + 未核验任务预留数量”维护，不得在本地重算产能公式。

### 4.2 商品单件预算

商品预算是**单件口径**，不是订单总额；商品模块传入的额外费用已经是每件金额，计算中心不得再次分摊。

#### 4.2.1 基础材料

```text
胶水标准用量（克/件）
= 单件标准克重（克/件） × (1 + 胶水损耗率)

胶水单件成本
= 胶水标准用量 × 胶水每克单价

色浆单件成本
= 胶水标准用量 × 色浆每克单价
```

胶水损耗率以 `0.05` 表示 5%，有效范围为 `[0, 1)`；损耗只应用一次。色浆直接使用已经包含损耗的胶水标准用量，不再次乘损耗率。胶水、色浆来源决定承担方，不改变用量或全资源价值。

#### 4.2.2 目标工序成本范围

```text
目标工序 = MAKING
  → 基础材料 + 制作工序 + 商品额外单件费用（只加入一次）

目标工序 = BAGGING
  → 基础材料 + 制作工序 + 捏毛装袋工序 + 商品额外单件费用（只加入一次）

目标工序 = SEAM_CUTTING
  → 基础材料 + 制作工序 + 捏毛装袋工序 + 缝边剪袋工序
  + 商品额外单件费用（只加入一次）
```

目标工序范围内的每个工序都按商品/方案中保存的单件字段形成明细。商品级额外单件费用不属于三道生产工序，作为独立明细**只加入一次**。装箱/打包发货不作为生产工序。

工序和额外费用的单件成本拆解固定如下；其中“人工/提成”属于人力成本，“其他材料/袋子/装饰品/综合材料/其他费用”属于非人工成本：

```text
制作工序单件人工成本
= 制作提成

制作工序单件非人工成本
= 制作工序其他材料费用

制作工序单件全资源成本
= 制作工序单件人工成本 + 制作工序单件非人工成本

捏毛装袋工序单件人工成本
= 捏毛装袋人工成本

捏毛装袋工序单件非人工成本
= 单件袋子成本 + 单件装饰品价格 + 捏毛装袋其他费用

捏毛装袋工序单件全资源成本
= 捏毛装袋工序单件人工成本 + 捏毛装袋工序单件非人工成本

缝边剪袋工序单件人工成本
= 缝边剪袋人工成本

缝边剪袋工序单件非人工成本
= 单件综合材料成本 + 缝边剪袋其他费用

缝边剪袋工序单件全资源成本
= 缝边剪袋工序单件人工成本 + 缝边剪袋工序单件非人工成本

商品额外单件费用
= 其他任务人工费 + 运输包装费 + 日常杂费
  + 房租水电费 + 模具单件摊销费 + 其他费用
```

基础胶水和色浆成本只作为 `MAKING` 的基础材料明细加入一次；因此：

```text
目标工序单件全资源成本
= 基础材料成本
  + 目标工序范围内各工序的单件成本
  + 商品额外单件费用
```

方案中的人工/提成字段只能由商品继承；自定义方案只能替换上述非人工字段以及方案允许的材料来源，不得替换人工成本。

#### 4.2.3 承担方、总成本和利润

对每一条预算明细 `i`，先得到其单件全资源金额 `full_i`、承担方 `bearer_i` 和成本性质。每条明细必须且只能有一个承担方，承担方只能是 `STUDIO` 或 `CUSTOMER`；一期只有材料明细允许选择客户承担，人工、提成和额外单件费用固定由工作室承担：

```text
全资源单件成本
= Σ full_i

工作室承担单件成本
= Σ full_i（bearer_i = STUDIO）

客户提供材料单件价值
= Σ full_i（bearer_i = CUSTOMER）

预计单件利润
= 方案售价 - 工作室承担单件成本

预计利润率
= 预计单件利润 ÷ 方案售价（方案售价 = 0 时返回空）
```

客户供料仍保留其标准用量、单价和全资源价值，但不进入工作室承担成本。预计利润允许为负；售价为零时利润金额仍可返回，利润率返回空。预算明细合计必须满足：

```text
Σ full_i = 全资源单件成本
工作室承担单件成本 + 客户提供材料单件价值
  = 全资源单件成本
```

人工、制作提成和商品额外分摊属于预算成本明细，但不属于生产材料成本来源。

### 4.3 个人任务标准工作量

生产或修复任务按**任务明细**计算后再汇总，不能用任务头总数量乘任意一个商品标准：

```text
明细基准秒数
= 明细计划数量 × 该明细冻结商品/方案的单件标准分钟 × 60

个人生产任务标准秒数
= Σ 明细基准秒数
```

- `NORMAL_PRODUCTION`、`EXTRA_PRODUCTION`、`REPAIR` 使用任务明细冻结的工序标准分钟。
- `OTHER_TASK` 的标准分钟由任务命令直接提供，表示整个任务预计经过时间，计算时乘 60 转为秒；不再用数量或商品标准分钟重复计算。
- 任务工作量使用计划数量；工资和实际成本使用核验后的完成数量，两个口径不能混用。商品快照中的单件标准分钟仍按整数保存，乘以计划数量后精确换算为整数秒。

```text
每日有效秒数 = 每日有效分钟 × 60
已占用秒数 = 调用方按任务生命周期汇总并传入的当日占用秒数
剩余有效秒数 = max(0, 每日有效秒数 - 已占用秒数)
超出有效时间 = 已占用秒数 > 每日有效秒数
```

计算中心不读取任务表，也不决定取消、核验任务是否应计入占用；生产模块必须先按自己的事实和投影口径汇总后传入。

### 4.4 小组协作任务标准工作量

小组效率体现流水线协作，不能按“每个人独立完成一整件产品”计算：

```text
小组基准秒数 = Σ（每条任务明细计划数量 × 该明细单件标准分钟 × 60）
小组任务标准秒数 = ceil(小组基准秒数 ÷ 小组效率因子)
成员每日有效秒数 = 每日有效分钟 × 60
成员剩余秒数 = max(0, 成员每日有效秒数 - 该成员已占用秒数)
小组可用秒数 = min(所有成员剩余秒数)
```

- 效率因子按小组人数取得，全局统一且必须大于 1；对整项小组任务只应用一次。
- 先汇总全部明细基准秒数，再整体除以效率因子；仅最终小组任务结果向上取整到整秒，不得逐明细舍入。
- 例如基准 6,000 秒、效率因子 1.2，结果为 5,000 秒；基准 1,000 秒、效率因子 1.3，结果为 770 秒（原始商向上取整）。
- 小组任务标准秒数是小组整体经过时间；同一数值分别计入任务快照中每名成员的日期负载，不乘成员人数。
- 其他小组任务的录入标准分钟已经是整个小组的预计经过时间，换算成秒后不再除以效率因子。
- 效率因子不进入工资总额、成员工资权重或产量拆分。

### 4.5 工作量比较

比较对象必须是“本次候选任务”与“创建前剩余有效秒数”，而不是把候选任务重复算入剩余负载：

```text
候选任务标准秒数 < 创建前剩余有效秒数 → UNDER_STANDARD
候选任务标准秒数 = 创建前剩余有效秒数 → WITHIN_STANDARD
候选任务标准秒数 > 创建前剩余有效秒数 → OVER_STANDARD
```

结果至少返回：候选任务标准秒数、比较前已占用秒数、每日有效秒数、比较前剩余秒数、超出有效时间标记、比较结果和全部输入快照。小组还返回每名成员的占用秒数、剩余秒数和本次任务增加秒数。输入缺失、负载异常、主体不可用或效率标准缺失返回 `UNAVAILABLE`。

### 4.6 实际劳动与生产材料金额

所有实际金额都以业务模块传入的历史快照单价为准，计算中心只负责乘法、合计和舍入：

```text
来源未舍入金额 = 完成数量 × 历史快照中的单件金额
生产材料来源金额 = HALF_UP(来源未舍入金额, 4 位小数)

完成数量 = 合格数量 + 返工/修补数量 + 报废数量 + 转线下库存数量
```

生产材料来源必须传入“当前核定工序、工作室承担、非人工”的历史单件成本。基础胶水/色浆在**一笔商品/方案预算**中只归入 `MAKING` 明细；对于每一条实际的 `MAKING` 生产或修复来源，按该来源对应的历史制作单件成本计算一次，后续包装工序不得再次取用这两项基础材料。未完成数量不形成劳动或生产材料金额。计算中心不判断成本分类、不读取商品当前值、不决定责任扣款。

### 4.7 工资金额和小组均分

生产劳动来源的基础工资金额：

```text
生产/修复来源工资未舍入金额
= 完成数量 × 冻结快照中的当前工序单件人工成本

生产/修复来源工资结算金额
= HALF_UP(来源工资未舍入金额, 2 位小数)

关联商品的其他任务来源工资未舍入金额
= 完成数量 × 冻结商品快照中的其他任务单件人工费

关联商品的其他任务来源工资结算金额
= HALF_UP(来源工资未舍入金额, 2 位小数)

未关联商品的其他任务基础工资
= 0

任务基础工资
= Σ 已舍入到分的来源工资结算金额
```

例如单件人工成本为 `0.3333` 元、同一工资来源明细完成 `3` 件，则先计算 `0.9999` 元，再将该来源明细舍入为 `1.00` 元；不能先把单件成本舍入为 `0.33` 元再乘数量。

其中生产/修复明细的“当前工序单件人工成本”由制作提成、捏毛装袋人工成本或缝边剪袋人工成本按工序确定；`OTHER_TASK` 不使用工序人工成本。超额制作激励、责任扣款、补偿和结转规则尚未确认，不在本目录擅自定义。

小组工资只对已确定的任务总金额均分，不把效率因子带入金额：

```text
总金额转换为币种最小单位整数
基础份额 = floor(整数总额 ÷ 成员数)
余数 = 整数总额 mod 成员数
按员工稳定业务标识升序，前“余数”名各增加一个最小单位

成员分配合计 = 任务总金额
```

成员分配合计必须严格等于任务总金额；成员集合来自任务时冻结的小组快照，不读取当前小组成员。

### 4.8 通用金额、比例和舍入

```text
未舍入金额 = 单价 × 数量
预算/成本明细金额 = HALF_UP(未舍入金额, 4 位小数)
结算明细金额 = HALF_UP(未舍入金额, 2 位小数)
合计金额 = Σ 已按该金额域精度舍入的明细金额
比例 = 分子 ÷ 分母（分母为 0 时：预计利润率返回空；其他比例请求返回明确的分母无效错误；不得返回无穷或默认 0）
```

商品预算和生产材料成本按 4 位小数在来源明细边界舍入；工资、应收、收退款和现金按 2 位小数在正式结算明细边界舍入；小组工资先转换为整数分再分配；合计只能由已保存明细重算。

商品预算的中间步骤不得提前舍入：先用未舍入的胶水用量计算胶水和色浆成本，再在对应预算明细输出边界按 `HALF_UP` 舍入到 4 位。工资必须先使用未舍入的单件成本乘完成数量，再在每个来源明细边界按 `HALF_UP` 舍入到 2 位。任何调用方都不得先把单价、用量或中间成本舍入后再传回计算中心。

### 4.9 全系统公式归属核对

公式是否进入计算中心，不按“有没有加减乘除”判断，而按“是否依赖某个业务模块对事实有效性的解释”判断。归属统一如下：

| 公式类别 | 权威归属 | 唯一口径 | 权威文档 |
|---|---|---|---|
| 商品日产能上限 | `calculation` | 模具数量 × 模具每日生产批次 | 本文 4.1 |
| 商品单件预算、利润、利润率 | `calculation` | 目标工序范围内单件成本明细合计 | 本文 4.2 |
| 个人/小组工作量与比较 | `calculation` | 计划数量 × 冻结分钟 × 60 得秒；小组汇总后整体除一次效率并向上取整到秒 | 本文 4.3～4.5 |
| 来源金额、工资明细金额 | `calculation` | 完成数量 × 历史快照单件金额 | 本文 4.6～4.8 |
| 小组金额均分 | `calculation` | 最小货币单位整除并按稳定员工标识分余数 | 本文 4.7 |
| 当日新制产能已用量和可安排量 | `production` | 已核验完成 + 未核验预留；上限由计算中心返回 | 《生产作业模块》6.6 |
| 生产来源可安排数量、需求义务和物理制品守恒 | `production` | 只按有效生产事实与活动预留重建 | 《生产作业模块》5.2.1、7.7 |
| 订单有效数量、有效应收、净收款和履约 | `orders` | 只按订单模块认定的有效事实重建 | 《订单模块》5.1 |
| 工资期间汇总和实际成本归集 | `finance` | 使用有效劳动/责任/调整来源及历史单件金额 | 《财务结算模块》5.1 |
| 账户余额和现金分配守恒 | `finance` | 期初 + 有效流入 − 有效流出；分配合计守恒 | 《财务结算模块》7.1.1 |
| 报表订单可归集利润 | `reporting` 派生展示 | 当前有效应收 − 已归集成本，不形成业务事实 | 《报表模块》4.1 |

业务模块拥有“哪些事实有效、哪些事实进入合计”的语义，并调用计算中心完成定点数运算；这不等于业务模块复制计算中心算法。报表只能消费上述结果和公开投影，不能产生可被业务命令反向依赖的新权威口径。

本次全系统公式核对统一检查以下六项，任何一项缺失都不得进入开发实现：

1. **输入口径**：明确使用商品/方案快照、任务计划数量、核验完成数量、有效事实或当前业务约束，禁止把计划数量与完成数量混用；
2. **业务范围**：明确目标工序、生产类型、承担方、订单状态或责任范围，禁止把不同阶段数量直接相加；
3. **归属边界**：纯数值运算调用 `calculation`，事实有效性和业务聚合由事实所有者模块完成，报表不产生新口径；
4. **舍入边界**：中间值不提前截断，明细在声明边界舍入，汇总只累加已保存明细，小组均分在最小货币单位处理；
5. **异常边界**：负数、零分母、零成员、非法效率和守恒失败必须显式拒绝或返回空值，不能静默使用 `0` 或 `max(0)` 掩盖错误；
6. **追溯依据**：结果保存公式规则版本、舍入版本、输入指纹和必要明细，历史结果不能被当前配置回算覆盖。

> `max(0, 每日有效秒数 - 已占用秒数)` 只适用于工作量模块定义的“剩余有效秒数”展示和比较，并且必须同时返回原始占用、每日上限和 `occupied > daily` 的超出信号；它不能用于掩盖生产来源、需求义务、物理制品或产能守恒中的负数。后四类数量一旦出现负数，必须拒绝写入或返回明确的数据一致性错误。

### 4.10 本轮公式核对结论

| 公式组 | 核对结论 | 开发状态 |
|---|---|---|
| 商品日产能 | 公式、适用范围和生产占用口径一致 | 可开发 |
| 商品预算 | 固定字段、目标工序范围、承担方、利润及客户供料口径一致 | 可开发 |
| 个人工作量 | 按明细计划数量乘冻结标准分钟、换算为秒后汇总 | 可开发 |
| 小组工作量 | 整体基准秒数只除一次效率因子，最终向上取整到秒；可用秒数取成员剩余最小值 | 可开发 |
| 工作量比较 | 与创建前剩余秒数比较，候选任务不重复占用 | 可开发 |
| 实际劳动和生产材料 | 都使用完成数量和历史快照单价，材料只取工作室承担非人工行 | 可开发 |
| 基础工资与小组均分 | 基础工资公式和等额分配规则一致，小组效率不进入工资 | 可开发 |
| 生产数量、产能和物理守恒 | 由生产模块按有效事实维护，负数不允许被截断 | 可开发 |
| 订单数量、应收、净收款和履约 | 由订单模块按有效事实聚合；有效交付和有效应收不得为负，收退款受订单义务额度限制 | 可开发 |
| 现金余额和现金分配 | 由财务模块按有效现金事实维护并严格守恒 | 可开发 |
| 报表订单利润 | 只作为派生展示，不产生新业务事实 | 可开发 |
| 超额制作激励 | 单价、计价数量、是否叠加制作提成尚未确认 | 阻塞对应工资金额开发 |
| 责任扣款与结转 | 是否扣款、基数、上限、小组到人和跨期结转尚未确认 | 阻塞对应工资金额开发 |

工时和金额精度契约已在本节锁定：工时结果与负载以秒保存，预算/成本与正式结算使用不同精度和值对象。超额制作激励及责任扣款相关业务金额规则仍按上表保持待确认，不得据此推导结算金额。

## 5. 规则版本

每个公开公式返回：

- `formulaCode`；
- `ruleVersion`；
- `roundingVersion`；
- 规范化输入指纹；
- 计算结果和必要明细。

公式版本是代码发布标识，不是数据库业务快照。历史业务模块保存当次返回的规则版本即可。

## 6. 公开接口设计

```java
interface ProductBudgetCalculator {
    ProductBudgetResult calculate(ProductBudgetInput input);
}
interface CapacityCalculator {
    DailyCapacityResult calculate(DailyCapacityInput input);
}
interface WorkloadCalculator {
    IndividualWorkloadResult assessIndividual(IndividualWorkloadInput input);
    TeamWorkloadResult assessTeam(TeamWorkloadInput input);
}
interface CostAmountCalculator {
    ExtendedAmountResult multiply(Quantity quantity, UnitCost unitCost);
}
interface MoneyAllocationCalculator {
    AllocationResult splitEqually(SettlementMoney total, List<String> orderedEmployeeIds);
}
```

工作量接口的时间输入、输出和快照字段统一使用整数秒（`DurationSeconds`）；商品与人员配置仍以整数分钟录入。`UnitCost`、`CostAmount`、`SettlementMoney`、`DurationSeconds` 和有符号金额差额是不同值对象，不能互相隐式转换。

所有输入输出不可变，不接受 Entity 或 Repository。

## 7. 异常和边界

- 业务数量、单价、单位成本、任务基础工资和分配总额不得为负；订单调整、工资调整、冲销和更正等明确声明为“有符号差额”的值对象允许为负，预计利润等计算结果也允许为负；禁止用一个通用 `Money` 校验把合法负结果误判为非法输入；
- 零成员、效率因子小于等于 1、非法除数和不允许为负的输入均返回明确校验错误；预计利润率售价为零时按公式约定返回空值，预计利润等有符号计算结果允许为负。
- 公式不擅自补默认值；缺失参数由调用方处理为业务拒绝；
- 输入顺序不应影响合计结果，除明确用于余数分配的稳定员工排序；
- 不使用二进制浮点数；
- 整数秒结果超出 `BIGINT` 范围或金额结果超出对应 `DECIMAL(19,scale)` 范围时，返回明确溢出错误，不截断、不饱和到最大值；
- 不读取系统时间和随机数。

## 8. 验收标准

- 每个公式有正常、零值、边界、精度和非法输入测试；
- 胶水用量只计算一次损耗，色浆成本不会重复乘损耗率；
- 商品预算明细之和等于汇总；
- 制作、捏毛装袋、缝边剪袋和商品额外费用均按固定字段拆解，人工/提成不被方案覆盖，基础胶水/色浆只在制作明细加入一次；
- 两个不同模块不能存在同名公式的复制实现；
- 个人已有任务后的剩余秒数和超排结果可重复计算；
- 任意人数（至少 2 人）小组效率及“最小成员剩余秒数”样例可重复计算，效率除法只在任务级舍入一次；
- 小组效率不会进入工资均分；
- 生产来源数量乘历史单件成本的精度、舍入和输入指纹稳定；
- 金额分配无分币差；
- ArchUnit 验证本模块不依赖业务模块、Spring 持久化和数据库。

## 9. 明确不采用

不建设公式表、公式脚本、表达式执行器、动态规则编辑器和计算快照表。
