# 公共业务与技术规则

## 1. 标识和编号

- 内部主键：正数 `BIGINT`，仅模块内部使用。
- 稳定业务标识：`VARCHAR(64)`，创建后不可修改、不可复用，可跨模块保存。
- 人工编号：如商品号、订单号、员工号，用于展示和搜索，不作为跨模块关联主键。
- 请求编号和命令执行标识：用于幂等、审计和问题定位。
- 跨模块禁止暴露数据库内部主键。

## 2. 通用数据类型

| 数据 | 数据库类型 | 规则 |
|---|---|---|
| 预算单价、单件成本、成本台账金额 | `DECIMAL(19,4)` | Java 使用 `BigDecimal`，HTTP 使用十进制字符串；金额边界按 `HALF_UP` 舍入到 4 位 |
| 应收、收退款、工资结算、现金及账户余额 | `DECIMAL(19,2)` | 人民币正式结算金额；按 `HALF_UP` 舍入到分 |
| 有符号成本差额 | `DECIMAL(19,4)` | 仅更正/冲销等有符号差额使用 `SignedCostAmount` |
| 有符号结算差额 | `DECIMAL(19,2)` | 人民币调整/更正/冲销差额使用 `SignedSettlementAmount` |
| 比例、损耗率、效率因子 | `DECIMAL(12,8)` | 明确范围，不使用浮点数 |
| 重量、用量 | `DECIMAL(19,4)` | 字段或值对象必须明确单位 |
| 商品及每日有效时间标准 | `INT` 分钟 | 非负，单件标准时长通常必须大于 0；录入和快照保留分钟 |
| 任务工作量、占用负载、剩余时间 | `BIGINT` 秒 | 非负；Java 使用 `DurationSeconds`；公式内部、持久化和比较统一使用整数秒 |
| 数量 | `BIGINT` | 正式数量非负；更正事实允许有符号差额 |
| 系统时间 | `DATETIME(6)` | 数据库统一保存 UTC |
| 业务日期 | `DATE` | 按工作室业务时区解释 |
| 状态和类型 | `VARCHAR(32)` | 使用稳定代码，不保存中文显示文本 |
| 内容指纹 | `CHAR(64)` | 规范化输入的 SHA-256 小写十六进制 |

## 3. 无服务端草稿

一期所有模块不提供业务草稿：

- 页面未提交内容只存在前端本地状态；
- 创建和编辑一次提交完整正式命令；
- 任一校验或写入失败，整个命令回滚；
- 预览和试算为只读，不持久化；
- `ACTIVE/INACTIVE`、`OPEN/CLOSED` 等状态不是草稿/发布状态；
- 不建立 `DRAFT` 业务状态或草稿表。

## 4. 事实、追溯记录、快照和投影

### 4.1 事实

事实表示已经发生的业务事件，例如生产核验、收款、发货、工资封账。事实不可覆盖修改，错误通过新的更正、失效或冲销事实处理。

### 4.2 追溯记录

生产来源链、成本台账、现金流水、审计日志等是追溯记录。它们本身就是业务记录，不应被称为快照。

### 4.3 快照

快照只用于冻结“可变定义在某一业务引用时的样子”，例如商品方案、小组成员、客户收货信息。快照由定义所有者模块管理，其他模块只保存：

```text
owner_module
snapshot_type
snapshot_business_id
snapshot_version
```

不得只保存裸版本号，不得复制上游快照载荷并冒充权威数据。

### 4.4 投影

投影用于列表、看板和报表，可以从事实或当前记录重建。投影损坏不得影响业务真相。

## 5. 内容版本和快照取得规则

适用快照的可变聚合必须有：

- `content_version`：业务内容每次成功修改后递增；
- `row_version`：乐观锁版本；
- 快照记录中的 `source_content_version`；
- 同一聚合、同一内容版本最多一个有效快照。

正式业务需要引用当前定义时，调用所有者的取得接口：

```text
锁定或校验当前聚合
→ 读取 content_version
→ 查找 source_content_version 相同的快照
→ 已存在则复用
→ 不存在则物化不可变快照
→ 返回完整 SnapshotRef
```

该过程由所有者模块自行调用也适用。普通查询不得偷偷创建快照。

## 6. 版本和并发

- `row_version` 用于防止并发覆盖；
- `content_version` 用于判断业务内容是否需要新快照；
- 事实版本用于同一来源的顺序和更正链；
- 报表水位版本只用于投影更新；
- 这些版本不可混用。

修改命令必须携带期望 `row_version`。冲突时返回稳定并发错误，不进行静默覆盖。

## 7. 更正、取消和删除

- 已被历史业务引用的记录不物理删除；
- 当前主数据使用停用；
- 未发生事实且没有活动引用的配置允许修改或删除，具体由模块说明；
- 已发生事实使用更正/失效/冲销记录；
- 取消不删除历史，只使当前有效关系失效；
- 更正链必须能从当前记录追溯到原始记录。

## 8. 金额、精度和舍入

- 一期商品售价、订单应收、工资和资金收付统一使用人民币（`CNY`），不做币种兑换；金额仍携带 `currency_code`，用于校验和未来扩展；
- 公式中间值保留足够精度，最终在明确边界舍入；
- 预算和成本明细使用 4 位小数、`HALF_UP`；应收、收退款、工资结算和现金使用 2 位小数、`HALF_UP`；不得把预算成本的小数精度直接带入实际支付金额；
- 预算/成本金额与结算金额使用不同类型：分别为 `CostAmount` 和 `SettlementMoney`；调整、更正、冲销等有符号差额使用明确的有符号类型，不以通用金额类型混用；
- 计件工资按每个来源明细分别以“完成数量 × 冻结单件人工成本”计算，明细结果舍入到分后再汇总；小组工资均分基于已经确定到分的任务金额；
- 工作量计算统一使用整数秒；商品标准分钟和每日有效分钟在输入边界转换为秒，业务展示再转换回分钟；
- 损耗率按小数存储（例如 `0.05` 表示 5%），损耗率范围为 `[0, 1)`；效率因子必须明确大于 1；
- 方案预算、任务工作量、实际劳动、生产材料、工资、应收和现金分别声明数量口径，不能把“计划数量”和“完成数量”混用；
- 生产任务明细必须满足 `计划数量 = 未完成数量 + 完成数量`，完成数量必须满足 `完成数量 = 合格数量 + 返工/修补数量 + 报废数量 + 转线下库存数量`；
- 已经是单件金额的商品额外费用不得再次按订单数量或产量分摊；
- 逻辑条件使用逻辑运算表达（例如 `∧` 表示“且”），不能用金额或数量加法替代；
- 舍入方式和规则版本由计算中心定义；中间值不得提前截断，明细金额在声明的金额边界舍入，汇总只累加已舍入明细；
- 工作量剩余秒数允许按公式返回 `max(0, 每日有效秒数 - 已占用秒数)`，但必须同时保留原始已占用秒数和超出信号；生产来源、需求义务、物理制品和新制产能守恒不允许使用 `max(0)` 掩盖负数；
- 预计利润率在售价为 0 时返回空；其他比例分母为 0 时返回明确校验错误，不返回无穷或默认 0；
- 单价、单位成本和正式支付金额默认非负；预计利润、对账差异以及明确建模为调整、冲销或更正的有符号金额允许为负，接口必须用不同值对象表达，不能依靠调用方约定；
- 任何金额合计必须能由已保存明细重算；
- 小组工资到人分配按币种最小单位分配，保证分配总和严格等于小组金额；
- 已封账金额不因当前单价、公式或资料变化自动重算。

## 9. 状态设计

每个状态必须回答：

- 谁能进入；
- 进入前置条件；
- 进入后允许的操作；
- 是否允许撤销；
- 如何更正历史；
- 并发时锁定什么；
- 状态是否权威，还是可重建投影。

禁止只用一个可覆盖 `status` 字段表达需要审计的历史变化。

## 10. 统一审计字段

当前记录通常包含：`created_at, created_by, updated_at, updated_by, row_version`。
事实通常包含：`occurred_at, recorded_at, operator_id, command_execution_id, corrects_fact_business_id, is_valid, reason_text`。
快照通常包含：`snapshot_business_id, snapshot_version, source_content_version, content_fingerprint, created_at, created_by_command_execution_id`。
