# 人员与小组模块

> 模块代码：`workforce`

## 1. 模块说明

人员与小组模块统一管理生产执行主体。员工是原子执行主体，小组是由多名员工组成的复合执行主体。模块同时拥有执行主体活动引用守卫，用于保证员工、小组和资格变更不会使正在活动的生产任务失效。

本模块不管理作业计划、生产数量、工资或金额计算。

## 2. 一期需求、范围与模块功能

- 创建员工，维护基本资料、在职状态和账号绑定；
- 办理入职、离职和返聘；
- 维护工种及员工资格；
- 创建、修改、停用小组并维护完整成员集合；
- 按小组人数维护全局统一效率因子；
- 维护全局每日有效工作分钟标准；
- 校验个人或小组执行资格；
- 创建或复用员工、小组、效率和有效时间快照；
- 为生产任务预留、调整和释放执行主体活动引用；
- 在影响可用性的变更前检查本模块活动引用守卫；
- 为财务结算解析历史员工和小组成员。

一期不提供组织架构、部门、岗位职级、考勤、请假、组长、小组可承接范围、组内岗位、组内步骤、成员贡献比例和个性化小组效率。

## 3. 业务概念

- **员工**：可独立承接作业的原子执行主体。
- **小组**：至少两名员工组成的复合执行主体，产出归小组共同所有。
- **执行主体**：类型为 `EMPLOYEE` 或 `TEAM` 的统一生产引用。
- **工种资格**：员工在指定日期是否可以承担某类作业的权威依据。
- **效率标准**：按小组人数配置的流水线协作效率因子，不是工资分配权重。
- **每日有效工作时间标准**：个人和小组任务共同使用的全局每日有效分钟上限。
- **执行主体快照**：正式安排任务时冻结的员工身份，或小组及其完整成员集合。
- **活动引用预留**：生产任务处于计划或执行状态期间，对小组和相关员工建立的可追溯占用。
- **活动引用守卫**：序列化任务预留与人员变更的本模块并发根。

内部能力：

```text
workforce
├─ employee              员工资料、就业事实和账号绑定
├─ qualification         工种定义和员工资格
├─ team                  小组及成员关系
├─ standard              人数效率和每日有效工作时间
├─ snapshot              执行主体与标准快照
└─ activityreservation   活动引用守卫、预留和释放
```

## 4. 模块边界

### 4.1 本模块拥有

员工、就业事实、工种、资格、小组、成员关系、人数效率标准、每日有效工作时间、必要快照、活动引用守卫和活动引用预留记录。

### 4.2 本模块不拥有

- 登录认证和角色权限：由 `platform` 拥有；
- 作业任务、工作日期、计划数量、日期负载、产能占用和生产事实：由 `production` 拥有；
- 工作量、效率换算和金额公式：由 `calculation` 提供；
- 工资期间、到人工资和小组工资分配：由 `finance.payroll` 拥有。

活动预留只保存任务稳定来源引用、被预留主体和状态，不复制商品、工序、数量或生产任务内容。

## 5. 业务规则

### 5.1 员工与资格

1. 员工编号创建后不可修改、不可复用。
2. 返聘沿用原员工身份。
3. 一个员工至多绑定一个平台账号，一个账号至多绑定一个员工。
4. 员工离职不删除历史任务、生产事实、工资和快照。
5. 员工资料修改递增 `content_version`。
6. 离职、撤销资格等减少可用能力的操作，必须锁活动守卫并确认没有活动预留。
7. 入职、返聘和授予资格可以直接完成，但仍使用本模块事务和版本控制。

### 5.2 小组

1. 小组至少包含 2 名当前在职员工。
2. 不保存组长、承接范围、组内岗位、组内步骤和成员贡献比例。
3. 一期允许同一员工属于多个小组。
4. 创建小组只校验成员在职；安排任务时按目标工种校验全部成员资格。
5. 小组或任一成员存在相关活动预留时，不允许修改成员或停用小组。
6. 小组产出属于小组整体，生产不拆成员个人产量。
7. 存在历史引用的小组不物理删除。

### 5.3 效率和有效时间

1. 启用的小组人数必须存在唯一活动效率标准，效率因子必须大于 1。
2. 商品工序标准时间及每日有效时间以整数分钟配置；计算中心将任务明细基准时间换算成整数秒后汇总。小组效率只对全部明细基准秒数之和应用一次：`小组标准秒数 = ceil(Σ明细基准秒数 ÷ 效率因子)`；不逐明细舍入、不按成员重复计算，也不用于其他任务。
3. 效率因子只用于小组标准工作量，不直接进入工资总额、成员权重或产量拆分。
4. 一期只有一套全局每日有效工作分钟标准。
5. 标准修改递增自己的 `content_version`；历史任务继续使用旧快照。
6. 已被活动任务引用的标准内容不可覆盖；修改形成新内容版本。

### 5.4 活动引用预留

1. 个人任务预留员工本人。
2. 小组任务同时预留小组和任务主体快照中的全部成员。
3. 预留来源使用 workforce 定义的 `WorkforceActivitySourceRef`，包含来源模块、来源类型和稳定业务标识，不依赖 production 类型。
4. 同一任务、同一预留范围只能存在一条有效预留。
5. 任务调整必须在一个事务中释放不再使用的预留并建立新预留。
6. 任务取消或终态核验完成后释放预留；历史预留记录不删除。
7. 预留和生产任务必须同事务成功或回滚。
8. 人员变更和生产预留竞争相同守卫行，不能先查后改。

## 6. 状态设计

- 员工就业：`EMPLOYED / LEFT`，返聘追加新就业事实；
- 工种资格：`ACTIVE / REVOKED`；
- 小组：`ACTIVE / INACTIVE`；
- 活动预留：`ACTIVE / RELEASED`；
- 快照不可变，不设置可编辑状态。

## 8. 业务流程

### 8.1 创建小组

校验至少两名成员且均在职，锁定员工根，写小组、成员关系、成员事实和审计。创建时不配置组长和工种范围。

### 8.2 安排任务取得快照并预留

```text
production 开启事务并锁任务守卫
→ workforce 校验个人或小组当前资格
→ 创建或复用主体及标准快照
→ 按稳定标识锁活动守卫
→ 写小组及成员活动预留并增加活动计数
→ production 写任务、负载和评估
→ 一次提交
```

### 8.3 影响可用性的人员变更

```text
workforce 开启事务
→ 计算受影响员工、小组和标准
→ 按稳定顺序锁活动守卫
→ active_reference_count 大于 0 时拒绝
→ 锁员工/小组根
→ 写变更事实、当前投影和内容版本
→ 一次提交
```

### 8.4 调整、取消和完成任务

生产模块调用本模块参与接口，在同一事务中调整或释放预留。释放只改变预留状态、时间和守卫计数，不删除历史记录。

## 10. 事务、锁序和并发

- 活动守卫统一按 `guard_type + guarded_business_id` 排序加锁；
- 小组任务必须锁小组及全部成员守卫；
- 人员变更锁序：活动守卫 → 员工根 → 小组根 → 成员/资格投影；
- 任务预留、调整和释放由生产开启事务，本模块加入现有事务；
- 预留记录、守卫计数和生产任务任一步失败全部回滚；
- 快照按来源内容版本使用唯一键防重；
- 当前根使用 `row_version`；死锁只允许重试整个幂等命令。

### 11.1 人员与小组交互原型基线

> 整理日期：2026-10-09。页面入口：[人员与小组原型](../../workforce-element-plus.html)。本节覆盖员工、小组、全局效率与每日有效时间三个页面域，不代表已经连接真实生产活动引用。

#### 11.1.1 员工页面与录入字段

| 页面 / 分区 | 展示与操作 |
|---|---|
| 员工列表 | 姓名、编号、电话、工种资格、所属小组、在职状态；关键词、状态、工种筛选、重置、分页、新增、详情、编辑 |
| 基本资料表单 | 姓名、编号、联系电话、入职日期；编辑时最近入职日期与在职状态只读，右侧同步预览 |
| 工种资格 | 制作、捏毛装袋、缝边剪袋、其他任务；可多选，也可暂不配置 |
| 员工详情 | 身份、资格、小组信息；编辑、办理离职或返聘 |
| 历史区域 | 就业记录、资格授予 / 撤销记录、活动任务引用，展示日期、变化、说明及操作人等 |

- **一期原型没有绑定平台账号功能。**手机号只作联系资料，不自动创建登录用户；新增与编辑页不提供绑定账号控件。
- 姓名必填，最多 30 字；手机号可空，填写时必须是 11 位且以 `1` 开头；入职日期不得晚于当天。
- 新增自动生成员工编号；编辑姓名、电话或资格不改变编号、入职 / 离职历史。
- 编辑资料不能直接覆盖在职状态或就业日期；离职和返聘从详情通过单独对话框办理。
- 存在活动任务时可以增加资格，但不能撤销已有资格；原型按员工是否有活动引用作整体保护，尚未实现逐工种精确引用守卫。

```text
员工列表 → 新增 / 编辑 → 填写身份与资格 → 保存
员工详情 → 办理离职 / 返聘 → 选择生效日期与说明 → 确认 → 保留就业历史
```

离职必须填写原因；生效日期不能晚于当天，也不能早于最近一次就业记录。存在活动任务的员工不能离职。返聘沿用原编号，并形成新的就业记录。

#### 11.1.2 小组页面与成员维护

| 页面 | 展示与操作 |
|---|---|
| 小组列表 | 小组名称、编号、成员、人数、状态；关键词 / 状态筛选、分页、重置、清除筛选、新增、详情、编辑 |
| 新增 / 编辑小组 | 名称、只读编号、在职员工选择；成员关键词筛选和右侧小组预览 |
| 小组详情 | 当前成员、员工资格和在职状态、成员变更、启停记录、活动任务引用；编辑及启停确认 |

- 名称必填且最多 30 字；成员至少两名、不得重复，必须全部在职。
- 新建启用小组，或启用已有小组，必须有匹配人数的有效全局效率标准；停用小组调整成员不因此自动启用。
- 小组或相关成员存在活动任务时，禁止成员调整和停用；页面显示引用任务供用户定位，不通过强删绕过。
- 成员选择不是员工资料编辑，不能在小组中配置工资、个人效率或任意小组专属效率。
- 当前原型可展示同一员工所属的多个启用小组；不能把多个成员关系直接理解为允许同日重复排班。
- 名称修改、成员调整与启停分别保留对应示例记录；成员记录保留当时成员展示值，不把历史变成当前名单。

#### 11.1.3 全局标准页面

| 标准 | 字段、展示与校验 |
|---|---|
| 人数效率标准 | 人数、效率因子、适用启用小组、版本、更新日期；人数为至少 2 的整数，效率因子大于 1；同人数只有一条当前标准 |
| 每日有效时间 | 一套全局当前标准，值为 1 至 1440 的整数分钟；通过修改生成新版本，不新增第二套当前标准 |
| 标准编辑 | 调整值和说明，说明最多 200 字；修改效率标准不允许改人数 |
| 版本记录 | 当前 / 历史版本、值、调整说明、操作人、活动引用和引用快照 |

- 修改当前标准会将旧版本归档并新增版本；值未变化不生成新版本。
- 已有任务的示例引用继续显示旧标准快照；修改当前标准不回写过去任务。
- 效率因子用于工作负载，不作为工资金额或成员分配权重。标准页不录入工资单价。

#### 11.1.4 原型数据与未实现边界

- 员工、小组、标准与历史均为页面内数据；操作能演示当前页变化，但未接入本地持久化，刷新恢复示例。
- Vue、Element Plus 和图标通过外部 CDN 加载，尚不能承诺离线可用。
- 活动引用是内置任务示例，不自动读取生产原型新增任务；引用保护只能确认交互含义，不能代替正式任务预留、锁、事务与并发验证。
- 本页不创建登录账号、不核定或支付工资、不实际排班、不提供真实服务端权限、审计或快照接口。
- 员工 / 小组新增取消后不新增记录；已确认操作仍需正式服务端幂等、版本及原子性保护。

#### 11.1.5 原型确认项

- 员工资料、资格维护、就业操作与历史分开，员工身份编号稳定。
- 小组成员、启停及活动引用可以定位；不把效率标准塞进小组编辑表单。
- 标准编辑和版本历史能展示“当前值变化、已有引用不变”的规则。
- 本节依据源码核对，未完成本轮逐页浏览器视觉验收；正式业务验收见第 12 节。

## 12. 验收标准

- 个人和小组通过统一接口完成资格校验、快照和活动预留；
- 小组任务同时预留小组和快照中的全部成员；
- 活动任务存在时，离职、撤销资格、成员变更和停用被拒绝；
- 任务取消或完成后释放预留，随后允许人员变更；
- 并发安排任务与人员变更竞争同一守卫，不出现先查后改漏洞；
- 同一员工可属于多个小组，但生产日期负载由生产模块统一累计；
- 小组数据不存在组长、承接范围、组内步骤和成员贡献比例；
- `workforce` 不依赖或访问 `production` 的类型、表和 Repository；
- 历史任务和财务结算可以解析旧员工、小组和标准快照。
