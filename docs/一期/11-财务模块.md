# 财务模块

> 模块代码：`finance`

## 1. 模块说明

财务模块记录真实发生的现金收款、付款、退款、赔付和账户余额。它不决定订单应收、工资应付或售后赔付义务，只在业务所有者确认资格后执行并保存现金事实。

## 2. 一期需求、范围与模块功能

- 现金/银行/平台账户维护；
- 订单收款和退款；
- 工资支付；
- 售后收费、退款和赔付；
- 经营费用支付；
- 一笔现金事实分配到一个或多个业务对象；
- 现金更正、冲销和账户对账；
- 余额和来源收付汇总。

不提供应收决定、成本预算、会计总账、发票和税务申报。

## 3. 模块边界

- `orders` 决定订单应收、退款义务和付款履约；
- `payroll` 决定员工应付工资；
- `after-sales` 决定售后收费、退款或赔付；
- `cost-ledger` 保存经营费用的成本意义；
- `finance` 校验可支付/可收金额后记录现金事实，并回传现金事实标识。

## 4. 业务规则

1. 现金事实必须引用明确账户、方向、业务日期、币种和金额。
2. 收入金额和支出金额均以正数保存，由 `direction` 区分。
3. 分配金额总和必须等于现金事实金额；不允许未解释差额。
4. 业务来源可收/可付余额必须通过来源模块公开资格接口校验。
5. 原现金事实不可覆盖；错误通过冲销或差额更正。
6. 冲销必须使用原账户、币种和相反方向，并关联原事实。
7. 账户余额是可重建投影，不是唯一历史来源。
8. 不同币种不自动换算；一期不做汇兑损益。

## 5. 状态设计

- 账户：`ACTIVE / INACTIVE`；
- 现金事实：通过 `is_valid` 和 `reverses_fact_business_id` 表达有效性；
- 对账：`MATCHED / DIFFERENT / RESOLVED`。

## 7. 公开接口设计

```java
interface FinanceApplicationService {
    CashFactRef receive(ReceiveMoneyCommand command);
    CashFactRef pay(PayMoneyCommand command);
    CashFactRef refund(RefundMoneyCommand command);
    CashFactRef reverse(ReverseCashFactCommand command);
    ReconciliationRef reconcile(ReconcileAccountCommand command);
}
interface FinanceEligibilityParticipant {
    PreparedCashOperation prepare(CashOperationRequest request);
    void commitBusinessLink(PreparedCashOperation prepared, CashFactRef cashFact);
}
interface FinanceQuery {
    AccountBalance getBalance(AccountId accountId);
    SourceCashSummary getSourceSummary(BusinessSourceRef source);
}
```

业务入口通常由财务模块作为命令所有者：先调用订单/工资/售后的支付资格参与接口，再写现金事实和业务支付关联，整个动作同事务提交。

## 8. 事务与并发

- 锁序：来源业务资格→财务账户→来源余额投影→现金事实；
- 同账户并发支付通过账户投影行锁串行化；
- 同一业务来源的累计支付不得超过资格返回上限；
- 幂等键防止支付按钮重复提交；
- 业务支付关联失败时现金事实和余额投影一起回滚；
- 冲销并发时锁定原事实，原事实只能被有效冲销一次。

## 9. 权限、页面和错误

权限：`finance.account.manage`、`finance.cash.receive`、`finance.cash.pay`、`finance.cash.reverse`、`finance.reconcile`、`finance.read`、`finance.sensitive.read`。

页面：账户列表、收支录入、现金流水、来源分配、对账、余额汇总。

错误码：`FINANCE_ACCOUNT_INACTIVE`、`FINANCE_CURRENCY_MISMATCH`、`FINANCE_ALLOCATION_MISMATCH`、`FINANCE_SOURCE_NOT_PAYABLE`、`FINANCE_AMOUNT_EXCEEDS_ELIGIBLE`、`FINANCE_FACT_ALREADY_REVERSED`、`FINANCE_BALANCE_CONFLICT`。

## 10. 验收标准

- 重复支付请求只形成一个现金事实；
- 超过订单待收/待退或工资待付金额被拒绝；
- 分配合计与现金金额一致；
- 跨模块关联失败全事务回滚；
- 冲销后余额、来源汇总和历史链正确；
- 账户投影可由现金事实完整重建；
- 经营费用支付能同时形成 finance 现金事实和 cost-ledger 成本事实。
