# 排班模块

> 模块代码：`scheduling`

## 1. 模块说明

排班模块只负责计划、任务、执行主体、工作日期、任务数量、当日负载、活动引用和核验入口。它不拥有商品标准、每日有效工作分钟标准、小组效率、生产数量和工资公式；这些能力必须通过公开接口取得。

## 2. 一期需求、范围与模块功能

- 为生产需求创建个人或小组任务；
- 创建修复任务和其他任务；
- 对已完成的其他任务形成可供工资自动采集的核验来源；
- 安排执行日期、主体、工序和数量；
- 调用公开能力评估工作量是否低于、符合或超过当日剩余有效时间；
- 调整任务日期、主体或数量；
- 取消任务并释放生产占用；
- 从任务入口提交生产核验；
- 查询个人、小组及成员日负载、待办和历史。

一期按“工作日期”排任务，不提供小时级开始/结束时间、班次编排或甘特图。系统不在小组内拆分流水线步骤，不计算工资，不维护生产阶段，不直接读取其他模块表。

## 3. 业务概念

- **任务类型**：`NORMAL_PRODUCTION / REPAIR / OTHER_TASK`。
- **执行主体**：`EMPLOYEE / TEAM`。
- **任务标准分钟**：本次任务按个人或小组效率公式计算的整体经过时间。
- **每日有效分钟**：由 `base-data` 提供的全局每日工作时间标准。
- **已占用分钟**：排班模块根据同一员工同一工作日尚有效任务的标准分钟累计得到。
- **剩余有效分钟**：每日有效分钟减去已占用分钟；公式和下限处理由 `calculation` 完成。
- **活动引用**：尚可调整、取消或核验的任务对人员、小组和生产来源的有效引用。
- **工作量评估记录**：保存创建或调整时公开公式返回的任务标准分钟、剩余有效分钟、结果、规则版本和上游快照引用。
- **其他任务**：打包发货等不改变制品生产阶段的工作；任务级直接录入预计标准分钟，不从商品工序标准推导。

## 4. 模块边界

### 4.1 排班拥有

任务、任务当前安排、当日负载守卫、商品日期产能占用、执行主体引用、实际参与员工引用、工作量评估记录、取消事实、任务核验事实和已核验其他任务工资来源。

### 4.2 排班不拥有

- 商品工时和单日最大产能：由 `product` 提供；
- 员工在职、资格和每日有效工作分钟标准：由 `base-data` 提供；
- 小组成员和人数效率：由 `team` 提供；
- 工作量和剩余时间公式：由 `calculation` 提供；
- 生产来源数量和核验结果：由 `production` 提供；
- 到人工资：由 `payroll` 提供；排班只向工资模块提供已核验其他任务来源。

排班可以汇总自己表中的有效任务占用，但不能复制个人/小组工作量公式、有效时间规则或上游定义。

## 5. 工作量评估

### 5.1 个人任务

```text
product.ProductSnapshotService.acquireCurrentSchedulingReference（生产/修复任务）
或任务直接录入标准分钟；关联商品时取得 product.ProductSnapshotService.acquireCurrentOtherTaskReference（其他任务）
+ base-data.EmployeeQualificationQuery.check
+ base-data.EmployeeSnapshotService.acquireCurrentAssignmentSubjectSnapshot
+ base-data.WorkTimeStandardSnapshotService.acquireCurrentDailyStandard
+ scheduling 汇总该员工当日已占用标准分钟
+ calculation.WorkloadCalculator.assessIndividual
→ 本任务标准分钟、当日剩余有效分钟、评估结果
```

### 5.2 小组任务

```text
scheduling 锁定小组活动引用守卫
+ team.TeamSnapshotService.acquireCurrentAssignmentSnapshot
+ product.ProductSnapshotService.acquireCurrentSchedulingReference（生产/修复任务）
  或任务直接录入标准分钟；关联商品时取得 product.ProductSnapshotService.acquireCurrentOtherTaskReference（其他任务）
+ base-data.WorkTimeStandardSnapshotService.acquireCurrentDailyStandard
+ scheduling 按小组快照成员逐人汇总当日已占用标准分钟
+ team 快照内的人数效率标准
+ calculation.WorkloadCalculator.assessTeam
→ 小组整体标准分钟、各成员剩余分钟、小组可用分钟、评估结果
```

生产/修复小组任务的标准分钟是“商品基准分钟 ÷ 效率因子”；其他小组任务直接录入的标准分钟已经是小组整体预计经过时间，不再应用效率因子。最终任务标准分钟同时占用快照中每名成员的当日时间。小组可用分钟取成员剩余分钟的最小值，不能把每日有效分钟乘以成员人数。

排班保存返回结果及所采用的商品、小组、员工、有效工作时间、效率标准快照引用，不复制公式和上游快照载荷。

### 5.3 商品单日产能

同一商品同一生产日期的活动制作任务总量不能超过商品公开接口返回的单日最大产能。模具数量和每日生产批次必须参与该上限；排班只保存本日已占用数量并执行原子加减，不重新计算商品产能公式。

## 6. 业务规则

1. 正式创建成功的任务直接进入 `ARRANGED`，不提供草稿。
2. 生产和修复任务必须先从 `production` 取得有效占用；其他任务不占用生产来源。
3. 生产/修复任务的标准分钟必须来自商品正式排班引用；其他任务必须直接录入大于 0 的任务标准分钟，排班不得套用商品制作工时。其他任务若需要自动计件工资，必须关联商品并取得商品其他任务正式引用；否则不得虚构商品快照或单件人工费。
4. 个人主体必须在工作日有效且具备目标工种资格。
5. 小组主体必须活动、成员完整、人数效率标准存在，并取得小组快照。
6. 小组任务为快照中的每名成员建立参与引用，并把小组标准分钟计入每名成员当日负载。
7. 同一员工可以有多个同日任务，但普通任务累计后不得超过剩余有效分钟。
8. `OVER_STANDARD` 默认拒绝创建或调整；确需超排必须使用有专门权限的显式覆盖命令并记录原因。
9. `UNAVAILABLE` 一律拒绝，排班不能自行补默认分钟、效率或有效时间。
10. 小组产出是共同产出，任务中不保存成员个人数量。
11. 调整任务必须先释放旧日期、旧主体和旧商品产能占用，再按固定锁序重新评估并保存新评估记录；旧记录保留。
12. 取消任务追加取消事实并释放成员负载、商品产能、活动引用和生产占用，不删除任务。
13. 已核验任务不能普通取消；错误通过核验更正流程处理。
14. 一期没有小时级时间段，因此不声称校验“时间窗口重叠”；并发和超排通过员工工作日负载守卫控制。

## 7. 状态设计

- `ARRANGED`：已安排、存在活动引用和占用；
- `IN_PROGRESS`：开始执行，仍存在活动引用和占用；
- `VERIFIED`：核验完成，活动引用和计划占用结束；
- `CANCELLED`：取消，活动引用和计划占用结束。

允许：`ARRANGED→IN_PROGRESS→VERIFIED`、`ARRANGED→VERIFIED`、`ARRANGED/IN_PROGRESS→CANCELLED`（无不可撤销生产事实时）。禁止从 `VERIFIED` 直接退回，错误使用更正事实。

## 8. 数据模型与表设计

| 表 | 类别 | 关键字段 | 关键约束与索引 |
|---|---|---|---|
| `scheduling_tasks` | 当前根 | `task_business_id, task_no, task_type, work_date, process_code, product_business_id, quantity, entered_standard_minutes, subject_type, subject_business_id, subject_snapshot_ref, production_source_business_id, status, active_assignment_version, row_version` | `UK(task_no)`, `UK(task_business_id)`, `IX(work_date, subject_type, subject_business_id, status)` |
| `scheduling_assignment_facts` | 事实 | `fact_business_id, task_business_id, assignment_version, operation_type, old_subject_ref, new_subject_ref, old_work_date, new_work_date, old_quantity, new_quantity, occurred_at, is_valid` | `UK(task_business_id, assignment_version)` |
| `scheduling_workload_assessments` | 不可变评估记录 | `assessment_business_id, task_business_id, assignment_version, task_standard_minutes, available_effective_minutes, assessment_result, product_snapshot_ref, subject_snapshot_ref, work_time_standard_snapshot_ref, efficiency_snapshot_ref, formula_rule_version, input_fingerprint, override_reason, created_at` | `UK(task_business_id, assignment_version)` |
| `scheduling_assessment_member_loads` | 评估明细 | `assessment_business_id, employee_business_id, employee_snapshot_ref, occupied_minutes_before, available_minutes_before, occupied_minutes_after` | `UK(assessment_business_id, employee_business_id)` |
| `scheduling_team_reference_guards` | 并发守卫 | `team_business_id, row_version` | `PK(team_business_id)`；由排班创建和小组变更协调共同锁定 |
| `scheduling_employee_day_loads` | 当前守卫/投影 | `employee_business_id, work_date, active_standard_minutes, row_version` | `UK(employee_business_id, work_date)`，分钟非负 |
| `scheduling_product_day_capacity_usages` | 当前守卫/投影 | `product_business_id, work_date, active_quantity, capacity_limit, product_content_version, row_version` | `UK(product_business_id, work_date)`，数量非负且不超过上限 |
| `scheduling_active_subject_references` | 活动引用 | `task_business_id, subject_type, subject_business_id, work_date, status` | 活动任务唯一，`IX(subject_type, subject_business_id, status)` |
| `scheduling_active_participant_references` | 活动成员引用 | `task_business_id, employee_business_id, subject_type, subject_business_id, work_date, occupied_standard_minutes, status` | `UK(task_business_id, employee_business_id)`, `IX(employee_business_id, work_date, status)` |
| `scheduling_production_links` | 当前关系 | `task_business_id, production_reservation_business_id, production_source_business_id, reserved_quantity` | `UK(task_business_id, production_source_business_id)` |
| `scheduling_cancellation_facts` | 事实 | `fact_business_id, task_business_id, reason_code, reason_text, occurred_at, operator_id, command_execution_id, is_valid` | 有效取消事实唯一 |
| `scheduling_verification_facts` | 事实 | `fact_business_id, task_business_id, production_verification_fact_business_id, completed_quantity, qualified_quantity, defective_quantity, occurred_at, is_valid, corrects_fact_business_id` | `UK(fact_business_id)`, `IX(task_business_id, occurred_at)` |

字段适用规则：

- `NORMAL_PRODUCTION / REPAIR`：`process_code、product_business_id、quantity、production_source_business_id` 必填，`entered_standard_minutes` 必须为空；`product_snapshot_ref` 必填并来自商品正式排班引用。
- `OTHER_TASK`：`entered_standard_minutes` 必填且大于 0，`production_source_business_id` 必须为空；`product_business_id、quantity、product_snapshot_ref` 仅在需要按商品其他任务人工费自动计件时成组填写，否则必须同时为空。
- `efficiency_snapshot_ref` 仅小组任务必填；个人任务为空。`subject_snapshot_ref` 和 `work_time_standard_snapshot_ref` 对所有任务必填。
- 数据库迁移必须用 `CHECK` 约束或等价命令校验落实上述条件，不能只依赖页面校验。

`employee_day_loads` 和 `product_day_capacity_usages` 是排班自有的当前守卫投影，可由任务和有效引用重建；它们不是员工资料、商品定义或生产事实。

## 9. 业务流程

### 9.1 创建任务

```text
锁定任务编号守卫
→ 小组任务锁定 scheduling_team_reference_guards
→ 取得并校验主体、工作时间和效率快照
→ 生产/修复任务取得商品正式排班引用；其他任务校验直接录入标准分钟，关联商品时取得商品其他任务正式引用
→ 按员工稳定业务标识顺序锁定 employee_day_loads
→ 锁定 product_day_capacity_usages（仅生产/修复任务）
→ 汇总现有占用并调用 calculation 正式评估
→ 校验商品当日产能（仅生产/修复任务）
→ production.ProductionReservationParticipant.prepareReserve（仅生产/修复任务）
→ 写任务、评估、成员负载和活动引用；生产/修复任务另写生产关系
→ production.ProductionReservationParticipant.commitReserve（仅生产/修复任务）
→ 一次提交
```

### 9.2 调整任务

锁定任务，按旧参与员工稳定标识释放旧负载和旧产能，再按创建流程的统一锁序锁定新主体；重新取得当前主体、工作时间和效率快照，重新评估并新增安排事实和评估记录，不覆盖历史。

### 9.3 取消任务

锁定任务、成员日负载、商品日期产能和活动引用；生产/修复任务调用 `production` 释放占用，其他任务跳过生产端口；追加取消事实并把状态改为 `CANCELLED`。小组修改随后自然不再被该任务阻塞。

### 9.4 核验任务

生产/修复任务：排班是入口和命令所有者，`production` 校验并写生产事实，排班写核验事实并结束活动引用、计划负载和产能占用，任一方失败整体回滚。

其他任务：不调用 `production`，由排班写完成核验事实并结束计划负载。如果任务在安排时已冻结商品其他任务正式引用，核验时必须录入完成数量，并以核验事实标识作为来源版本形成可供工资模块读取的“其他任务工资来源”；未冻结商品人工费依据的其他任务不自动计件结算。

## 10. 公开接口设计

```java
interface SchedulingApplicationService {
    TaskRef arrange(ArrangeTaskCommand command);
    TaskRef reschedule(RescheduleTaskCommand command);
    void cancel(CancelTaskCommand command);
    VerificationRef verify(VerifyTaskCommand command);
}
interface TeamActiveReferenceGuardPort {
    PreparedReferenceGuard lockAndCheckNoActiveReferences(TeamId teamId);
    void complete(PreparedReferenceGuard prepared);
}
interface SchedulingParticipantPort {
    PreparedScheduleImpact prepareBusinessChange(ScheduleImpactRequest request);
    void commitBusinessChange(PreparedScheduleImpact prepared);
}
interface SchedulingQuery {
    EmployeeDailyLoadView getEmployeeDailyLoad(EmployeeId employeeId, LocalDate date);
    SubjectDailyLoadView getSubjectDailyLoad(AssignmentSubjectRef subject, LocalDate date);
    TaskView get(TaskId id);
}
interface SchedulingPayrollSourceFeed {
    PayrollSourcePage listVerifiedOtherTaskSources(PayrollSourceCursor cursor, TimeRange range);
}
```

`TeamActiveReferenceGuardPort` 只用于 `workforce-coordination`；它不暴露任务表、Repository 或通用查询。

## 11. 事务与并发

- 固定锁序：任务/命令守卫→小组活动引用守卫→员工日期负载（员工标识升序）→商品日期产能→生产来源→上游快照唯一键→任务明细；
- 小组修改和小组任务创建必须竞争同一 `scheduling_team_reference_guards` 行；
- 员工作为个人或任意小组成员时都写入相同的员工日期负载，防止跨主体漏算；
- 商品日期产能使用原子守卫，防止并发任务超出单日最大产能；
- 核验和取消必须按与创建兼容的顺序释放负载、产能和生产占用；
- 所有评估在正式命令内重新执行，页面预览不构成授权；
- 死锁只重试整个幂等命令，不局部重试 SQL。

## 12. 权限、页面和错误

权限：`scheduling.arrange`、`scheduling.adjust`、`scheduling.cancel`、`scheduling.verify`、`scheduling.override.over-standard`、`scheduling.read`。

页面：日期排班列表、个人/小组及成员日负载、任务详情、取消、核验、其他任务。创建时必须显示任务标准分钟、每日有效分钟、已占用分钟、剩余分钟、评估结果、商品产能剩余和阻塞原因。

错误码：`SCHEDULING_SUBJECT_INELIGIBLE`、`SCHEDULING_STANDARD_UNAVAILABLE`、`SCHEDULING_OVER_STANDARD`、`SCHEDULING_EMPLOYEE_DAY_CAPACITY_EXCEEDED`、`SCHEDULING_PRODUCT_CAPACITY_EXCEEDED`、`SCHEDULING_PRODUCTION_QUANTITY_INSUFFICIENT`、`SCHEDULING_TASK_ALREADY_VERIFIED`、`SCHEDULING_VERSION_CONFLICT`。

## 13. 验收标准

- 排班代码中没有复制个人/小组、剩余时间或商品产能公式；
- 个人和小组任务通过公开接口取得上游标准并调用计算中心评估；
- 小组效率确实缩短整体标准时间，不等同成员独立完成；
- 小组标准分钟计入每名成员同日负载，成员被其他个人/小组任务占用时不会漏算；
- 每日有效分钟变化后新任务使用新快照，历史评估仍可解释；
- 模具数量和每日批次限制同商品单日任务总量；
- 并发创建不会超员工日负载、商品产能或生产可用数量；
- 取消/核验任务释放计划负载、产能、生产占用和小组活动引用；
- 生产/修复任务核验跨模块失败全回滚；
- 其他任务使用直接录入标准分钟；只有安排时已冻结商品其他任务正式引用的任务，核验后才能按完成数量和已冻结单件人工费生成工资来源；
- 历史任务可解析当时主体和评估依据。

## 14. 待确认问题

本模块已按工作日粒度冻结一期结构。小时级班次、开始结束时间和甘特图明确不属于一期，不阻塞开发。
