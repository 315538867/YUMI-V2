# 商品模块

> 模块代码：`product`

## 1. 模块说明

商品模块独立管理商品录入配置、制作规格、固定工序字段、单件额外费用、内置标准方案、多个自定义方案、预算结果和对外业务快照。商品字段的含义、预填默认值和录入选项由商品模块自己拥有，不依赖通用“基础资料模块”。

## 2. 一期需求与模块功能

录入商品时，一次提交以下完整内容：

```text
商品
├─ 基本字段
├─ 制作工序字段
├─ 捏毛装袋工序字段
├─ 缝边剪袋工序字段
└─ 额外单件费用
```

提交成功后系统自动生成内置标准方案并完成预算计算。后续编辑商品时，内置标准方案自动同步；用户可以另外建立多个自定义方案。

## 3. 本期范围

### 3.1 本期提供

- 商品创建、编辑、停用和查询；
- 商品图片的正式文件引用；
- 固定结构的三类工序字段；
- 商品单日最大产能参数；
- 内置标准方案自动生成和同步；
- 自定义方案创建、编辑、停用；
- 只读预算预览和正式预算结果；
- 商品及方案快照的创建或复用。

### 3.2 本期不提供

- 通用材料目录；
- 任意增加工序或动态字段；
- 库存、采购、领料；
- 装箱生产工序；
- 服务端草稿；
- 方案“默认选择”字段；
- 用户独立编辑内置标准方案。

## 4. 商品字段

### 4.1 工艺本质与数量语义

商品的三道工序不是三个都“生产一件制品”：

```text
制作：原料 → 制品，完成物理制品从 0 到 1
捏毛装袋：对已经存在的制品进行包装加工
缝边剪袋：对已经存在的制品继续完成包装加工
```

制作是唯一创造物理制品数量的工序。捏毛装袋和缝边剪袋只改变既有制品的包装阶段，不得新增制品数量，也不得生成新的产品身份。

因此，制作工序的正常生产与制作返工必须严格区分：正常制作完成从 0 到 1；已经存在的制品返回制作工序时只能进行修补，不会再次创造制品。捏毛装袋或缝边剪袋返工则表示重做对应包装工序。无法修补或重做的制品必须报废；报废缺口需要另行正常补产。

### 4.2 基本字段

| 字段 | 含义和规则 |
|---|---|
| 商品编号 | 系统生成，创建后不可修改或复用 |
| 商品名称 | 必填，可重名，以商品编号区分 |
| 商品说明 | 可选，不参与公式 |
| 单件标准克重 | 必填且大于 0 |
| 制作星级 | 从商品模块的制作星级选项选择；名称和标准分钟写入商品，不动态引用 |
| 单件标准制作分钟 | 由星级带出并保存，后续静态数据变化不自动更新 |
| 标准售价 | 内置标准方案售价 |
| 胶水损耗率 | 默认值仅预填，提交后写入商品 |
| 胶水单价 | 每克单价；默认值仅预填，提交后写入商品 |
| 色浆单价 | 每克单价；默认值仅预填，提交后写入商品 |
| 制作提成 | 单件制作人工成本，属于商品，不允许方案自定义 |
| 模具数量 | 必须大于 0 |
| 模具每日生产批次 | 每个模具每日标准批次数，必须大于 0 |
| 状态 | `ACTIVE / INACTIVE` |

```text
商品单日最大产能 = 模具数量 × 模具每日生产批次
```

公式由计算中心执行，商品模块保存输入和计算结果。

### 4.3 制作工序字段

| 字段 | 规则 |
|---|---|
| 单件标准制作分钟 | 来自商品基本字段，方案中只读 |
| 单件制作提成 | 人力成本，商品级维护，方案中只读 |
| 其他材料费用 | 单件金额，可在自定义方案中替换 |

胶水用量按“单件标准克重 ×（1 + 损耗率）”计算；胶水成本和色浆成本都使用该用量分别乘各自每克单价，色浆不重复计算损耗。公式由计算中心执行，不建立通用材料明细。

### 4.4 捏毛装袋工序字段

| 字段 | 规则 |
|---|---|
| 单件标准分钟 | 由静态选项带出后保存到商品 |
| 单件人工成本 | 商品级维护，方案中只读 |
| 单件袋子成本 | 直接录入单件金额，不录入袋子数量和单价拆分 |
| 单件装饰品价格 | 直接录入单件金额 |
| 单件其他费用 | 本工序除人工、袋子和装饰品外的金额 |

本工序不设置“是否包含”。是否执行由方案的目标工序决定。

### 4.5 缝边剪袋工序字段

| 字段 | 规则 |
|---|---|
| 单件标准分钟 | 由静态选项带出后保存到商品 |
| 单件人工成本 | 商品级维护，方案中只读 |
| 单件综合材料成本 | 缝线等材料合并录入，不单列来源 |
| 单件其他费用 | 本工序其他金额 |

该工序没有客户供料选项，不设置缝线来源。

### 4.6 额外单件费用

以下字段均为已经分摊到每件商品的金额，直接录入，不由商品模块再次分摊：

| 字段 | 说明 |
|---|---|
| 其他任务人工费 | 打包发货等非三类生产工序的单件人工费，不是制作提成 |
| 运输包装费 | 外层运输包装等单件费用 |
| 日常杂费 | 已分摊单件金额 |
| 房租水电费 | 已分摊单件金额 |
| 模具单件摊销费 | 已计算完成的单件摊销金额 |
| 其他费用 | 不能归入以上项目的单件金额 |

装箱/打包发货不作为生产工序，其费用放在额外单件费用中；如果需要安排实际工作，由生产作业模块的“其他任务”处理。

## 5. 方案设计

### 5.1 统一结构

内置标准方案和自定义方案使用同一套结构：

```text
方案级字段
├─ 方案名称
├─ 商品克重（继承，只读）
├─ 目标工序
├─ 售价
├─ 胶水来源
└─ 色浆来源

目标工序范围内的工序字段
├─ 制作工序
├─ 捏毛装袋工序（目标到此或更后）
└─ 缝边剪袋工序（目标到此）
```

目标工序就是本方案的最后一道生产工序，只能为：`MAKING`、`BAGGING`、`SEAM_CUTTING`。

### 5.2 内置标准方案

- 商品创建时自动生成；
- `scheme_type = SYSTEM_STANDARD`；
- 不是交互意义上的“默认选项”，不设置默认选择字段；
- 不允许用户独立编辑或删除；
- 商品基本字段、工序字段或额外费用变化时自动同步；
- 售价使用商品标准售价；
- 胶水、色浆、袋子和装饰品来源均为工作室；
- 目标工序为商品标准交付的最后一道工序，商品编辑时一并提交。

### 5.3 自定义方案

- `scheme_type = CUSTOM`；
- 与内置标准方案使用相同表结构、完整工序字段和计算模型，不另建“自定义方案专用结构”；
- 方案级可修改：名称、目标工序、售价、胶水来源、色浆来源；
- 制作工序可修改：其他材料费用；
- 捏毛装袋可修改：袋子成本、袋子来源、装饰品价格、装饰品来源、其他费用；
- 缝边剪袋可修改：综合材料成本、其他费用；该工序无来源选项；
- 商品克重、各工序标准分钟、制作提成和各工序人工成本由商品同步到方案，只读；
- 商品额外单件费用由商品同步到方案，只读；
- 自定义方案的可编辑字段变化，或者商品同步导致方案有效内容变化时，都递增方案 `content_version`。

材料来源只有：`STUDIO`、`CUSTOMER`。客户提供材料时仍保留标准资源价值和用量计算，但不计入工作室承担成本。

## 6. 预算规则

### 6.1 成本范围和明细口径

商品预算始终按**单件**计算，商品额外费用已经是每件金额，不能再次分摊：

```text
目标工序 = MAKING
  → 基础材料（胶水、色浆）
  + 制作工序成本
  + 商品额外单件费用

目标工序 = BAGGING
  → 基础材料
  + 制作工序成本
  + 捏毛装袋工序成本
  + 商品额外单件费用

目标工序 = SEAM_CUTTING
  → 基础材料
  + 制作工序成本
  + 捏毛装袋工序成本
  + 缝边剪袋工序成本
  + 商品额外单件费用
```

- 基础材料由单件标准克重、胶水损耗率、胶水单价和色浆单价计算；损耗只计算一次。
- 商品级胶水、色浆等基础材料只归入 `MAKING` 明细，不能在捏毛装袋或缝边剪袋中重复计算。
- 每个工序的人工、制作提成、非人工材料和其他费用分别保存成本性质；预算汇总可以包含全部成本，但生产材料成本来源只读取“当前工序 + `PROCESS_NON_LABOR` + `STUDIO`”。制作工序人工成本就是制作提成；制作工序非人工成本是其他材料费用；捏毛装袋、缝边剪袋分别按人工成本与非人工成本拆分后再合计。
- 内置方案使用商品工序字段；自定义方案只替换允许自定义的工序非人工字段和材料来源。
- 人工标准、制作提成、各工序人工成本和额外单件费用始终继承商品，只读。
- `全资源单件成本 = 工作室承担单件成本 + 客户提供材料单件价值`；预计利润为“方案售价 - 工作室承担单件成本”，允许为负，售价为 0 时利润率为空。
- 计算公式全部由 `calculation` 提供；商品模块只组装输入、保存结果、计算规则版本、舍入版本和输入指纹。

### 6.2 输出

- 全资源单件成本；
- 工作室承担单件成本；
- 客户提供材料标准价值；
- 预计单件收入；
- 预计单件利润；
- 预计利润率；
- 分项成本明细。

预算单价、成本明细和预计利润以 4 位小数保存，利润率以 8 位小数计算/返回；预算明细按 `HALF_UP` 舍入到 4 位，商品售价录入精确到分。预算成本不得因最终结算精度较低而提前舍入。

## 7. 模块边界

### 7.1 商品模块拥有

商品录入默认值、制作星级选项、工序标准时间选项、商品当前定义、工序配置、额外费用、方案当前定义、预算结果和商品/方案快照。

### 7.2 商品模块不拥有

客户、人员与小组、订单成交事实、生产事实、作业任务、成本台账、现金事实和工资结果。

### 7.3 上游和下游

- 商品录入页面通过本模块查询录入默认值、制作星级和工序时间选项；提交时把最终值写入商品当前记录；
- 调用 `calculation` 计算产能和预算；
- 调用 `platform` 管理图片引用、幂等和审计；
- 向 `orders` 提供商品/方案当前快照；
- 向 `production` 提供两类能力：其一是按生产需求已经冻结的商品/方案快照解析工序标准分钟、人力成本和非人工成本依据；其二是按商品编号读取安排当时的当前单日产能上限及内容版本。生产任务不得为了取得工时或人工标准重新读取商品当前值；关联商品的其他任务因没有生产需求快照，可以在安排时取得商品当前快照和其他任务单件人工费并立即冻结；页面预览另走只读查询；
- 向 `finance.costledger` 提供按方案快照和具体工序解析的非人工成本依据；只解析历史快照，不返回当前商品价格替代历史依据。

## 8. 状态设计

- 商品：`ACTIVE / INACTIVE`；
- 方案：`ACTIVE / INACTIVE`；内置方案随商品状态，不单独停用；
- 预算结果没有业务状态，始终对应当前内容版本；
- 快照不可修改，只能产生新版本。

停用商品或方案只禁止新业务引用，不影响历史订单和快照解析。

| 表 | 类别 | 关键字段 | 关键约束与索引 |
|---|---|---|---|
| `product_budget_results` | 当前派生结果 | `budget_business_id, scheme_business_id, product_content_version, scheme_content_version, formula_rule_version, rounding_version, input_fingerprint, full_resource_unit_cost, studio_borne_unit_cost, customer_supplied_unit_value, expected_unit_revenue, expected_unit_profit, expected_profit_rate, calculated_at` | `UK(scheme_business_id)`, 指纹和版本必须与当前方案一致 |

商品或方案正式修改时必须同步重新计算；计算失败则整个修改回滚，不能留下“内容已更新但预算仍旧”的状态。

`cost_nature` 固定区分 `PROCESS_NON_LABOR / LABOR / COMMISSION / ESTIMATED_ALLOCATION`。成本台账自动归集生产材料及工序费用时，只能读取当时方案快照中“当前工序 + `PROCESS_NON_LABOR` + 工作室承担”的成本行；不得把人工、提成或额外预计分摊重复登记为生产材料成本。

| `product_snapshots` | 不可变快照 | `snapshot_business_id, product_business_id, snapshot_version, source_content_version, base_payload_json, process_payload_json, extra_cost_payload_json, daily_capacity, content_fingerprint, created_at` | `UK(product_business_id, source_content_version)`, `UK(snapshot_business_id)` |
| `product_scheme_snapshots` | 不可变快照 | `snapshot_business_id, scheme_business_id, snapshot_version, source_scheme_content_version, source_product_content_version, product_snapshot_business_id, complete_scheme_payload_json, budget_payload_json, content_fingerprint, created_at` | `UK(scheme_business_id, source_scheme_content_version, source_product_content_version)` |

快照使用结构化 JSON 保存完整不可变载荷，是因为载荷只读且必须原样还原；当前业务字段仍使用规范化表，不以 JSON 代替当前模型。

## 10. 业务流程

### 10.1 创建商品

```text
读取商品模块录入配置仅用于页面预填
→ 用户一次提交完整商品
→ 校验固定字段和目标工序
→ 调用计算中心计算单日产能
→ 写商品、三类工序和额外费用
→ 自动生成内置标准方案
→ 调用计算中心计算预算
→ 写预算结果、文件关系、幂等和审计
→ 一次提交
```

### 10.2 编辑商品

```text
锁定商品并校验 row_version
→ 校验是否有不允许变更的业务限制
→ 更新完整商品聚合
→ content_version + 1
→ 完整同步内置标准方案并递增其 content_version
→ 只同步各自定义方案的继承只读字段，保留其可编辑字段
→ 对有效内容发生变化的自定义方案递增 content_version
→ 重算内置方案及所有受商品继承字段影响的自定义方案
→ 一次提交
```

已有历史快照不修改。

### 10.3 创建或编辑自定义方案

一次提交完整方案；商品模块装配并保存完整方案结构，校验目标工序和来源，只接受允许编辑的字段，把当前商品只读字段写入方案，重算预算并递增方案内容版本；不创建服务端半成品。

### 10.4 取得当前快照

- 商品快照：比较 `product.content_version`；相同版本存在则复用，否则创建；
- 方案快照：同时比较 `scheme.content_version` 和 `product.content_version`；任一变化都需要新方案快照；
- 方案快照引用本次产品快照，并冻结完整继承字段及预算结果；
- 接口返回类型化 `SnapshotRef`，消费者不保存快照载荷副本。

## 12. 事务与并发

- 商品聚合、内置方案、预算结果、文件关系和审计原子提交；
- 编辑商品时按商品根→从属工序→方案→预算结果的顺序锁定；
- 同一商品并发编辑使用 `row_version` 拒绝后提交者；
- 快照使用唯一键防止并发重复创建；冲突后读取已创建快照返回；
- 自定义方案与商品并发修改时，方案提交必须重新校验商品 `content_version`，避免基于过时继承值提交。

## 13. 权限、审计与错误

权限：`product.create`、`product.update`、`product.deactivate`、`product.read`、`product.scheme.manage`、`product.snapshot.read`。

错误码：`PRODUCT_NOT_FOUND`、`PRODUCT_INACTIVE`、`PRODUCT_FIELD_INVALID`、`PRODUCT_TARGET_PROCESS_INVALID`、`PRODUCT_SCHEME_SYSTEM_MANAGED`、`PRODUCT_SCHEME_INVALID`、`PRODUCT_BUDGET_CALCULATION_FAILED`、`PRODUCT_VERSION_CONFLICT`、`PRODUCT_SNAPSHOT_CONFLICT`。

审计必须能显示商品或方案修改前后版本、操作者、原因和受影响预算结果。

## 14. 页面与交互要求

- 商品录入配置：胶水损耗率、胶水单价、色浆单价、制作星级和工序标准时间选项；
- 商品列表：编号、名称、制作规格、状态、标准售价和单日最大产能；原型列表不再展示目标工序列；
- 新建/编辑商品：按“基本信息→制作→捏毛装袋→缝边剪袋→额外费用→预算预览”分区；
- 页面选择星级时带出分钟，提交后显示为商品保存值；
- 自定义方案在商品编辑/详情中管理，不在新建商品时强制填写；
- 方案页面将继承只读字段明确标识，不提供编辑控件；
- 内置标准方案标识为“系统方案”，不显示设为默认、编辑或删除按钮；
- 来源选择只有“工作室提供/客户提供”；
- 目标工序变化时只展示目标范围内的工序字段。

### 14.1 商品交互原型基线

> 整理日期：2026-10-09。页面入口：[商品原型](../../product-element-plus.html)。本节记录商品及方案原型，不把预算演示当成实际成本或工资结算。

#### 14.1.1 页面结构与已确认取舍

| 页面 | 展示与操作 |
|---|---|
| 商品列表 | 名称与编号、制作规格、标准售价、单日最大产能、状态；名称 / 编号搜索、状态筛选、重置、新建、详情和编辑 |
| 商品详情 | 基本规格、基础材料、工序参数、额外费用、预算及方案列表；编辑商品、新增自定义方案 |
| 新建 / 编辑商品 | 完整商品定义分区录入，实时预算预览；取消、创建或保存修改 |
| 自定义方案新建 / 编辑 | 方案级字段、继承只读参数、适用工序的材料费用与预算；取消、保存 |

- **移除的是商品录入中的目标工序选择，不是标准售价。**标准售价保留在商品表单、列表与预算中。
- 商品列表也不再单列目标工序；目标工序仍是自定义方案和订单成交约定的字段，不能从方案或订单中一并删除。
- 商品当前示例数据仍有工序范围，详情与预算按该范围展示；新建商品的内部默认范围为制作，原型不提供独立编辑这个范围的控件。此行为是当前演示边界，不新增一条正式业务规则。
- 列表“导出”目前只显示提示，没有生成下载文件。

#### 14.1.2 商品表单字段

| 分区 | 字段与交互 |
|---|---|
| 基本信息 | 自动编号、名称、说明、单件标准克重、标准售价、模具数量、模具每日生产批次、启停状态 |
| 基础材料 | 胶水损耗率、胶水单价、色浆单价；保存到商品，方案只读继承 |
| 制作 | 制作星级、自动带出的标准分钟、制作提成、其他材料费用 |
| 捏毛装袋 | 单件标准分钟、自动带出的人工成本、袋子成本、装饰品价格、其他费用 |
| 缝边剪袋 | 单件标准分钟、自动带出的人工成本、综合材料成本、其他费用 |
| 额外费用 | 其他任务人工费、运输包装费、日常杂费、房租水电费、模具单件摊销费、其他费用 |
| 预算预览 | 按当前范围计算单件预算成本、售价减预算成本和模具数量 × 每日批次的产能 |

当前选项是页面内示例标准：制作一至四星分别带出 20、30、40、50 分钟；捏毛装袋提供 10、12、15 分钟，缝边剪袋提供 6、8、10 分钟，并查页面内的人工单价表。不提供独立标准配置页，也未连接计算中心接口。

```text
商品列表
  → 新建商品 / 编辑商品
  → 基本信息、材料、工序和额外费用
  → 查看实时预算
  → 创建 / 保存
  → 列表或商品详情
```

商品保存目前主要检查名称非空，数值范围主要由输入控件限制；不能据此宣称正式服务端字段、版本和快照校验已经完整实现。

#### 14.1.3 标准方案与自定义方案

| 内容 | 当前原型规则 |
|---|---|
| 标准方案 | 根据商品当前字段自动生成，随商品修改同步；列表标识为系统标准，没有独立编辑、删除或设为默认操作 |
| 自定义方案身份 | 名称、版本、启停状态；可新增、编辑、启用或停用 |
| 方案级成交参数 | 目标工序、方案售价；目标可选制作、捏毛装袋、缝边剪袋 |
| 材料来源 | 胶水、色浆；适用时包含袋子、装饰品；每项只选工作室或客户提供 |
| 可替换非人工费用 | 制作其他材料费、袋子与装饰品价格及其他费、缝边综合材料及其他费，按目标范围展示 |
| 继承只读字段 | 商品克重、损耗、胶水 / 色浆单价、工序时间与人工标准、商品额外费用；不能在方案页另造人工标准 |
| 预算 | 完整标准成本、工作室承担成本、客户供料标准价值、方案售价减工作室承担成本 |

- 选择客户供料只影响工作室承担的材料预算，不把客户提供材料当成工作室实际支出。
- 方案目标越靠后，预算包含的前序工序越多；预算金额是预估，不生成真实材料耗用、成本台账或工资。
- 自定义方案保存及启停会更新页面中的版本；当前编辑保存把方案状态设为有效，不能据此宣称实现正式方案版本历史或快照仓库。

#### 14.1.4 数据、联动与确认边界

- 本原型的商品和方案操作仅更新页面内数据，没有 `localStorage` 保存；刷新会恢复内置示例，编号也是演示生成逻辑，不保证正式全局唯一。
- Vue、Element Plus 和图标目前通过外部 CDN 加载，不能承诺断网可用；这与已经使用本地资源的订单等原型不同。
- 订单原型维护自己的商品 / 方案示例池，不自动读取本页新增或编辑的商品；同名商品不代表已经形成跨页真实数据联动。
- 没有新增正式商品接口、计算服务、材料目录、库存、采购、工资或成本入账能力。
- 原型确认应覆盖列表筛选、分区表单、预算变化、只读继承、方案启停，以及“保留标准售价、商品录入不显示目标工序”的取舍。
- 本节依据源码核对，未完成本轮逐页浏览器视觉验收；正式业务验收见第 15 节。

## 15. 验收标准

- 商品创建一次形成完整商品、内置标准方案和预算结果；任一步失败无残留；
- 修改制作星级或工序时间选项不改变既有商品分钟；
- 商品编辑自动同步内置方案且不能独立编辑内置方案；
- 内置方案和自定义方案使用同一套完整方案表和 DTO；
- 自定义方案只能修改允许字段，克重、人工、标准分钟和额外费用始终由商品同步且只读；
- 制作被明确为唯一完成物理制品从 0 到 1 的工序，后续工序只加工既有制品的包装；
- 目标工序正确控制成本范围；
- 客户供料保留全资源价值但不进入工作室承担成本；
- 可按历史方案快照和具体工序解析工作室承担的非人工成本行，当前商品修改不改变该结果；
- 人工、提成和额外预计分摊不会被错误返回为生产材料成本依据；
- 模具数量和每日批次参与单日最大产能；
- 快照按内容版本复用，商品继承字段变化会使方案产生新快照；
- 历史订单仍能解析旧商品/方案快照；
- 生产任务的工序标准和人工依据只从生产需求冻结的商品/方案快照解析，不会误用商品当前值；安排时读取的当前单日产能上限连同商品内容版本固化在产能占用记录中；
- 关联商品的其他任务能冻结商品快照和其他任务单件人工费，后续商品修改不回溯；
- 商品模块不访问客户、人员与小组、订单或生产作业表。

## 16. 明确不采用

不采用旧方案中的通用材料表、动态材料预算行、装箱工序、方案默认选择、方案可编辑人工工时/提成、商品保存后持续引用全局默认值、每次编辑无条件生成快照。
