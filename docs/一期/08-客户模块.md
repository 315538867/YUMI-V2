# 客户模块

> 模块代码：`customer`

## 1. 模块说明

客户模块管理可复用的客户身份、联系方式、默认收货信息和客户快照。客户可以先于订单建立并被多个订单复用；订单只保存当次交易取得的客户快照引用，不回读客户当前资料解释历史订单。

## 2. 一期需求、范围与模块功能

- 创建、修改和停用客户；
- 维护联系人、联系电话和默认收货信息；
- 查询客户当前资料和状态；
- 按客户当前内容版本创建或复用不可变快照；
- 允许订单在取得快照时提交本次收货信息覆盖值；
- 为订单和报表提供公开查询与变化数据源。

一期不提供客户分级、销售线索、跟进记录、营销、授信、会员体系和通用 CRM 能力。

## 3. 业务概念

- **客户当前资料**：客户现在的名称、联系人、电话、默认地址和启停状态。
- **本次收货信息**：订单取得客户快照时明确传入的交付信息；它属于该快照，不修改客户默认资料。
- **客户快照**：正式订单引用时冻结的客户身份和交付联系信息。

## 4. 模块边界

### 4.1 本模块拥有

客户当前资料、客户变化事实、客户内容版本和客户快照。

### 4.2 本模块不拥有

- 订单、成交价格、应收和发货：由 `orders` 拥有；
- 现金收款和退款：由 `finance` 拥有；
- 售后案例：由 `orders` 内部售后子域拥有；
- 账号、权限、文件、审计和幂等：由 `platform` 提供；
- 报表投影：由 `reporting` 拥有。

客户模块不读取订单或财务结算表。下游只能通过公开查询或客户快照取得客户信息。

## 5. 业务规则

1. 客户编号创建后不可修改、不可复用。
2. 停用客户只禁止新订单引用，不删除历史客户、订单和快照。
3. 客户资料修改递增 `content_version`，不回写历史快照。
4. 同一客户同一内容版本和相同收货覆盖值重复取得快照时返回同一引用。
5. 收货覆盖值只进入本次客户快照，不更新客户默认地址。
6. 客户快照不可修改；错误订单通过订单变更处理，不能篡改历史客户快照。
7. 本模块不提供服务端草稿。

## 6. 状态设计

- 客户：`ACTIVE / INACTIVE`；
- 客户快照：不可变，无生命周期状态；
- 客户变化使用事实记录，不覆盖已有变化历史。

## 7. 数据模型与表设计

| 表 | 类别 | 关键字段 | 关键约束与索引 |
|---|---|---|---|
| `customer_customers` | 当前记录 | `customer_business_id, customer_no, name, contact_name, phone, default_address, status, content_version, row_version, created_at, updated_at` | `UK(customer_no)`, `UK(customer_business_id)`, `IX(status, name)` |
| `customer_change_facts` | 事实 | `fact_business_id, customer_business_id, version_before, version_after, operation_type, changed_fields_json, reason_text, occurred_at, operator_id, command_execution_id` | `UK(fact_business_id)`, `IX(customer_business_id, occurred_at)` |
| `customer_snapshots` | 快照 | `snapshot_business_id, customer_business_id, snapshot_version, source_content_version, override_fingerprint, customer_no, name, contact_name, phone, address, content_fingerprint, created_at` | `UK(customer_business_id, source_content_version, override_fingerprint)`, `UK(snapshot_business_id)` |

`override_fingerprint` 在未覆盖收货信息时使用固定空值指纹，保证唯一键稳定。

## 9. 事务、并发和快照

- 客户当前记录、变化事实、内容版本、审计和幂等结果同事务提交；
- 修改、停用和重新启用使用 `row_version` 防止并发覆盖；
- 快照按“客户内容版本 + 收货覆盖指纹”创建或复用，唯一键处理并发重复创建；
- 页面预检查不能替代订单正式命令中的客户状态复核；
- 订单取得快照时客户必须为 `ACTIVE`，解析历史快照不受当前停用状态影响。

## 10. 权限、页面和错误

权限：`customer.manage`、`customer.read`。

页面：客户列表、客户详情、客户新增/编辑、状态变更和历史变化。

错误码：`CUSTOMER_NOT_FOUND`、`CUSTOMER_INACTIVE`、`CUSTOMER_NO_DUPLICATED`、`CUSTOMER_VERSION_CONFLICT`、`CUSTOMER_SNAPSHOT_CONFLICT`。

### 10.1 客户交互原型基线

> 整理日期：2026-10-09。页面入口：[客户原型](../../customers-element-plus.html)。本节按当前 HTML 与本地脚本记录页面和操作，不代表正式客户接口、审计或数据库已经实现。

#### 10.1.1 页面与操作入口

| 页面 | 展示内容 | 操作 |
|---|---|---|
| 客户列表 | 客户名称与编号、联系人、联系电话、默认收货地址、启停状态；启用客户数量 | 搜索名称、编号、联系人或电话，按状态筛选、重置、分页；新增、查看、编辑、停用或恢复 |
| 客户详情 | 当前客户基本资料、默认收货信息及使用说明 | 编辑资料、停用或恢复；启用客户可进入新建订单并带入客户 |
| 新建 / 编辑 | 基本资料与默认收货信息分区，右侧资料预览 | 核对客户资料、返回修改、确认创建或保存；离开时确认是否丢弃未保存内容 |
| 状态确认 | 客户身份、当前状态与操作影响 | 确认停用 / 恢复，不删除客户，不回写历史订单 |

列表采用搜索与状态筛选组合，不要求每个条件独占一整行；当前原型每页显示 8 条记录。筛选变化返回第一页。

#### 10.1.2 录入字段与保存校验

| 字段 | 当前原型规则 |
|---|---|
| 客户编号 | 新建确认后生成 `C-序号`，编辑时只读，不手工修改 |
| 客户名称 | 必填，去首尾空格，最多 80 字符，不允许换行或控制字符 |
| 联系人 | 必填，最多 40 字符，不允许换行或控制字符 |
| 联系电话 | 必填，允许数字及 `+`、括号、空格、短横线；长度 6 至 30 字符，至少 6 位数字 |
| 默认收货地址 | 必填，最多 200 字符；用于新订单的默认值，不代表每次交付都使用同一地址 |
| 启停状态 | 新建默认启用；后续通过单独的确认操作切换，不在编辑表单中无提示修改 |

操作路径：

```text
列表新增 / 详情编辑
  → 填写基本资料与默认收货地址
  → 核对客户资料
  → 返回修改，或确认保存
  → 客户详情
```

- 预览后再次修改内容，必须重新核对，不能确认过期预览。
- 编辑与状态变更携带打开时的资料版本；版本已变化则提示重新打开，不直接覆盖。
- 字段内容变化或状态变化时增加版本；未改动资料不新增版本。
- 离开新建 / 编辑页可继续填写，也可丢弃；丢弃不写入客户记录。

#### 10.1.3 与订单的关系

- 客户详情的“新建订单”进入订单原型，带入客户选择和默认收货信息；本次订单可另填收件人、电话与地址。
- 订单确认时冻结客户资料版本和本次收货信息。客户改名、改电话、改地址或停用，不覆盖已确认订单的客户及配送快照。
- 停用客户保留历史资料，但不能用于新订单；订单确认前仍需复核客户当前状态和版本。
- 客户原型没有独立客户账本、信用额度、客户账户或正式历史审计页面；详情的说明不等于这些能力已经实现。

#### 10.1.4 保存与演示边界

| 文件 / 存储 | 当前用途 |
|---|---|
| `customers-element-plus.html` | 列表、详情、表单、保存预览、启停确认及离开提示 |
| `customer-store.js` | 示例客户、字段校验、版本检查、订单客户快照和本地保存 |
| `yumi-v2-customers-v1` | 当前浏览器 `localStorage` 的客户数据，最多保存 500 位客户 |
| `order-finance-store.js` | 与订单原型跳转时传递订单演示状态，不代表客户模块拥有订单事实 |

- 依赖使用 `assets/vendor/` 中的本地 Vue、Element Plus 和图标资源。
- 客户写入本地存储成功后才更新页面数据；存储失败提示本次尚未保存。
- 原型跳转可以通过 URL 片段携带客户与订单演示状态；这不是正式同步接口，不适用于真实客户敏感数据传输。
- 本地保存不提供多用户协作、可靠并发、备份、正式权限与不可覆盖审计。客户后端表及快照接口仍按正式设计实现。

#### 10.1.5 原型确认项

- 新建、编辑、预览、确认、取消及离开提示形成完整路径。
- 停用和恢复需要确认，客户编号不变，历史订单快照不变。
- 从启用客户进入订单时能带入默认资料；停用或版本变化会被提示。
- 本节依据源码核对，不宣称已完成本轮逐页浏览器视觉验收；正式验收仍见第 11 节。

## 11. 验收标准

- 客户修改后新订单取得新快照，历史订单仍解析旧快照；
- 本次收货信息覆盖不会修改客户默认信息；
- 停用客户不能创建新订单，但历史订单和售后仍可展示；
- 同一内容版本和相同覆盖值并发取得快照只产生一条记录；
- 客户模块 SQL 和 Repository 不访问订单、财务或售后表；
- 系统不存在承载客户、员工、商品配置的通用“基础资料模块”。
