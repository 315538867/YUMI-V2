# 工资结算模块

> 模块代码：`payroll`

## 1. 模块说明

工资结算模块自动采集有效生产核验、已核验其他任务和责任处理结果，按业务来源中已冻结的人力成本标准计算到人工资，负责小组共同产出的到人分配、扣款、调整、复核、封账和支付关联。

## 2. 已确认的一期需求、模块功能与工资逻辑

1. 工资按期间自动采集有效来源，不由人工逐条录入产量。
2. 个人任务：有效核验数量 × 对应商品快照中的工序单件人力成本。
3. 小组任务：先按任务整体计算工资金额，再按任务保存的小组快照完整成员均分。
4. 小组不拆成员个人产量；均分只是工资模块的到人结果。
5. 小组效率因子只用于排班，不进入工资总额和分配权重。
6. 制作提成、捏毛装袋人工成本、缝边剪袋人工成本和其他任务人工费维护在商品上；方案中只读。
7. 关联商品的已核验其他任务按“完成数量 × 商品快照中的其他任务单件人工费”自动计件；没有商品人工费依据的其他任务不自动生成工资来源，需要支付时通过有原因的工资调整处理。
8. 已封账期间不可覆盖；遗漏、更正和跨期责任处理进入后续补差。
9. 实际工资支付由财务模块记录，工资模块保存支付关联。
10. 封账工资作为实际人工成本提交成本台账。
11. 不提供工资草稿状态；计算结果可以复核，但每次运行都保留完整记录。

## 3. 本期范围

- 工资期间管理；
- 自动采集生产核验和排班其他任务工资来源；
- 个人工资计算；
- 小组工资等额分配；
- 责任修复、扣款、免扣或人工调整明细；
- 计算、复核、封账、补差；
- 工资单查询和支付资格；
- 封账人工成本提交。

不提供考勤、基本工资、社保个税、人事合同和银行代发文件。

## 4. 模块边界

- 生产数量和主体来自 `production` 有效核验事实；
- 已核验其他任务的完成数量、主体和商品快照来自 `scheduling` 公开工资来源；
- 商品人力成本来自来源事实或来源任务已冻结的 `product` 快照：生产来源随生产核验提供，其他任务来源随排班核验提供；工资模块不读取商品当前值；
- 个人身份来自 `base-data` 员工快照；
- 小组成员来自任务保存的 `team` 快照；
- 售后责任和扣款依据来自 `after-sales` 或生产责任事实；
- 实际人工成本提交 `cost-ledger`；
- 实际支付由 `finance` 完成。

工资模块不修改生产事实、小组成员、商品提成和现金事实。

## 5. 计算规则

### 5.1 个人来源

```text
来源工资金额 = 有效核验数量 × 工序单件人力成本
```

工序单件人力成本：

- 制作：商品快照中的制作提成；
- 捏毛装袋：商品快照中的装袋人工成本；
- 缝边剪袋：商品快照中的缝边剪袋人工成本；
- 其他任务：关联商品时使用商品快照中的其他任务单件人工费；没有商品快照或人工费依据时不自动生成计件来源。

### 5.2 小组来源

```text
小组任务工资总额 = 有效核验数量 × 工序单件人力成本
```

然后调用计算中心均分：转换为最小货币单位，整除成员数，余数按员工稳定标识升序依次补 1 个最小单位。分配合计必须等于任务工资总额。

### 5.3 责任和调整

- 扣款、免扣和补偿形成独立结果明细，不改写原工资来源；
- 每项必须引用责任事实或人工调整原因；
- 负数净工资是否允许：一期不允许，最低为 0，超出部分结转后续责任余额；
- 已封账来源发生更正时，不重开原期间，以补差正负明细进入后续期间。

## 6. 状态设计

- 工资期间：`OPEN / CALCULATING / CALCULATED / REVIEWED / CLOSED`；
- 计算运行：`RUNNING / SUCCEEDED / FAILED / SUPERSEDED`；
- 员工结果：`CALCULATED / REVIEWED / CLOSED / PARTIALLY_PAID / PAID`；
- 调整：正式创建即有效，通过更正事实失效，不使用草稿。

## 8. 业务流程

### 8.1 自动计算

```text
锁定工资期间并建立运行
→ 按截止时间读取 production 有效生产工资来源
→ 按截止时间读取 scheduling 已核验其他任务工资来源
→ 合并后按“来源模块+来源类型+来源标识+来源版本”去重
→ 解析来源上的员工/小组、商品快照；缺少应有快照或单件人工费时拒绝该来源
→ 固化 payroll_source_facts 和来源指纹
→ 计算个人来源金额
→ 小组来源计算整体金额并均分
→ 应用责任扣款、免扣和历史补差
→ 生成员工结果和明细
→ 运行标记 SUCCEEDED，期间标记 CALCULATED
```

失败运行完整保留错误信息，但不改变上一次可复核结果。

### 8.2 复核和封账

复核确认来源数量、单价、分配和调整。封账时重新校验来源未变化，为每个有效来源写封账守卫，写封账事实，并在同一事务向成本台账提交人工成本。

### 8.3 支付

财务模块锁定员工工资结果并校验待付金额，写现金事实后工资模块写支付关联。累计支付达到净工资后状态为 `PAID`。

## 10. 事务与并发

- 同一期间同一时刻只允许一个计算运行；
- 封账锁序：期间→员工结果（员工标识升序）→有效来源守卫→成本来源守卫；
- 来源在计算后、封账前发生新增、更正或失效时拒绝封账并要求重算；
- 已封账来源不能进入另一个有效封账；
- 支付锁序：工资结果→财务账户；
- 金额分配使用整数最小单位，禁止浮点舍入差。

## 11. 权限、页面和错误

权限：`payroll.period.manage`、`payroll.calculate`、`payroll.review`、`payroll.close`、`payroll.adjust`、`payroll.read`、`payroll.sensitive.read`。

页面：期间列表、自动计算、来源差异、员工工资单、小组分配明细、复核、封账、补差和支付情况。工资属于敏感数据，普通员工只可查看本人。

错误码：`PAYROLL_PERIOD_OVERLAP`、`PAYROLL_SOURCE_CHANGED`、`PAYROLL_PRODUCT_SNAPSHOT_INVALID`、`PAYROLL_TEAM_SNAPSHOT_INVALID`、`PAYROLL_ALLOCATION_MISMATCH`、`PAYROLL_RESULT_NOT_REVIEWED`、`PAYROLL_PERIOD_ALREADY_CLOSED`、`PAYROLL_SOURCE_ALREADY_CLOSED`、`PAYROLL_PAYMENT_EXCEEDS_PAYABLE`。

## 12. 验收标准

- 个人工资使用当时商品快照的人力成本而非当前商品；
- 已核验且关联商品的其他任务按商品快照中的其他任务人工费自动采集；
- 无商品人工费依据的其他任务不产生自动计件来源，可通过有原因的工资调整支付；
- 小组任务先算整体再均分，分配总和无分币差；
- 修改当前小组成员不改变历史工资分配；
- 效率因子不进入工资总额或成员权重；
- 同一生产来源不能进入两个封账期间；
- 计算后来源变化会阻止封账；
- 封账和成本提交任一步失败全部回滚；
- 已封账更正进入后续补差，不覆盖原工资单；
- 超额支付被拒绝，冲销支付后待付金额恢复。
