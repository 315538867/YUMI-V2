# 财务结算模块

> 模块代码：`finance`

## 1. 模块说明

财务结算模块统一管理工作室的工资结算、实际成本和真实现金。三类能力处于同一顶层模块，以减少逐人工资核定、人工成本、工资支付和经营费用支付之间不必要的跨模块事务；但内部仍保持独立聚合、表、Repository、应用服务、状态和权限。

```text
finance
├─ payroll      工资来源、参考计算、逐人核定、调整、员工应付和支付状态
├─ costledger   材料、人工、售后、经营费用成本及分摊、更正、归集
└─ cash         真实收付、现金分配、来源收付汇总和冲销
```

必须始终区分：

```text
工资应付 ≠ 人工成本
成本发生 ≠ 现金支付
订单/售后金额义务 ≠ 真实收退款
```

## 2. 一期需求、范围与模块功能

### 2.1 工资结算

- 按期间自动采集有效生产、修复、其他任务和生产责任来源；
- 个人计件参考、小组共同产出参考到人均分；参考不是确定工资；
- 按员工人工填写实际核定金额和说明，逐人核对并确认；
- 参考刷新、报废成本参考计算及已核定结果追溯；实际工资由负责人逐人填写并确认，人工差额调整必须有原因；
- 员工应付、部分支付和已付状态；
- 单个员工核定成功时形成该员工应付和对应人工成本，不自动核定其他员工；一期不提供统一封账生成应付的命令。

### 2.2 成本台账

- 归集生产材料、生产人工、售后和经营费用；
- 保存来源、分类、承担方、计价依据和业务日期；
- 直接归集和明确规则分摊；
- 冲销、差额更正、来源唯一守卫和失败重试；
- 按订单、商品、生产来源、工资期间、售后案例和期间查询。

### 2.3 资金管理

- 实际资金流水和按业务日期的收支汇总；一期不管理资金账户；
- 订单收款、订单退款、售后收费/退款/赔付；
- 工资付款和日常收支登记；日常支出可选择同时计入经营费用；
- 一笔现金分配到一个或多个业务来源；
- 现金冲销和业务来源收付投影；不提供账户余额、转账、期初余额或账户对账。

一期不提供考勤、基本工资、社保个税、银行代发文件、材料库存、采购、会计总账、会计科目、借贷凭证、发票和税务申报。

## 3. 模块边界

### 3.1 本模块拥有

- 工资期间、参考运行、生产劳动/责任来源接收投影、固化参考来源、逐人核定事实、工资结果、调整、员工应付和工资支付分配；
- 成本事实、成本明细、分摊、来源守卫、归集游标和失败记录；
- 现金事实、现金分配、业务来源收付投影和冲销；不拥有资金账户。

### 3.2 本模块不拥有

- 订单应收、退款和售后金额义务：由 `orders` 拥有；
- 生产数量、工序、劳动和责任事实：由 `production` 拥有；
- 商品/方案定义和快照内容：由 `product` 拥有；
- 员工、小组和执行主体快照内容：由 `workforce` 拥有；
- 计算公式：由 `calculation` 提供。

模块不得读取上述模块底层表。payroll、costledger、cash 子域也不得直接写彼此的表。

## 4. 统一金额与来源规则

1. 所有金额使用定点十进制和明确币种，不使用浮点数。
2. 来源必须使用稳定业务标识、来源版本和用途；不得使用数据库主键。
3. 同一来源版本和用途只能形成一组有效工资或成本结果。
4. 正式事实不可覆盖，错误通过冲销、失效或差额更正。
5. 业务发生日期、记录时间、支付日期分别保存。
6. 计算保存规则版本、舍入版本、输入指纹和结果，不复制计算中心公式。
7. 历史结果使用来源任务保存的商品、人员、小组和标准快照，不读当前值重新解释。
8. 内部子域协作使用类型化应用接口，不通过通用 JSON 或直接 Repository 调用。
9. 生产劳动和责任来源分别通过 `ProductionLaborSourceFeed`、`ProductionResponsibilitySourceFeed` 的独立单调游标增量接收；只有整页来源及对应本地投影同事务提交成功后才推进各自游标。
10. `feedItemBusinessId` 是劳动/责任来源幂等键；重复拉取、失败重试和进程重启不得形成重复工资或责任结果。劳动与责任不得共用游标或互相覆盖。

财务金额按公共金额域区分：成本台账金额、成本单价和成本明细为 `CostAmount`，精度 4 位；应收、工资、收退款和现金为人民币 `SettlementMoney`，精度 2 位；成本差额和结算差额分别使用有符号差额类型。工资参考的每个有效来源明细先按冻结单件人工成本乘完成数量，再 `HALF_UP` 舍入到分，之后汇总；正式应收、收退款和现金在各自事实明细边界精确到分。不同金额类型不允许隐式转换。

## 5. 工资结算子域

### 5.1 工资参考与实际核定规则

1. 工资参考按期间自动采集来源，不由人工逐条录入生产量；系统参考、实际核定、员工应付和实际付款分别保存与展示。
2. 正常生产和修复任务的基础计件参考：`完成数量 × 任务冻结商品/方案快照中的工序单件人力成本`；其中 `完成数量 = 合格 + 返工/修补 + 线上报废`，未完成数量不进入参考。
3. 小组任务先计算任务整体参考金额，再按任务保存的小组快照完整成员均分；该分配不直接产生员工应付。
4. 小组不拆成员个人产量；均分只是到人参考结果。
5. 小组效率因子只用于生产标准工作量，不进入工资总额和分配权重。
6. 制作正常任务使用商品快照中的制作提成；捏毛装袋、缝边剪袋使用对应人工成本；关联商品的其他任务按其冻结的其他任务单件人工费和完成数量计件，未关联商品的其他任务不自动产生计件工资。超额制作激励一期暂不启用，超额任务劳动事实仍可追溯，但不自动计算或生成激励金额；如实际工资需要覆盖该工作，由用户在逐人工资核定时明确填写。
7. 小组参考均分转换为最小货币单位后整除成员数，余数按员工稳定标识升序依次补一个最小单位；合计必须等于任务参考总额。成员实际工资逐人核定，可以与参考不同，不要求实际核定合计等于任务参考总额。
8. 实际核定金额由负责人明确填写，非负且精确到分，核定说明必填；系统逐项展示报废相关成本和胶水减免参考，负责人可逐项填写处理金额及说明。系统不选择哪些成本必须扣除，不生成自动扣款合计，不从基础工资参考或实际核定金额中自动减去这些金额。
9. 核定后来源更正不覆盖原核定事实、参考快照或已付金额；需要补差时另行提交有原因的人工调整，原核定链永久保留。
10. 售后问题不自动成为工资责任；人工调整可以保存售后案例稳定引用和明确原因。
11. 生产责任来源只由有效报废处置产生，系统依历史依据展开成本参考明细；返工是无责任返工，不列入责任成本处理、不占用胶水免扣重量，报废转线下仍保留责任及明细，非报废业务移交不产生扣款责任。人工填写的处理明细只作为本次工资核定说明的一部分，不形成独立扣款应收、自动抵扣、成本或现金事实。
12. 报废的 `EMPLOYEE / TEAM / STUDIO / CUSTOMER / WAIVED` 责任来源全部接收；只有员工或小组承担的有效报废才进入员工扣款参考及胶水重量减免计算。工作室、客户及免除责任仍保留审计，但不生成员工扣款参考或占用员工减免重量。来源缺少有效报废处置关联、类型或数量不匹配时应报接收错误，不得把整个缺陷数量当作报废数量。
13. 首次报废责任来源为 `APPLY`；责任更正按顺序接收原版本 `REVERSE` 和新版本 `APPLY`；报废更正为非报废时只接收旧版本 `REVERSE`，原来源转为失效，不等待不存在的替代责任项。待核定员工根据有效报废集合重算参考和当月胶水减免，重跑不重复使用额度；已核定员工保留原依据并展示后续更正提示，不自动重算实际工资。
14. 小组责任来源保存所认定历史作业的小组快照引用；任务核验使用本任务安排快照，售后池内直接报废使用人工选定归责证据中的历史安排快照。需要到人计算时通过 workforce 公开快照接口读取成员，不使用当前成员、不直接访问人员表，也不要求生产模块预先分摊金额。
15. 确认命令携带员工结果标识、预期行版本、参考指纹、逐项人工处理明细、实际工资金额、核定说明和幂等键。持锁后从服务端参考运行取得成本行及其依据、状态和缺失项，校验人工明细引用属于当前员工及运行，原子写核定事实、处理明细、员工应付及人工成本；不接受客户端篡改系统成本参考。缺依据的行显示空值和原因，不阻止人工填写或核定；处理金额留空与明确填 0 分别保存，均不自动改变实际工资。零金额确认不生成成本。已确认结果不能再次执行确认，幂等重试只返回原结果。
16. 核定日期取工作室业务时区下的确认日期，记录精确确认时间和操作人；人工成本使用该核定日期，工资期间、核定日期和付款日期不能混用。
17. 已核定的人工差额调整由单独命令追加事实并同步调整应付与成本，不直接改核定金额；调整后应付不得小于零或已付净额。发生真实工资款退回时，先按 7.1.2 登记该员工实际退回金额，再人工调整应付；错误付款记录的整笔冲销与真实部分退回不能混用。

### 5.1.1 已确认的金额计算边界

工资来源和实际成本必须按不同公式、不同事实保存：

```text
生产/修复明细基础参考
= 完成数量 × 冻结商品/方案快照中的当前工序单件人工成本

关联商品的其他任务基础参考
= 完成数量 × 冻结商品快照中的其他任务单件人工费

未关联商品的其他任务基础参考
= 0

任务基础参考
= Σ 任务明细基础参考

员工系统基础参考
= Σ（本期间到该员工的有效任务基础参考）

员工当前应付
= 该员工实际核定金额 + Σ（核定后的有效人工差额调整）

员工待付
= 员工当前应付 - 该员工有效付款净额

生产材料实际成本
= 完成数量 × 来源冻结的生效生产依据中“当前工序 + 工作室承担 + 非人工”的单件成本
```

其中完成数量固定为“合格 + 返工/修补 + 线上报废”，未完成数量不计入工资或生产材料成本。产品级胶水、色浆等基础材料在一笔预算内只归入制作明细；对每条实际制作生产或修复来源按其历史制作单件成本计算一次，包装工序不得重复取用。人工、制作提成、商品额外预计分摊不得再次登记为 `DIRECT_MATERIAL`。每一条来源金额都要保存未舍入输入、已舍入金额、计算规则版本、舍入版本和输入指纹。

### 5.1.2 报废成本逐项展示与人工填写

工资核算按员工展示其承担的有效报废数量、责任来源、商品、工序、历史成本参考和人工处理明细。报废转线下仍展示，不根据线下售价或未知收入反冲参考；返工、非报废移交、工作室/客户/免除责任不进入员工责任处理明细。

| 展示分组 | 逐项内容 |
|---|---|
| 基础材料 | 胶水、色浆 |
| 制作 | 制作提成（即制作人工，不重复加一次人工）、其他材料费用 |
| 捏毛装袋 | 人工、袋子、装饰品、该工序其他费用 |
| 缝边剪袋 | 人工、综合材料、该工序其他费用 |
| 额外单件费用 | 其他任务人工费、运输包装费、日常杂费、房租水电分摊、模具摊销、其他费用 |

**系统展示：** 每行保留来源和成本项稳定标识、历史标准单价、关联报废数量、到人参考金额、供料/承担方、已发生工序标记及依据。非胶水标准成本行按关联报废数量乘历史标准单价计算，保留 4 位成本精度；小组金额以 `0.0001` 元为单位等分历史成员，余数按员工稳定标识分配，只表示参考分配，不拆个人产量。胶水使用 5.1.3 的重量先分配、再按员工行计价规则，不再把胶水金额另做一次均分；另列标准重量、当月免扣重量、此次减免重量及减免前后参考，不覆盖原材料成本台账。

历史分项标准通过 `ProductCostBasisQuery.resolveReferenceCostLines` 取得，不复用只返回非人工行的材料入账接口。`occurrence_status = OCCURRED / NOT_OCCURRED / UNKNOWN`，`reference_kind = STANDARD_COST / ESTIMATED_ALLOCATION`；标准参考与财务实际成本不是同一字段。缺依据时仍可展示对应成本项及缺失提示，负责人无需等待重新定义扣款公式。

成本项目沿用历史商品/方案和生效生产依据，按实际已发生的阶段事实去重展开；同一原始材料行不能因经过多个工序重复列入。尚未经历的工序标为“未发生”，仅展示历史单价标准，到人已发生参考金额为空、行状态为 `NOT_APPLICABLE`，不伪造 0 成本或触发缺失警告；无法追溯的行标为“依据缺失”，金额为空、行状态为 `INCOMPLETE`。具备完整依据的适用行状态为 `COMPLETE`。客户供料保留标准价值及“非工作室承担”标识，不混入工作室成本。额外单件费用单独标为“预计分摊”，不得伪装为报废时新发生的实际费用。工资人工参考、财务实际核定工资和商品单件人工标准明确区分。

**负责人填写：** 各成本行旁提供可选的“本次处理金额”和说明，金额非负、精确到分，默认留空，不把系统参考复制为默认扣款。0 表示明确本次不作金额处理，留空表示未按该项填写；不要求每行填写，也不强制人工金额等于或不超过参考。负责人再单独填写最终实际工资及核定说明，系统不以明细合计反推工资，不要求“基础工资参考－处理金额＝实际工资”。人工明细可以用于说明负责人判断，但不是独立扣款账户或债权，不产生跨期责任余额。

**保存与更正：** 确认时保存当次服务端参考行、来源版本、胶水配置及运行引用，以及负责人填写的明细、最终工资和说明；所有内容同事务提交，失败整体回滚。引用过期或不属于该员工的明细拒绝提交。已核定明细不能直接覆盖；后续工资变化通过有原因的人工差额调整追加，并可携带本次处理明细，与原核定分别保留。重算系统参考不复制或修改历史人工决定。

**缺失边界：** 只按真实的历史成本/人员依据或胶水配置缺失标记对应行 `INCOMPLETE`，其他可计算行继续展示，人工核定不受阻。不再等待“哪些成本必须计入统一扣款公式”的确认，也不再使用 `RESPONSIBILITY_RULE_UNCONFIRMED`；系统没有统一自动扣款金额。没有员工承担的有效报废时显示“无相关报废”，不生成一组虚假的零扣款行。超额制作激励一期仍不自动计算，不因此把成本明细标为缺失。

### 5.1.3 每人每月胶水免扣重量

本节细化胶水行的重量减免参考和追溯，不决定负责人必须扣除的金额，不建立实际工资扣款或额度余额账户。

**设置与生效：** `finance.payroll` 提供统一设置“每人每月胶水免扣重量（克）”，所有员工使用同一月度标准，一期不增设个人覆盖配置。重量使用 `DECIMAL(19,4)`，非负；0 表示明确不减免，未配置不能默认为 0。每次提交保存不可变版本、生效自然月、原因和操作人。同一生效月可追加修订版本；查询某月时先取不晚于该月的最近生效月，再取该生效月的最新版本。允许配置未来月份；追溯修改已开始月份必须显示受影响月份和历史核定提示，保留旧配置及全部旧计算运行，不回写已核定工资。

**归月与范围：** 月份由工作室业务时区下责任来源的 `business_date` 决定，不按录入时间或工资期间重置。任务报废使用原任务工作日期；售后池内直接报废使用处置业务日期，不能回填原制作日期。每人每个自然月单独计算，未使用重量不跨月、不转给别人。工资参考须覆盖期间跨越的全部员工自然月，即使当前无报废也取得零来源版本守卫，以识别以后新增或迟到来源。同月即使拆成多个工资期间也只有一份标准；跨月期间分别引用各自然月计算结果。来源更正涉及日期或责任人时，原、新员工月份都必须重算。

**来源与到人：** 只处理人工认定的有效员工或小组报废责任，返工、非报废移交、工作室/客户/免除责任均不占用额度。胶水重量和历史单价必须来自责任来源冻结的历史生产依据，不取当前商品价格；仅对已发生并由工作室承担的历史胶水行提供减免参考，客户供料不占员工免扣重量。按现有标准用量口径使用含损耗重量，不重复加损耗、不把色浆当成胶水减免。`cost_line_business_id` 是来源上下文内的稳定行键，由原始成本来源事实标识、工序和成本项编码组成，不使用当前预算行号或本次运行随机编号；不新增材料目录。同一历史胶水行在同一报废参考中只能计一次，包装或修复链不得因重复引用原制品而重复加入。同一原材料行只出现一次，实际新增修复用料以独立来源行展示，不重复引用原材料；是否作金额处理由负责人填写。

员工责任全部归该员工；小组责任沿用基础参考的等额到人原则，使用归责证据中的历史完整成员。先将每条胶水行报废总重量按 `HALF_UP` 保留 4 位，再换为 `0.0001g` 整数单位均分，余数按员工稳定标识升序分配，不按当前成员、产能或效率加权。其他成本参考行按 5.1.2 的 4 位成本精度均分；人工填写的处理金额不由该分配规则决定。重量分配不代表拆分实际个人产量。

**抵扣与重算：** 按员工自然月汇集截至来源游标的全部有效责任，包括不属于本次工资期间、已核定但仍有效的来源。按 `business_date → responsibility_chain_business_id → cost_line_business_id` 升序逐行使用重量标准；更正版本不改变稳定排序键。每行减免重量为该行分配重量与本月剩余标准的较小值，使用该行冻结胶水单价计价，不能按最高价优先抵扣。每个员工胶水行分别以分配重量、减免重量和剩余重量乘历史每克单价，分别保留未舍入乘积和按 `HALF_UP` 舍入到 4 位的减免前/后参考；减免金额展示为该行减免前参考减减免后参考，避免三次独立舍入不守恒。员工、期间及小组展示合计只相加这些已舍入行，不重新对小组总重量计价，也不再生成 2 位扣款总额。胶水减免不冲减色浆、其他成本或成本台账。

每次月度运行都是完整有效集合上的纯重算，不从上次“剩余额度”继续扣，不生成使用/返还现金或实际扣款流水。没有工作室承担的已发生胶水行时，不要求胶水配置，也不占用重量；某条候选来源缺历史成本依据、成员或重量时，该员工当月相关胶水参考整体标为不完整，不能跳过它后宣称后续行额度准确；缺失项分别记录 `RESPONSIBILITY_BASIS_MISSING / GLUE_ALLOWANCE_POLICY_MISSING`；不再设置统一扣款公式缺失项。可核对已知事实，但不把不完整金额填成 0。

**版本与并发：** 月度运行保存配置版本、责任 Feed 截止游标、有效来源版本集合、成员/成本依据指纹、算法/舍入版本和逐行分配明细；工资运行引用月度运行，不另算一份额度。责任归集按更正前后员工月份的并集锁定守卫并递增 `source_revision`，即使该月没有工资期间或守卫尚不存在也必须创建并锁定。刷新先固定输入再计算，发布时校验全部月份版本及配置选择结果；过期运行标为 `SUPERSEDED`，不得被确认。逐人核定持相同守卫校验指纹，迟到来源或配置修订后要求刷新待核定结果。已核定快照保持原样，可显示新参考与差异提示，但不自动重算应付和实际工资。

胶水明细参考数值验收（不代表实际扣款）：月标准 100g，同一员工先有 60g、0.10 元/g，再有 80g、0.20 元/g，减免分别为 60g、40g，胶水参考成本为 0 元、8 元。若前一条责任被免除，重算后一条减免 80g、胶水参考为 0，不能沿用此前剩余 0g。两条即使分在同月不同工资期间，结果仍一致；下一自然月重新使用当月标准。小组三人分配 1g 时，按稳定标识分别为 0.3334g、0.3333g、0.3333g，合计仍为 1g。

### 5.1.4 已核定结果的复核与人工调整

`CalculatePayrollCommand.run_type = PENDING_REFERENCE / CONFIRMED_REVIEW`。前者仅刷新待核定员工当前参考；后者为已核定员工生成独立只读复核运行，供查看迟到来源、责任更正及配置变化后的逐项参考，不改变员工确认状态、原核定的运行引用、处理明细、应付或已付金额。两者都保存不可变来源及成本行，并遵循相同的发布版本校验；`CONFIRMED_REVIEW` 不得拿去重复确认工资。

追加调整可引用当前有效复核运行并填写新的处理明细；命令及调整事实保存 `reference_run_business_id / reference_fingerprint`，引用明细必须来自该员工同一复核运行。提交持锁校验版本，过期时要求重新核对，不静默把人工金额复制到新行。未附处理明细的纯金额调整仍可直接提交，不强制运行成本复核。调整只按负责人明确填写的有符号差额改变应付，处理明细不参与自动加减；历史确认及历史调整明细分别保留。

### 5.2 状态

- 工资期间核定进度：`PENDING / PARTIALLY_CONFIRMED / CONFIRMED`，由员工结果派生，不是封账状态；新增期间不生成应付；
- 计算运行：`RUNNING / SUCCEEDED / FAILED / SUPERSEDED`；
- 员工核定状态：`PENDING_CONFIRMATION / CONFIRMED`；付款状态独立为 `UNPAID / PARTIALLY_PAID / PAID`，仅已核定员工可付款；零金额已核定结果无待付款，不生成零金额付款事实；
- 调整正式创建即有效，通过更正事实失效，不使用草稿。

### 5.4 流程

```text
持续按两个独立游标读取生产劳动来源和责任来源的 `APPLY / REVERSE`
→ 分别幂等保存劳动/责任来源接收项并更新各自当前投影
→ 各 Feed 整页提交成功后分别推进自己的游标
→ 创建期间
→ 按截止游标读取本地劳动来源投影及涉及自然月的完整责任集合，固定月配置和来源版本
→ 固化来源版本及快照引用
→ 调用计算中心计算个人/小组金额与月度胶水明细，发布前校验配置和月来源版本，过期则重跑
→ 按运行类型形成待核定参考或已核定只读复核，不生成应付或成本，不替换原核定引用
→ 打开单个员工，逐项查看报废成本及胶水减免参考，可填写各项处理金额，再独立填写最终工资和核定说明
→ 校验参考指纹和员工行版本，确认该员工
→ 同事务写该员工核定事实、应付和 DIRECT_LABOR 成本事实
→ 后续由 cash 子域支付
```

## 6. 成本台账子域

### 6.1 成本分类

- `DIRECT_MATERIAL`：生产材料及非人工工序成本；
- `DIRECT_LABOR`：逐人工资实际核定及其有效人工差额调整；
- `AFTER_SALES`：售后正式确认由工作室承担的成本；
- `OPERATING_EXPENSE`：房租、水电和其他实际经营费用；
- `ADJUSTMENT`：明确的成本差额调整。

商品预算中的人工、房租水电单件分摊、日常杂费和模具摊销是预计口径，不自动全部登记为实际成本。人工以逐人实际核定为准，经营费用以正式费用事实为准，避免重复入账。

一期不做材料管理，生产材料成本使用任务冻结的商品/方案快照中“工作室承担”的录入价格，计价口径标记为 `STANDARD_INPUT_PRICE`。

### 6.2 来源模式

- 生产材料：读取 `ProductionMaterialCostSourceFeed` 异步归集，覆盖正常生产、制作超额生产和修复任务；修复仍按来源生效生产依据中的返工工序标准非人工成本归集；金额为“完成数量 × 当前工序工作室承担的历史单件非人工成本”；
- 生产人工：逐人核定时在模块内部同事务登记，来源为核定事实而非参考来源，金额等于实际核定金额；正数生成一笔成本，零金额不生成；后续人工差额调整追加关联成本差额；
- 售后成本：读取 `OrderAfterSalesCostSourceFeed` 异步归集；
- 经营费用：日常支出明确选择“同时计入经营费用”时在模块内部同事务登记；未选择只记现金，日常收入不生成经营费用。不得借日常收支重复登记订单、工资、材料或售后专属成本。

生产和售后来源 Feed 必须对更正输出 `REVERSE`，替代事实再输出 `ACCRUE`。归集失败不回滚上游事实，但必须记录失败并幂等重试，当前页未全部成功不得推进游标。

生产材料来源必须包含 `ResolvedProductionBasis` 及指纹，财务保存原依据后通过 product 的公开解析接口提取对应工序成本行；胶水等供料方以该依据中的订单生效约定为准，而非方案默认值。缺少依据或校验失败时记录归集失败，不得回读当前商品或以模板成本兜底。`REVERSE` 使用原入账成本及原依据精确抵消，不能按新供料约定重算原金额。

逐人核定人工成本先归属员工及工资期间；参考来源用于追溯，不自动按参考金额把实际人工成本分摊到订单。需要订单分摊时保存明确的分摊依据和明细，分摊合计等于该成本，不另生成一笔成本；缺少分摊的订单报表必须提示人工成本未完整归集。

## 7. 资金管理子域

### 7.1 业务规则

1. 现金事实必须包含方向、业务类型、业务日期、币种、金额、记录人和记录时间；一期没有账户字段。
2. 一笔现金可以分配到多个来源，分配合计必须严格等于现金金额。
3. 订单和售后收付资格由 `orders` 决定，cash 子域不得复制其规则。
4. 工资支付资格由 payroll 子域的员工应付决定。
5. 同一来源累计收付不得超过允许金额。
6. 现金事实不可编辑，错误通过冲销或差额事实更正。
7. 来源收付合计和期间现金净额是可重建投影，不是账户余额，也不代表利润或当前可用资金。
8. 日常收支由 cash 的单一命令登记，方向、分类、金额、用途、业务日期和记录标识为必填；支出的 `count_as_expense` 默认 false，收入必须为 false。不是每次支出都自动形成成本。
9. 业务日期由用户选择，默认当天且可补录历史日期、不晚于当天；记录时间独立保存。月度现金统计和本条可选经营费用均使用该日期，不能用录入月份归集。
10. 日常收支以本条业务记录为唯一现金分配来源，分配金额等于本条现金金额；金额必须大于零且精确到分。需要计费用时只生成一笔等额 `OPERATING_EXPENSE`，费用金额按成本精度表示，不因双重保存而统计两次现金。
11. 冲销使用有效的反向流水抵消原流水，原流水仍进入其原业务日期的收付统计；不能同时把原流水剔除再计入反向流水。工资付款冲销同事务反向影响已付净额，现金分配按反向流水方向抵减原来源，不重复冲减。联动经营费用也只通过关联的反向成本抵消原成本，不再另扣一次。

### 7.1.1 现金公式

```text
期间现金净额
= 期间有效现金流入合计 - 期间有效现金流出合计

订单净收款
= 订单有效收款合计 - 订单有效退款合计

来源累计已分配现金
= 该来源有效现金分配合计

单笔现金分配合计
= 现金事实金额
```

一期不录入期初资金余额；冲销通过新的反向现金事实改变收付汇总，不直接修改原流水。按业务日期分别归月，反向流水不回改原月记录。收款资格和退款资格由 `orders` 返回，cash 不自行推导；工资支付资格由 payroll 返回。任何来源累计收付超过允许金额、币种不一致或现金分配不守恒都必须拒绝。

### 7.1.2 工资款实际退回

真实退回使用独立的 `PAYROLL_RETURN` 现金流入，不用“整笔冲销后重录付款”模拟，也不登记为日常收入。由 `finance.cash` 拥有命令，通过 payroll 内部能力维护已付净额，不引入资金账户或责任余额结转。

- 从原工资付款的员工分配明细进入，一次退回对应一个原分配和一个员工核定结果；金额大于零、精确到分，币种与原付款相同，可分次退回。业务日期由用户选择，不早于原付款日期且不晚于当天；原因必填，凭证随本条退回记录保存且可选。
- 累计未被冲销的退回金额不得超过原分配金额；持锁后重新校验原付款未被整笔冲销、该员工可退余额及预期版本，禁止借甲的退回冲减乙的付款。
- 同事务追加退回现金事实、原付款分配关联和 payroll 反向支付分配，减少该员工已付净额，推进版本并记录审计。失败全部回滚，幂等重试不重复退回；其他员工及原月份现金事实不变。
- `已付净额 = 有效付款分配 - 付款冲销分配 - 实际退回分配 + 退回冲销分配`；它不得为负，也不得超过当前应付。退回本身不改变应付或人工成本；后续人工差额调整单独写核定调整和成本差额。
- 原付款存在尚未冲销的退回记录时，不允许整笔冲销原付款。错误退回记录可通过通用冲销命令整笔反向更正；须锁相同原分配并校验恢复后的已付净额不超过应付，必要时先更正工资调整。反向事实不能再次冲销，不允许绕过原分配累计上限。
- 月度统计按实际退回日期计入“工资款退回”现金流入；工资付款仍保留在原付款月份。不能净额替代流入/流出总额，不能把工资退回同时计为经营收入或负人工成本。

验收例：9 月一笔 2,000 元工资付款分给甲乙各 1,000 元；10 月甲实际退回 100 元，则 10 月仅新增 100 元流入，甲已付净额为 900 元、乙仍为 1,000 元。负责人随后将甲应付人工下调 100 元，才产生对应成本差额；不得虚构 2,000 元流入及 1,900 元流出。

### 7.3 收付凭证归属与保存

工资款实际退回与其他收付遵循相同凭证归属规则：凭证可选，上传时归本次退回现金事实，原付款凭证只通过关联追溯，不复制为退回凭证。

- 凭证属于本条现金事实，不属于工资期间、订单整体或独立凭证池。订单页面登记收款、退款或售后赔付时，凭证随本次 finance 现金命令提交；财务共享查询原现金事实及同一凭证关系，不再上传或复制一份。
- 收付款、工资付款和日常收支命令可携带 `voucher_file_refs`，允许为空。若提供附件，先上传为平台临时文件，再在业务提交事务中正式化、写本条凭证关系并通过平台公开文件参与能力注册 `owner_module = finance, owner_type = CASH_FACT, owner_business_id = 本条现金事实标识` 的文件引用；任何一步失败都不能留下已提交现金或有效业务引用。
- finance 保管凭证的业务关系，platform 保管文件内容与引用保护。查询现金详情同时返回凭证列表及受权限保护的查看能力，订单页面和财务页面按同一现金标识访问；正式引用中的文件不得独立删除。
- 冲销保留原流水与原凭证；反向流水独立保存其凭证并关联原现金事实，不能把原支付凭证当作发生了一次新支付的证明。支付事实不可因更换附件而覆盖；需要补充附件时追加关系和审计，错误附件保留更正链。
- 文件类型、大小和数量上限由平台部署配置及业务校验共同约束，原型的本地演示限制不是正式归档标准。校验文件权限和有效状态，不能接受任意文件标识或只保存浏览器临时地址。
- 已确认必须支持记录内上传、查看和追溯；订单收款、退款、售后赔付、工资付款、日常收入、日常支出及冲销的凭证均为可选附件。提供附件时必须校验并正式归档，未提供附件时不阻止业务提交；该规则须同时用于命令校验、页面提示和验收。

## 8. 关键业务流程

### 8.1 逐人工资核定

```text
锁胶水配置守卫及该员工期间涉及的全部自然月守卫
→ 锁工资期间和该员工结果
→ 校验配置选择、月来源版本、待核定状态、预期行版本、参考指纹、人工金额和说明
→ 固化该员工确认时的劳动参考、报废成本行及人工处理明细
→ 锁核定业务标识对应的成本来源守卫
→ 写该员工核定事实及应付
→ costledger 内部登记 DIRECT_LABOR
→ 一次提交
```

金额为零时跳过成本写入但仍保存核定事实；任何失败均不留下已核定、应付或成本的部分结果。确认一人不确认其他员工，参考刷新不覆盖已核定员工。

### 8.2 工资支付

```text
锁工资员工结果
→ 校验该员工已核定及剩余应付
→ 锁业务来源收付守卫和来源现金投影
→ 写现金事实与工资支付分配
→ 更新已付金额、工资状态和来源收付投影
→ 一次提交
```

### 8.3 订单及售后收付

```text
finance 开启事务
→ orders participant.prepare 锁业务义务并返回允许金额
→ 锁业务来源收付守卫和来源现金投影
→ 写现金事实和分配
→ orders participant.commitPaymentLink
→ 更新来源收付投影并一次提交
```

### 8.4 日常经营收支登记

```text
校验方向、分类、所选业务日期、金额、用途、凭证和是否计费用，不接受专属业务来源
→ 锁本条日常记录来源收付守卫；仅计费用支出再锁成本来源守卫
→ 写一条现金事实、日常记录及唯一来源分配
→ 仅 count_as_expense 为 true 的支出由 costledger 内部写同额同日 OPERATING_EXPENSE
→ 写现金/可选成本关联、凭证引用及来源收付投影
→ 一次提交
```

未计费用时不生成成本空记录；成本登记失败必须连同现金、日常记录和凭证引用一起回滚。日常收支页面只提交这一条命令，不再调用第二个费用命令模拟联动。

日常收支冲销复用现金冲销命令：锁原来源、关联成本来源守卫（如有）及原事实，追加反向现金；原记录存在经营费用时同步追加等额反向成本，使用同一所选冲销业务日期。两者任一步失败全部回滚，原月份及原凭证不被覆盖。已联动的成本不得单独冲销造成现金/费用关联失衡；不存在关联费用时不能凭空新增反向成本。

### 8.5 成本归集

```text
取得 Feed 租约和游标
→ 读取生产或售后不可变来源
→ 解析历史快照或来源金额
→ 调用计算中心计算和舍入
→ 写成本事实、分摊和来源守卫
→ 全页成功后推进游标
```

## 10. 事务、锁序和并发

- 工资退回：对应员工应付 → 来源收付守卫/投影 → 原付款现金事实及员工分配 → 退回现金事实及反向支付分配。与付款、人工调整、付款冲销竞争同一员工应付及来源守卫，锁后重算已付净额和原分配可退余额。整笔付款冲销涉及多名员工时先按稳定标识锁全部员工应付和来源守卫，不能先锁现金后补拿员工锁；退回冲销共用该顺序。

- 工资参考发布及逐人核定：胶水配置守卫 → 员工自然月守卫（员工、月份升序）→ 期间 → 员工结果 → 成本来源守卫（仅核定时）；持锁后校验配置、月来源版本及参考指纹。人工差额调整不重新计算参考；若附本次处理明细，按同一前置守卫校验所引用参考运行，无处理明细时只锁期间 → 员工结果 → 成本来源守卫；
- 工资支付：员工应付 → 来源收付守卫/投影 → 现金事实和分配；
- 订单/售后收付：orders 义务 → finance 来源收付守卫/投影 → 现金事实 → orders 支付关联；
- 日常收支：来源收付守卫/投影 → 成本来源守卫（仅计费用时）→ 现金事实 → 成本事实（可选）；
- 成本归集：游标/租约 → 来源守卫（稳定标识升序）→ 原成本事实 → 新成本事实；
- 冲销：来源义务/应付 → 来源收付守卫/投影 → 关联成本来源守卫（如有）→ 原现金事实 → 冲销事实；
- 同一业务来源并发收付由稳定来源守卫串行化；首次付款也必须先创建或锁定守卫，不能仅锁可能尚不存在的投影行；
- 多来源现金命令先完成全部外部 prepare，再写任何现金事实；
- 死锁只重试整个幂等命令，不能局部重试 SQL；
- 任一步失败时，同事务内工资、成本、现金和外部支付关联全部回滚。

### 11.1 财务结算交互原型基线

本轮方案补充的“原工资付款员工分配 → 登记实际退回 → 核对金额、日期、原因及可选凭证 → 确认”属于待实现的正式交互要求，详情须能追溯原付款与退回，月度汇总单列工资款退回；不能据此声称现有 HTML 已提供该入口。下列当前原型描述保持演示边界，整笔冲销入口不能替代部分退回。

> 整理日期：2026-10-09。页面入口：[财务结算原型](../../finance-element-plus.html)。本节记录用户已经确认的页面操作与当前演示边界；正文已同步一期无资金账户、逐人工资核定的业务口径，但正式后端事务、权限和审计仍未实现。

- **订单收款和退款回到订单详情登记。**财务只共享显示对应流水及原记录凭证，不重复创建订单收付。

#### 11.1.2 逐人核定工资

下表中的“报废成本明细、人工处理金额”是本轮确认后的目标设计，现有 HTML 尚未实现，不视为已通过原型或业务验收。

| 页面 / 字段 | 当前原型规则 |
|---|---|
| 核算期间 | 期间名称、起止日期；名称不重复，日期有效，不与已有期间重叠 |
| 员工列表 | 员工及编号、核算期间、系统参考、实际核定、已付 / 待付、待核定 / 已核定；按员工、期间、状态筛选 |
| 系统参考 | 展示示例劳动来源、完成数量、未完成数量、历史人工单价和到人参考；待核定可刷新来源 |
| 实际核定金额 | 由用户人工填写，不默认将参考值当成实发；非负，最多两位小数，不超过 999999.99 元 |
| 报废成本明细 | 材料、人工和预计分摊逐项展示，带来源、历史单价、工序发生状态、承担方和胶水减免参考；不显示自动扣款合计 |
| 人工处理金额 | 每项可选填写金额及说明，默认留空，可明确填 0；不自动从实际工资扣除，不要求合计与工资差额相等 |
| 核定说明 | 必填，最多 200 字符；与确认时的参考来源一起保留 |
| 确认预览 | 核对基础工资参考、逐项成本及人工处理明细、独立填写的实际工资和说明；返回修改或确认该员工 |

```text
新增核算期间 → 形成每位示例员工的待核定记录
  → 打开一个员工 → 核对来源与参考 → 人工填写金额和说明
  → 核对并确认该员工 → 形成已核定结果及对应人工成本
  → 另行登记实际工资付款
```

- 新建期间不生成确定应付；确认一位员工不自动确认整个期间或其他员工。
- 现有原型示例仍使用合格、返工、报废、转线下四分类，属于待修订的旧演示模型；正式完成数量统一为“合格 + 返工/修补 + 线上报废”，转线下作为报废去向时不额外增加数量。未完成数量不计参考，小组参考按冻结成员均分；不能直接用旧示例证明新契约已实现。
- 一期不计算制作超额激励；报废成本逐项提供参考，负责人可逐项填写处理金额并独立确定实际工资，不自动扣减；小组效率不参与金额计算或分钱。
- 来源或核定内容变化后需重新核对；确认保留参考快照、人工金额、说明和确认时间，原型不提供已核定结果直接重算覆盖的操作。
- 正数核定同时增加一笔人工成本，零金额确认不生成成本；**核定不等于付款**，不增加现金支出。
- 当前员工与劳动 / 责任来源是财务页面的示例，不自动取得人员原型新增员工或生产原型新任务。

#### 11.1.3 工资付款与来源分配

| 字段 | 当前原型规则 |
|---|---|
| 业务类型 | 仅工资付款；订单收退款不在此选择 |
| 业务日期 | 用户选择，有效且不晚于当天，不早于关联员工核定来源的可付款日期 |
| 实际付款金额 | 大于零，最多两位小数，不超过 999999.99 元 |
| 来源分配 | 选择 1 至 10 项已核定且有待付的员工来源，不重复；每项金额大于零、不超过该员工待付；合计严格等于本次付款 |
| 备注与凭证 | 备注最多 200 字符；凭证随本条工资付款记录保存 |

- 可以从某员工进入付款，也可一次向多个已核定员工分配本次实际付款；一次流水并不把工资核算变成集体确认。
- 允许部分支付，已付 / 待付由有效付款与反向记录计算；同一人工成本不因分次支付重复产生。
- 先核对本次现金金额、每位员工分配和凭证，再确认登记；实际现金支出按用户选择的业务日期统计。

#### 11.1.4 日常经营收支录入

| 字段 | 当前原型规则 |
|---|---|
| 收支方向 | 日常支出或日常收入，切换方向重新选择分类 |
| 分类 | 支出示例含房租、水电 / 网络、日常运费、办公 / 日常用品、其他日常支出；收入含废旧物品处理、补贴、其他日常收入 |
| 登记日期 | 默认当天但可以选择历史日期，不晚于当天；用于这条收支和关联费用的月份归属 |
| 实际金额 | 大于零，最多两位小数，不超过 999999.99 元 |
| 用途说明 | 必填，最多 200 字符 |
| 收支凭证 | 跟随本条记录上传与查看，不放到独立凭证池让用户再次关联 |
| 同时计入经营费用 | 仅支出显示，默认不勾选；只在费用尚未归集时选择，避免重复计成本 |

```text
资金收付 → 登记日常收支
  → 选择方向、分类、日期，填写实际金额和用途，附本次凭证
  → 支出可选择同时计入经营费用
```

- “生成资金流水”是保存同一条日常收支后形成查询记录，不是让用户去另一个表单再录一次付款。
- 不勾选经营费用只记录现金；勾选时同时形成关联费用，两者使用所选日期归属同月，可以互相定位。
- 日常收入不形成经营费用；订单、工资、材料和售后专属业务不能借日常分类绕过来源规则。
- **最终口径是选择日期，不是录入时刻决定月份。**例如 10 月补录 9 月的收支，选择 9 月日期就进入 9 月；系统另存录入时间以区分。
- 日常费用联动保存使用同一份本地状态，写入成功后才更新页面；这不等于正式数据库跨子域事务已经实现。

#### 11.1.5 凭证与冲销

- 订单收退款、工资付款和日常收支共用 `payment-vouchers.js`。每条最多 3 份 JPG、PNG、WebP 或 PDF，单份不超过 300KB；当前本地数据还有总容量保护。
- 凭证属于具体收付流水，详情展示本条附件；关联成本可以定位付款及其凭证，无需再上传一套。
- 当前支持上传且允许空附件；所有收付类型均可传可不传，正式规则不要求以凭证存在作为提交前置条件。
- 上传仅是在本地读取文件并保存内容，没有正式附件服务器、权限下载、扫描或备份。
- 冲销填写原因，追加相反方向的现金事实，原记录不删除；不允许再次冲销同一原流水或冲销反向事实。
- 已联动经营费用的日常支出，冲销同时追加负数费用更正；原成本保留，不能只撤现金而留下错误费用。
- 订单关联流水的冲销交给订单共享脚本校验，同步订单净收款；工资付款冲销只回退已付，不重新核定工资。
- 当前冲销反向记录使用当天作为业务日期，没有独立冲销日期选择；原凭证从被冲销记录追溯，不复制为新付款凭证。

| 汇总 | 当前内容与计算口径 |

| 人工成本 | 取逐人实际核定金额，不取系统参考；成本日期按原型核定成本记录，不简单等同付款日期 |

- 成本台账展示计价明细、来源版本与有效性；部分材料和其他成本仍为内置示例，不随生产原型操作真实更新。

## 12. 验收标准

- 个人和小组工资参考计算使用冻结来源，且小组参考分配合计严格守恒；计算参考不生成应付或人工成本；
- 小组效率不进入工资金额和分配权重；
- 单个员工人工核定同时形成该员工应付和人工成本，任一步失败全部回滚；零金额确认不生成成本，未核定员工不能付款；其他员工状态不变；
- 生产劳动、生产责任和生产/售后成本来源重复消费均不重复入账，失败可重试且各自游标不跳过；
- 责任来源更正按照 `REVERSE` 原版本、`APPLY` 新版本更新本地投影；报废改为非报废时仅 `REVERSE` 并失效原来源。待核定员工可刷新报废成本参考及胶水减免，已核定员工保留确认时的责任事实参考和实际金额，后续实际工资变化须人工确认，不覆盖原核定；
- 财务完整保留员工、小组、工作室、客户和免除责任来源，但接收来源时不预设实际扣款金额；责任来源只参与生成参考值；
- 客户供料标准价值可查询，但不登记为工作室实际成本；
- 工资、成本和现金事实不能互相替代，均可独立追溯；
- 超过订单、售后或工资允许金额的收付被拒绝；
- 日常支出不勾选计费用只生成现金，勾选时同事务生成同额同日现金及成本；日常收入不能生成经营费用，任一步失败不留下部分数据；关联冲销也须成对原子处理；
- 冲销后工资已付、来源收付汇总和历史链正确；实际部分退回只影响原员工分配，跨月统计、累计上限与冲销互斥按 7.1.2 验收；一期无账户表、账户接口或账户余额；
- payroll、costledger、cash 不直接访问彼此 Repository；
- `finance` 不复制订单、生产、商品和人员模块的规则或当前数据。
