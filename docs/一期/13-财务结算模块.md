# 财务结算模块

> 模块代码：`finance`

## 1. 模块说明

财务结算模块统一管理工作室的工资结算、实际成本和真实现金。三类能力处于同一顶层模块，以减少工资封账、人工成本、工资支付和经营费用支付之间不必要的跨模块事务；但内部仍保持独立聚合、表、Repository、应用服务、状态和权限。

```text
finance
├─ payroll      工资来源、核算、调整、封账、员工应付和支付状态
├─ costledger   材料、人工、售后、经营费用成本及分摊、更正、归集
└─ cash         账户、真实收付、现金分配、余额、冲销和对账
```

必须始终区分：

```text
工资应付 ≠ 人工成本
成本发生 ≠ 现金支付
订单/售后金额义务 ≠ 真实收退款
```

## 2. 一期需求、范围与模块功能

### 2.1 工资结算

- 按期间自动采集有效生产、修复、其他任务和生产责任来源；
- 个人计件、小组共同产出到人均分；
- 扣款、免扣、补偿和人工调整；
- 计算、复核、封账和后续期间补差；
- 员工应付、部分支付和已付状态；
- 封账时同时确认生产人工成本。

### 2.2 成本台账

- 归集生产材料、生产人工、售后和经营费用；
- 保存来源、分类、承担方、计价依据和业务日期；
- 直接归集和明确规则分摊；
- 冲销、差额更正、来源唯一守卫和失败重试；
- 按订单、商品、生产来源、工资期间、售后案例和期间查询。

### 2.3 资金管理

- 现金、银行和平台账户；
- 订单收款、订单退款、售后收费/退款/赔付；
- 工资付款和经营费用付款；
- 一笔现金分配到一个或多个业务来源；
- 现金冲销、余额投影和账户对账。

一期不提供考勤、基本工资、社保个税、银行代发文件、材料库存、采购、会计总账、会计科目、借贷凭证、发票和税务申报。

## 3. 模块边界

### 3.1 本模块拥有

- 工资期间、运行、生产劳动/责任来源接收投影、固化来源、工资结果、调整、封账、员工应付和工资支付分配；
- 成本事实、成本明细、分摊、来源守卫、归集游标和失败记录；
- 财务账户、现金事实、现金分配、余额投影、冲销和对账。

### 3.2 本模块不拥有

- 订单应收、退款和售后金额义务：由 `orders` 拥有；
- 生产数量、工序、劳动和责任事实：由 `production` 拥有；
- 商品/方案定义和快照内容：由 `product` 拥有；
- 员工、小组和执行主体快照内容：由 `workforce` 拥有；
- 计算公式：由 `calculation` 提供。

模块不得读取上述模块底层表。payroll、costledger、cash 子域也不得直接写彼此的表。

## 4. 统一金额与来源规则

1. 所有金额使用定点十进制和明确币种，不使用浮点数。
2. 来源必须使用稳定业务标识、来源版本和用途；不得使用数据库主键。
3. 同一来源版本和用途只能形成一组有效工资或成本结果。
4. 正式事实不可覆盖，错误通过冲销、失效或差额更正。
5. 业务发生日期、记录时间、支付日期分别保存。
6. 计算保存规则版本、舍入版本、输入指纹和结果，不复制计算中心公式。
7. 历史结果使用来源任务保存的商品、人员、小组和标准快照，不读当前值重新解释。
8. 内部子域协作使用类型化应用接口，不通过通用 JSON 或直接 Repository 调用。
9. 生产劳动和责任来源分别通过 `ProductionLaborSourceFeed`、`ProductionResponsibilitySourceFeed` 的独立单调游标增量接收；只有整页来源及对应本地投影同事务提交成功后才推进各自游标。
10. `feedItemBusinessId` 是劳动/责任来源幂等键；重复拉取、失败重试和进程重启不得形成重复工资或责任结果。劳动与责任不得共用游标或互相覆盖。

财务金额按公共金额域区分：成本台账金额、成本单价和成本明细为 `CostAmount`，精度 4 位；应收、工资、收退款、现金及账户余额为人民币 `SettlementMoney`，精度 2 位；成本差额和结算差额分别使用有符号差额类型。工资每个有效来源明细先按冻结单件人工成本乘完成数量，再 `HALF_UP` 舍入到分，之后汇总；正式应收、收退款和现金在各自事实明细边界精确到分。不同金额类型不允许隐式转换。

## 5. 工资结算子域

### 5.1 已确认计算规则

1. 工资按期间自动采集，不由人工逐条录入生产量。
2. 正常生产和修复任务的基础计件工资：`完成数量 × 任务冻结商品/方案快照中的工序单件人力成本`；其中 `完成数量 = 合格 + 返工/修补 + 报废 + 转线下库存`，未完成数量不进入工资。
3. 小组任务先计算任务整体工资，再按任务保存的小组快照完整成员均分。
4. 小组不拆成员个人产量；均分只是到人结算结果。
5. 小组效率因子只用于生产标准工作量，不进入工资总额和分配权重。
6. 制作正常任务使用商品快照中的制作提成；捏毛装袋、缝边剪袋使用对应人工成本；关联商品的其他任务按其冻结的其他任务单件人工费和完成数量计件，未关联商品的其他任务不自动产生计件工资。超额制作的激励金额公式尚未确认，劳动来源仍须独立采集并保留任务类型。
7. 小组均分转换为最小货币单位后整除成员数，余数按员工稳定标识升序依次补一个最小单位；合计必须等于任务工资总额。
8. 负数净工资、净工资最低为零、超出扣减如何结转后续期间，均属于尚未确认的责任金额规则；在确认前不得形成已确认净工资或责任余额。
9. 已封账来源发生更正时不重开原期间，以正负补差进入后续期间。
10. 售后问题不自动成为工资责任；人工调整可以保存售后案例稳定引用和明确原因。
11. 生产责任来源只提供责任事实，不提供扣款金额；财务根据本模块规则决定是否产生金额影响。
12. `EMPLOYEE / TEAM / STUDIO / CUSTOMER / WAIVED` 责任来源全部接收；不产生扣款的类型仍保留用于审计，不得在接收阶段丢弃。
13. 首次责任来源为 `APPLY`；责任更正按顺序接收原版本 `REVERSE` 和新版本 `APPLY`。未封账期间可重算，已封账期间不重开，差额进入后续期间。
14. 小组责任来源保存生产任务时的小组快照引用；需要到人计算时通过 workforce 公开快照接口读取成员，不直接访问人员表，也不要求生产模块预先分摊金额。

### 5.1.1 已确认的金额计算边界

工资来源和实际成本必须按不同公式、不同事实保存：

```text
生产/修复明细基础工资
= 完成数量 × 冻结商品/方案快照中的当前工序单件人工成本

关联商品的其他任务基础工资
= 完成数量 × 冻结商品快照中的其他任务单件人工费

未关联商品的其他任务基础工资
= 0

任务基础工资
= Σ 任务明细基础工资

员工应付毛额
= Σ（本期间有效任务基础工资） + Σ（本期间有效工资调整）

生产材料实际成本
= 完成数量 × 历史方案快照中“当前工序 + 工作室承担 + 非人工”的单件成本
```

其中完成数量固定为“合格 + 返工/修补 + 报废 + 转线下库存”，未完成数量不计入工资或生产材料成本。产品级胶水、色浆等基础材料在一笔预算内只归入制作明细；对每条实际制作生产或修复来源按其历史制作单件成本计算一次，包装工序不得重复取用。人工、制作提成、商品额外预计分摊不得再次登记为 `DIRECT_MATERIAL`。每一条来源金额都要保存未舍入输入、已舍入金额、计算规则版本、舍入版本和输入指纹。

### 5.1.2 尚未确认的金额公式

以下内容仍不能在代码或文档中擅自推导：

- 超额制作激励金额的单价、计价数量和是否叠加正常制作提成；
- 责任来源是否形成扣款；
- 责任扣款的计算基数、上限、免扣规则；
- 小组责任到成员的金额分配；
- 扣款超过当期工资后的余额结转、冲销和后续期间补差。

在这些问题确认前，系统只能接收并保存劳动/责任来源，不能宣称已完成对应金额结算。

### 5.2 状态

- 工资期间：`OPEN / CALCULATING / CALCULATED / REVIEWED / CLOSED`；
- 计算运行：`RUNNING / SUCCEEDED / FAILED / SUPERSEDED`；
- 员工结果：`CALCULATED / REVIEWED / CLOSED / PARTIALLY_PAID / PAID`；
- 调整正式创建即有效，通过更正事实失效，不使用草稿。

### 5.4 流程

```text
持续按两个独立游标读取生产劳动来源和责任来源的 `APPLY / REVERSE`
→ 分别幂等保存劳动/责任来源接收项并更新各自当前投影
→ 各 Feed 整页提交成功后分别推进自己的游标
→ 创建期间
→ 按截止时间读取本地劳动来源投影和责任来源投影
→ 固化来源版本及快照引用
→ 调用计算中心计算个人/小组金额
→ 形成员工结果
→ 复核并处理调整
→ 封账时写工资应付和 DIRECT_LABOR 成本事实
→ 后续由 cash 子域支付
```

## 6. 成本台账子域

### 6.1 成本分类

- `DIRECT_MATERIAL`：生产材料及非人工工序成本；
- `DIRECT_LABOR`：工资封账确认的生产人工；
- `AFTER_SALES`：售后正式确认由工作室承担的成本；
- `OPERATING_EXPENSE`：房租、水电和其他实际经营费用；
- `ADJUSTMENT`：明确的成本差额调整。

商品预算中的人工、房租水电单件分摊、日常杂费和模具摊销是预计口径，不自动全部登记为实际成本。人工以工资封账为准，经营费用以正式费用事实为准，避免重复入账。

一期不做材料管理，生产材料成本使用任务冻结的商品/方案快照中“工作室承担”的录入价格，计价口径标记为 `STANDARD_INPUT_PRICE`。

### 6.2 来源模式

- 生产材料：读取 `ProductionMaterialCostSourceFeed` 异步归集，覆盖正常生产、制作超额生产和修复任务；修复仍按历史方案快照中的返工工序标准非人工成本归集；金额为“完成数量 × 当前工序工作室承担的历史单件非人工成本”；
- 生产人工：工资封账时在模块内部同事务登记；工资来源金额使用完成数量，不使用未完成数量；
- 售后成本：读取 `OrderAfterSalesCostSourceFeed` 异步归集；
- 经营费用：费用确认或付款时在模块内部登记。

生产和售后来源 Feed 必须对更正输出 `REVERSE`，替代事实再输出 `ACCRUE`。归集失败不回滚上游事实，但必须记录失败并幂等重试，当前页未全部成功不得推进游标。

## 7. 资金管理子域

### 7.1 业务规则

1. 现金事实必须包含账户、方向、业务日期、币种和金额。
2. 一笔现金可以分配到多个来源，分配合计必须严格等于现金金额。
3. 订单和售后收付资格由 `orders` 决定，cash 子域不得复制其规则。
4. 工资支付资格由 payroll 子域的员工应付决定。
5. 同一来源累计收付不得超过允许金额。
6. 现金事实不可编辑，错误通过冲销或差额事实更正。
7. 账户余额是可重建投影，对账差异不允许静默改余额。

### 7.1.1 现金公式

```text
账户余额
= 期初余额 + 有效现金流入合计 - 有效现金流出合计

订单净收款
= 订单有效收款合计 - 订单有效退款合计

来源累计已分配现金
= 该来源有效现金分配合计

单笔现金分配合计
= 现金事实金额
```

期初余额必须来自可审计的期初余额事实；冲销只通过新的反向现金事实改变有效余额，不直接修改原流水。收款资格和退款资格由 `orders` 返回，cash 不自行推导；工资支付资格由 payroll 返回。任何来源累计收付超过允许金额、币种不一致或现金分配不守恒都必须拒绝。

## 8. 关键业务流程

### 8.1 工资封账

```text
锁工资期间和来源守卫
→ 固化有效来源和计算结果
→ 写员工应付及封账事实
→ costledger 内部登记 DIRECT_LABOR
→ 一次提交
```

### 8.2 工资支付

```text
锁工资员工结果
→ 校验剩余应付
→ 锁账户和来源现金投影
→ 写现金事实与工资支付分配
→ 更新已付金额、工资状态和余额
→ 一次提交
```

### 8.3 订单及售后收付

```text
finance 开启事务
→ orders participant.prepare 锁业务义务并返回允许金额
→ 锁账户和来源现金投影
→ 写现金事实和分配
→ orders participant.commitPaymentLink
→ 更新余额并一次提交
```

### 8.4 经营费用支付

```text
校验费用、金额和凭证
→ 锁账户和成本来源守卫
→ 写现金支出
→ costledger 内部写 OPERATING_EXPENSE
→ 建立现金与成本关联并更新余额
→ 一次提交
```

### 8.5 成本归集

```text
取得 Feed 租约和游标
→ 读取生产或售后不可变来源
→ 解析历史快照或来源金额
→ 调用计算中心计算和舍入
→ 写成本事实、分摊和来源守卫
→ 全页成功后推进游标
```

## 10. 事务、锁序和并发

- 工资封账：期间 → 来源守卫 → 员工结果 → 成本来源守卫；
- 工资支付：员工应付 → 账户 → 来源现金投影 → 现金事实和分配；
- 订单/售后收付：orders 义务 → finance 账户 → 来源现金投影 → 现金事实 → orders 支付关联；
- 经营费用：账户 → 成本来源守卫 → 现金事实 → 成本事实；
- 成本归集：游标/租约 → 来源守卫（稳定标识升序）→ 原成本事实 → 新成本事实；
- 冲销：原现金事实 → 来源义务/应付 → 账户和投影 → 冲销事实；
- 同账户并发收付由账户投影行锁串行化；
- 多来源现金命令先完成全部外部 prepare，再写任何现金事实；
- 死锁只重试整个幂等命令，不能局部重试 SQL；
- 任一步失败时，同事务内工资、成本、现金和外部支付关联全部回滚。

### 11.1 财务结算交互原型基线

> 整理日期：2026-10-09。页面入口：[财务结算原型](../../finance-element-plus.html)。本节记录用户已经确认的页面操作与当前演示边界；正文的账户、统一封账等设计内容不能直接当成原型已实现能力。

#### 11.1.1 一级入口与本期页面取舍

| 入口 | 展示内容 | 可操作项 |
|---|---|---|
| 月度汇总（默认） | 所选月实际收入、实际支出、资金净额、成本合计、待核定提示；现金及成本分类 | 选择月份、上月 / 下月 / 本月、查看分类与全部明细、定位来源 |
| 工资结算 | 每位员工在核算期间的系统参考、实际核定、已付 / 待付与状态 | 新增期间、逐人核算、查看已核定结果、登记工资付款 |
| 成本台账 | 来源、分类、归集对象、业务日期、计价依据、金额、有效性 | 搜索、分类 / 状态筛选、重置、查看来源与计价明细 |
| 资金收付 | 实际现金流水、业务来源、日期、金额、记录状态 | 登记工资付款、登记日常收支、搜索筛选、详情、符合条件的冲销 |

- **本期原型没有资金账户。**不选择账户，不提供账户维护、开户余额、转账或账户余额页面；筛选条件采用组合布局，不要求一行只放一个条件。
- **系统计算的工资金额只是参考标准，不是确定金额。**实际工资逐人填写、核对、确认；未核定不得付款。
- **订单收款和退款回到订单详情登记。**财务只共享显示对应流水及原记录凭证，不重复创建订单收付。
- 月度汇总放在财务结算内，日常经营收支在“资金收付 → 登记日常收支”记录，不要求跳去独立报表或账户模块。

#### 11.1.2 逐人核定工资

| 页面 / 字段 | 当前原型规则 |
|---|---|
| 核算期间 | 期间名称、起止日期；名称不重复，日期有效，不与已有期间重叠 |
| 员工列表 | 员工及编号、核算期间、系统参考、实际核定、已付 / 待付、待核定 / 已核定；按员工、期间、状态筛选 |
| 系统参考 | 展示示例劳动来源、完成数量、未完成数量、历史人工单价和到人参考；待核定可刷新来源 |
| 实际核定金额 | 由用户人工填写，不默认将参考值当成实发；非负，最多两位小数，不超过 999999.99 元 |
| 核定说明 | 必填，最多 200 字符；与确认时的参考来源一起保留 |
| 确认预览 | 核对该员工的参考、人工金额和说明；返回修改或确认该员工 |

```text
新增核算期间 → 形成每位示例员工的待核定记录
  → 打开一个员工 → 核对来源与参考 → 人工填写金额和说明
  → 核对并确认该员工 → 形成已核定结果及对应人工成本
  → 另行登记实际工资付款
```

- 新建期间不生成确定应付；确认一位员工不自动确认整个期间或其他员工。
- 完成数量取示例核验结果中的合格、返工、报废及转线下数量；未完成数量不计参考。小组参考按冻结成员示例均分，分尾差按员工编号分配。
- 制作超额激励公式尚未明确时不编造参考金额；责任来源提示人工核实，不自动扣款；小组效率不参与金额计算或分钱。
- 来源或核定内容变化后需重新核对；确认保留参考快照、人工金额、说明和确认时间，原型不提供已核定结果直接重算覆盖的操作。
- 正数核定同时增加一笔人工成本，零金额确认不生成成本；**核定不等于付款**，不增加现金支出。
- 当前员工与劳动 / 责任来源是财务页面的示例，不自动取得人员原型新增员工或生产原型新任务。

#### 11.1.3 工资付款与来源分配

| 字段 | 当前原型规则 |
|---|---|
| 业务类型 | 仅工资付款；订单收退款不在此选择 |
| 业务日期 | 用户选择，有效且不晚于当天，不早于关联员工核定来源的可付款日期 |
| 实际付款金额 | 大于零，最多两位小数，不超过 999999.99 元 |
| 来源分配 | 选择 1 至 10 项已核定且有待付的员工来源，不重复；每项金额大于零、不超过该员工待付；合计严格等于本次付款 |
| 备注与凭证 | 备注最多 200 字符；凭证随本条工资付款记录保存 |

- 可以从某员工进入付款，也可一次向多个已核定员工分配本次实际付款；一次流水并不把工资核算变成集体确认。
- 允许部分支付，已付 / 待付由有效付款与反向记录计算；同一人工成本不因分次支付重复产生。
- 先核对本次现金金额、每位员工分配和凭证，再确认登记；实际现金支出按用户选择的业务日期统计。

#### 11.1.4 日常经营收支录入

| 字段 | 当前原型规则 |
|---|---|
| 收支方向 | 日常支出或日常收入，切换方向重新选择分类 |
| 分类 | 支出示例含房租、水电 / 网络、日常运费、办公 / 日常用品、其他日常支出；收入含废旧物品处理、补贴、其他日常收入 |
| 登记日期 | 默认当天但可以选择历史日期，不晚于当天；用于这条收支和关联费用的月份归属 |
| 实际金额 | 大于零，最多两位小数，不超过 999999.99 元 |
| 用途说明 | 必填，最多 200 字符 |
| 收支凭证 | 跟随本条记录上传与查看，不放到独立凭证池让用户再次关联 |
| 同时计入经营费用 | 仅支出显示，默认不勾选；只在费用尚未归集时选择，避免重复计成本 |

```text
资金收付 → 登记日常收支
  → 选择方向、分类、日期，填写实际金额和用途，附本次凭证
  → 支出可选择同时计入经营费用
  → 核对 → 确认登记
  → 在流水及所选日期的月度汇总中查看
```

- “生成资金流水”是保存同一条日常收支后形成查询记录，不是让用户去另一个表单再录一次付款。
- 不勾选经营费用只记录现金；勾选时同时形成关联费用，两者使用所选日期归属同月，可以互相定位。
- 日常收入不形成经营费用；订单、工资、材料和售后专属业务不能借日常分类绕过来源规则。
- **最终口径是选择日期，不是录入时刻决定月份。**例如 10 月补录 9 月的收支，选择 9 月日期就进入 9 月；系统另存录入时间以区分。
- 日常费用联动保存使用同一份本地状态，写入成功后才更新页面；这不等于正式数据库跨子域事务已经实现。

#### 11.1.5 凭证与冲销

- 订单收退款、工资付款和日常收支共用 `payment-vouchers.js`。每条最多 3 份 JPG、PNG、WebP 或 PDF，单份不超过 300KB；当前本地数据还有总容量保护。
- 凭证属于具体收付流水，详情展示本条附件；关联成本可以定位付款及其凭证，无需再上传一套。
- 当前支持上传但允许空附件；正式哪些收付必须附凭证，不能默认为已经校验必传。
- 上传仅是在本地读取文件并保存内容，没有正式附件服务器、权限下载、扫描或备份。
- 冲销填写原因，追加相反方向的现金事实，原记录不删除；不允许再次冲销同一原流水或冲销反向事实。
- 已联动经营费用的日常支出，冲销同时追加负数费用更正；原成本保留，不能只撤现金而留下错误费用。
- 订单关联流水的冲销交给订单共享脚本校验，同步订单净收款；工资付款冲销只回退已付，不重新核定工资。
- 当前冲销反向记录使用当天作为业务日期，没有独立冲销日期选择；原凭证从被冲销记录追溯，不复制为新付款凭证。

#### 11.1.6 月度汇总口径与明细追溯

| 汇总 | 当前内容与计算口径 |
|---|---|
| 月份 | 默认当月，可选历史月及上月 / 下月 / 本月，不允许未来月 |
| 实际资金收支 | 只取所选月业务日期内的有效现金事实；收入、支出分别求和，资金净额为收入减支出 |
| 收支分类 | 订单实际收款、日常收入、工资付款、材料付款、售后付款、订单退款、经营支出、其他支出及冲销流入 / 流出 |
| 当月发生的成本 | 按成本业务日期统计有效人工、材料、售后、经营费用、调整及其他成本，包含负数更正 |
| 人工成本 | 取逐人实际核定金额，不取系统参考；成本日期按原型核定成本记录，不简单等同付款日期 |
| 材料成本 | 材料耗用成本与材料采购付款分列，不因付款就认定已经耗用 |
| 分类明细 | 点击分类或全部明细查看编号、发生日期、来源 / 说明、金额，再定位流水、成本或订单 |

- **资金净额不叫利润；成本合计也不是现金支出合计。**工资核定月和付款月可能不同，不能把工资参考、应付、成本和实际付款相加重复计算。
- 订单本月实收不是本月全部订单成交金额；退款和冲销单独展示。反向流水按反向记录业务日期进入相应月份，不回改原月记录。
- 材料与售后分类有展示槽位，不代表已提供材料采购或售后付款的专属新增页面；缺少来源时不虚构金额或说明这些业务已实现。
- 成本台账展示计价明细、来源版本与有效性；部分材料和其他成本仍为内置示例，不随生产原型操作真实更新。

## 12. 验收标准

- 个人和小组工资计算使用冻结来源，且小组分配合计严格守恒；
- 小组效率不进入工资金额和分配权重；
- 封账同时形成员工应付和人工成本，任一步失败全部回滚；
- 生产劳动、生产责任和生产/售后成本来源重复消费均不重复入账，失败可重试且各自游标不跳过；
- 责任来源更正按照 `REVERSE` 原版本、`APPLY` 新版本更新本地投影；已封账结果通过后续期间补差，不重开原期间；
- 财务完整保留员工、小组、工作室、客户和免除责任来源，但接收来源时不预设扣款金额；
- 客户供料标准价值可查询，但不登记为工作室实际成本；
- 工资、成本和现金事实不能互相替代，均可独立追溯；
- 超过订单、售后或工资允许金额的收付被拒绝；
- 经营费用支付同时形成现金和成本，失败不留下部分数据；
- 冲销后工资已付、来源汇总、账户余额和历史链正确；
- payroll、costledger、cash 不直接访问彼此 Repository；
- `finance` 不复制订单、生产、商品和人员模块的规则或当前数据。
