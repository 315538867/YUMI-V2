# 报表模块

> 模块代码：`reporting`

## 1. 模块说明

报表模块通过各业务模块公开的只读数据源建立可重建投影，用于经营看板、统计和对账。报表不是业务事实来源，任何业务命令不得依赖报表结果作权威判断。

## 2. 一期需求、报表范围与模块功能

- 订单履约：数量、发货、收款和完成；
- 生产进度：需求、在制、合格、不合格和报废；
- 作业负载：个人/小组标准秒数、有效秒数和评估结果；页面展示时格式化为分钟；
- 小组效率：按人数和实际任务的计划/完成对比；
- 售后：受理、未完成义务、处理时长和金额；
- 工资：期间人数、系统参考、实际核定、人工补差、应付和支付，参考不计入成本；
- 成本：订单/商品/期间分类成本；
- 现金：按日期、业务类型的实际流入、流出和净额；一期无账户余额；
- 工资款实际退回按退回业务日期单列现金流入，保留原付款月份的流出；只取 finance 公开事实，不把退回重复计为经营收入或负人工成本，成本变化以独立人工调整事实为准；
- 订单利润：收入、成本、售后成本和毛利；
- 数据对账：来源事实与报表投影差异。

## 3. 模块边界

- 各业务模块按稳定业务子域提供 `changedSince(cursor, limit)` 类型的公开数据源；游标类型、全序规则和更正语义由来源 Feed 拥有，报表只把返回的下一游标作为不透明值保存；
- 报表不得读取其他模块数据库表，不得要求开放 Repository；
- 报表只拥有自己的水位、重建批次、差异和投影表；
- 报表延迟或失败不能阻止业务写入；
- 页面涉及操作资格时必须回到业务模块实时查询。

## 4. 更新规则

- 每个来源 Feed 必须提供稳定全序和可续读游标；游标内部可以使用时间、业务标识和版本组合，但对报表模块保持不透明；
- 水位只在整批成功后推进；
- 同一投影同一来源仅一个 worker 持有租约；
- 重复、乱序和来源更正必须幂等处理；
- 全量重建写影子版本，核对通过后切换；
- 删除投影后可从公开数据源重建；
- 页面显示最新成功时间和延迟状态。

### 4.1 指标计算来源与公式边界

报表只做公开结果的筛选、分组、聚合和展示，不重新实现订单、生产、计算中心或财务公式。每个指标必须标注来源模块、来源版本和计算时间；来源模块没有提供权威口径时，报表不得自行补一个“看起来合理”的公式。

一期统一按以下方式取数：

| 报表指标 | 权威来源 | 报表允许的处理 | 禁止的处理 |
|---|---|---|---|
| 订单当前应收、有效发货、净收款、交付/付款履约 | `orders` 公开查询或 `OrderReportingFeed` | 按日期、客户、订单分组汇总 | 用现金流水反推应收，或用任务数量反推发货 |
| 生产需求、在制、合格、不合格、报废、转线下库存 | `production` 数量投影或 `ProductionReportingFeed` | 按商品、订单、需求类型和日期分组 | 从任务计划数量自行推导生产事实 |
| 个人/小组标准秒数、有效秒数、评估结果 | `production` 已保存的计算结果 | 按主体、日期和任务类型汇总，页面格式化展示为分钟 | 在报表再次乘数量、除效率或重算剩余时间 |
| 工资参考、实际核定、直接材料、经营费用和实际现金收支 | `finance` 对外投影或独立的 `PayrollReportingFeed`、`CostReportingFeed`、`CashReportingFeed` | 按期间、订单、分类和业务日期汇总；工资参考不计应付或成本 | 使用当前商品价格、当前工资标准或当前公式回算历史金额；合并工资、成本、现金为一个未定义的通用 Feed |

线上报废与实物去向必须分列或交叉展示：线上报废可以分为实际销毁、报废转线下；全部转线下还包括未报废的业务移交。线上报废与全部转线下存在交集，不能相加成“总损失”或物理退出量。物理守恒只使用系统内、已消费、实际销毁、已转线下四个互斥分量；唯一退出标识用于去重。报废转线下仍显示报废责任及逐项成本参考，不显示或推测线下售价、销售利润或库存余额。工资敏感查询可展示负责人填写的处理明细和最终核定工资，但不得把参考行或处理金额重新汇总成系统认定的应扣款、实际成本或现金；月度人工成本仍只读取实际工资核定及有效差额调整。

订单利润展示必须区分三种口径：订单当前有效应收、订单净收款和财务已归集成本；三者不能互相替代。只有当订单收入和各类成本都有可追溯的来源关联时，才允许展示：

```text
订单可归集利润
= 当前有效应收金额 - 订单已归集成本

订单可归集利润率
= 订单可归集利润 ÷ 当前有效应收金额
```

当前有效应收金额为 0 时利润率返回空。经营费用尚未形成明确的订单分摊事实时，不得把期间经营费用平均摊入订单利润；报表应显示“未包含经营分摊”或只展示已归集成本。报表中的利润属于派生展示结果，不是新的财务事实，也不得被其他业务命令反向引用。

一期的“小组效率”报表只展示 `calculation` 已返回并由 `production` 保存的安排数量、完成数量、个人基准秒数、小组标准秒数和效率因子；时间在展示层转换为分钟，不改变保存值和汇总值。一期不定义“完成量反推实绩效率率”或“按成员产量计算效率率”的新公式。后续如需新增效率率，必须先在计算中心和人员/生产模块完成独立业务确认。

## 5. 数据模型与表设计

### 5.1 管理表

| 表 | 类别 | 关键字段 | 关键约束与索引 |
|---|---|---|---|
| `reporting_projection_versions` | 投影版本 | `projection_code, projection_version, status, build_batch_business_id, activated_at, retired_at, row_version` | `PK(projection_code, projection_version)`, `IX(projection_code, status)` |
| `reporting_active_projection_versions` | 活动指针 | `projection_code, projection_version, switched_at, row_version` | `PK(projection_code)`，每个投影只有一个活动指针 |
| `reporting_watermarks` | 水位 | `projection_code, projection_version, source_feed_code, provider_module, cursor_value, cursor_schema_version, last_occurred_at, last_success_at, lag_seconds, status, row_version` | `PK(projection_code, projection_version, source_feed_code)` |
| `reporting_projection_leases` | 投影租约 | `projection_code, projection_version, lease_owner, lease_until, row_version` | `PK(projection_code, projection_version)` |
| `reporting_rebuild_batches` | 运行记录 | `batch_business_id, projection_code, projection_version, rebuild_type, status, processed_count, error_count, started_at, finished_at` | `UK(batch_business_id)`, `UK(projection_code, projection_version)` |
| `reporting_rebuild_batch_sources` | 重建来源 | `batch_business_id, source_feed_code, start_cursor, end_cursor, processed_count, status` | `PK(batch_business_id, source_feed_code)` |
| `reporting_reconciliation_runs` | 对账记录 | `run_business_id, reconciliation_code, business_date, source_fingerprint, projection_fingerprint, status, started_at, finished_at` | 对账代码/日期/来源指纹唯一 |
| `reporting_reconciliation_differences` | 差异 | `difference_business_id, run_business_id, dimension_key, source_value, projection_value, difference_value, severity, status, resolution_note` | `UK(difference_business_id)` |

### 5.2 业务投影

| 表 | 主键/维度 | 核心指标 |
|---|---|---|
| `report_order_fulfillment_daily` | 日期、订单 | 应收、数量、发货、收款、履约状态 |
| `report_production_progress_daily` | 日期、商品、需求类型 | 需求、在制、合格、不合格、报废 |
| `report_production_workload_daily` | 日期、主体 | 标准秒数、有效秒数、已安排标准秒数、评估结果 |
| `report_team_efficiency_daily` | 日期、人数 | 安排数量、完成数量、个人基准秒数、小组标准秒数、效率因子 |
| `report_after_sales_daily` | 日期、案例类型 | 新增、完成、待处理、金额 |
| `report_payroll_period_summary` | 工资期间 | 待核定/已核定人数、系统参考及完整性、实际核定、人工补差、应付、已付和待付 |
| `report_order_cost_summary` | 订单 | 直接材料、人工、经营分摊、售后、总成本 |
| `report_cash_flow_daily` | 业务日期、业务类型 | 有效流入、流出、现金净额；无账户与期初余额 |
| `report_order_profit_summary` | 订单 | 当前有效应收、已归集成本、可归集利润、可归集利润率 |
| `report_reconciliation_summary` | 日期、对账代码 | 检查数、差异数、未解释差异数 |

所有业务投影包含 `projection_version`、`source_checkpoint_fingerprint` 和 `updated_at`，业务维度唯一键必须同时包含 `projection_version`。这样旧版本与影子重建版本可以并存，切换失败时仍可继续读取原活动版本。

## 6. 公开接口设计

```java
interface ReportingQuery {
    ReportPage query(ReportCode code, ReportCriteria criteria);
    ReportingFreshness getFreshness(ReportCode code);
}
interface ReportingAdministrationService {
    RebuildRef rebuild(RebuildProjectionCommand command);
    ReconciliationRef reconcile(RunReconciliationCommand command);
}
```

各来源模块提供自己的 `ReportingFeed`，并定义 Feed 专属游标和值对象。一个顶层模块可以按内部子域提供多个 Feed；一期至少包括：

- `CustomerReportingFeed`；
- `ProductReportingFeed`；
- `WorkforceReportingFeed`；
- `ProductionReportingFeed`；
- `OrderReportingFeed` 和 `AfterSalesReportingFeed`，均由 `orders` 提供；
- `PayrollReportingFeed`、`CostReportingFeed` 和 `CashReportingFeed`，均由 `finance` 提供。

报表模块不向来源模块输出 `ReportingCursor` 公共类型，也不定义通用数据库读取接口，避免业务模块反向依赖 `reporting`。水位以 `projection_code + projection_version + source_feed_code` 区分同一投影版本消费的不同 Feed，不能只按 `source_module` 保存。

## 7. 事务、并发与历史

- 单批拉取、投影写入和水位推进在同一事务中完成；任一行失败，本批水位不得推进。
- 同一 `projection_code + projection_version` 通过 `reporting_projection_leases` 保证同一时刻只有一个 worker；worker 按稳定的 `source_feed_code` 顺序处理各来源，避免多个 Feed 并发覆盖同一投影行。
- 重建写入独立影子版本，完成对账后锁定 `reporting_active_projection_versions` 并以短事务切换活动指针；失败时继续使用旧版本。
- 来源事实发生更正或失效时，以来源业务标识和版本幂等重放，不直接覆盖来源历史。
- 报表投影可删除重建；水位、重建批次和对账差异作为报表自身追溯记录保留。

## 8. 权限、页面和错误

权限按内容拆分：`report.order.read`、`report.production.read`、`report.after-sales.read`、`report.payroll.read`、`report.cost.read`、`report.cash.read`、`report.admin`。工资、成本和现金继续受敏感资源范围限制。

页面：经营总览、各主题报表、数据时效提示、对账差异、重建管理。

错误码：`REPORT_CODE_INVALID`、`REPORT_CRITERIA_INVALID`、`REPORT_PROJECTION_LAGGING`、`REPORT_REBUILD_ALREADY_RUNNING`、`REPORT_SOURCE_QUERY_FAILED`、`REPORT_RECONCILIATION_DIFFERENCE`。

### 8.1 现有原型中的汇总入口

> 整理日期：2026-10-09。目前没有独立报表 HTML 原型；不能将正文列举的全部报表页视为已经完成。

- 用户确认的“按月查看人工、材料、售后成本、订单收入和日常收支”放在 [财务结算原型](../../finance-element-plus.html) 的“月度汇总”，详细页面、计算口径和明细入口见 [财务结算模块第 11.1 节](13-财务结算模块.md#111-财务结算交互原型基线)。
- 月度汇总分别展示实际现金收支和成本，不叫利润；没有资金账户选择，不增加独立月度报表录入表单。
- 汇总查看分类及来源明细；订单收退款从订单详情记录，日常收支从财务资金收付记录，汇总页不重复录入业务事实。
- 当前汇总基于财务本地原型与共享订单示例，未实现 reporting 的数据源消费、水位、投影重建、跨模块对账或正式利润报表。
- 生产原型的整体 / 工序进度及需求缺口也属于示例展示，不构成已经实现的正式 reporting 投影。

## 9. 验收标准

- 报表 SQL 只访问 reporting 自有表；
- 重复和乱序数据不会重复累计；
- 失败批次不推进水位；
- 全量影子重建不影响在线旧投影；
- 投影与来源可自动对账并定位差异维度；
- 删除投影后可重建一致结果；
- 报表延迟明确显示；
- 业务模块不依赖 reporting。

## 10. 待确认问题

本模块当前无阻塞一期开发的结构问题；各报表具体列顺序和导出样式属于页面详细设计。
