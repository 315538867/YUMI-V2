# 页面交互统一施工清单（P1）

目标：全站页面使用同一套查询、分页、状态和详情/编辑骨架。规则以 `DESIGN.md` 和
`frontend-standards.md` 为准，本文件记录施工项、验收和明确不做项。

## 1. 统一规则

### 1.1 页面骨架

- 工作区页面统一白底卡片：`1px` 浅边框、圆角 `8px`、内边距 `16px`。
- 页面标题使用 `h1`，18px/600；标题右侧只放当前页主动作。
- 详情页默认只读；新建、编辑、收款、发货等显式按钮进入，不在详情内直接切换编辑态。
- 长表单使用整页（新建/编辑路由），短命令使用弹窗。

### 1.2 列表查询

- 统一工具条：关键词、状态、`查询`、`重置`、主新增动作；由 `ListPage` 外壳统一渲染标题、工具条与分页插槽。
- 查询条件、页码、每页条数写入 URL：`keyword`、`status`、`page`、`size`。
- 页码从 1 开始；默认 `size=20`，可选 20/50/100。
- 刷新、分享链接、浏览器前进/后退后恢复相同查询结果。
- 后端统一 `page` 从 1 开始；未提供分页的接口全量加载，不伪造总数。

### 1.3 状态

- 统一使用 `PageState`（新）：加载覆盖数据区、失败显示中文错误 + 重试、空态说明原因。
- 表格空态用 `empty-text`，文案说明“为什么空”；查询无结果写“没有匹配的…”。
- 失败时保留上次数据，不整页白屏；重试只重跑当前查询。

## 3. 验收

- 刷新带查询参数的 URL，筛选条件、页码、结果一致。
- 浏览器后退/前进能恢复上一条查询。
- 查询无结果、接口失败、首次加载三种状态表现一致，失败可重试。
- 详情页无就地编辑；编辑入口进入整页，保存后回到详情并刷新。
- E2E 覆盖：客户编辑整页、订单列表分页、URL 刷新恢复、空态。
- lint、format、typecheck、unit、build、E2E 全部通过。

## 4. 明确不做

- 不补后端未提供的分页接口（员工、小组、缺陷原因等）；先全量加载，接口补齐后接入。
- 编辑页由 `EditorPage` 统一承载 `PageState`：加载时遮罩，失败时显示重试但不隐藏已加载表单；字段错误仍内联，不弹 toast。
- 不改业务字段、权限模型和金额计算。
- 不重做视觉主题；沿用 P3 的 `DESIGN.md` 与令牌。

### 生产整体进度口径

- 真实需求：未取消需求的 `requiredQuantity` 合计。
- 已排班：首个工序有效任务（未取消）的计划数量，按需求封顶；首个工序按目标工序确定：制作→制作，捏毛装袋→捏毛装袋，缝边剪袋→制作。
- 生产事实：首个工序已处理完成数量（含返工与报废），按需求封顶。
- 已完成履约：订单项投影的 `fulfilledQuantity` 合计。
- 待完成：真实需求 - 已完成履约，包含在制、目标就绪与履约缺口。
- 工序进度：需求只统计经过该工序的目标链；已排班为该工序有效任务计划量，已完成为该工序核验合格数量，均按需求封顶；待完成 = 需求 - 已完成。
