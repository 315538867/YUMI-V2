# YUMI 前端设计契约（DESIGN.md）

本文件是页面视觉与交互的可执行契约。代码里的令牌在 `frontend/src/platform/theme/tokens.css`，
码表在 `frontend/src/platform/display/domain-codes.json`；两者与本文件冲突时，以本文件为准并同步修改代码。

## 1. 产品定位

- 面向工作室内部的全白常规后台，重点是可读、可核对、可连续操作。
- 页面由“浅灰底 + 白色工作区”构成，不使用大面积品牌色块、渐变背景或装饰性插画。
- 信息密度优先：一屏内优先呈现业务字段、金额、数量与状态，不用卡片堆叠代替表格。

## 2. 色彩

| 令牌 | 值 | 用途 |
|---|---|---|
| `--el-color-primary` | `#2563eb` | 主按钮、链接、选中态 |
| `--el-color-primary-light-9` | `#e9effd` | 选中行、轻量高亮底色 |
| `--el-color-success` | `#15803d` | 成功、已完成、启用 |
| `--el-color-warning` | `#b45309` | 待处理、部分完成、风险提醒 |
| `--el-color-danger` | `#b91c1c` | 失败、报废、错误 |
| `--el-color-info` | `#5f6673` | 中性、已取消、辅助信息 |
| `--el-text-color-primary` | Element Plus 默认 | 正文与数值 |
| `--el-text-color-secondary` | `#5f6673` | 说明、辅助字段 |
| `--el-text-color-placeholder` | `#6b7280` | 输入占位 |
| 页面背景 | `#f7f8fa` | 内容区底色 |
| 工作区背景 | `#ffffff` | 页面卡片、侧栏、顶栏 |

规则：

- 状态色只用于标签、图标和小面积强调，不整行、整卡铺色。
- 所有文字与背景对比度至少 4.5:1；主色、成功、警告、危险、辅助文字均已按此校验。
- 业务页面禁止写死十六进制色值；新颜色先加到 `tokens.css`，再更新本表。

## 3. 字体与层级

| 场景 | 字号 | 字重 |
|---|---|---|
| 首页大标题 | 20px | 600 |
| 工作区页标题 `h1` | 18px | 600 |
| 顶栏当前页名 | 15px | 600 |
| 区块标题 `h2` | 16px | 600 |
| 正文、表格、表单 | 14px | 400 |
| 辅助说明、时间、单位 | 13px | 400 |

- 中文使用系统默认无衬线字体，不引入第三方字体。
- 金额、数量、日期使用等宽感呈现由组件负责，页面不自造格式。
- 标题与正文之间不叠加多余空行；区块间距统一 20px。

## 4. 间距与布局

- 间距刻度：4 / 8 / 12 / 16 / 20 / 24px。
- 应用外壳：侧栏 `216px`，顶栏 `56px`，内容区 padding `20px`。
- 工作区卡片：白底、`1px` 浅边框、圆角 `8px`、内边距 `16px`。
- 工具栏：横向单行，控件间距 `8px`，距表格 `12px`；窄屏才换行。
- 表单：默认单列；商品设置等宽表单可用三列，列间距 `16px`，控件不拉伸填满。
- 表格：撑满工作区宽度，`border` 样式；金额列右对齐，状态列居中或左对齐。
- 弹窗：只用于短命令（收款、更正、确认），长表单必须使用整页。

## 5. 组件规则

| 组件 | 规则 |
|---|---|
| `el-button` | 每个区域最多一个主按钮；删除/作废用危险色；权限入口用 `PermissionButton` |
| `el-table` | 必须提供 `empty-text`；加载用 `v-loading`；不手写斑马纹 |
| `el-tag` / `CodeTag` | 状态、类型、工序一律走码表，不直接输出编码 |
| `el-form` | 字段校验内联展示；接口错误统一 toast；提交中禁用按钮 |
| `el-empty` | 空态文案说明“为什么空、下一步做什么”，不只写“暂无数据” |
| `el-alert` | 只用于页面级阻断或批量提示；字段错误不放进 alert |
| `el-tabs` | 详情页关联内容用页签，不用多张卡片纵向堆叠 |
| 金额/时间 | 只用 `MoneyText` / `DateTimeText` |

## 6. 交互与状态

- 详情页默认只读；新建、编辑、收款、发货、完成等操作由显式按钮进入。
- 列表筛选条件与当前页保持同步；刷新后不丢筛选（P1 待补齐 URL 查询参数）。
- 加载态覆盖数据区域，不整页白屏；失败时保留上次数据并给出重试入口。
- 破坏性操作必须二次确认，确认文案写明对象、数量和影响。
- 成功提示只出现一次；失败不得伪装成功。

## 7. 无障碍

- 所有输入、下拉、日期控件必须有可见标签或 `aria-label`；placeholder 不能替代名称。
- 键盘可完成主要流程；焦点可见；弹窗打开后焦点进入弹窗，关闭后回到触发按钮。
- 图标按钮必须有中文 `aria-label`；纯装饰图标对辅助技术隐藏。
- 表格表头与数据列语义正确；不使用颜色作为唯一状态表达。
- 门禁：`frontend/e2e/accessibility.spec.ts` 对登录页与 11 个主要业务页执行 axe（WCAG 2.1 A/AA），严重与致命问题必须为 0。

## 8. 视觉回归

- 基线目录：`frontend/e2e/visual.spec.ts-snapshots/`。
- 覆盖稳定页面：登录、经营总览、订单空态、商品空态；业务数据页不进入基线。
- 截图前冻结动画、固定视口 `1280×800`，容差 `maxDiffPixelRatio: 0.01`。
- 基线按操作系统命名（如 `*-chromium-darwin.png`）；换平台需重新生成并在评审中说明。
- 有意修改视觉时：先改令牌/页面，再运行 `pnpm exec playwright test e2e/visual.spec.ts --update-snapshots`，并在提交中附截图差异说明。

## 9. 变更流程

1. 先改 `tokens.css` 或码表，再改页面。
2. 同步更新本文件对应表格。
3. 运行 lint、format、typecheck、unit、build、E2E；无障碍与视觉回归必须通过。
4. 视觉变更需在提交信息里写明影响页面与基线更新原因。
