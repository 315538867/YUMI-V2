# 报表模块详细设计

> 模块：`reporting`　状态：已完成技术一致性审查，待 G0 多方签字冻结　版本：v1.0　日期：2026-09-29　实施阶段：G12

## 1. 边界

`reporting` 只拥有报表投影、水位、重建批次和对账差异，不拥有任何业务资格、余额、状态或完成事实。它只能调用其他模块公开查询；禁止直接读取其他模块表、调用 Repository 或参与业务写事务。

低频详情可实时组合公开查询；列表、趋势和经营分析读取 reporting 自有投影。投影故障不能阻断业务命令。

## 4. 更新与重建

平台提交后任务按模块登记 `reporting.refresh.{projectionCode}`，任务只携带来源游标范围，不携带完整业务对象。每个来源模块必须在自己的 named interface 暴露 `ReportingFeedQuery.changedSince(cursor, limit)` 只读能力，稳定游标固定为 `(occurredAt, businessId, version)`；worker 调用该公开查询并幂等 upsert 自有投影，禁止以“报表需要”为由开放 Repository 或跨模块 SQL。

- 同一投影同一来源仅一个增量 worker 持有租约；
- 水位只在整批成功后推进；
- 单批失败不部分推进水位；
- 全量重建写入影子投影，核对通过后原子切换版本；
- 业务页面超出 5 分钟时显示“数据延迟”，并提供有权限的重建入口。

## 5. 公开契约与 HTTP

```java
public interface ReportingQuery {
    ReportPage query(ReportCode code, ReportCriteria criteria);
    ReportingFreshness getFreshness(ReportCode code);
}
public interface ReportingAdministrationService {
    RebuildBatchRef rebuild(RebuildProjectionCommand command);
    ReconciliationRunRef reconcile(RunReportingReconciliationCommand command);
}
```

HTTP：`GET /api/v1/reports/{reportCode}`、`GET /api/v1/reports/{reportCode}/freshness`、`POST /api/v1/reporting/projections/{code}/rebuild`、`POST /api/v1/reporting/reconciliations/{code}`。

权限按报表拆分：`reporting.order.read`、`reporting.production.read`、`reporting.scheduling.read`、`reporting.after-sales.read`、`reporting.payroll.read`、`reporting.cost.read`、`reporting.finance.read`、`reporting.admin`。工资、成本和现金报表继续受敏感资源范围限制。

错误码：`REPORT_CODE_INVALID`、`REPORT_CRITERIA_INVALID`、`REPORT_PROJECTION_LAGGING`、`REPORT_REBUILD_ALREADY_RUNNING`、`REPORT_SOURCE_QUERY_FAILED`、`REPORT_RECONCILIATION_DIFFERENCE`。

## 6. 验收

Flyway 使用 `V090-V099`。必测：增量幂等、水位不越过失败批次、重复任务、乱序来源、来源更正、全量影子重建切换、差异定位、5 分钟时效告警、日终 30 分钟目标、权限脱敏、业务模块不可依赖 reporting、reporting 无跨模块 SQL。
