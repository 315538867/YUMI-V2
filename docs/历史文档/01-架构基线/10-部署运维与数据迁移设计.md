# YUMI V2 部署运维与数据迁移设计

> 状态：已完成技术一致性审查，待 G0 多方签字冻结　版本：v1.0　日期：2026-09-29　适用阶段：G0/G1/G13/G14

## 1. 环境与拓扑

环境固定为 `local`、`test`、`staging`、`production`。生产拓扑包含：前端静态资源、至少两个无状态应用实例、MySQL 8.4 主实例及备份存储、S3 兼容对象存储、日志/指标/链路采集和受控迁移任务。定时 worker 与 HTTP 应用可同镜像不同进程角色运行。

应用镜像不可变；配置、证书和密钥由环境注入。生产数据库、对象存储和备份使用不同凭证；开发不得使用生产数据或密钥。

## 2. 配置与密钥

必需配置组：数据库 URL/账号/连接池、会话空闲 8 小时/最长 7 天、BCrypt cost 12、对象存储、文件限制、提交后任务租约与重试、日志采样、OpenTelemetry、报表 worker、备份位置和迁移开关。

密钥不进入 Git、镜像、日志和错误响应。轮换数据库或对象存储密钥必须支持双凭证过渡；会话签名或加密密钥轮换必须明确旧会话失效策略。

## 3. 发布流程

1. CI 完成后端/前端测试、Modulith、ArchUnit、SQL 所有权、空库 Flyway 和镜像扫描；
2. staging 从生产结构副本执行迁移与回归；
3. 生产发布前创建恢复点并验证备份可读；
4. 独立迁移任务先执行向前兼容迁移；
5. 滚动发布应用并执行健康、登录和核心只读烟测；
6. 开启写入并观察错误、延迟、锁等待和任务积压；
7. 删除旧字段只能在旧应用完全退出后的后续版本完成。

应用回退只能回到仍兼容当前数据库结构的版本；破坏性数据错误通过前向修复迁移或恢复点处理，不提供虚假 down migration。

## 4. 可观测性和告警

日志为结构化 JSON，必须包含 `timestamp, level, service, environment, requestId, commandExecutionId, accountId, module, action, resultCode, durationMs`，并对密码、Cookie、地址、电话、工资和银行信息脱敏。

核心指标：HTTP P50/P95/P99、错误率、JDBC 池、事务回滚、锁等待/死锁、幂等冲突、提交后任务积压、报表水位、文件失败、迁移错误、备份时间和恢复演练结果。

告警门槛：5 分钟窗口错误率 >1%；写命令 P95 >1 秒持续 10 分钟；死锁 >5 次/10 分钟；action task 最老积压 >10 分钟；报表水位 >5 分钟；备份失败一次即告警。

## 5. 备份、恢复和目标

- MySQL 每日全量备份 + binlog 连续归档，目标 RPO 15 分钟、RTO 4 小时；
- 对象存储启用版本化，文件数据库记录与对象清单每日核对；
- 备份加密并保留 35 天；月度归档按经营和合规要求另行保留；
- 每季度在隔离环境执行恢复演练，必须验证登录、核心查询、事实链、文件下载和投影重建；
- 审计、迁移证据和上线证据至少保留 180 天。

## 6. 首期容量与服务目标

基线：100 个并发会话，读取 30 QPS，写入 10 TPS。普通查询 P95 <500ms/P99 <1s；写命令 P95 <1s/P99 <2s；首期报表 P95 <3s；非业务拒绝类 5xx 错误率 <0.5%。容量测试使用脱敏且与目标数量级一致的数据。

## 7. 数据迁移控制表

迁移使用 `platform_migration_batches`、`platform_migration_id_mappings` 和 `platform_migration_errors`。每条旧记录按来源系统、实体类型和旧 ID 唯一防重；目标业务标识首次生成后永久复用。转换脚本必须可重放，不能用“已插入多少行”推断完成。

迁移顺序：受控代码与账号 -> 主数据 -> 历史快照 -> 订单 -> 生产来源与核验 -> 排班 -> 发货付款与完成 -> 售后 -> 工资 -> 成本 -> 现金 -> 报表重建。

## 8. 固定切换策略

1. 样本迁移并逐条业务复核；
2. 至少两次全量演练并记录耗时和异常；
3. 旧系统继续作为权威，新系统做影子只读核对；
4. 公告维护窗口并停止旧系统写入；
5. 导入最终增量，完成精确事实和汇总对账；
6. 原子切换入口至新系统；
7. 旧系统只读 90 天，不进行同一权威事实双写。

切换前允许回到旧系统继续写；新系统开始正式写入后，不允许简单切回并形成双权威，只能暂停新写、评估前向修复或恢复到切换恢复点后重新执行迁移。

## 9. 对账与容差

账号、主数据标识、订单、生产来源、核验、发货、收付款、售后完成、工资封账和现金事实要求数量与金额零不可解释差异。展示舍入允许的差异只能出现在明确的最小币种单位分配，并必须有尾差明细。报表投影差异可通过重建修复，但来源事实差异必须在切换前清零。

## 10. 上线门禁与稳定期

Go/No-Go 需要业务、技术、数据和运维负责人共同签字。阻断条件：不可解释数据差异、恢复演练失败、P95/P99 未达标、跨模块访问门禁失败、严重权限漏洞、持续死锁或回滚不完整。

上线后稳定期 14 天：每日检查错误、延迟、锁、任务、水位、备份、现金/成本/工资对账；严重问题未关闭不得结束稳定期。每个故障必须记录时间线、影响、临时措施、根因、修复和防复发验证。
