# YUMI V2 前端与管理端架构设计

> 状态：已完成技术一致性审查，待 G0 多方签字冻结　版本：v1.0　日期：2026-09-29　适用阶段：G0/G1-G12

## 1. 技术与边界

管理端使用 Vue 3、TypeScript、Vite、Vue Router、Pinia。前端只依赖 HTTP 契约，不复制后端业务资格、金额、工作量、完成条件或工资算法；按钮可根据权限隐藏，但后端必须重新鉴权。

## 2. 工程结构

```text
frontend/src/
  app/                 # 启动、路由、全局错误和依赖装配
  shared/              # HTTP、认证、权限、格式化、通用组件
  modules/<module>/
    pages/              # 路由页面与绑定
    composables/        # 页面流程和派生状态
    services/           # HTTP 调用与响应标准化
    contracts/          # 请求、响应、视图模型
    components/         # 模块内组件
  testing/              # mock server、fixture、E2E 辅助
```

禁止页面直接拼 URL、直接访问 localStorage 会话、跨模块 import 私有 composable，或在 Pinia 中长期复制服务端权威聚合。

## 3. 会话、权限与请求

- 会话由 HttpOnly、Secure、SameSite=Lax Cookie 承载；前端不读取 token；
- 启动调用 `/api/v1/session` 获取账号、角色、资源范围和权限代码；
- HTTP 客户端统一传 `X-Request-Id`；写命令生成 `Idempotency-Key`；更新命令传 `expectedVersion`；
- 401 清除内存会话并跳登录；403 显示无权；409 显示并发冲突并要求刷新；422 展示字段/业务错误；5xx 展示请求编号；
- 自动重试仅用于幂等 GET 和尚未获得响应的安全网络失败，不自动重放未知结果的写命令。

## 4. 路由与页面目录

| 模块 | 路由前缀 | 首期页面 |
|---|---|---|
| platform | `/system` | 登录、账号、角色权限、审计、文件、提交后任务 |
| master-data | `/master-data` | 商品、客户、员工、静态数据、工时标准、小组配置、效率因子、预算模板与定制方案 |
| orders | `/orders` | 订单列表/详情、录入、确认、变更、交付约定、发货、付款、完成 |
| production | `/production` | 需求、在制品、核验、质量、修复池、来源追踪 |
| scheduling | `/scheduling` | 日历、任务创建/调整/取消、个人与小组负荷、核验提交 |
| after-sales | `/after-sales` | 案例、义务、退回、生产关联、交付、结算、完成 |
| payroll | `/payroll` | 规则版本、期间、计算复核、员工工资单、封账、补差、支付状态 |
| cost-ledger | `/cost-ledger` | 成本条目、对象成本、调整、分摊 |
| finance | `/finance` | 现金账户、现金流水、工资支付、经营支出、对账 |
| reporting | `/reports` | 八类首期报表、水位、重建和差异 |

路由元数据只保存 `permissionCode` 和资源范围要求；复杂资格由页面调用后端 eligibility/query 接口决定。

## 5. 状态边界

Pinia 只保存当前会话、导航偏好、页面筛选条件和短生命周期查询缓存。业务表单的未提交内容只保存在页面 composable，首期不持久化到服务端；离开页面后不保证恢复。列表返回后重新进入页面应重新读取数据并校验水位和版本。

跨模块页面采用“主模块页面 + 公开摘要卡片”：例如订单详情可显示生产、付款和成本摘要，但分别调用公开 HTTP，不拼接底层模型。

## 6. 交互规则

每个页面必须设计 loading、empty、partial、forbidden、conflict、validation、server-error 和 stale-projection 状态。写操作按钮在发送后禁用；超时后先按幂等键查询结果，不直接生成新键重试。

敏感字段默认遮罩；工资、成本、现金导出需要独立权限并写审计。文件先上传为临时文件，业务命令成功后由后端正式关联。

## 7. 测试与构建门禁

- 单元：格式化、权限、错误映射、composable 状态转换；
- 组件：表单校验、冲突、空态和敏感遮罩；
- HTTP 契约：请求头、响应信封、错误码和分页；
- E2E：登录、权限拒绝、订单到制作、发货付款完成、售后、工资、成本现金和报表水位；
- 构建：TypeScript 严格模式、ESLint、单元测试、生产构建和依赖漏洞检查全部通过。

构建产物使用内容哈希，运行配置不编译进代码；后端版本与前端契约版本不兼容时阻止发布。
