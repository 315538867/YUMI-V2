## 1. 权威范围

本文统一冻结数据库版本、公共字段、表所有权、迁移编号、模块间引用、索引和验证规则。各业务表的最终业务字段由本文“表注册表”指向的模块详细设计表格共同组成；禁止在 Flyway 中增加未登记表或由开发人员临时决定字段。

若本文与模块设计冲突：模块所有权和公共规则以本文为准，模块内业务字段以对应模块详细设计为准，冲突必须先修正文档再开发。

## 2. 数据库基线

- MySQL 8.4 LTS，字符集 `utf8mb4`，排序规则 `utf8mb4_0900_ai_ci`；
- 事务隔离级别 `READ COMMITTED`；应用显式事务；
- Java `long` 对应 `BIGINT`，禁止 `UNSIGNED`；
- 业务金额 `DECIMAL(19,4)`，比例、效率和损耗率 `DECIMAL(12,8)`；业务数量统一使用有符号 `BIGINT` 并按语义设置 `CHECK(value >= 0)` 或允许有符号差额，禁止以浮点或小数列保存件数；
- UTC 时间 `DATETIME(6)`，业务日期 `DATE`；
- 状态和类型使用受控 `VARCHAR(32/64)`，不使用数据库 ENUM；
- JSON 仅允许保存模块自有值对象快照、请求指纹或不可查询载荷引用，核心可查询字段必须结构化；
- 跨模块不建立物理外键，只保存稳定业务标识；引用上游快照时必须完整保存 `<purpose>_snapshot_owner_module + <purpose>_snapshot_type + <purpose>_snapshot_business_id + <purpose>_snapshot_version` 四字段，不允许只保存裸版本号，也不复制快照载荷；模块内可建立外键；
- 稳定业务标识统一使用服务端生成的 UUIDv7 小写规范文本；列预留 `VARCHAR(64)` 并使用二进制排序规则；哈希和指纹使用 SHA-256 小写十六进制；
- Flyway 是结构唯一来源，生产环境禁止 ORM 自动建表和人工改表。

## 3. 公共字段模板

| 类别 | 必需字段 |
|---|---|
| 可变实体 | `id BIGINT PK, <entity>_business_id VARCHAR(64), version BIGINT, created_at DATETIME(6), created_by VARCHAR(64), updated_at DATETIME(6), updated_by VARCHAR(64)` |
| 不可变事实 | `id BIGINT PK, fact_business_id VARCHAR(64), occurred_at DATETIME(6), recorded_at DATETIME(6), operator_id VARCHAR(64), command_execution_id VARCHAR(64), corrects_fact_id VARCHAR(64) NULL, is_valid BOOLEAN, reason_text VARCHAR(500) NULL` |
| 专用不可变快照（一类一表） | `id BIGINT PK, snapshot_business_id VARCHAR(64), <owner>_business_id VARCHAR(64), snapshot_version BIGINT, fingerprint CHAR(64), created_at DATETIME(6), created_by VARCHAR(64)`；类型由登记表固定 |
| 多类型不可变快照 | 在专用快照公共字段上增加 `snapshot_type VARCHAR(64)`，并建立受控代码检查和 `UNIQUE(<owner>_business_id, snapshot_type, snapshot_version)` |
| 投影 | 业务主键 + `last_fact_id VARCHAR(64), source_watermark VARCHAR(128), updated_at DATETIME(6), version BIGINT` |

业务编号和稳定业务标识分别承担人工识别与系统引用；任何外部引用都不得使用数据库自增主键。`created_by/updated_by/operator_id` 保存稳定账号标识。

### 3.1 字段类型与空值字典

模块表格未重复写出类型时，必须按下表生成 DDL；只有模块详细设计明确声明例外时才允许偏离：

| 字段语义或后缀 | MySQL 类型与规则 |
|---|---|
| `id` | `BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY`，只用于模块内部锁定和关联 |
| 除内部主键 `id` 外的身份与引用字段：`*_id`、`*_business_id`、`*_fact_id`、`*_snapshot_id`、`request_id`、`command_execution_id`、`operation_id` | `VARCHAR(64) CHARACTER SET ascii COLLATE ascii_bin NOT NULL`；UUIDv7 值增加 `CHECK(CHAR_LENGTH(column)=36)`；仅当模块详细设计逐字段明确标注“本地数值外键”时才可使用 BIGINT，外部引用永不使用数值主键 |
| 当前可变实体精确字段 `version` | `BIGINT NOT NULL DEFAULT 0 CHECK(version >= 0)`；创建为 `0`，每次成功修改加一 |
| `snapshot_version`、`*_snapshot_version`、`agreement_version` | `BIGINT NOT NULL CHECK(column > 0)`；所属所有者/类型内从 `1` 单调递增；跨模块快照引用版本必须大于零 |
| `source_version`、`source_*_version`、`expected_version` | `BIGINT NOT NULL CHECK(column >= 0)`；复制或校验可变实体乐观版本时允许 `0`；若来源明确是快照则按快照版本规则大于零 |
| 其他业务 `*_version` | 必须在模块字段表明确声明是“乐观版本”“快照序号”还是“来源版本”，禁止依赖通配命名猜测初值 |
| `*_quantity`、`quantity`、`member_count` | `BIGINT NOT NULL`；存量和发生量 `CHECK >= 0`，更正差额字段允许有符号 |
| `*_amount`、`*_price`、`*_cost`、`*_payable`、`*_paid` | `DECIMAL(19,4) NOT NULL`；是否允许负值由事实类型约束 |
| `*_rate`、`*_ratio`、`efficiency_factor`、`loss_rate` | `DECIMAL(12,8) NOT NULL`；普通比率按业务约束大于零或位于 `[0,1]`；`collaboration_efficiency_factor` 在 ACTIVE 标准和对应快照中必须 `> 1` |
| `*_minutes`、`standard_minutes`、`effective_minutes` | `DECIMAL(19,8) NOT NULL CHECK(column >= 0)` |
| `occurred_at`、`recorded_at`、`created_at`、`updated_at`、`completed_at`、`*_at` | `DATETIME(6)`，应用和数据库会话统一 UTC；仅表格标注 `NULL` 的完成、撤销、过期或租约时间允许空 |
| `business_date`、`work_date`、`start_date`、`end_date`、`*_date` | `DATE NOT NULL`，按 Asia/Shanghai 业务日解释 |
| `status`、`*_status`、`*_type`、`*_code` | `VARCHAR(64) CHARACTER SET ascii COLLATE ascii_bin NOT NULL`，值必须来自文档登记的受控代码 |
| `fingerprint`、`sha256`、`*_hash` | `CHAR(64) CHARACTER SET ascii COLLATE ascii_bin NOT NULL`，保存 SHA-256 小写十六进制；密码哈希字段除外，使用 `VARCHAR(100)` 保存 BCrypt |
| `name`、`*_name`、`display_name`、`original_name` | `VARCHAR(200) NOT NULL`；模块明确允许空名称时仍不得保存空白字符串 |
| `reason_text`、`description`、`note`、`*_message` | 短文本 `VARCHAR(500)`；审计或迁移长说明使用 `TEXT`，不得存敏感凭据 |
| 布尔字段 | `BOOLEAN NOT NULL` 并显式默认值；事实有效性默认 `TRUE` |
| `sort_order`、`attempt_count`、`max_attempts`、`failed_attempts` | `INT NOT NULL`，计数默认 `0`，排序从 `1` 开始 |
| `payload_reference`、`detail_reference`、`response_body_reference`、`source_watermark` | `VARCHAR(512)`；只保存受控引用，不内联不可控大对象或凭据 |
| 模块自有 JSON | `JSON`；只用于不可按字段查询的值对象或迁移原始摘要，必须有 schema/version 字段 |

除表格显式标注 `NULL` 外，业务列一律 `NOT NULL`；字符串不得用空串代替空值；默认值只允许用于布尔值、计数器和明确的初始状态。外键、唯一键、索引和 `CHECK` 必须具名，名称格式固定为 `fk_<table>_<target>`、`uk_<table>_<purpose>`、`ix_<table>_<purpose>`、`ck_<table>_<rule>`。

## 6. 关系和约束

- 模块内父子表默认使用父表稳定业务标识并建立物理外键和索引；若为了热点锁定明确采用本地数值 FK，必须在模块最终字段表逐字段标注类型和目标表，且公开契约不可暴露它。未明确标注的 `*_id` 一律按稳定 `VARCHAR(64)` 处理。
- 跨模块引用列命名为 `<module>_<type>_business_id`；引用历史快照时必须保存 `<purpose>_snapshot_owner_module + <purpose>_snapshot_type + <purpose>_snapshot_business_id + <purpose>_snapshot_version`。四字段同时非空或同时为空，消费者不保存快照载荷，也不得建立跨模块 FK。
- `master-data` 对外稳定快照类型固定为 `PRODUCT`、`PRODUCT_CUSTOMIZATION_PROFILE`、`PRODUCT_MAKING_STANDARD`、`CUSTOMER`、`EMPLOYEE_ASSIGNMENT_SUBJECT`、`WORK_TEAM`、`TEAM_EFFICIENCY_STANDARD`、`PRODUCT_STANDARD_BUDGET`、`PRODUCT_CUSTOMIZATION_BUDGET`；后两类是预算计算结果，调用方不得自造同义类型，也不得用预算结果替代商品或方案定义快照。
- 上述 `master-data` 快照采用一类一表，物理表不重复保存 `snapshot_type`；类型由本登记和专用 Ref 固定，解析端口使用显式分派，不接受任意表名或动态 SQL。
- 数量余额由来源事实与消费事实重算，同时用 `CHECK(quantity >= 0)` 和锁定查询防止负数。
- 一条有效事实唯一的场景使用生成列 `active_unique_key = IF(is_valid, business_key, NULL)` 再建立唯一索引，不依赖多个 NULL 的误判。
- 所有 `FOR UPDATE` 条件必须命中唯一索引或窄范围复合索引；禁止无索引范围锁。
- 模块表名必须以前缀或已登记的稳定业务名唯一归属；CI 扫描 Repository SQL 中出现的表名并校验所有权。

## 7. Repository 映射

每个聚合分别定义写 Repository 和查询 Repository。写 Repository 只操作本模块聚合表；查询 Repository 只操作本模块表和本模块投影。跨模块详情由 application 层调用公开 Query，不在 SQL 中 JOIN。

事实 Repository 至少提供 `append`、按业务标识读取有效链和锁定根实体；投影 Repository 提供幂等 upsert 与 rebuild。禁止通用 BaseRepository 暴露任意表 CRUD。
