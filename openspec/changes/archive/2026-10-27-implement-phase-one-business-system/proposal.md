## Why

当前仓库只有六个 HTML 业务原型及已确认的一期方案，示例数据和浏览器存储不能提供真实业务的权限、并发、事务及历史追溯保障。需要将全部一期能力转为正式系统的行为规范、工程设计和可逐项验收的任务，而不是仅实施本轮讨论的工资页面。

## What Changes

- 建立九模块单体及管理端工程，按公开接口串联客户、商品、人员、生产、订单、售后、财务和报表。
- 建立平台账号、角色和权限维护及安全引导；账号与员工资料保持独立，不增加员工绑定账号。
- 将订单确认、供料依据、任务安排、核验、交付、收付款建成有权限、幂等、锁序和回滚保护的正式命令。
- 生产分别记录线上结果与实物去向；同一报废转线下只退出一次，移交后不再由系统管理。
- 工资逐人核定；报废成本和胶水减免逐项展示，负责人填写处理金额及最终工资，不生成自动扣款合计。
- 支持已核定工资的逐人/多人部分付款及有原因的人工差额调整；实际退回不替代人工调整，也不重复产生现金或成本。
- 财务分别保存工资应付、实际成本和真实现金；凭证可选且归本条收付，工资实际部分退回不伪造整笔冲销。
- 正式页面覆盖六个现有原型入口，补齐方案要求的售后、设置和只读报表；当前原型不删除、不直接作为生产数据源。
- 增加公式、边界、真实 MySQL 事务/并发、页面和重建验收；保留历史方案版本与核定依据。

## Capabilities

### New Capabilities

- `system-foundation`：模块边界、通用数据精度、事实更正、幂等事务与上线验收基础。
- `platform-security`：登录、授权、审计、编号、文件生命周期及提交后任务。
- `business-calculation`：预算、产能、工作量、基础工资、成本到人及胶水减免纯计算。
- `customer-management`：客户、收货信息、启停及正式引用时的历史快照。
- `product-management`：商品、标准/自定义方案、预算及最终供料生产依据。
- `workforce-management`：员工就业、资格、小组、标准、快照及活动引用保护。
- `production-operations`：需求、排班、负载、核验、返工、报废、移交及数量追溯。
- `order-management`：订单确认、版本变更、应收退款、发货、履约及已有订单接管。
- `after-sales-management`：退回、修复、补发、路线变更、池内处置和售后结案。
- `payroll-settlement`：参考采集、逐项成本、胶水标准、人工核定、复核和调整。
- `cost-ledger`：生产及售后成本归集、实际人工成本、经营费用和分摊。
- `cash-management`：真实收付、日常收支、凭证、工资部分退回、冲销及月度汇总。
- `operating-reports`：通过公开来源构建可重建报表、差异对账和延迟状态。
- `management-ui`：正式管理端页面、跨模块导航、类型化接口、权限和反馈状态。

### Modified Capabilities

无。项目此前没有 OpenSpec 主规范；以上均为新能力规范。售后和财务能力的规范拆分不改变九个顶层模块的边界。

## Impact

- 计划新增 `backend/`、`frontend/`、测试与部署验证配置；本次提案没有创建这些业务工程。
- 后端沿用已确认的 Java 21、Spring Boot 3.5、Spring Modulith、JdbcClient、MySQL 和 Flyway。前端工程选型及构建方案见 `design.md`，属于本提案技术决策，不伪称历史方案已冻结。
- 新增接口、迁移、公开 Feed 和页面；已有 HTML、JS store 与 `.superpowers/` 临时预览不会被导入数据库或当作真实账务。
- 本提案不包含资金账户、员工账号绑定、材料库存/采购、线下库存销售、服务端业务草稿、自动工资扣款、自动超额激励或会计总账。
- 提案覆盖与基线映射见 `coverage.md`；实施清单见 `tasks.md`，实施与部署须另获授权。
